# AI 获客系统 PC 端交互与视觉优化设计

## 1. 目标

对唯一真源 `prototype/index.html` 做全系统 PC 端交互与视觉优化，在不删减现有业务功能的前提下，建立统一的企业 SaaS 系统壳层、组件体系、状态反馈和任务闭环。

视觉与系统样式参考线上增长云台商家端：`https://huoke.jiazucloud.com/`。不仅复用其深色侧栏和蓝灰配色，内容区域也必须采用同类后台工作区结构：轻量页面标题、连续白色工作面、紧凑筛选与操作栏、低装饰表格和列表。保留新版原型的企业 Agent 经营闭环与业务结构，但不保留大面积深色驾驶舱和层层卡片表达。

## 2. 设计范围

### 包含

- 全局侧栏、顶栏、面包屑、页面内容区。
- 企业 Agent、运营计划、任务与审批。
- 营销场景生成、数字人混剪、爆款追踪、自动化运营、作品与产物。
- AI 销售、PPT / 朋友圈、Agent 中心、本地工作台。
- 知识大脑、数字人、提示词管理、结果复盘。
- 平台与数据源、成员与权限、用量。
- 加载、空态、错误、进行中、待确认、完成与失败状态。

### 不包含

- 移动端原型、移动端导航和触控交互。
- 1024px 以下的窄屏适配。
- 新后端接口、真实生成能力、线上发布和外部系统集成。
- 与本轮 UI 优化无关的 PRD、会议记录和知识卡片改动。

## 3. 全局信息架构

侧栏固定宽度 228px，按任务属性分为五组：

1. **工作台**
   - 企业 Agent
   - 运营计划
   - 任务与审批
2. **内容运营**
   - 营销场景生成
   - 数字人混剪
   - 爆款追踪
   - 自动化运营
   - 作品与产物
3. **智能业务**
   - AI 销售
   - PPT / 朋友圈
   - Agent 中心
   - 本地工作台
4. **智能资产**
   - 知识大脑
   - 数字人
   - 提示词管理
   - 结果复盘
5. **管理**
   - 平台与数据源
   - 成员与权限
   - 用量

顶栏固定高度 56px，显示面包屑、当前企业、通知和账号操作。页面内容区使用 24px 至 32px 外边距，每个页面仅保留一个明确主操作。页面标题直接位于工作区顶部，不再默认包裹为独立大卡片。

## 4. 视觉系统

### 颜色

- 侧栏：深蓝黑，文字使用带蓝相的浅灰。
- 页面背景：低对比浅蓝灰。
- 内容工作面：白色，1px 浅边框，4px 至 6px 圆角，默认无阴影；只有浮层使用轻阴影。
- 主操作：深蓝色。
- 成功与正常运行：青绿色。
- 待确认：橙色。
- 高风险、失败和阻断：红色。

### 字体与间距

- 字体栈：`PingFang SC`, `HarmonyOS Sans SC`, `Microsoft YaHei`, `system-ui`, `sans-serif`。
- 默认正文 14px，辅助信息 12–13px，页面主标题 22–24px。
- 建立 4 / 8 / 12 / 16 / 24 / 32px 间距尺度，避免每个模块使用随意间距。
- 保持紧凑但不拥挤的企业工具节奏，不使用大面积装饰渐变、发光和玻璃拟态。

## 5. 共用组件规则

- **页面头部**：标题、一句说明、状态和唯一主按钮，直接置于内容背景，不使用独立卡片。
- **工作区工具栏**：筛选、搜索、批量操作和主操作形成一条紧凑工具栏，与下方列表或表格连续衔接。
- **指标区**：使用横向连续指标条或表内摘要，避免大量独立小卡片。
- **任务列表**：统一任务名称、责任人、时间、风险、状态和操作位置。
- **表格**：统一表头、行高、状态标签和操作列，低频操作收入“更多”。
- **表单**：按任务步骤分组，默认只显示必要输入，高级参数渐进展开。
- **审批**：必须显示影响对象、引用依据、风险和通过后动作。
- **状态反馈**：统一为“准备 → 生成 → 待确认 → 完成 / 失败”。
- **空状态**：说明为什么为空，并提供下一步入口。
- **反馈**：普通成功使用 Toast；高风险或不可逆动作使用明确确认层。

## 6. 核心交互

### 企业 Agent 首页

首屏仅回答四个问题：当前经营状态、待处理事项、Agent 正在做什么、已产生什么结果。对话式入口作为“下达目标”的主入口，以紧凑白色输入工具栏呈现，不使用大面积深色英雄区。计划、审批、执行和结果在同一白色工作面中形成连续任务流。

### 全系统内容骨架

企业 Agent、AI 销售、PPT / 朋友圈、知识大脑、结果复盘及其他业务页共享以下骨架：

1. 轻量页面标题与主操作。
2. 必要时出现的筛选或任务输入工具栏。
3. 连续指标摘要。
4. 主列表、表格、表单或工作流主体。
5. 贴近当前对象的状态反馈和次级操作。

不为每段内容重复添加圆角卡片。相邻信息优先使用分割线、浅色表头、背景层级和间距分组。表单控件、按钮、表格行高及状态标签统一使用参考站的紧凑后台密度。

### 内容与产物生成

营销场景生成、数字人混剪、PPT / 朋友圈共享六步任务框架：

1. 选择目标。
2. 引用知识。
3. 配置产物。
4. 生成预览。
5. 人工确认。
6. 导出或发布。

用户离开页面后任务继续运行，并可在全局任务中心查看。生成结果允许返回局部修改，不强制重启整条流程。

### 审批与任务

首页、任务中心和业务页保持状态一致。高风险操作不能仅通过 Toast 模拟完成，必须展示确认内容。审批完成后原位置更新状态并提供“查看结果”。

### 知识与复盘

知识大脑负责资料、事实、权限和 Agent 授权。结果复盘位于“智能资产”分组，承接内容表现、线索结果、策略建议和知识候选。学习建议只能进入候选状态，不得自动改动企业事实、权限和合规规则。

## 7. 异常与安全边界

- 数据缺失时显示数据来源、时间范围和缺口，不伪造完整结论。
- 生成失败时保留用户输入，提供局部重试或返回修改。
- 涉及价格、承诺、外发和发布时展示引用依据和风险级别。
- 当平台未开放发布 API 时，只展示导出或人工发布，不宣称自动发布。
- 不从会议材料推断未验证的硬件、部署、审批或商业能力。

## 8. PC 端验收

### 视口

- 主验收：1440 × 900、1920 × 1080。
- 最小支持宽度：1024px。
- 不验收移动端、平板竖屏和 1024px 以下的布局。

### 核心点击链路

- 企业 Agent → 运营计划 → 任务审批。
- 营销场景生成 → 生成 → 人工确认。
- PPT / 朋友圈模式切换 → 生成 → 提交审核。
- 知识大脑 → 结果复盘 → 建议进入下轮计划。
- 侧栏分组、面包屑、页面内跳转和返回。

### 质量检查

- 检查文字溢出、遮挡、横向滚动、按钮层级和状态反馈。
- 对照参考站检查内容区结构，不接受仅侧栏和配色接近、主体仍为展示型大卡片的结果。
- 运行现有原型测试，并补充导航分组、核心交互状态和 PC 宽度契约检查。
- 最终查看真实渲染截图，不仅以代码和静态测试作为完成证据。

## 9. 实施约束

- 保留现有单 HTML 可直接打开的原型形态。
- 优先收敛 CSS 变量和共用类，避免继续增加页面级局部样式。
- 尽量复用现有 DOM 与交互函数；只在统一壳层、状态或关键任务流需要时做局部结构调整。
- 保留工作区中用户已有的未提交改动，不处理无关文件。
