# 企业 Agent 经营闭环设计

> 版本：v1.0
> 状态：已完成产品结构与执行治理确认，进入原型实施
> 关联方案：`2026-07-23-enterprise-knowledge-base-design.md`

## 1. 产品定位

AI 获客从单点内容生成工具调整为“企业 Agent 驱动的经营执行系统”。企业 Agent 是企业经营总控和老板的对话入口；内容、视频、AI 销售、PPT/朋友圈等业务 Agent 是场景执行单元；企业知识大脑提供稳定事实、规则、素材和权限边界；经营数据层提供当前目标、过程数据和结果数据。

系统的核心闭环为：

```text
企业知识与经营数据
  → 企业 Agent 诊断
  → 生成周期运营计划
  → 调度业务 Agent 执行
  → 风险分级与人工审批
  → 发布或业务动作
  → 回收曝光、线索和成交结果
  → 复盘与优化建议
  → 人工确认知识候选
  → 下一周期诊断
```

企业知识库是长期大脑，但不承担实时经营指标存储。一次经营结果不能直接改写企业事实，只能形成策略建议或知识候选。

## 2. 目标用户与核心任务

### 2.1 老板与企业管理员

- 用自然语言提出经营目标、询问现状和分配任务。
- 查看企业诊断、确认周期运营计划和预算边界。
- 审批发布、报价、客户外发和预算等高风险动作。
- 查看结果复盘和企业 Agent 的学习建议。

### 2.2 部门负责人

- 管理本部门业务 Agent、知识范围和运营任务。
- 审核中风险产物，处理异常和知识缺口。
- 对本部门结果和知识质量负责。

### 2.3 执行人员

- 接收人工任务、补充资料、修改草稿并提交审批。
- 查看自己被授权的计划、任务、知识与结果。

## 3. 信息架构

左侧导航按经营流程而不是工具类型组织：

1. **经营**：企业 Agent、运营计划、任务与审批。
2. **业务 Agent**：内容与视频、AI 销售、PPT/朋友圈。
3. **大脑与复盘**：知识大脑、结果复盘。
4. **管理**：成员与权限、平台与数据源。

企业 Agent 是登录后的日常首页。原“工作台”升级为企业经营驾驶舱，原内容创作、爆款、作品、知识库、成员和平台绑定能力保留并重新归组。

## 4. 首次启用与日常工作衔接

首次启用仍保持三个用户可见阶段：

1. **上传最小知识包**：企业身份、产品或服务为必需；客户与销售、品牌素材、当前经营为可选增强包。
2. **AI 提取并确认关键事实**：只确认价格、承诺、有效期、权限和发布规则等高风险内容。
3. **能力解锁并生成首个任务**：展示已可用业务 Agent、受限能力和待补知识，随后进入企业 Agent 首页。

首次启用收集的是企业稳定事实和可授权资料。当前阶段目标、渠道现状和本月数据进入经营数据层，供诊断使用，但不自动变成正式知识。

## 5. 企业 Agent 日常驾驶舱

驾驶舱按“对话—诊断—计划—执行—结果—学习”组织，不采用同权重卡片堆叠。

### 5.1 对话主入口

- 顶部显示当前周期目标和 Agent 工作状态。
- 老板可直接输入“诊断本周获客”“安排下周运营计划”“写一份汇报 PPT”等任务。
- 快捷指令只作为示例，不替代自由对话。
- 每次响应需要说明使用的数据范围、知识依据和下一步动作。

### 5.2 经营诊断

- 展示综合健康度和关键经营信号。
- 明确区分已连接数据、人工填报数据、缺失数据和推断结论。
- 对知识不足、数据未连接和指标异常给出可执行补救动作。

### 5.3 周期运营计划

- 计划由目标、策略、任务、业务 Agent、负责人、时间、审批规则和预期结果组成。
- 老板确认计划后，企业 Agent 才批量下发任务。
- 计划允许逐项修改、暂停和重新生成，不要求整份推翻。

### 5.4 Agent 执行监控

- 每个业务 Agent 显示当前目标、执行任务、责任人、状态、下一节点和结果回传情况。
- 状态统一为：待开始、执行中、待审核、已完成、受阻、已暂停。
- 任务完成不等于闭环完成；只有结果数据已回收或明确标记无法回收，任务才进入复盘。

### 5.5 审批中心

- 聚合发布、客户外发、报价、预算和正式知识变更等高风险动作。
- 审批项必须展示内容摘要、风险原因、知识依据、影响范围和执行对象。
- 支持批准、退回修改、转交和拒绝，并保留审批记录。

### 5.6 结果复盘与学习

- 回收曝光、互动、线索、有效线索、成交和人工评价。
- 对不同内容、渠道、客户场景和执行策略进行归因，生成下一轮建议。
- 学习结果分为“运营策略建议”和“知识候选”；前者可用于下一轮计划草拟，后者必须由有权限的人确认后进入知识大脑。

## 6. 任务与风险模型

任务统一包含：目标、输入、使用知识、业务 Agent、负责人、截止时间、风险等级、审批节点、产物、执行结果和复盘结论。

| 风险等级 | 示例 | 执行规则 |
|---|---|---|
| 低风险 | 诊断、草拟计划、文案/PPT 初稿、素材整理 | Agent 自动执行并记录 |
| 中风险 | 批量生成、计划调整、知识候选修改 | 完成后通知负责人确认 |
| 高风险 | 对外发布、客户外发、报价、预算、正式知识变更 | 必须人工审批后执行 |

高风险审批不允许被企业 Agent 或业务 Agent 关闭。权限不足时只能提交申请或转交有权限负责人。

## 7. 权限与数据边界

- 老板/管理员：全局诊断、计划确认、高风险审批和权限配置。
- 部门负责人：本部门计划、业务 Agent、知识候选和中风险确认。
- 执行人员：处理授权任务和提交审核。
- 审阅者：只查看指定计划与结果。
- 知识、任务、结果均带企业、部门、项目、负责人和安全等级范围。
- Agent 的可见范围取当前任务发起人权限、Agent 服务身份权限和任务目的三者交集。

## 8. 异常与降级

- **知识不足**：说明缺少的知识包和受影响能力，允许上传资料或对话补充。
- **数据未连接**：标明未连接来源，支持人工填报或文件导入后继续诊断。
- **Agent 执行失败**：保存上下文、失败原因和已完成步骤，支持重试、转人工或暂停。
- **发布受阻**：显示平台授权、内容审核或人工审批的具体阻塞点。
- **结果无法回收**：允许人工补录并标注来源，复盘时降低结论置信度。

## 9. 原型实施范围

本轮原型实现：

- 企业 Agent 驾驶舱和自由对话式任务入口。
- 经营诊断、周期计划、业务 Agent 执行监控。
- 任务与审批列表、风险分级和审批交互。
- 结果复盘、策略建议和知识候选确认。
- 与现有知识初始化、知识治理、内容创作和平台绑定页面的导航衔接。
- 桌面端与移动端关键状态。

本轮不接入真实模型、CRM、平台发布、预算支付或自主策略修改。所有数据与动作均为原型演示，界面必须明确数据状态和自动化边界。
