# 企业 AI 经营大脑后台设计规范 V1.0

> 日期：2026-08-05
> 状态：已实施，待视觉复核
> 适用范围：`prototype/index.html` 及后续 PC / 响应式后台页面
> 参考方向：微伴式企业后台骨架 + 星云有客式经营闭环
> 证据边界：借鉴公开产品的信息组织与交互范式，不复制其品牌、页面、文案或专有资产

## 1. 设计结论

企业 AI 经营大脑采用“高密度业务后台”而非“AI 对话产品”作为基本形态。

视觉上保持国内成熟 SCRM 后台的克制、稳定和高效率；交互上围绕企业建档、诊断、内容生产、线索承接、人工审核和结果复盘形成业务闭环。AI 是嵌入各业务页面的分析与执行能力，不是占据首页中心的独立聊天入口。

一句话设计定义：

> 用微伴式清晰后台承载日常操作，用星云有客式数据闭环表达经营结果，让 AI 建议、执行依据和人工控制点自然出现在任务过程中。

## 2. 设计目标与非目标

### 2.1 目标

- 老板进入首页后 10 秒内看懂当前重点、待确认事项和下一步。
- 运营人员能在列表、详情、任务和审核之间连续工作，减少跨模块跳转。
- 任何 AI 生成或自动执行都能看到来源、状态、影响范围和人工确认点。
- 同类页面使用相同骨架、密度和反馈，不因模块不同重新发明交互。
- 桌面端优先支持 1366–1920px；1024px 仍可完整工作；窄屏进行真实重排。
- 规范可被设计、前端、测试和产品共同验收。

### 2.2 非目标

- 不复刻微伴或星云有客的品牌视觉和页面细节。
- 不把后台包装成低代码 Agent 编排器。
- 不用大面积渐变、发光、玻璃卡片营造“AI 感”。
- 不新增与业务无关的控制台、模型参数或提示词配置。
- 不用更多卡片掩盖信息架构问题。

## 3. 核心设计原则

### 3.1 业务对象先于 AI 能力

导航和标题优先使用“企业档案、经营计划、营销物料、AI 获客、企业知识”等业务语言。AI 只作为动作或状态出现，例如“AI 分析建议”“生成草稿”“依据不足”，不将“Agent、模型、工作流”作为老板端的主入口。

### 3.2 结果先于过程

首页首先回答三件事：现在最重要的是什么、需要我做什么、最近产生了什么结果。详细执行过程进入任务详情或抽屉，不在首页平铺完整流水线。

### 3.3 操作就近

查看、修改、审核、重试等动作应出现在对象所在行、详情顶部或当前状态节点旁。禁止让用户先进入另一个“成果中心”或“审批中心”才能完成原模块中的任务。

### 3.4 状态可见

异步任务必须显示当前状态、开始时间、预计下一步、失败原因和恢复动作。状态不能只用颜色表示，必须同时包含文字与形态。

### 3.5 人工可控

对外发布、价格承诺、客户外发、正式知识修改和高成本生成必须设置明确确认门。确认界面必须说明对象、依据、影响范围和确认后会发生什么。

### 3.6 证据可追溯

硬事实和主要分析结论必须能追溯至已确认企业信息、上传资料、业务数据或用户输入。不得用界面精致度替代能力接入证据。

## 4. 设计 Token

### 4.1 颜色

V1.0 延续当前原型已经使用并经过渲染的冷灰蓝系统。代码实现使用 OKLCH；以下为语义角色，不再按页面增加自定义颜色。

| Token | 当前值 | 用途 |
|---|---:|---|
| `--bg` | `oklch(0.968 0.009 225)` | 页面底色 |
| `--surface` | `oklch(0.995 0.002 225)` | 面板、表格、弹窗 |
| `--surface-2` | `oklch(0.978 0.006 225)` | 表头、悬停、次级区域 |
| `--rail` | `oklch(0.215 0.027 235)` | 左侧主导航 |
| `--ink` | `oklch(0.27 0.022 225)` | 主文字 |
| `--ink-2` | `oklch(0.46 0.018 220)` | 次级文字 |
| `--ink-3` | `oklch(0.62 0.014 215)` | 辅助信息 |
| `--line` | `oklch(0.91 0.009 225)` | 常规边界 |
| `--line-2` | `oklch(0.855 0.012 225)` | 强边界、控件边界 |
| `--brand` | `oklch(0.53 0.125 252)` | 品牌识别与数据编码 |
| `--brand-d` | `oklch(0.45 0.125 252)` | 主操作 |
| `--accent` | `oklch(0.66 0.11 62)` | 少量提醒与客户模式标识 |
| `--ok` | `oklch(0.6 0.09 155)` | 成功、完成、低风险 |
| `--warn` | `oklch(0.7 0.13 65)` | 待确认、中风险、信息不足 |
| `--danger` | `oklch(0.58 0.15 25)` | 失败、高风险、不可逆警告 |

约束：

- 同一视口只有一个主操作色，即 `--brand-d`。
- `--accent` 不用于大面积背景或常规按钮，只用于少量高信号提醒。
- 状态色不承担唯一信息表达，必须配合文字、图标或边界。
- 业务平台自身颜色仅可用于小尺寸平台标识，不用于整块面板。
- 页面内不得增加任意原始十六进制颜色；新增色必须先进入 Token 评审。

### 4.2 字体

- 中文 UI：`"PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei", system-ui, sans-serif`。
- 数字、日期和版本：`"Sora", system-ui, sans-serif`，必须启用等宽数字。
- 数据密集型后台不使用独立展示字体；标题通过字号、字重和留白建立层级。
- 禁止使用衬线字体、装饰字体或全大写英文标题制造风格。

### 4.3 字号与行高

| 场景 | 字号 | 字重 | 行高 |
|---|---:|---:|---:|
| 页面标题 | 20px | 600 | 1.4 |
| 关键结论标题 | 24px | 600 | 1.4 |
| 区块标题 | 14–16px | 600 | 1.45 |
| 正文 | 13–14px | 400 | 1.55 |
| 表格正文 | 13px | 400/500 | 1.45 |
| 辅助文字 | 11.5–12.5px | 400 | 1.5 |
| 数值指标 | 24–28px | 600 | 1.1 |

辅助文字不得低于 11px。可点击文本不得仅靠颜色区分。

### 4.4 间距、圆角与阴影

- 基础网格：4px；主要布局节奏：8px。
- 页面左右间距：桌面 28px，平板 20px，窄屏 14–16px。
- 面板间距：16px；紧密组件间距：8px；标题与说明：3–6px。
- 主面板圆角：6px；控件圆角：4px；强调面板最大 8px。
- 胶囊圆角只用于状态标签、计数和筛选条件，不用于普通按钮。
- 常规面板只用 1px 边框，不使用阴影；浮层、悬浮菜单和抽屉可用一级或二级阴影。
- 禁止在同一页面混用 6px、12px、16px、24px 多套卡片圆角。

### 4.5 动效

- 常规反馈 120–180ms；页面或抽屉进入 180–240ms。
- 动效只解释状态变化，不用于装饰。
- 按钮按下可有 0.98 缩放；列表悬停只改变底色或边界。
- 加载状态使用进度、骨架或状态文字；禁止长时间只显示旋转图标。
- 尊重 `prefers-reduced-motion`，关闭位移与循环动画。

## 5. 全局页面骨架

### 5.1 桌面框架

```text
┌──────── 228px 主导航 ────────┬────────────────── 56px 顶栏 ──────────────────┐
│ 品牌 / 产品                  │ 页面名称 / 面包屑      用量 / 企业切换 / 用户  │
│ 业务分组导航                 ├───────────────────────────────────────────────┤
│                              │ 页面标题 + 说明 + 唯一主操作                   │
│                              │ 筛选或子导航（按需）                           │
│                              │ 主工作区                                       │
│ 用户与退出                   │ 列表 / 分栏 / 工作台                           │
└──────────────────────────────┴───────────────────────────────────────────────┘
```

- 主导航宽度固定为 228px，支持折叠但不在 V1.0 默认折叠。
- 顶栏高度 56px，承载全局上下文，不放页面级重复操作。
- 页面标题区必须包含页面名称和一句用途说明；最多一个实心主操作。
- 内容区默认不设置窄版最大宽度，表单向导除外。
- 页面背景与面板表面保持轻微层次，不用阴影堆叠卡片。

### 5.2 导航

主导航按业务阶段分为：

1. 经营：首页、企业档案、品牌与经营。
2. 增长：营销物料、AI 获客。
3. 资产与管理：企业知识、设置。

规则：

- 一级导航不超过 8 项；子能力优先放在页面内标签页。
- 选中态使用浅色背景、亮色文字和单一侧边标记。
- 计数只表示明确待处理数量，不用“新”“热”长期装饰导航。
- “Agent 中心、提示词、本地工作台”等平台能力不出现在客户主导航。

### 5.3 页面标题区

- 左侧：页面标题 + 一句说明。
- 右侧：唯一主操作或页面级状态。
- 筛选、批量操作和视图切换进入独立工具栏，不与标题混排。
- 标题区不使用卡片背景。

### 5.4 抽屉、弹窗与整页详情

| 容器 | 使用条件 |
|---|---|
| 右侧抽屉 | 查看列表对象详情、快速编辑、审核、查看依据；关闭后保留列表上下文 |
| 小弹窗 | 单一确认、短表单、删除或提交审批 |
| 宽弹窗 | 对比、冲突处理、选择素材；内容不超过一个主要任务 |
| 整页详情 | 长流程、复杂生成、需要持续保存或多标签内容 |

抽屉建议宽度 480–640px；包含长文预览或双栏依据时可达 760px。禁止把复杂工作台塞入小弹窗。

## 6. 信息密度与布局

### 6.1 页面密度

- 默认控件高度 36px，核心触控操作在窄屏提升到至少 44px。
- 常规表格行高 44px；包含两行信息时使用 56–64px。
- 指标卡优先横向连续排列，共用一个外框和分隔线，不为每个指标建立悬浮卡片。
- 一屏主区块控制在 3–5 个；其余内容通过列表、标签页或展开呈现。

### 6.2 栅格

- 首页：主次两栏，主栏约 2/3，侧栏约 1/3。
- 列表详情：列表 40–48%，详情 52–60%；对象复杂时使用抽屉替代永久双栏。
- 工作台：主编辑区自适应，预览或状态侧栏 320–360px。
- 表单：桌面双列，标签与字段语义完整；长文本、上传和复杂选择跨两列。

### 6.3 卡片使用边界

卡片只用于独立对象、独立任务或不同信息层级。下列内容不应继续卡片化：

- 同一组指标。
- 同一列表中的每一行。
- 连续流程中的每一步。
- 仅包含标题和一句说明的导航入口。

这些内容优先使用共用面板、分隔线、表格或紧凑列表。

## 7. 基础组件规范

### 7.1 按钮

层级：

1. 主按钮：每个标题区或操作组最多一个。
2. 次按钮：边框按钮，用于查看、返回、保存草稿等。
3. 文字按钮：低频、无风险的辅助动作。
4. 危险按钮：仅在确认弹窗或明确危险区域出现。

按钮文案必须描述结果，如“生成品牌报告”“提交人工审核”“重试失败镜头”，禁止笼统使用“确定”“处理”“开始”。

### 7.2 表单

- 标签常驻，不用占位符代替标签。
- 必填、选填、示例和说明分别表达，避免全部塞入占位符。
- 校验在失焦或提交后就近显示；顶部可附错误摘要。
- 允许“不清楚”时提供显式选项，不让用户编造答案。
- 自动保存必须显示保存状态和最后保存时间；未实现时不得写“已自动保存”。

### 7.3 表格与列表

- 表头使用中性浅底，正文按行分隔。
- 主要对象列可展示标题 + 一行辅助信息；其余列保持单行。
- 行悬停只改变背景；选中行增加品牌色边界或浅色底。
- 行尾动作最多显示 2 个，其余进入“更多”。
- 表格必须有空状态、加载状态、错误状态和筛选无结果状态。
- 横向滚动只允许发生在表格容器内，不允许整页横向滚动。

### 7.4 状态标签

统一状态词：

- 中性：草稿、未开始、已归档。
- 进行：分析中、生成中、执行中、同步中。
- 待人处理：待补充、待确认、待审核、待发布。
- 成功：已确认、已完成、已发布、合规通过。
- 异常：部分成功、生成失败、发布失败、已失效。

相同状态在所有模块保持相同颜色与文案，不得出现“完成、成功、已生成”混用表示同一阶段。

### 7.5 标签页与步骤条

- 标签页用于并列视图，不表达必须依次完成的流程。
- 步骤条用于有前后依赖的向导或生成流程。
- 步骤条必须区分未开始、当前、已完成、失败和需人工处理。
- 超过 5 步时显示阶段摘要，详情进入任务时间线。

### 7.6 通知与反馈

- Toast 只报告短暂结果，不承载需要用户决策的信息。
- 成功反馈说明完成了什么；失败反馈说明原因和下一步。
- 需要确认或持续处理的事项进入页面状态、抽屉或任务中心。
- 同一操作不得同时出现 Toast、顶部提示和弹窗三重反馈。

## 8. 业务交互模式

### 8.1 标准对象流

```text
列表 → 查看详情 → 创建或修改 → 保存草稿 → 提交确认/审核 → 完成 → 查看版本与结果
```

同一业务对象的草稿、审核、版本和下载留在所属模块内，不建立重复的“作品库”或“成果中心”。

### 8.2 创建任务

创建流程包含：

1. 明确任务目标。
2. 选择业务对象与企业知识范围。
3. 展示系统将使用的已确认事实和素材。
4. 标记缺失信息、风险和预计消耗。
5. 用户确认后创建任务。

创建后返回任务详情，并保留返回原列表的上下文。

### 8.3 任务详情

任务详情固定包含：

- 目标与当前状态。
- 输入、来源和版本。
- 执行时间线。
- 当前产物或结果。
- 风险、人工确认点和失败恢复。
- 负责人、创建人和操作记录。

执行过程采用纵向时间线，不用横向铺满 7–10 个小卡片。

### 8.4 人工审批

审批卡必须显示：

- 审批对象。
- 为什么需要审批。
- 使用的事实与资料版本。
- 对外对象或影响范围。
- 批准后会执行的具体动作。
- “批准”“退回修改”以及必要的“转交负责人”。

高风险动作不能使用默认选中或一键批量通过。

### 8.5 失败与恢复

- 系统失败保留用户输入和已完成步骤。
- 支持只重试失败步骤，不强制重跑完整任务。
- 失败信息使用用户能理解的业务原因，同时提供诊断编号供支持人员查询。
- 部分成功要明确哪些完成、哪些失败、是否产生费用或对外影响。

### 8.6 批量操作

- 只有同类对象、同一状态且风险可控时允许批量操作。
- 选择后出现临时批量工具栏，未选择时不长期占位。
- 发布、价格更新、正式知识修改等高风险动作不默认开放批量确认。

## 9. AI 专属交互模式

### 9.1 AI 的四种呈现

1. 建议：给出结论、理由和下一步，用户决定是否采用。
2. 草稿：可编辑，明确标记未确认，不自动对外。
3. 执行：显示任务状态、输入输出和人工控制点。
4. 监测：发现异常或机会，创建待处理事项，不直接改变正式数据。

### 9.2 AI 建议卡

一张建议卡只解决一个决策，包含：

- 建议标题。
- 业务影响。
- 依据摘要。
- 信息缺口或置信边界。
- 主要动作与查看详情。

禁止使用“AI 已为你完成一切”“一键实现增长”等夸大文案。

### 9.3 依据与置信边界

- 硬事实显示来源、版本和确认状态。
- AI 判断显示使用了哪些事实及判断逻辑摘要。
- 缺少数据时使用“无法判断”或区间，不生成伪精确分数。
- 置信度不是装饰百分比；没有可解释计算依据时不展示数值。

### 9.4 自动化权限

按动作风险分层：

| 风险 | 默认行为 | 示例 |
|---|---|---|
| 低 | 可自动执行并回传 | 内部分析、生成草稿、整理资料 |
| 中 | 执行前轻确认或按规则审批 | 消耗较高的视频生成、批量内容任务 |
| 高 | 必须人工审批 | 对外发布、客户外发、报价、正式知识修改 |

## 10. 数据展示规范

### 10.1 指标卡

- 每组 3–5 个指标，使用真实数据或明确的演示标识。
- 数值、单位、时间范围和口径同时出现。
- 趋势必须包含比较基线，例如“较上周”或“较试点基线”。
- 指标点击后进入对应明细，不创建无法解释的装饰数字。

### 10.2 漏斗

漏斗必须显示每阶段数量、阶段转化率和时间范围。阶段定义保持稳定；数据未接入时明确标注“示例数据”或隐藏模块。

### 10.3 趋势与排行

- 图表必须使用填充或实体数据编码，不只画轮廓。
- 颜色优先使用品牌蓝深浅变化，状态色只标异常。
- 图例、单位、时间范围和空数据原因不可缺失。
- 排行必须说明排序口径，避免将曝光量直接解释为经营效果。

### 10.4 异常提醒

提醒格式统一为：发生了什么 → 影响什么 → 建议处理 → 查看依据。提醒卡不超过两级优先级，避免整页红黄标签。

## 11. 页面模板

### 11.1 首页

默认结构：

1. 当前最重要事项与唯一主操作。
2. 下一步或待补信息。
3. 待确认事项。
4. 最近成果。
5. 用量与异常任务。

AI 对话入口降为顶部快捷动作或辅助面板，不在首次首页占据最大面积。

### 11.2 标准列表页

```text
页面标题 + 主操作
筛选工具栏
批量工具栏（选择后出现）
表格 / 紧凑列表
分页
详情抽屉
```

### 11.3 分步建档

- 左侧或顶部显示阶段；主区只处理当前任务。
- 每步说明为什么需要这些信息、预计耗时和是否影响正式输出。
- 支持保存退出与继续；冲突信息并列展示并人工确认。

### 11.4 诊断工作台

- 左侧维度导航，右侧问题与证据。
- 顶部显示完成度、信息缺口和诊断状态。
- 结论区分事实、证据、AI 判断和无法判断。

### 11.5 内容生成工作台

- 主区：目标、输入、内容编辑或生成步骤。
- 右侧：来源、素材命中、品牌规范和产物预览。
- 生成前展示消耗和确认门；失败后支持局部重试。

### 11.6 审核页面

- 左侧或主区展示待审核内容。
- 右侧固定展示来源、风险、影响范围和历史版本。
- 底部或顶部保留一个主审批动作，退回修改为次操作。

### 11.7 设置页

- 使用左侧二级导航或分组列表，不使用功能卡片宫格。
- 保存只影响当前分组；危险设置单独分区。
- 权限配置同时显示角色、数据范围、知识范围和高风险动作规则。

## 12. 状态、权限与边界

### 12.1 页面状态

每个核心页面必须覆盖：

- 首次空状态。
- 有数据状态。
- 加载或执行中。
- 筛选无结果。
- 网络或系统失败。
- 无权限。
- 数据失效或来源异常。
- 部分成功。

空状态说明为什么为空并提供唯一下一步，不使用装饰插画代替指导。

### 12.2 权限表达

- 不向无权限用户展示敏感正文后再禁用按钮；应隐藏内容并解释申请方式。
- 禁用态说明缺少什么条件。
- Agent 权限与发起人权限分开表达；高风险动作始终进入审批。
- 权限变更写入审计记录，并显示生效范围。

### 12.3 能力接入状态

统一使用：

- 已接入：有真实服务、数据和成功/失败反馈。
- 原型演示：交互可演示，但未连接真实服务。
- 待接入：只有入口或说明，不模拟成功终态。

不得用 Toast 或定时器模拟结果后声称能力已交付。

## 13. 文案规范

### 13.1 语气

简洁、直接、可信、业务化。避免“颠覆、黑科技、智能赋能、全自动增长”等空泛表达。

### 13.2 标题

- 页面标题优先 4–8 个字。
- 区块标题说明对象，不写口号。
- 关键结论可使用完整句，但必须包含明确对象和判断。

### 13.3 操作与状态

- 动作使用“动词 + 对象”：上传企业资料、生成经营计划、提交人工审核。
- 状态使用完成时态：已确认、待审核、生成失败。
- 风险提示说明后果：批准后将向 12 位客户发送当前话术。

### 13.4 演示数据

示例企业、数据和产物必须明确标记“示例”或“能力演示”。缺少真实基线时不得展示未经说明的增长承诺。

## 14. 响应式与无障碍

### 14.1 断点

| 范围 | 行为 |
|---|---|
| ≥1366px | 完整侧栏、多栏工作台、固定详情侧栏 |
| 1024–1365px | 保留侧栏，减少页面间距和次级列宽 |
| 768–1023px | 侧栏变抽屉，多栏重排，详情使用抽屉或整页 |
| <768px | 单列任务流、底部或抽屉导航、44px 触控目标 |

产品当前可继续将 1024px 作为 PC 原型最低宽度，但新增模块必须避免依赖固定宽表；长期响应式实现不得设置整页 `min-width: 1024px`。

### 14.2 可访问性

- 正文对比度至少 4.5:1；大文字和图标至少 3:1。
- 所有可聚焦元素提供清晰的 `:focus-visible`。
- hover、focus、active 同时校验前景和背景颜色。
- 状态不用颜色单独表达。
- 表单标签与控件建立程序关联；图标按钮提供可读名称。
- 弹窗打开后管理焦点，关闭后返回触发元素。
- 动态结果使用适当的可访问通知，但避免重复朗读。

## 15. 当前原型迁移建议

### 15.1 保留

- 228px 深色侧栏和 56px 顶栏。
- 冷灰蓝页面背景、白色面板和品牌蓝主操作。
- 36px 控件、44px 表格行高和紧凑信息密度。
- 首页“当前重点—下一步—待确认—最近成果”的新结构。
- 企业档案的快速画像、六维诊断、品牌视觉和资料分层。

### 15.2 优先统一

1. 删除或收口旧版驾驶舱、Agent 卡片和重复成果入口。
2. 将卡片宫格型模块入口改为标签页、列表或工作台。
3. 统一圆角、状态词、按钮层级和标题区结构。
4. 将复杂确认流程从通用弹窗迁移为标准审核抽屉或整页任务详情。
5. 清理代码中的原始颜色、平台专属色和多套视觉规则。
6. 补齐失败、部分成功、无权限、空数据和能力待接入状态。
7. 逐步取消整页 `min-width: 1024px`，实现真实窄屏重排。

### 15.3 暂不扩张

- 不新增客户 CRM 自动成交闭环，除非产品范围再次确认。
- 不新增面向客户的 Agent 配置中心。
- 不为格优复制一套页面；继续使用客户模式和行业配置包。
- 不为设计规范单独制造无业务价值的组件展示控制台。

## 16. 验收标准

### 16.1 规范检查

- 新页面只使用已定义 Token、骨架和组件层级。
- 每个页面最多一个实心主操作。
- 同一状态在所有模块颜色和文案一致。
- AI 结论包含依据或明确的信息缺口。
- 高风险动作具有人工确认和影响范围说明。

### 16.2 代码检查

- 无未定义 Token、重复颜色体系或无说明的原始颜色。
- 无整页意外横向滚动、文本裁切和控件遮挡。
- 列表、表单、弹窗和抽屉具备键盘焦点状态。
- 页面核心状态可被自动化测试定位。
- 演示能力不得模拟为真实接入终态。

### 16.3 真实渲染

至少检查：

- 1920×1080。
- 1440×900。
- 1366×768。
- 1024×768。
- 820×1180。
- 390×844。

检查内容包括导航、标题区、表格横向范围、弹窗/抽屉、长文案、空状态、错误状态、焦点和唯一主操作。

### 16.4 交付证据

设计规范、源码检查、自动测试和真实渲染分别报告。候选 HTML、截图或结构测试通过不等于生产能力已接入。

## 17. 治理与变更

- 本文是后台视觉与交互真源；产品范围仍以对应产品规格为准。
- 新增 Token、组件或状态前，先证明现有规则无法覆盖。
- 设计变更先更新规范，再更新公共样式和页面。
- 一次改造优先处理公共 Token、公共组件和关键页面，不整文件重写现有原型。
- 每次大版本保留迁移说明，记录废弃规则、替代方案和受影响页面。

## 18. 实施顺序建议

1. 将 Token 与公共骨架收口为唯一实现。
2. 统一按钮、状态、表格、表单、标签页、弹窗和抽屉。
3. 先改首页、企业档案和 AI 获客三个关键页面。
4. 再改品牌与经营、营销物料和企业知识。
5. 最后补齐设置、权限、响应式和全状态验收。

本规范获确认后，应另行编写实施计划；规范确认本身不代表 `prototype/index.html` 已完成迁移。
