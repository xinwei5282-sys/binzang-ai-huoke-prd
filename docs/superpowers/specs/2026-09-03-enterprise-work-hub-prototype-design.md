# 企业工作中枢与受控 Agent 原型设计

> 版本：v1.0
> 状态：产品蓝图已确认，待书面规格复核后进入实现计划
> 原型真源：`prototype/index.html`

## 1. 背景与目标

当前产品已经覆盖企业诊断、经营计划、企业知识、营销物料和 AI 获客，但老板与员工的日常业务材料尚未形成统一执行闭环。会议音视频、聊天记录、客户判断、项目要求、待办和交付物之间仍是分散关系。

本轮将现有原型升级为面向企业多账号的 SaaS 原型，覆盖以下核心工作：

1. 上传会议音频或视频并形成转写、会议纪要和证据。
2. 结合会议、聊天和历史材料更新客户意向与下一步建议。
3. 将建议转成可确认的任务树；人和 Agent 的动作使用同一套待办模型。
4. 根据已确认待办生成 PPT、合同、报价和沟通话术。
5. 在同一项目的要求或产物不一致时明确提醒员工，由员工判断如何处理。
6. 支持上传聊天截图、PDF、Word、TXT 或直接粘贴文本。

可验证目标：用户能够在静态原型中完成“客户会谈上传 → 纪要与意向 → 待办确认 → Agent 生成 → 冲突处理 → 对外动作 → 客户与项目回写”的完整点击路径，并能清楚识别哪些状态只是演示。

## 2. 已确认的产品决策

### 2.1 产品形态

- 按多租户 SaaS 设计，不做老板个人专用工具。
- 每个企业租户包含多个账号；数据、权限、待办和产物按账号与协作范围区分。
- “老板、员工、销售、法务”等仅作为权限模板，实际授权落在账号能力上。

### 2.2 架构路线

采用“任务中枢 B + 受控 Agent C”的组合架构：

- B 是工作真源，保存客户、项目、任务、负责人、期限、状态、冲突与结果。
- C 是执行层，在任务授权范围内进行理解、生成、比较和内部整理。
- Agent 不得绕过任务、权限或人工门直接执行高风险对外动作。
- 所有 Agent 生成动作本身也必须成为任务树中的子任务。

### 2.3 内容归属

- 会议音视频、转写、纪要和聊天记录归入“企业大脑 → 企业记忆”。
- 客户意向、需求、异议、关键人和跟进历史归入客户档案。
- 项目范围、报价口径、交付要求、文件和冲突归入项目空间。
- 待办、负责人、期限、Agent 状态和人工判断归入工作中枢。
- PPT 直接复用现有“营销物料 → PPT”生成与编辑能力。
- 合同和报价在“项目空间 → 商务文件”中生成和管理。
- 沟通话术在“客户档案 → 跟进助手”中生成和管理。

### 2.4 老板会议要求与员工产物

- 老板会议中提取的要求不需要老板二次确认。
- 该要求作为同项目中的高优先级参考，而不是自动覆盖员工文件的强制事实。
- 发现不一致时向员工展示具体差异、双方来源和影响。
- 员工可以选择“采纳老板要求”“保留当前方案并说明理由”或“发起协商”。
- 处理结果形成项目记录和版本轨迹。

## 3. 范围与非目标

### 3.1 本轮原型范围

- 升级首页为多账号工作驾驶舱。
- 新增工作中枢：我的待办、客户、项目。
- 在企业大脑中新增企业记忆。
- 新增会议与沟通详情。
- 新增客户档案与跟进助手。
- 新增项目空间、商务文件和冲突处理。
- 将 PPT 生成任务衔接到现有营销物料/PPT 流程。
- 覆盖老板账号与员工账号的典型权限差异。
- 覆盖桌面与移动端关键页面和交互状态。

### 3.2 本轮非目标

- 不接真实语音转写、说话人识别或大模型服务。
- 不接真实文件存储、多租户数据库或第三方会议平台。
- 不接真实合同签署、报价审批、消息发送或 CRM。
- 不扫描未关联到客户或项目的员工个人草稿。
- 不自动把 AI 推断写成已确认企业事实。
- 不复制现有 PPT 编辑器，也不改变既有 PPT 生成与编辑规格。

## 4. 信息架构

现有一级导航保持“首页、品牌与经营、营销物料、AI 获客、企业大脑、设置”，并新增“工作中枢”。

建议顺序：

1. 首页
2. 品牌与经营
3. 工作中枢
4. 营销物料
5. AI 获客
6. 企业大脑
7. 设置

子导航：

- 工作中枢：我的待办、客户、项目。
- 企业大脑：诊断总览、企业 VI、企业知识、企业记忆、外部情报、进化与治理。
- 客户档案内：概览、沟通时间线、跟进助手、关联项目与交付物。
- 项目空间内：概览、要求与决策、任务、项目文件、商务文件、冲突记录。

全局上传入口可出现在首页、客户页和项目页，但底层只创建一份企业记忆记录；客户、项目和任务引用该记录，不复制原始文件。

## 5. 核心对象与关系

### 5.1 对象

| 对象 | 作用 | 关键字段 |
|---|---|---|
| 企业租户 | SaaS 数据隔离边界 | 企业 ID、套餐、策略、成员 |
| 账号 | 身份与权限主体 | 账号 ID、权限集、可见范围 |
| 企业记忆 | 会议、聊天和文件的唯一归档 | 类型、原文件、转写、纪要、来源、权限、版本、状态 |
| 客户 | 累计客户理解 | 阶段、意向、关键人、需求、预算、异议、证据、时间线 |
| 项目 | 一次合作或交付的协作空间 | 范围、报价、要求、成员、文件、决策、冲突 |
| 任务 | 人和 Agent 共用的执行单元 | 父任务、负责人、截止时间、状态、输入、产物、异常 |
| 交付物 | 可审核、下载或使用的成果 | 类型、版本、状态、来源、关联任务、关联客户/项目 |
| 冲突 | 同一项目内不一致的显式记录 | 左右内容、来源、影响、处理人、处理动作、处理说明 |

### 5.2 关系

- 一条企业记忆可关联一个客户、零个或一个项目，并产生多个候选任务。
- 一个客户可以包含多次会议、聊天和多个项目。
- 一个项目可以包含多条要求、多个文件、多个任务和多个交付物。
- 一个主任务可以包含人工作业和 Agent 作业子任务。
- 一个交付物必须关联创建它的任务，并回挂客户或项目。
- 冲突必须关联具体项目、双方来源和处理记录。

## 6. 权限与文件边界

### 6.1 三层文件范围

1. **个人文件**：默认仅上传账号可见；允许个人总结和生成；不参与企业检索与冲突检查。
2. **项目文件**：账号主动关联项目后，对项目授权账号可见；参与项目生成与一致性检查。
3. **企业记忆/正式知识**：按企业知识权限可见；候选信息与已确认事实继续使用现有知识治理边界。

老板或企业管理账号可以查看企业业务全局，但不默认扫描员工未关联的个人草稿。

### 6.2 Agent 权限

Agent 可见范围取以下三者交集：

- 当前账号权限；
- 当前任务授权范围；
- Agent 服务身份权限。

低风险内部整理可自动执行。对外发送、金额、合同条款、结果承诺和正式知识变更必须停在人工门；静态原型只演示该门禁，不执行真实外部动作。

## 7. 主流程

### 7.1 客户会谈到下一步

1. 用户上传会议音频或视频。
2. 用户选择已有客户和项目，或创建新客户；项目可稍后补充。
3. 系统演示转写、说话人识别和纪要生成状态。
4. 会议详情展示摘要、原文、需求、预算、异议、承诺、风险与引用时间点。
5. 系统结合客户全部历史材料分析客户阶段与意向，并展示判断依据。
6. 系统生成下一步建议、候选待办、负责人/期限建议和所需交付物。
7. 当前账号编辑并确认任务计划。
8. 确认后创建任务树；PPT、合同、报价和话术分别创建 Agent 子任务。
9. Agent 子任务完成后进行项目一致性检查。
10. 用户处理冲突、审核交付物并人工完成对外动作。
11. 跟进结果回写客户档案和项目空间，系统更新意向阶段并生成新的下一步建议。

### 7.2 聊天记录上传

1. 支持多张截图、PDF、Word、TXT 和直接粘贴文本。
2. 上传时选择“个人使用”或关联客户/项目。
3. 个人材料只在个人范围内处理；关联客户或项目后进入企业记忆。
4. 系统演示 OCR/解析，展示来源段落、低置信度和无法识别状态。
5. 解析结果进入客户时间线并触发客户意向更新和候选待办。

### 7.3 个人材料自主处理

1. 员工上传材料并选择“仅个人”。
2. 系统允许总结、改写和生成个人草稿。
3. 个人草稿不被老板工作台聚合，也不进入项目冲突检查。
4. 员工主动关联项目后，界面明确提示可见范围变化；确认后才进入项目协作。

### 7.4 同项目报价冲突

1. 员工从项目任务生成报价草稿。
2. 系统将报价金额、范围、付款条件和交付承诺与项目中的会议要求及商务文件比较。
3. 发现不一致时，任务进入“待判断”，并展示差异和来源定位。
4. 员工选择采纳、保留并说明或发起协商。
5. 系统记录处理动作，不自动覆盖任一原始材料。

## 8. 交付物路由

### 8.1 PPT

- “生成 PPT”任务不创建新编辑器。
- 点击任务动作后进入现有“营销物料 → PPT”。
- 系统自动带入客户、项目、会议纪要、任务要求、企业正式知识和企业 VI 的演示上下文。
- 继续遵循现有 PPT 流程：填写需求 → 审核大纲 → 后台生成任务 → PPT 列表 → 详情编辑与下载。
- 新 PPT 任务和生成结果回挂原任务、客户与项目。

### 8.2 合同与报价

- 入口位于“项目空间 → 商务文件”。
- 生成上下文包含项目要求、客户信息、会议要求、报价口径和企业合同规则。
- 草稿必须展示版本、来源和风险提示。
- 金额、条款与承诺不一致时必须进入冲突处理。

### 8.3 沟通话术

- 入口位于“客户档案 → 跟进助手”。
- 生成上下文包含客户意向阶段、历史沟通、异议、下一步任务和项目要求。
- 话术可编辑、复制和标记已采用。
- 标记采用后写入客户时间线；原型不提供真实消息发送。

## 9. 页面规格

### 9.1 首页工作台

- 老板账号：需我判断、重点客户、企业任务、Agent 执行和异常。
- 员工账号：我的待办、我负责的客户与项目、待处理冲突和个人快捷入口。
- 顶部提供统一上传入口。
- 首页只聚合和导航，不在卡片内复制完整业务编辑器。

### 9.2 企业记忆

- 列表支持会议、聊天、文件筛选。
- 每条记录展示来源、关联客户/项目、上传账号、可见范围、处理状态和下一步。
- 上传抽屉支持文件类型、个人/项目范围、客户/项目关联和格式提示。
- 详情入口进入会议与沟通详情。

### 9.3 会议与沟通详情

- 左侧或顶部展示媒体播放/文件信息。
- 主区展示纪要、转写和证据定位。
- 右侧或次级区展示客户意向、阶段依据、风险、下一步和候选待办。
- 允许修正客户阶段、编辑候选任务并确认创建任务树。

### 9.4 客户档案

- 展示客户阶段、意向强度和证据，不只显示一个分数。
- 展示关键人、需求、预算、异议、风险和建议。
- 时间线聚合会议、聊天、任务、交付物和人工跟进结果。
- 跟进助手生成话术，并保留采用记录。

### 9.5 项目空间

- 概览展示目标、状态、成员、下一节点和风险。
- 要求与决策区保留老板会议要求及其他来源。
- 任务区展示主任务与子任务树。
- 商务文件区生成和管理合同与报价。
- 冲突区展示待判断和已处理记录。

### 9.6 我的待办

- 支持我的、我创建的、Agent 执行、待判断、受阻、逾期和已完成筛选。
- 任务展示客户、项目、负责人、期限、来源、产物和下一动作。
- Agent 子任务展示执行步骤，但不伪造真实服务已接入。

## 10. 状态与异常

| 对象 | 正常状态 | 异常状态 | 可恢复动作 |
|---|---|---|---|
| 上传/解析 | 待处理 → 处理中 → 已完成 | 格式不支持、解析失败、低置信度 | 替换文件、重试、人工修正 |
| 客户意向 | 已分析、人工已修正 | 证据不足、信息冲突 | 补材料、修正阶段、保留原判断 |
| 任务 | 草稿 → 已确认 → 执行中 → 已完成 | 受阻、逾期、生成失败、已取消 | 改负责人/期限、重试、转人工、取消 |
| 冲突 | 待判断 → 已处理 | 协商中、材料缺失 | 采纳、保留说明、发起协商、补材料 |
| 交付物 | 草稿 → 待审核 → 可使用 | 缺资料、敏感内容、版本过期、生成失败 | 补资料、编辑、重试、重新生成 |

所有异常必须进入可处理的待办或状态区，不静默失败。失败重试只重试当前动作，不删除已完成步骤或原始材料。

## 11. 原型实现约束

- 唯一原型真源继续为 `prototype/index.html`。
- 延续现有 CSS 变量、侧边栏、卡片、表格、抽屉、模态框、状态徽标和事件委托模式。
- 复用现有 `go()`、子视图切换、`review` 路由和 PPT 状态模型；新增页面不得另建孤立应用。
- 静态定时器只用于演示状态变化，界面必须显示“演示数据”或等价边界提示。
- 上传只读取文件名、类型、大小和本地预览；不得声称已完成真实云端处理。
- 账号切换使用演示账号状态，验证老板与员工的内容差异。
- 移动端不复制桌面多栏布局，关键判断、任务和主操作按优先级纵向排列。

## 12. 验收场景

### 12.1 功能路径

1. 老板账号上传客户会议，查看纪要、客户意向与依据，确认任务并进入 PPT 生成。
2. 员工账号上传个人文件，自主生成摘要，保持个人私有。
3. 员工把文件关联项目，生成报价后看到与老板会议要求的差异，并完成一种冲突处理。
4. 上传聊天截图或文档，完成解析演示并在客户时间线看到新增记录、意向变化和候选任务。
5. 从 PPT 子任务进入营销物料/PPT，带入上下文并完成现有 PPT 演示流程。
6. 从项目生成合同或报价草稿，从客户跟进助手生成并采用沟通话术。

### 12.2 状态覆盖

- 上传成功、格式不支持、处理中、解析失败和低置信度。
- 无客户、无项目、无会议、无任务、无冲突和无交付物空态。
- Agent 待开始、执行中、待判断、已完成、受阻和生成失败。
- 客户意向证据充分、证据不足和人工修正。
- 项目冲突待判断、采纳、保留说明和发起协商。

### 12.3 质量门槛

- 全量 `node:test` 通过。
- `git diff --check` 通过。
- `127.0.0.1:8010` 页面与 `prototype/index.html` SHA-256 一致。
- 1440×900 与 390×844 真实浏览器关键路径可用。
- 无控制台错误、横向溢出、遮挡、空白页或无法关闭的抽屉/模态框。
- 所有新增页面可通过侧边栏或业务动作到达，返回路径明确。
- 所有演示数据、定时器和未接入能力均有清晰边界说明。

## 13. 实施拆分建议

实现计划应按以下顺序拆分，避免同时改动全部页面：

1. 导航、演示账号、核心对象状态与共享组件。
2. 企业记忆上传、列表和会议详情。
3. 客户档案、意向证据与跟进助手。
4. 项目空间、商务文件与冲突处理。
5. 我的待办、任务树与 Agent 状态。
6. 首页工作台聚合与 PPT 路由衔接。
7. 桌面/移动浏览器验收、异常态补齐和文档一致性检查。

每一阶段都应复用同一套演示对象和状态，避免各页面复制彼此不一致的数据。
