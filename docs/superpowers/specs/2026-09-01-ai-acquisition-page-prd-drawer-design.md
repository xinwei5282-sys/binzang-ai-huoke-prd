# AI 获客页面级 PRD 抽屉设计

> 日期：2026-09-01
> 状态：已确认方案
> 参照：沉香 AI 原型 2026-08-31 页面 PRD 抽屉
> 原型真源：`prototype/index.html`

## 1. 目标

在不改变 AI 获客现有业务流程的前提下，把页面级 PRD 直接展示在原型中。产品、设计、研发和验收人员进入任一 AI 获客二级页时，可以从固定入口查看与当前页面严格对应的字段级 PRD，不再依赖脱离页面的 Markdown 摘要。

同时统一现有 PRD 中的版本、日期和命名：现行名称使用“营销视频”和“AI 混剪”，不再把“短视频创作”或“AI 视频”作为当前入口。

## 2. 范围

### 2.1 本期包含

- AI 获客总览：`acquisition`
- 获客计划：`plan`
- 爆款追踪：`burst`
- AI 混剪：`remix`
- 营销视频：`create`
- 数字人：`avatar`
- 右侧固定“页面 / PRD”入口
- 与当前路由联动的页面级 PRD 抽屉
- 对应 Markdown PRD 的版本、日期、旧术语和结构同步
- 页面 PRD 内容、路由联动、可访问性和视觉布局测试

### 2.2 本期不包含

- 品牌与经营、营销物料、企业大脑、设置等其他一级模块的页面 PRD 抽屉
- 在线编辑、审批或发布 PRD
- 从 Markdown 运行时解析并渲染 PRD
- 修改 AI 获客既有生成、审核、发布或 Remotion 流程
- 将静态原型描述为已上线生产能力

## 3. 方案选择

采用“全部 AI 获客二级页独立 PRD + 路由感知抽屉”。

未采用仅覆盖营销视频和 AI 混剪的局部方案，因为获客计划、爆款追踪和数字人仍会缺少页面契约。未采用全模块共用一份总 PRD 的方案，因为字段、状态、权限和验收无法与当前页面准确对应。

## 4. 信息架构与组件边界

### 4.1 页面入口

- 浏览器视口右侧中部固定一个 44×92px 竖向入口。
- 入口分两行显示“页面”和“PRD”。
- 入口只在 `acquisition`、`plan`、`burst`、`remix`、`create`、`avatar` 六个路由显示。
- 入口位于页面内容层之外，不占用工作区宽度，不跟随页面滚动。
- 入口的可访问名称为“查看{当前页面名} · 页面 PRD”。

### 4.2 PRD 抽屉

- 点击入口后显示全屏遮罩和右侧全高抽屉。
- 桌面端宽度为 720px，窄屏不超过视口宽度。
- 标题为“{当前页面名} · 页面 PRD”。
- 正文独立滚动，页头和页脚固定。
- 支持页头关闭、页脚关闭、点击遮罩和 Esc 关闭。
- 关闭后焦点返回触发入口。
- 抽屉打开时锁定页面背景滚动，并保持焦点在抽屉内部循环。

### 4.3 与任务详情抽屉的隔离

现有 `detailDrawer` 继续只处理任务详情、错误恢复和审核操作。页面 PRD 使用独立 DOM、样式类、状态变量和开关函数，禁止复用或覆盖任务详情抽屉的标题、正文和页脚。

同一时刻只允许一个遮罩式抽屉打开。打开页面 PRD 前若任务详情抽屉处于打开状态，先关闭任务详情抽屉并恢复页面状态，再打开页面 PRD。

## 5. 页面 PRD 内容模型

原型内维护一个只读 `PAGE_PRD_CONTENT` 映射，以路由键为主键。每个页面必须提供以下字段：

- `label`：页面中文名
- `status`：需求状态
- `version`：页面 PRD 版本
- `route`：原型路由键
- `updatedAt`：更新日期
- `overview`：页面目标、适用角色、页面入口、权限要求
- `rules`：页面级业务规则
- `fields`：字段、类型、必填或展示规则、业务口径
- `actions`：按钮或操作、展示条件、执行结果、权限与记录
- `boundary`：本页产品边界和生产能力说明
- `flows`：主要状态与跳转链路
- `logs`：通知、埋点和审计要求
- `exceptions`：权限、加载失败和空状态
- `acceptance`：页面验收标准
- `tech`：接口、状态、幂等、版本、外部依赖和性能评估项

`prototype/index.html` 继续作为当前原型和交互真源；对应 Markdown 页面 PRD 保存完整产品契约，原型映射负责在评审页面展示同一口径。两者术语或版本冲突时，阻止提交并先完成同步。

## 6. 六个页面的内容重点

### 6.1 AI 获客总览

覆盖任务汇总、筛选、待确认事项、部分成功恢复、账号与发布边界。明确总览只聚合任务，不替代各任务的创建和编辑页面。

### 6.2 获客计划

覆盖目标、渠道、计划周期、企业事实依据、建议动作、人工确认、执行状态和结果回收。证据不足时必须展示信息缺口，不生成虚假增长承诺。

### 6.3 爆款追踪

覆盖平台、关键词、时间窗、抓取状态、八维拆解、证据来源、内容候选和人工采用。未接入真实平台时明确为演示或待接入状态。

### 6.4 AI 混剪

覆盖两步流程、口播来源、数字人和声音、分镜素材、首尾关键帧、后台质量门禁、分镜级问题、人工确认和 Remotion 渲染。阻断项未处理或未人工确认时不得创建正式渲染任务。

### 6.5 营销视频

覆盖视频类型、场景和目标客户推断、封面、平台文案、口播、分镜、素材、质量门禁、审核和生成。Prompt P-042、P-043、P-044 的输入输出边界必须在页面 PRD 中可追溯。

### 6.6 数字人

覆盖形象、声音、授权、训练、口播版本、生成状态、AI 标识和失败恢复。未授权或授权过期的形象与声音不得训练或出片。

## 7. 交互与状态

1. 页面路由变化后，入口的名称和目标 PRD 同步更新。
2. 用户按下入口时固化当前路由，避免点击过程中路由变化导致标题与正文不一致。
3. 打开抽屉后渲染该路由的完整页面 PRD。
4. 路由不存在映射时隐藏入口，不回退展示其他页面 PRD。
5. 抽屉打开期间若代码触发路由切换，先关闭抽屉；下次打开读取新路由。
6. 关闭抽屉后恢复背景滚动和入口焦点。

## 8. 视觉规范

- 沿用当前企业后台的中性蓝灰设计令牌，不复制沉香项目的绿色品牌色。
- 抽屉采用浅灰页面背景、白色章节卡片和低对比边框。
- 元数据展示状态、页面键、路由、版本和更新日期。
- 字段与操作使用表格；窄屏允许表格区域横向滚动，不让整个页面溢出。
- 产品边界使用独立提示块，视觉上区别于普通说明。
- 状态流使用可换行的步骤标签与箭头。
- 信息密度以评审可读为目标，不使用营销卡片、渐变或装饰性图形。

## 9. PRD 文档同步

- `PRD_企业AI经营大脑_当前开发基线.md`：更新版本、日期和 AI 获客菜单口径。
- `PRD_提示词.md`：更新版本、日期，并明确 P-042、P-043、P-044 属于当前基线。
- `PRD_视频模板化生成与换人换产品.md`：保留历史参考状态，删除现行章节中的“短视频创作 / AI 视频”旧入口。
- `prd/pages/README.md`：更新版本、日期和页面索引。
- AI 获客模块及六个页面 PRD：统一采用页面概述、页面级业务规则、页面字段、操作与结果、产品边界、状态与跳转、通知与日志、异常与空状态、页面验收标准、技术评估项的顺序。
- 新增 `prd/pages/AI获客-总览.md`；将 `prd/pages/AI获客-短视频创作.md` 重命名为 `prd/pages/AI获客-营销视频.md`，并同步所有内部链接。
- 删除旧 `AI获客-AI视频.md`，以 `AI获客-AI混剪.md` 为现行页面真源。

## 10. 异常与降级

- 缺少某页 PRD 映射：隐藏入口，并由自动测试报错。
- 映射字段不完整：测试失败，不渲染残缺章节。
- 表格内容过宽：仅表格容器横向滚动。
- JavaScript 异常：不得影响现有导航和任务详情抽屉。
- 窄屏：抽屉占满可用宽度，关闭按钮保持可见。
- `prefers-reduced-motion`：关闭抽屉位移动画。

## 11. 验收与测试

### 11.1 结构测试

- 六个 AI 获客路由均有独立 PRD 映射。
- 每个映射均包含全部必需章节和非空验收标准。
- 入口只在规定路由显示，标题与当前页面一致。
- 页面 PRD 与任务详情使用不同 DOM 标识和状态函数。
- PRD 文档中不再存在作为现行入口的“短视频创作 / AI 视频”口径。

### 11.2 交互测试

- 点击入口可打开抽屉。
- 页头、页脚、遮罩和 Esc 均可关闭。
- Tab 焦点不离开打开的抽屉。
- 关闭后焦点返回入口。
- 六个路由切换后分别展示对应标题与关键字段。
- 打开、关闭页面 PRD 不改变任务、表单和筛选状态。

### 11.3 浏览器验收

- 1440×900：入口位置、720px 抽屉、章节层级、背景锁定和表格滚动正常。
- 390×844：入口不遮挡关键操作，抽屉不横向溢出，页头和页脚可操作。
- 控制台无错误；页面、抽屉和表格无非预期溢出。
- 人工检查 AI 获客总览、AI 混剪和营销视频三个关键页面截图。

## 12. 完成定义

只有同时满足以下条件才可提交实现：

1. 六个页面 PRD 已按统一结构完成。
2. 原型能根据当前路由展示对应页面 PRD。
3. 旧术语、版本和日期已同步。
4. 全量自动测试、`git diff --check` 和项目完整验收通过。
5. 桌面与手机关键截图已人工检查。
6. 提交只包含本次 AI 获客 PRD、原型和测试相关文件，不夹带工作区其他改动。
