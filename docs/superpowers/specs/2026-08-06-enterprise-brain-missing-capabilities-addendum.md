# 企业 AI 经营大脑 V1.0 缺失能力补充规格

> 日期：2026-08-06
> 依据：2026-06-26、2026-07-23、2026-07-31 会议内容，以及《企业 AI 经营大脑 V1.0 内部产品研发方案》
> 用途：给产品、设计、前端、后端和开发 Agent 的逐项实施契约
> 状态：V1.0 补充规格；本文件只补充缺失能力，不改变既有菜单和已确认的通用产品方向

## 0. 执行规则

1. “原型已有”只表示页面或交互已展示，不表示后端能力已实现。
2. 每一项必须先有数据对象和状态，再做页面；不得用静态数字冒充真实能力。
3. 殡葬是行业客户配置，不得把殡葬字段写死在通用数据结构中。
4. 高风险事实（价格、地址、联系方式、规格、政策、承诺、资质）没有已确认来源时不得对外生成；缺失时返回“信息不足”，不得猜测。
5. 生成、发布、Agent 执行和质量评估必须能追溯到企业、知识版本、任务和操作者。

## 2. 逐项实施契约

### KB-01 企业画像、诊断、知识库统一数据（P0）

**目标**：快速画像和诊断结果必须进入企业大脑，后续内容生成读取同一份已确认数据。

**最小数据对象**：`company_profile`、`diagnosis_result`、`brand_preference`、`knowledge_item`。

每个对象至少包含：`id`、`company_id`、`source_type`、`source_id`、`status`、`version`、`owner_id`、`updated_at`。

**状态**：`未填写 → 草稿 → 待确认 → 已确认 → 已过期`。

**交互**：用户在快速画像或诊断中保存/确认后，企业大脑显示“已进入知识库”；点击可查看来源和版本，不复制第二份内容。

**验收**：确认一条企业事实后，营销物料、PPT、公众号文章和AI视频的生成输入中都能看到该事实及来源。

### KB-02 资料自动解析与知识抽取（P0）

**目标**：老板上传资料即可完成初步整理，不要求先学习知识库概念。

**输入**：营业执照、企业介绍、产品手册、报价表、服务流程、案例、评价、图片、音频、视频、Excel。

**处理链**：上传 → 病毒/格式检查 → OCR/ASR/表格解析 → 自动分类 → 提取事实/素材 → 生成候选知识 → 待确认。

**Excel规则**：自动识别产品唯一键；抽取结构化字段；抽取嵌入图片；用 `product_id` 关联文字事实与图片/视频素材；无法识别时进入待确认，不静默丢弃。

**验收**：每个候选知识必须显示原文件、页码/时间码/表格行、提取方式和置信度。

### KB-03 AI 知识质量决策（P0）

**质量维度**：来源权威性、证据数量、跨源一致性、新鲜度、完整度、权限、历史使用质量。

**决策**：

- `auto_usable`：可供授权 Agent 使用；
- `draft_only`：只能作为草稿参考；
- `quarantined`：禁止调用，等待处理。

**高风险闸门**：价格、地址、联系方式、规格、政策、承诺、资质必须有已确认来源；冲突或过期时不得自动对外输出。

**验收**：质量结果可解释，至少显示原因、来源、下一次复核时间、可用 Agent 和处理按钮；“AI已验证”必须对应真实评估记录，不能只显示标签。

### KB-04 企业事实中心（P0）

**目标**：把容易出错的事实从普通文档中提取为结构化、可版本管理的事实。

**字段**：事实类型、名称、值、单位/币种、适用范围、有效期、来源、负责人、审核人、版本、变更原因、对外输出规则。

**页面**：企业大脑 → 知识库 → 知识库内容；增加“事实”筛选和高风险事实标识，不新增独立资料库。

**验收**：修改价格或地址时必须产生新版本；历史内容可追溯；未确认新版本不能覆盖已确认版本。

### KB-05 知识到内容的调用契约（P0）

每次生成任务必须提交：`company_id`、任务类型、目标客户、场景、已确认事实、可用素材、品牌偏好、禁用词、Agent权限、引用要求。

生成结果必须返回：引用知识 ID、素材 ID、事实版本、未满足的字段、风险提示、是否需要人工确认。

**禁止**：调用 `draft_only` 或 `quarantined` 内容作为对外硬事实；找不到事实时自行补全。

**验收**：营销场景生成至少打通一条真实链路；生成预览中能查看“本内容使用了哪些企业知识”。

### KB-06 知识缺口自动转任务（P1）

AI发现缺失时生成维护任务，字段：缺口类型、影响功能、影响等级、补充建议、负责人、截止日期、状态、来源任务。

缺口等级：`阻塞生成`、`影响质量`、`建议完善`。

**验收**：因缺少价格导致生成失败时，维护中心自动出现“补充价格信息”任务，并能返回原生成任务。

### KB-07 使用结果反哺知识维护（P1）

触发来源：用户修改生成内容、回答未命中、引用错误、内容投诉、发布后数据差、知识长期未使用。

**验收**：维护任务能显示受影响的内容/Agent；知识修订后可重新评估相关黄金任务。

### KB-08 Agent 权限、审批和审计（P1）

权限至少分为：可读取、可生成内部草稿、可生成对外内容、可发布、可修改知识。

每次调用记录：操作者、Agent、知识版本、输入任务、输出、审批人、发布时间和结果。

**验收**：未授权 Agent 无法读取对应知识；高风险内容进入人工确认；审计记录可按企业、Agent、知识和任务查询。

### KB-09 老板对话到任务执行（P1）

统一链路：老板指令 → 任务识别 → 检查知识前置条件 → 生成执行计划 → 调用 Agent → 人工确认 → 执行/发布 → 结果反馈。

**验收**：输入“根据本周重点产品生成营销内容”时，系统能展示使用的产品、缺少的信息、计划步骤和确认节点，而不是直接生成无来源内容。

### KB-10 通用产品与行业包（P1）

数据层使用：通用字段 + 行业字段 + 客户覆盖配置。

殡葬行业可配置服务项目、案例模板、行业词库和专属 Agent，但不能改变通用企业、产品、客户、品牌、素材和事实对象。

**验收**：新建一个非殡葬行业企业时，不需要复制项目或修改代码即可完成建档和内容生成。

### KB-11 发布账号和发布结果（P1）

发布前必须有平台账号绑定、授权状态、人工确认状态和合规检查结果。

发布后记录平台、发布时间、平台内容 ID、成功/失败原因、撤回/重试状态。

**验收**：未授权账号不能显示“发布成功”；失败任务可以重试且不重复扣除生成额度。

### KB-12 用量、成本和效果反馈（P1）

每个任务记录模型/API、耗时、消耗额度、预计成本、实际成本、重试次数和结果。

内容结果至少关联曝光、咨询、留资、预约和成交（没有真实数据时显示“未接入”，不显示虚构数值）。

**验收**：能回答“哪些知识被用于哪些内容、带来什么结果、成本是多少”。

### KB-13 海报图像模型生成上下文（P0）

**目标**：海报生成采用“结构化任务参数 + 企业信息 + 品牌视觉 + 授权素材参考”的图像模型调用方式。模型名称以实际接入配置为准，当前原型按 **GPT Image 2 · 待接入** 展示，不代表接口已经连接。

**生成请求必须拆成四部分**：

1. `request`：海报用途、画布比例、产品/服务、主标题、CTA、素材来源。
2. `enterprise`：企业名称、行业、发展阶段、目标客户、产品价值主张。
3. `brand`：品牌语气、主色/辅助色、字体、图片风格、Logo 和禁用表达。
4. `constraints`：只使用已确认事实、不得虚构价格/地址/案例/承诺、发布前人工审核。

**知识注入规则**：

- 只发送本次任务所需且当前用户/Agent 有权限的字段，不把整份知识库原文发送给模型。
- 企业画像、品牌偏好、产品事实和素材必须携带 `knowledge_id`、版本和来源。
- 未确认或已隔离知识不能进入对外海报的硬事实提示。
- 没有已确认价格、地址或承诺时，海报不得自行生成具体数值或保证性文案。

**结果对象**：`poster_generation` 至少保存 `model`、`request`、`enterprise_snapshot`、`brand_snapshot`、`knowledge_refs`、`asset_refs`、`quality_result`、`review_status`、`output_refs`、`usage_record_id`。

**审核状态**：`草稿 → 生成中 → 待审核 → 已确认 → 已导出/已发布`；模型生成失败、审核退回和导出失败必须保留失败原因，不扣除无有效结果的额度。

**V1 验收**：在生成任务详情中能够查看“本次传入的企业信息、品牌信息、知识来源和约束”；修改企业知识版本后重新生成，必须使用新版本并保留旧任务快照。

## 3. V1.0 开发顺序

1. 先实现 KB-01、KB-02、KB-03、KB-04，完成企业知识底座。
2. 再实现 KB-05，优先打通“企业知识 → 营销场景生成 → 人工确认”。
3. 然后实现 KB-06、KB-07，形成自动维护闭环。
4. 最后接入 KB-08 至 KB-12 的权限、Agent、发布、成本和效果能力。

## 4. 开发 Agent 交付门禁

- 未提供数据对象、状态和验收条件的功能，不得标记为已完成。
- 页面演示、自动测试、真实接口和真实发布必须分开标注。
- 不得新建“成果中心”或第二套“作品库”存储知识生成结果。
- 不得将“AI质量78分”“已发布”“已验证”等静态文案当作真实业务结果。
- 每完成一项，必须补充：代码/页面位置、测试命令、测试结果、未接入依赖和人工验收项。
