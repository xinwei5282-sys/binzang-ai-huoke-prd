# 企业大脑知识总览与引导资料联动设计

日期：2026-08-11
状态：已确认，待实施

## 1. 背景

当前“企业大脑 → 知识总览”主要展示固定演示数据，包括知识健康度、正式知识数量、来源覆盖率、Agent 调用次数和知识域覆盖率。这些内容不能回答客户最直接的问题：“系统已经了解了我的企业什么？”同时，页面没有完整反映最新四步企业信息引导，也没有把客户上传资料的处理状态、待确认候选和已确认企业信息建立清晰联系。

本次调整把知识总览的首要任务改为展示企业认知结果，并明确区分客户确认内容、上传资料证据、AI 提取候选和仍待补充的信息。

## 2. 目标

1. 知识总览第一屏回答“系统已经了解了这家企业什么”。
2. 页面结构与最新四步企业信息引导一一对应。
3. 客户上传资料作为来源证据或待确认候选，不直接成为正式企业事实。
4. 总览使用当前企业实际填写和上传状态，不再用固定演示数字冒充真实指标。
5. 客户能够从总览直接返回对应步骤补充信息或处理候选。

## 3. 范围

### 3.1 本次包含

- 重构知识总览第一屏的信息架构。
- 建立四步引导字段到四张企业认知卡的映射。
- 汇总客户上传文件、官网和公众号内容源的处理状态。
- 持久化安全的资料任务元数据和待确认候选。
- 调整现有知识治理和自动质检内容的展示优先级与能力标识。
- 增加自动测试和桌面、手机真实浏览器验证。

### 3.2 本次不包含

- 接入真实 OCR、文档解析、官网采集或公众号采集服务。
- 保存上传文件本体或实现云端对象存储。
- 实现后端知识库、租户接口或正式发布能力。
- 改造企业档案诊断逻辑、营销内容生成或 Agent 权限模型。
- 用 AI 自动确认、覆盖或补写客户未确认的企业事实。

## 4. 信息架构

### 4.1 页面标题区

保留“企业大脑”标题、当前知识蓝图、Agent 授权和上传资料入口。知识总览仍与“知识库”“维护中心”并列。

标题下首先显示企业认知汇总，不再优先展示知识健康分。汇总文案根据当前状态生成，例如：

> 已确认 24 项企业信息，5 项资料候选待确认，2 份资料处理中。

数字必须来自当前表单、候选和任务状态；没有数据时显示空态说明，不显示示例数字。

### 4.2 四张企业认知卡

#### 01 企业身份

展示：

- 企业名称。
- 统一社会信用代码。
- 法定代表人。
- 成立日期。
- 注册地址。
- 经营范围。
- 所属行业。
- 当前发展阶段。

来源包括客户手填和营业执照识别候选。营业执照候选在客户保存前只显示为“待确认”。

#### 02 业务、产品与客户

展示：

- 主营业务。
- 核心产品或服务。
- 经营模式。
- 主要成交或收费方式。
- 谁负责付款。
- 核心客户。
- 关键购买场景。
- 客户痛点。
- 可验证价值。
- 核心优势。
- 服务边界。

公司介绍、产品手册、报价表、服务方案、客户案例、销售话术和评价资料只作为来源证据或候选。

#### 03 获客与经营

展示：

- 客户主要来源。
- 生意稳定程度。
- 客户跟进负责人。
- 已选择的经营模式及对应经营状态摘要。
- 当前最想改善的一个环节。
- 客户主动填写的经营数字。

经营数字未填写时不显示零值，也不根据文字状态推算线索量、转化率、成本或收入。

经营月报、销售漏斗、渠道截图、官网和公众号内容源作为辅助证据展示其处理状态。

#### 04 目标、资源与品牌

展示：

- 目标方向。
- 希望看到改善的周期。
- 客户填写的目标结果。
- 预算周期与对应金额区间。
- 主要负责人。
- 每周可投入时间。
- 参与执行人数。
- 当前已有能力。
- 执行上的主要困难。
- Logo 状态。
- 品牌表达语气。
- 禁止使用的表述。

主色、视觉风格和图片风格不重新进入初始设置摘要；已有旧数据继续作为品牌识别候选保留。

### 4.3 资料证据汇总

四张卡片下方显示资料证据条，汇总：

- 已上传资料数量。
- 已解析数量。
- 解析中数量。
- 待确认候选数量。
- 失败数量。
- 等待授权的官网或公众号内容源数量。

资料证据条提供“查看资料”“处理候选”“继续上传”入口。资料详情仍在资料收件箱和待确认视图中处理，不在总览重复展示完整列表。

### 4.4 下方治理区

现有知识健康、自动质检和业务知识域覆盖下沉到第一屏之后。展示规则如下：

- 能从当前状态计算的待确认、冲突、过期、失败和缺口可继续显示。
- 没有真实数据来源的固定健康分、知识条数、调用次数和固定覆盖率不再作为客户真实指标展示。
- 尚未接入的自动质检能力保留“原型演示 · 待接入”标识。
- 黄金任务回归、来源一致性、知识新鲜度等模拟结果不得写成当前企业真实结果。

## 5. 状态与优先级

企业认知字段采用以下状态优先级：

1. `confirmed`：客户手工填写或采用候选后保存的内容。
2. `draft`：客户正在编辑但尚未保存的内容。
3. `candidate`：从资料中提取、尚待客户确认的候选。
4. `conflict`：候选值与已确认值不一致。
5. `missing`：没有已确认值，也没有候选。

总览正式摘要只读取 `confirmed`。`draft`、`candidate` 和 `conflict` 必须分别显示状态，不得拼接成正式企业描述。

每张企业认知卡显示状态统计，例如：

> 已确认 8 项 · 待确认 2 项 · 待补充 3 项

“信息完整度”只表示当前已确认字段覆盖情况，不作为提交门槛，也不代表知识质量或诊断准确率。

## 6. 资料任务与候选数据

### 6.1 资料任务元数据

原型在浏览器本地保存以下安全元数据：

- 任务 ID。
- 文件名或内容源地址。
- 资料类型。
- 当前状态。
- 状态说明。
- 候选数量。
- 创建或更新时间。

不保存文件本体、图片内容、文档正文或客户个人数据。

支持状态：

- 已排队。
- 采集中。
- 解析中。
- 待确认。
- 部分成功。
- 失败。
- 等待授权。
- 已取消。

### 6.2 候选元数据

每条候选至少保存：

- 对应企业字段。
- 候选值。
- 来源文件或内容源。
- 当前正式值。
- 状态：待确认、已采用、已忽略或冲突。

采用候选时必须由客户触发；采用后写入表单草稿，客户保存后才成为 `confirmed`。

### 6.3 数据流

```text
客户填写或上传
  → 表单草稿 / 异步资料任务
  → AI 提取候选
  → 客户采用、忽略或处理冲突
  → 保存为已确认企业信息
  → 四张企业认知卡
  → 知识总览和后续诊断使用
```

## 7. 交互

- 四张卡片默认显示关键摘要和状态数量。
- “查看详情”展开本卡全部字段、状态和来源。
- “补充信息”打开对应的四步引导步骤，并保留已有草稿。
- “处理候选”进入待确认视图或定位到对应候选。
- “继续上传”复用现有上传资料入口。
- 采用候选后立即刷新卡片状态；保存后升级为已确认内容。
- 资料任务状态变化时同步刷新资料证据汇总。

## 8. 空态与异常

### 8.1 空表单

客户未填写任何内容时，四张卡片分别显示待补充状态，页面主提示为：

> 还没有已确认的企业信息。可以从四步引导填写，也可以上传资料生成待确认候选。

### 8.2 解析中

资料解析中时显示当前阶段和下一步，不阻塞客户继续填写或进入其他页面。

### 8.3 解析失败

只标记当前任务失败，保留其他任务与表单内容，提供重试或移除入口。

### 8.4 等待授权

公众号账号或历史内容未授权时显示“等待授权”，允许继续授权或改为单篇文章链接。

### 8.5 内容冲突

并列显示当前正式值、候选值和来源，由客户选择保留原值或采用候选。系统不得自动覆盖。

### 8.6 页面刷新

刷新后恢复四步表单草稿、资料任务元数据、候选、状态和品牌折叠状态。无法恢复的文件本体不应显示为仍可读取，只保留处理结果元数据。

## 9. 实现边界

继续使用 `prototype/index.html` 作为单文件原型真源。实现时在现有企业引导草稿状态之外增加两个独立、可测试的本地状态：

- 企业知识总览候选状态。
- 企业资料任务元数据状态。

通过纯读取函数把表单草稿、候选状态和任务状态转换为知识总览视图模型，再由单一渲染函数更新页面。渲染函数不得直接修改表单、候选或任务状态。

## 10. 测试与验证

### 10.1 自动测试

覆盖：

- 四张卡片与四步引导字段映射完整。
- 已确认值优先于候选值。
- 待确认候选不进入正式摘要。
- 冲突值不自动覆盖正式值。
- 空值显示待补充，不显示示例事实。
- 经营模式变化后第三张卡只汇总当前模式。
- 未填写经营数字时不显示零值或推算值。
- 预算必须同时带周期和区间。
- 资料任务状态统计正确。
- 表单草稿、候选和任务元数据刷新后可恢复。
- 补充信息和处理候选跳转到正确位置。
- 未接入能力继续显示明确边界。

### 10.2 真实浏览器验证

桌面端使用 1440×900，手机端使用 390×844，覆盖：

- 空表单知识总览。
- 四步均有手工填写内容。
- 多经营模式与动态获客字段。
- 多文件上传和不同任务状态。
- 资料候选待确认、采用和冲突。
- 官网、公众号文章和公众号账号等待授权。
- 页面刷新后的状态恢复。
- 四张卡展开、补充信息、处理候选和继续上传。

检查不得出现横向溢出、按钮遮挡、状态不可辨识或移动端关键信息缺失。

## 11. 验收标准

1. 知识总览第一屏按四步引导展示客户实际企业信息。
2. 每张卡清晰区分已确认、待确认、冲突和待补充状态。
3. 上传资料、官网和公众号内容源状态能在资料证据汇总中反映。
4. 未确认候选不进入正式企业摘要。
5. 固定演示健康分、知识数量和 Agent 调用次数不再冒充当前客户真实数据。
6. 客户可从总览直接补充对应步骤或处理候选。
7. 页面刷新后安全元数据和表单草稿可恢复，文件本体不在本地持久化。
8. 自动测试通过，并完成 1440×900 与 390×844 的真实浏览器检查。
9. 页面继续明确 OCR、文档解析、官网采集、公众号采集和自动质检为待接入能力。
