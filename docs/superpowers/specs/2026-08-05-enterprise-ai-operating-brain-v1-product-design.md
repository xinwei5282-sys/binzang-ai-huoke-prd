# 企业 AI 经营大脑 V1.0 内部产品研发方案

> 日期：2026-08-05
>
> 状态：待用户复核
>
> 用途：产品、设计、前端和后续研发对齐
>
> 范围：V1.0 产品定义与原型范围，不包含本次后端实现方案

## 1. 产品结论

“企业 AI 经营大脑”是面向缺少专业品牌、经营策划和内容团队的中小企业主的经营诊断与品宣内容生成产品。

V1.0 不追求“企业全流程自动化”，而是先完成一条能被老板理解、使用和验收的价值链：

```text
用户手动填写企业信息
  → 形成经确认的企业档案
  → 生成企业诊断
  → 生成品牌报告和经营计划
  → 生成 PPT、海报和公众号文章
  → 用户审核、下载或人工发布
```

AI 获客是产品中的 PC 端测试能力，保留爆款追踪、内容创作和 AI 视频，但不作为首版标准产品上线的阻塞条件。

## 2. 产品目标

### 2.1 用户目标

- 老板不需要理解 Agent、模型、提示词或本地 Codex。
- 10–15 分钟内完成企业快速画像。
- 30–45 分钟内完成可用于正式诊断的主要信息。
- 用户能看懂分析依据、信息缺口和建议优先级。
- 企业能直接获得可使用的报告、计划和品宣物料。

### 2.2 业务目标

- 用“企业诊断 + 品牌报告 + 经营计划”建立首次信任。
- 以 PPT、海报和公众号文章作为高频刚需能力。
- 通过企业档案、品牌视觉和企业资料沉淀使用价值。
- 在标准产品上叠加行业包和大客户配置，不为格优分叉产品。

## 3. 用户与角色

| 角色 | 主要任务 | V1.0 权限 |
|---|---|---|
| 企业主 / 经营负责人 | 填写信息、确认事实、设定目标、审核成果 | 企业级查看和确认 |
| 市场 / 运营人员 | 补充资料、创建物料、人工发布 | 按模块授权 |
| 审核人 | 审核对外事实、品牌表达和发布内容 | 审核与退回 |
| 平台服务人员 | 帮助建档、配置模板、陪跑和排查失败 | 授权后服务 |

## 4. V1.0 范围

### 4.1 标准版必须完成

1. 引导式企业建档。
2. 六维企业诊断。
3. 品牌视觉设置和企业资料上传。
4. 企业品牌报告。
5. 月度、季度、年度和自定义周期的经营计划。
6. PPT 生成。
7. 海报生成。
8. 公众号文章生成和发布包导出。
9. 各模块内的草稿、列表、审核、版本、下载和失败重试。
10. 企业知识、素材、数据源和待确认信息。
11. 成员、权限、平台账号、用量和帮助。
12. 新企业赠送 10 次海报生成额度。

### 4.2 PC 端测试能力

- 获客计划。
- 爆款追踪：关键词、对标账号、榜单、相对基线、收藏、八维拆解和内容公式。
- 内容创作：用企业知识对拆解公式进行重写。
- AI 视频：选题、脚本、确认脚本、分镜与首帧、确认分镜、逐镜生成、失败镜头重做、混剪质检和 MP4 成片。

测试能力可进入 V1.0 原型和定向客户试用，但不阻塞标准版首发。

### 4.3 不在 V1.0 范围

- 企查查或其他公开企业信息自动补全。
- CRM、客户标签和自动成交闭环。
- 自动报价、客户消息自动外发和个微托管。
- 未经人工审核的自动发布。
- 面向客户的 Agent 中心、提示词、模型、Provider 和本地 Codex 配置。
- 硬件捆绑销售。
- 以“作品库”或“成果中心”名义另建一套重复列表。
- 为格优建立独立产品或代码分支。

## 6. 企业建档与六维诊断

### 6.1 方法论来源

V1.0 将成熟咨询框架转换为老板能理解的引导问题：

- 商业模式画布：客户、价值、渠道、关系、收入、成本、资源、活动和伙伴。
- Bain Elements of Value：客户购买的功能、效率、风险、信任和情绪价值。
- BCG Strategy Palette：企业的环境可预测性、可塑造性和当前资源约束。
- McKinsey 7-S：战略、结构、流程、人员、能力、风格和共同目标的匹配。

产品不宣称使用某咨询公司的专有评分，不复制专有问卷，只将公开框架转化为通用诊断逻辑。

### 6.2 三阶段信息收集

#### 阶段一：快速画像

目标时长 10–15 分钟，包含 12 类必填信息：

1. 企业一句话介绍。
2. 最多三个主要产品或服务。
3. 本期重点推广产品。
4. 主要目标客户。
5. 客户最主要的问题。
6. 客户选择企业的原因。
7. 产品或服务的价格区间。
8. 当前主要获客渠道。
9. 月度咨询、有效线索和成交数量区间。
10. 当前最需要解决的问题。
11. 本周期目标。
12. 可投入的人员、时间和预算。

完成后可生成“初步企业画像”，不标记为正式咨询诊断。

#### 阶段二：六维诊断

| 维度 | 核心问题 | 主要输出 |
|---|---|---|
| 定位与战略 | 企业是谁、要去哪里、不做什么 | 发展阶段、战略清晰度、核心矛盾 |
| 客户与市场 | 为谁创造价值、谁决策、市场如何变化 | 核心客户、购买任务、机会与威胁 |
| 产品与客户价值 | 产品解决什么、客户为什么买 | 产品组合、价值主张、同质化风险 |
| 商业模式与增长 | 如何触达、成交、收入和复购 | 漏斗堵点、渠道效率、收入风险 |
| 品牌与营销 | 企业如何表达、客户为什么信 | 定位、信任证据、内容和视觉缺口 |
| 组织与执行 | 谁决策、谁执行、有什么能力与约束 | 责任、流程、能力和资源缺口 |

每个问题必须提供选项、填写示例或区间，允许“不清楚”，不得用空白大文本框代替引导。

#### 阶段三：资料验证

用户可上传产品手册、报价表、企业介绍、服务流程、成功案例、客户评价、经营数据、历史 PPT、海报、公众号文章和图片。

系统将填写结果与资料中的信息并列展示。信息冲突时必须人工确认，不自动覆盖。

### 6.3 信息状态与准确性

企业信息状态统一为：

```text
未填写 → 草稿 → 待确认 → 已确认
```

只有“已确认”信息可作为正式品牌报告、经营计划和对外物料中的硬事实。

诊断结果必须区分：

- 用户确认事实。
- 上传资料证据。
- AI 分析判断。
- 信息缺口或无法判断。

每条主要结论显示依据、判断理由、信息完整度、置信度和建议补充项。缺少数据时不伪造精确结论。

## 7. 核心页面与流程

### 7.1 首页

首页优先展示：

1. 企业诊断完成度和下一步。
2. 待用户确认的信息和成果。
3. 最近品牌报告、计划和物料的快捷入口。
4. 本月用量和异常任务。
5. PC 端测试能力开启时的爆款提醒和获客计划。

首页不使用“企业 Agent 驾驶舱”作为首次用户的主界面。

### 7.2 品牌报告

列表与详情在同一模块内完成，支持：

- 新建、生成中、待确认、已完成和生成失败。
- 报告预览、结论依据、版本记录、下载和重新生成。
- 企业概况、发展阶段、六维诊断、优势、问题、原因、优先级和信息缺口。

### 7.3 经营计划

支持月度、季度、年度和自定义周期。格优客户可默认选用 90 天试点模板，但通用产品不使用“90 天经营计划书”作为固定产物。

计划包含：

- 目标和衡量指标。
- 问题与策略。
- 行动任务。
- 负责人和时间。
- 预算与资源。
- 风险和人工确认点。
- 周期复盘方式。

### 7.4 营销物料

每类物料在自己的页面内管理列表和生命周期，不再转存到另一套作品库。

#### PPT

- 用途：企业介绍、品牌汇报、经营计划或销售方案。
- 输入：已确认企业信息、报告或计划、品牌视觉和用户要求。
- 输出：可编辑文件、PDF 预览、缩略图和质量检查结果。

#### 海报

- 选择用途、尺寸、主标题、行动指引和产品。
- 默认使用企业品牌色、Logo、字体和图片风格。
- 新企业赠送 10 次有效生成额度。未形成有效成果的系统失败不扣次数。

#### 公众号文章

- 支持标题、摘要、正文、封面、文中配图、CTA 和合规检查。
- 状态：草稿、生成中、待审核、待发布、已导出、已发布、发布失败。
- 首版默认导出“封面 + 正文 + 图片 + 发布说明”。
- 只有官方发布接口完成真实授权和端到端验证后，才显示立即发布或定时发布。

### 7.5 AI 获客

“爆款追踪”是统一模块名称。“搜索抓取”只是其内部操作，不作为产品模块名。

```text
爆款追踪
  → 相对基线判定
  → 八维拆解
  → 提取可迁移公式
  → 结合企业知识重写
  → 生成图文或脚本
  → 可选进入 AI 视频
```

爆款优先由已授权的第三方数据服务或官方接口提供。拆解复用内容结构和转化模式，不复制原文或原片。

AI 视频的高成本节点前必须有脚本和分镜两道人工确认门。单个镜头失败时只重做失败镜头，不整片重新生成。

## 8. 品牌视觉

企业可设置：

- Logo 及使用规则。
- 主色、辅助色和禁用色。
- 标题字体与正文字体。
- 图片风格和画面禁区。
- PPT 版式、海报模板和公众号封面规范。
- 品牌语气、禁用词和禁止承诺。

正式成果默认继承企业已确认的视觉规范，用户不需要每次重新选风格。

## 9. 状态和人工确认

### 9.1 通用生成任务状态

```text
草稿 → 排队中 → 生成中 → 待审核 → 已完成
                         └→ 生成失败
待审核 → 退回修改 → 重新生成
```

失败时必须显示失败阶段和可重试范围，不统一显示“生成失败”。

### 9.2 必须人工确认的内容

- 企业硬事实和对外口径。
- 价格、规格、服务承诺和合规内容。
- 品牌报告与经营计划正式版。
- 公众号或其他对外发布。
- AI 视频脚本与分镜。
- 格优殡葬行业内容的发布前合规审核。

## 10. 成果归属与列表原则

成果在创建它的模块中管理：

| 成果 | 创建与管理位置 |
|---|---|
| 品牌报告 | 品牌与经营 → 品牌报告 |
| 经营计划 | 品牌与经营 → 经营计划 |
| PPT | 营销物料 → PPT |
| 海报 | 营销物料 → 海报 |
| 公众号文章 | 营销物料 → 公众号文章 |
| 获客图文 | AI 获客 → 内容创作 |
| AI 视频 | AI 获客 → AI 视频 |

不建立“营销物料列表 + 作品库列表”的双重管理模式。

## 11. 行业包与格优配置

### 11.1 通用底座

企业档案、知识、任务、权限、用量、审计和生成协议不因客户分叉。

### 11.2 殡葬行业包

- 行业诊断追问。
- 殡葬用品、服务流程和门店场景知识。
- 行业敏感词、风险等级和强制审核。
- 寿衣、殡仪服务和门店内容模板。

### 11.3 格优大客户配置

- 总部、区域和门店组织关系。
- 总部品牌资产和门店本地化信息组合规则。
- 格优专属品牌报告、经营计划和 PPT 模板。
- 90 天试点计划模板。
- 3–5 家种子门店的小范围人工审核、发布和结果记录。

## 12. 用量与计费原则

- 新企业赠送 10 次海报有效生成额度。
- 生成前显示预计消耗。
- 用户主动重新生成或变更方向后生成扣除额度。
- 系统失败且未产生有效成果不扣除额度。
- 用量明细记录时间、操作人、成果和扣减原因。
- 超出免费额度后可按次增购或升级套餐，具体价格不在本方案内硬编码。

## 13. 多端范围

### 13.1 H5 / 移动端优先

- 引导建档。
- 企业诊断进度。
- 报告和计划预览。
- PPT、海报和公众号文章的轻量创建与审核。
- 下载、确认和用量查看。

### 13.2 PC 端

- 完整编辑。
- 批量资料和素材管理。
- 爆款追踪。
- 内容创作。
- AI 视频。

### 13.3 小程序

小程序作为 H5 之后的同产品适配目标，不阻塞 V1.0 H5 内部测试。不单独设计一套业务数据和功能逻辑。

## 14. 帮助与陪跑

V1.0 提供：

- 首次使用引导。
- 填写示例和示例企业。
- 主要页面的操作说明。
- 报告结论的解读提示。
- 帮助中心或服务入口。
- 付费服务的课程、案例和一对一指导入口。

服务人员不能在未经企业授权时读取企业资料。

## 15. V1.0 验收标准

### 15.1 产品与交互

- 新用户能从首页进入快速画像并保存草稿。
- 用户可分多次完成六维诊断，每个问题有示例或选项。
- 未确认事实不得进入正式对外成果。
- 用户可查看诊断依据、信息缺口和置信度。
- 各成果在原模块中完成列表、编辑、审核、版本和下载，没有重复作品库。
- 未真实接入的能力显示“能力演示·待接入”，不显示伪造在线状态。

### 15.2 标准成果

至少能用一家真实授权测试企业的已确认信息生成：

1. 企业诊断报告。
2. 企业品牌报告。
3. 一份指定周期的经营计划。
4. 一份可编辑 PPT 和对应 PDF 预览。
5. 一张符合品牌规范的海报。
6. 一篇包含封面、正文和配图的公众号文章发布包。

不以静态页面存在、文件结构正确或接口定义存在代替真实成果验收。

### 15.3 PC 测试能力

- 爆款追踪显示数据来源、相对基线和八维拆解。
- 内容创作展示企业知识依据，不复制原文。
- AI 视频不能跳过脚本和分镜确认。
- 单镜头失败可单独重做，完成后交付 MP4 和质检结果。

## 16. 研发顺序

### P0：首版闭环

1. 产品壳层与菜单收口。
2. 快速画像和六维诊断。
3. 企业信息确认、品牌视觉和企业资料。
4. 企业诊断、品牌报告和经营计划。
5. PPT、海报和公众号文章。
6. 各模块列表、审核、版本、下载和用量。
7. H5 核心链路验证。

### P1：PC 端测试能力

1. 爆款追踪。
2. 内容创作。
3. AI 视频两道确认门和失败镜头重做。
4. 获客计划和手工结果记录。

### P2：配置和陪跑

1. 殡葬行业包。
2. 格优大客户配置。
3. 填写示例、课程、帮助和服务入口。

## 17. 产品证据与状态标注

内部方案、原型和汇报必须使用以下状态：

| 状态 | 证据要求 |
|---|---|
| 已设计 | 有已确认方案或 PRD |
| 原型可演示 | 原型交互可操作，不表示后端成功 |
| 已部署 / 有接口契约 | 线上前端或接口契约可验证 |
| 已端到端验证 | 授权测试完成真实任务和成果 |
| 已客户验收 | 有客户验收记录和实际交付证据 |

页面可点击、演示数据或已定义接口均不能单独证明真实能力已交付。
