# 企业知识工作区与公众号计划发布时间设计

日期：2026-08-12  
状态：已确认，待实施

## 1. 目标

本次调整收口四个已确认问题：

1. 企业知识不再承载 Agent 授权配置，避免与“设置 > Agent 权限”重复。
2. “资料收件箱”和“待确认”合并为一个连续处理工作区，避免同一资料重复出现。
3. 公众号文章支持结合已生效经营计划推荐发布时间，同时允许每篇文章单独修改。
4. “完善企业初步信息”的四个步骤支持直接点击切换，草稿不丢失、未确认内容不自动成为企业事实。

## 2. 信息架构

### 2.1 企业知识

企业知识顶部只保留两个工作区：

- 正式知识
- 资料与待处理

删除以下企业知识内能力：

- “Agent 授权”主操作入口
- Agent 授权独立面板
- 企业知识内的 Agent 授权编辑弹窗与专用路由
- 不再需要的消费者知识蓝图 Agent 授权渲染逻辑

“设置 > Agent 权限”保持不变，继续作为统一权限配置入口。

### 2.2 资料与待处理

采用已选择的 A 方案：单列表、来源行内展开候选。

每份文件、网页、公众号来源或授权数据源只显示一条来源记录。来源记录包含：

- 来源名称与类型
- 提交人或采集方式
- 当前处理阶段
- 候选数量与异常数量
- 最近更新时间
- 当前可执行操作

状态统一为：

| 状态 | 含义 | 可执行操作 |
|---|---|---|
| 处理中 | 排队、采集、解析或识别尚未完成 | 查看进度、取消 |
| 待确认 | 已形成一个或多个知识候选 | 展开候选、确认采用 |
| 有冲突 | 候选与正式知识或其他来源冲突 | 展开证据、人工裁决 |
| 处理失败 | 采集、授权、解析或识别失败 | 查看原因、重试 |
| 已完成 | 候选已处理，正式知识已更新或明确忽略 | 查看处理记录 |

点击来源行后，在原行下方展开该来源对应的候选内容。候选条目包含提取值、当前正式值、来源定位、置信度、负责人和处理动作。

资料的状态按未完成事项计算：存在冲突时优先显示“有冲突”；无冲突但仍有候选时显示“待确认”；仍在运行时显示“处理中”；全部候选处理后显示“已完成”。同一资料不得同时出现在另一份“待确认”列表。

### 2.3 正式知识

正式知识继续按知识域和内容类型筛选，只显示已确认、可追溯且未失效的内容。上传资料或外部来源本身不直接成为正式知识。

## 3. 公众号文章计划发布时间

### 3.1 创建任务字段

公众号文章创建任务增加：

- `publishing_account_id`：本篇发布账号
- `operating_plan_id`：关联的已生效经营计划，可不关联
- `plan_milestone_id`：关联的计划节点，可不关联
- `recommended_publish_at`：系统根据计划节点给出的推荐时间
- `scheduled_publish_at`：本篇实际自动发布时间，可编辑
- `schedule_source`：`plan_recommended | manually_set | immediate`
- `auto_publish_enabled`：本篇是否自动发布

账号级“审核后自动发布”只作为新文章默认值。文章创建后，以本篇的 `auto_publish_enabled` 和 `scheduled_publish_at` 为最终执行依据。

### 3.2 推荐规则

默认读取当前已审核生效的经营计划：

1. 用户选择计划节点后，系统根据节点日期和内容用途生成推荐时间。
2. 原型案例默认展示“节点前 2 天的上午发布”，并明确标记为系统推荐。
3. 用户可以修改为任意合法的未来时间；修改后 `schedule_source=manually_set`。
4. 用户手动修改后，经营计划节点变化只产生提醒，不静默覆盖本篇时间。
5. 未关联经营计划时仍可手动设置发布时间，或选择审核后立即发布。

推荐时间不是经营承诺，也不是强制计划。真实系统需要由排程服务基于租户时区执行。

### 3.3 自动发布门禁

到达 `scheduled_publish_at` 时，只有全部条件满足才创建发布任务：

- 文章状态为已审核通过
- 发布账号仍处于授权可用状态
- 本篇自动发布已开启
- 发布方式可用，API 或 RPA 会话满足各自前置条件
- 当前内容版本与审核版本一致
- 关联计划节点未取消；计划变更但本篇为手动时间时只提示，不阻断

任一条件不满足时进入“暂停发布”，列表展示具体阻断原因，不自动改期、不跳过审核门。

### 3.4 文章列表

公众号文章列表显示：

- 文章标题
- 发布账号
- 经营计划节点
- 本篇自动发布时间
- 发布状态
- 阅读
- 分享
- 操作

文章数据继续绑定当前 `article_id`。不显示“在看”和“新增关注”。

## 4. 企业初步信息四步切换

### 4.1 交互

四个步骤卡均为可点击控件：

1. 企业身份
2. 业务、产品与客户
3. 获客与经营
4. 目标、资源与品牌

点击任一步骤时：

1. 先保存当前页面表单为租户草稿。
2. 切换目标步骤并恢复该步骤已保存内容。
3. 更新步骤状态和整体完整度。
4. 将焦点移动到目标步骤标题，方便键盘和辅助技术用户理解切换结果。

“上一步 / 下一步”继续保留。所有字段均可选，步骤切换不做必填拦截，也不要求按顺序填写。

### 4.2 步骤状态

- 当前步骤：高亮并标记 `aria-current=step`
- 已填写：该步骤至少有一个草稿字段，但尚未最终确认
- 已确认：该步骤内容已经通过“完成初步设置”确认
- 可选：当前步骤完全没有内容

步骤点击只保存草稿，不得把内容自动写成正式企业事实。只有用户点击“完成初步设置”后，确认流程才按既有规则执行。

### 4.3 响应式与可访问性

- 桌面端保持四列步骤卡。
- 390px 手机端保持两列。
- 步骤控件使用 `button`，具备可见焦点和不少于 44px 的触控高度。
- 键盘可使用 Tab 聚焦并通过 Enter/Space 切换。

## 5. 状态与数据关系

```text
资料来源
  → 处理中
  → 生成知识候选
  → 待确认 / 有冲突
  → 人工采用或忽略
  → 已完成
  → 正式知识（仅被采用内容）

已生效经营计划
  → 计划节点
  → 推荐发布时间
  → 用户确认或单篇修改
  → 审核与账号门禁
  → 定时发布
  → 文章级阅读 / 分享回收
```

## 6. 原型边界

- 资料采集、文档解析、定时调度、公众号 API 和 RPA 发布在静态原型中均为交互演示，不得表述为已上线能力。
- 经营计划只提供排程上下文，不会自动创建未经用户确认的发布任务。
- 未确认候选不进入正式知识。
- 文章计划时间、账号、内容版本和执行结果需要分别保存，避免计划变更覆盖历史任务。

## 7. 验收标准

1. 企业知识页面不再出现 Agent 授权入口、面板或专用路由；设置中的 Agent 权限仍存在。
2. 企业知识只显示“正式知识”和“资料与待处理”两个工作区。
3. 同一资料只显示一次，点击可行内展开其候选内容。
4. 处理中、待确认、有冲突、处理失败、已完成五种状态可展示并具有对应操作。
5. 创建公众号文章时可选账号、经营计划、计划节点，并显示推荐时间与可编辑的本篇发布时间。
6. 用户手动修改发布时间后，计划变化不会静默覆盖。
7. 文章未审核、账号失效或版本不一致时不会自动发布，并显示阻断原因。
8. 文章列表按文章展示账号、计划节点、发布时间、阅读和分享。
9. 企业初步信息四个步骤均可点击切换，当前草稿自动保存且不会自动成为企业事实。
10. 1440×900 与 390×844 下无横向溢出，关键操作可见；控制台无新增错误。
11. 相关结构测试、交互测试和 `git diff --check` 通过；全量测试中的历史基线问题需单独标注。
