# 企业级知识库设计

> 版本：v1.1
> 状态：已完成产品结构确认，待实施计划确认
> 本次决策：AI 获客与杭小消复用同一知识库底座，业务差异通过行业知识蓝图和输出适配实现。

## 1. 背景与定位

AI 获客产品正在从内容生产工具升级为企业 AI Agent 工作平台。现有知识库以单个用户上传文件、按文件夹浏览为主，无法支撑多部门共同维护、企业权限控制、知识版本治理和多个 Agent 的受控调用。

本方案将知识库定义为企业的统一知识与规则中枢：连接企业已有资料和业务系统，经过提取、分类、确认和治理，形成可信企业知识，并按用户身份、业务场景和 Agent 权限提供知识服务。该底座同时服务 AI 获客、杭小消及后续行业产品，不为单个业务复制独立的采集、审核、检索和权限系统。

知识库属于企业租户，不属于某个员工。员工上传资料只代表提交知识候选，不代表资料已经成为企业正式知识。

## 2. 设计目标

- 建立以企业租户为边界的统一知识空间。
- 允许不同部门共同提交、确认和维护知识，同时明确责任人。
- 客户上传资料前无需理解复杂分类，系统自动提取并推荐归属。
- 价格、规格、地址、联系方式、承诺等硬事实必须可追溯、可确认、可版本化。
- 通过业务知识域、组织归属、适用范围和安全等级管理知识，而不是只依赖文件夹。
- Agent 只能在当前用户、任务目的和授权范围内调用知识。
- 支持知识冲突、过期、纠错、归档和使用反馈的完整生命周期。
- 通过可配置的行业知识蓝图承载分类、关系和审核差异，让 AI 获客与杭小消复用同一套底层能力。
- 支持文本、图片、音频、视频及其可检索描述，并保留原件、来源和版权信息。
- 让未命中、高频问题和人工纠错形成可治理的知识补充任务。

## 3. 非目标

- 不把企业知识库设计成个人笔记或个人网盘。
- 不允许普通员工随意创建企业一级知识域。
- 不把未经确认的上传文件直接作为正式价格、承诺或发布依据。
- 不将 CRM 中全部客户个人数据复制进知识库；客户数据通过授权业务接口按任务读取。
- 不在本方案中锁定具体第三方存储、OCR、ASR、向量数据库或企业系统供应商。
- 不允许 Agent 绕过权限网关直接检索整个企业知识空间。
- 不把 AI 获客六类知识域或杭小消四类内容硬编码进公共底座。
- 不在首次登录页面暴露版本、审批流、检索策略和权限矩阵等治理复杂度。

## 4. 总体架构

企业知识库按“公共底座—行业蓝图—业务应用”三层设计。

### 4.1 公共底座

公共底座由七个边界清晰的能力组成：

1. **数据源中心**：连接文件、链接、企业云盘、协作平台和业务系统。
2. **知识加工中心**：完成文档解析、OCR、ASR、内容提取、去重、冲突检测、自动分类和质量判断。
3. **统一知识与资产模型**：分离保存原始资料、知识条目和多模态资产，并建立可追溯关系。
4. **知识治理中心**：负责候选、确认、版本、有效期、纠错、归档、来源、版权和质量检查。
5. **组合检索服务**：统一提供关键词、标签、全文、语义向量和结构化事实精确查询。
6. **权限与安全中心**：控制成员、部门、Agent 和输出渠道的查看、调用及执行范围。
7. **反馈与输出服务**：把问答日志转化为知识缺口，并向对话、内容、PPT、数字人和富媒体卡片提供适配输出。

### 4.2 行业知识蓝图

行业蓝图是公共底座上的配置，不复制底层服务。每套蓝图定义：

- 行业知识分类和必备知识项。
- 结构化事实字段及其校验规则。
- 知识之间的关系模型或任务链。
- 必须人工确认的高风险内容。
- 默认负责人、复核周期、安全等级和 Agent 范围。
- 面向不同产品界面的输出卡片和调用方式。

### 4.3 业务应用

- AI 获客消费企业、产品、客户、品牌、销售和经营规则知识，供内容、销售、PPT、数字人及企业自动化 Agent 使用。
- 杭小消消费法律法规、日常问答、典型案例、消费警示和维权任务链，供消费者问答、数字人和富媒体卡片使用。
- 新业务优先新增行业蓝图和输出适配器，不重新建设知识库。

数据主链路为：

```text
企业资料或业务系统
  → 企业暂存收件箱
  → 解析与知识提取
  → 自动分类、去重和冲突检测
  → 业务负责人确认
  → 正式知识发布
  → 按权限提供给 Agent
  → 使用反馈进入治理中心
```

原始资料与提取知识分离保存。一份原始文件只保留一份，但可以提取出多条分属不同知识域的正式知识。

## 5. 企业角色与责任

| 角色 | 主要责任 |
|---|---|
| 企业知识管理员 | 建立企业知识空间、维护一级知识域、配置数据源和安全策略 |
| 业务知识负责人 | 对本业务域知识的准确性、有效性和发布结果负责 |
| 知识维护人员 | 上传资料、编辑知识、处理待确认、冲突和过期事项 |
| 普通员工 | 查询授权知识、提交资料、提出纠错，不直接发布企业正式知识 |
| 外部协作者 | 只查看或提交企业明确共享的资料，不进入企业内部知识空间 |
| Agent | 按任务授权读取知识，不拥有管理权和越权浏览权 |

上传者、知识维护人员和业务负责人可以是不同的人。关键知识发布必须记录确认人和确认时间。

角色只决定可执行的操作类型，不能单独决定可访问的数据范围。例如业务知识负责人可以审核和发布，但只能处理自己负责的知识域；普通员工可以查看，但只能查看被授权的部门、产品和安全等级范围。

## 6. 企业首次初始化

企业知识初始化只对首位企业管理员触发。后续新增成员直接进入其有权限的企业工作空间，不重复建立知识库。首次体验必须保持轻量，用户只感知三个阶段。

### 6.1 用户可见的三步流程

1. **交资料**：上传文件、粘贴链接、连接云盘或绑定授权内容源；不要求提前整理或逐项填写分类表单。
2. **AI 分析**：系统识别行业并套用建议蓝图，完成解析、分类、标签、去重、冲突检测、来源和版权检查，生成知识地图与缺口报告。
3. **确认并启用**：管理员只确认价格、承诺、政策、法律效力、有效期和敏感范围等关键内容，然后激活首个 Agent 或业务工作流。

资料很少的企业可以选择“与 AI 对话补充”作为次入口，但对话结果仍进入相同的知识候选、确认和发布流程。

### 6.2 系统后台完成的初始化任务

创建企业租户、建立管理员身份、推荐部门和负责人、生成知识分类、配置默认安全等级、建立首批 Agent 授权等任务由系统根据上传资料和租户信息生成建议。用户无需在首次登录时完成八项配置；未确认的建议进入治理中心持续处理。

初始化允许中途保存和恢复。未完成关键事实确认时，可以浏览处理进度，但依赖这些事实的内容发布、销售承诺和自动执行能力保持受限。

## 7. 上传与数据接入

### 7.1 接入方式

- 首次初始化批量上传。
- 知识库日常自由上传。
- 对话中提交文件或链接，并明确要求加入企业知识库。
- 企业云盘、协作平台、官网、公众号或店铺的授权同步。
- CRM、ERP、客服等业务系统通过授权接口提供任务所需数据。
- Agent 产物经过人工确认后提交为知识候选。

### 7.2 上传交互

上传时不要求员工选择最终知识域。仅允许填写两个可选信息：资料来源部门或负责人、是否包含敏感内容。

所有资料先进入企业暂存收件箱。系统展示上传、解析、提取、待确认、处理失败等真实状态。解析失败的资料保留原文件和失败原因，允许授权用户重试或更换文件。

### 7.3 提取与确认

系统从资料中提取知识候选，并为每条候选保存：原始文件、页码或位置、提取时间、置信度、推荐知识域和安全等级。

以下内容必须单独确认后才能生效：

- 价格、规格、地址、联系方式和有效时间。
- 对外服务承诺、优惠政策和合同规则。
- 禁用词、审批条件和自动执行权限。
- 客户隐私、员工信息及其他敏感数据。

普通介绍性内容允许业务负责人批量确认，但仍需保留来源。

## 8. 知识蓝图与分组模型

企业知识采用“行业蓝图定义的业务域 + 多维属性”，而不是无限层级文件夹。行业蓝图负责提供默认结构，企业管理员可以在受控范围内调整二级主题，不能修改公共底层对象和权限逻辑。

### 8.1 AI 获客知识蓝图

AI 获客蓝图默认提供：

1. 企业与组织。
2. 产品与服务。
3. 市场与客户。
4. 品牌与内容。
5. 销售与客户服务。
6. 经营流程与制度。
7. 合规、权限与管理规则。
8. 素材、案例与历史成果。

企业可以在一级域下创建有限的二级主题，但不得用层层文件夹代替标签和适用范围。

### 8.2 杭小消知识蓝图

杭小消复用相同知识对象、生命周期、权限和检索服务，默认提供：

1. 法律法规：法条、效力层级、适用地区、生效与失效时间、发布机构和原始来源。
2. 日常问答：消费者问题、标准答复、适用场景、相关依据和复核状态。
3. 典型案例：案情、争议焦点、处理依据、处置结果和相关责任主体。
4. 消费警示：风险类型、警示内容、适用对象、时效和发布机构。
5. 维权任务链：消费场景 → 法律依据 → 维权步骤 → 典型案例 → 责任主体。
6. 多模态资产：图文、图片、音频、视频、原件、可检索描述、标签、关联知识和版权信息。

指定官方网站和授权公众号内容可以作为自动采集源，但新增内容必须先进入候选区并通过人工审核，不能直接成为正式知识。消费者问答中的高频问题、未命中问题和人工纠错形成候选补充任务和周期质量报告。

### 8.3 知识类型

系统自动识别知识类型：结构化事实、文档知识、规则、SOP、问答话术、案例、图片素材、视频素材和历史产物。

### 8.4 多维属性

每条知识同时具有：

- 业务归属：属于哪个知识域。
- 组织归属：哪个部门和负责人维护。
- 适用范围：产品、地区、客户、渠道、业务阶段和有效期。
- 标签：支持跨知识域检索的多值标签。
- 安全等级：可对外公开、全员内部、部门内部、管理层可见、机密、严格受限。
- Agent 范围：允许哪些 Agent 在什么任务中调用。

### 8.5 文件与知识解耦示例

《2026 产品报价与服务方案.pptx》只作为一份原始资料保存，但可以提取：

- 企业介绍 → 企业与组织。
- 产品名称和卖点 → 产品与服务。
- 产品价格 → 产品与服务中的硬事实。
- 适用客户 → 市场与客户。
- 成交案例 → 素材、案例与历史成果。
- 服务承诺 → 合规、权限与管理规则。

所有知识均可追溯到原文件具体页码。

## 9. 知识对象与生命周期

正式知识对象至少包含：企业、知识域、知识类型、标题、正文或结构化字段、来源、负责人、确认人、版本、生效时间、失效时间、适用范围、安全等级、Agent 范围、状态和更新时间。

知识状态为：

```text
待处理 → 待确认 → 已发布 → 待复核 → 已失效或已归档
                 ↘ 存在冲突
```

- 新资料与已发布知识冲突时，不自动覆盖，进入“存在冲突”。
- 负责人可以选择采用新版本、保留旧版本并设置失效时间、拆分适用范围或暂不发布。
- 删除正式知识默认采用归档或失效处理，保留历史版本和使用记录。
- Agent 生成内容不能自动升级为企业事实，只能进入知识候选。

## 10. 持续维护与治理

知识库首页以治理待办为中心，展示：

- 待确认知识。
- 新旧资料冲突。
- 即将过期或长期未复核的知识。
- 解析失败的数据源。
- 缺少负责人或权限配置的知识。
- 被 Agent 高频使用但频繁人工修改的知识。

维护同时采用事件触发和周期复核：价格、联系方式、活动政策等高变更知识设置短复核周期；产品规格、流程和制度在变更时复核；企业历史和品牌故事采用低频复核。

每次修改需要记录修改人、修改原因、前后版本和影响范围。如果修改会影响已配置的 Agent 或自动化工作流，系统在发布前明确提示受影响对象。

## 11. 权限与安全

权限不是文件夹上的单一开关，而是由人员操作权限、知识数据权限、Agent 任务权限和审批规则共同决定。

### 11.1 人员操作权限

系统将权限动作拆分为：查看、上传、编辑、提交审核、审核、发布、导出、授权给 Agent 和配置自动化任务。企业可以按角色授予动作，但授权结果必须同时受知识域和组织范围约束。

- 企业知识管理员可以管理企业级知识结构和权限策略，但不能绕过机密知识的专项授权。
- 业务知识负责人可以审核和发布自己负责知识域内的知识。
- 知识维护人员可以上传、编辑和提交审核，不能直接发布关键知识。
- 普通员工可以查看授权知识、提交候选资料和提出纠错。
- 外部协作者只能访问明确共享给自己的内容。

### 11.2 知识数据权限

每条正式知识必须带有企业、知识域、归属部门、适用范围、安全等级、允许调用的 Agent、是否允许对外输出和是否需要二次审批等权限属性。

安全等级默认包括：可对外公开、全员内部、部门内部、管理层可见、机密和严格受限。系统可以依据知识类型推荐等级，但正式发布时由授权负责人确认。

典型默认规则：

| 知识类型 | 人员范围 | Agent 范围 | 对外输出 |
|---|---|---|---|
| 企业介绍 | 全员 | 内容、销售、PPT Agent | 允许 |
| 产品标准报价 | 销售及管理层 | 销售、PPT Agent | 审核后允许 |
| 价格底线 | 管理层及指定负责人 | 企业 Agent | 禁止自动输出 |
| 管理层偏好 | 管理层及明确授权人员 | 企业 Agent | 禁止 |
| 客户资料 | 客户负责人及授权协作人 | 销售 Agent | 按任务授权 |

管理层规则、老板偏好、价格底线、合同和财务数据默认受限。客户个人数据原则上保留在 CRM 等业务系统，Agent 通过任务授权查询最小必要信息，不进行无边界复制。

### 11.3 权限判定规则

每次访问或调用均实时计算权限交集：

```text
可用知识
= 当前企业
∩ 当前用户角色和数据范围
∩ 知识安全等级与适用范围
∩ Agent 授权范围
∩ 当前任务目的
∩ 知识有效状态
```

任何一个条件不满足即拒绝访问。系统拒绝时只说明无权访问或需要审批，不向无权限用户暴露受限知识是否存在。

### 11.4 审批与审计

权限控制是否具备资格，审批控制某一次高风险操作是否可以执行。以下操作默认进入人工审批：

- 对外发布包含价格、承诺或合同规则的内容。
- 调用管理层、机密或严格受限知识。
- 跨部门读取、批量导出或外发受限知识。
- Agent 修改、删除或新增企业正式知识。
- 自动发布 Agent 执行正式发布。
- 企业 Agent 执行会影响外部系统或经营结果的动作。

所有查看、导出、修改、发布、审批和 Agent 调用都进入审计记录，记录人员、Agent、任务目的、知识版本、执行结果和时间。

## 12. Agent 知识服务与输出适配

每次 Agent 调用携带：企业、当前用户、所属部门、Agent、任务目的和目标输出范围。知识服务根据这些条件生成最小必要知识包，并记录使用了哪些知识及其版本。

员工主动发起任务时，Agent 的最终权限不得超过发起人的权限。即使 Agent 自身被授权读取某个知识域，只要当前用户无权访问，该次任务仍不能调用。

企业自动化 Agent 使用独立的企业服务身份，不继承老板或管理员的全部权限。服务身份必须明确配置可读取的知识域、可执行动作、运行条件、有效时间和审批节点；超出范围时停止执行并转人工处理。

典型知识包：

- 内容 Agent：产品、客户、品牌、素材和合规规则。
- 销售 Agent：产品、价格、客户问题、话术和销售 SOP。
- PPT Agent：企业介绍、产品、案例、品牌规则和授权经营数据。
- 企业 Agent：经营流程、组织权限和管理层规则。
- 自动发布 Agent：内容、平台规则、合规状态和审批权限。

关键事实未命中时，Agent 必须返回“知识库未提供”或转人工确认，不得自行生成价格、规格、案例和承诺。

### 12.1 杭小消调用方式

- 消费者问题先通过关键词、标签、全文和语义向量多路召回，再使用结构化法条和时效字段校验关键依据。
- 命中文本时返回可追溯答复；命中图片、视频或专题资产时，由输出适配器组装图文卡、视频卡、快捷操作按钮或专题卡。
- 多模态原件保留在资产层，检索层保存转写文本、可检索描述、标签和关联知识，避免把媒体原件重复复制到不同业务库。
- 输出必须继承知识的有效期、版权、渠道和权限约束；没有合法输出范围的素材只能内部检索，不能注入对外回答。

## 13. 原型信息架构

企业知识库原型包含一个首次补充页面和六个日常管理页面。

### 13.1 首次补充页面

首屏只呈现“上传文件、粘贴链接、连接云盘、绑定内容源”四种入口，以及“没有资料，和 AI 对话补充”的次入口。上传后进入分析进度页，完成后展示行业知识蓝图、完整度、冲突和必须确认项；确认关键内容后进入工作台。六类 AI 获客知识域或杭小消内容分类只作为 AI 生成的知识地图，不在上传前要求客户逐项填写。

### 13.2 日常管理页面

1. **知识概览**：知识健康度、业务域覆盖、治理待办和 Agent 使用情况。
2. **数据源中心**：上传、连接器、同步状态和原始资料。
3. **业务知识域**：按固定业务域浏览正式知识及适用范围。
4. **待审核**：待确认、冲突、过期和失败处理。
5. **治理中心**：负责人、复核周期、版本和质量规则。
6. **Agent 授权**：配置不同 Agent 可调用的知识域、安全等级和任务范围。

治理中心同时承接首次初始化未完成事项、自动采集候选、问答反哺缺口、冲突版本、过期复核、来源版权和负责人配置。首次引导中的“继续补充”统一跳转到治理中心对应待办，不再创建第二套补充流程。

员工草稿与提交区只用于准备知识候选，不构成个人知识库，也不被企业 Agent 默认调用。它必须与企业正式知识区明显区分。普通员工可以提交候选、查看授权知识和提出纠错，但看不到没有权限的业务域和管理层规则。

权限配置不单独堆成一个复杂页面，而是嵌入主要业务位置：

- 成员管理中配置角色、部门和数据范围。
- 知识域设置中配置负责人、维护人员和默认安全等级。
- 知识详情中展示可见范围、Agent 范围、对外输出和有效期。
- 发布审核中同时确认内容、权限范围和有效期。
- Agent 授权中配置知识域、安全等级、任务范围、执行动作和审批节点。
- 审计记录中查看谁通过哪个 Agent 使用了哪一版知识并执行了什么操作。

知识列表和详情应使用可直接理解的权限摘要，例如：“销售部门可见｜销售 Agent 可用｜对外输出需审核｜2026-12-31 失效”。

## 14. 异常与恢复

- 上传中断：保留上传任务和已完成部分，允许重试。
- 解析失败：显示失败原因，不生成虚假摘要。
- 提取置信度低：进入人工确认，不自动发布。
- 资料冲突：并列展示来源、版本和适用范围，由负责人裁决。
- 负责人离职或权限撤销：知识不丢失，治理中心提示重新指定负责人。
- 数据源断开：保留最后同步版本并标记可能过期，不继续声称实时同步。
- Agent 越权请求：拒绝调用并记录审计事件，不返回知识存在性细节。

## 15. 验收标准

- 新企业首次登录只需要完成交资料、AI 分析、确认并启用三个用户可见阶段，不要求先填完企业知识表单。
- AI 获客和杭小消复用相同的上传、解析、知识对象、生命周期、检索、权限、审计和反馈服务。
- 切换行业蓝图只改变知识分类、结构化字段、关系模型、审核要求和输出适配，不复制底层知识数据。
- 企业知识空间与个人用户身份分离，新增成员不重复初始化企业知识库。
- 员工可以不选知识域直接上传，资料先进入待整理收件箱。
- 一份文件可以提取到多个业务知识域，并能追溯到原文件位置。
- 硬事实、企业规则和敏感知识未经授权确认不能发布或供 Agent 调用。
- 每条正式知识都有负责人、来源、版本、有效期、安全等级和 Agent 范围。
- 冲突知识不会自动覆盖，必须由业务负责人处理。
- Agent 只能获得当前任务所需且有权访问的知识包，调用过程可审计。
- 员工发起任务时，Agent 无法突破该员工的数据范围和安全等级。
- 企业自动化 Agent 使用独立服务身份，并配置明确的知识、动作和审批范围。
- 对外发布、跨部门调用和使用高风险知识时能够进入人工审批。
- 杭小消可以管理法律法规、日常问答、典型案例、消费警示、维权任务链和多模态资产，并追溯原始来源及有效期。
- 杭小消授权内容源的新增内容必须经过人工审核后发布；高频问题、未命中问题和纠错可以生成治理待办。
- 图片、音频和视频同时保留原件与可检索描述，命中后可以按输出渠道组装富媒体卡片。

## 16. 实施边界与拆分

本设计包含完整产品目标，但实施必须拆成两个可独立验收的工作包：

1. **原型工作包**：调整首次补充页面、分析结果、知识蓝图切换、治理中心入口和杭小消示例状态；只验证信息架构与交互，不宣称底层能力已经实现。
2. **平台能力工作包**：实现统一知识对象、行业蓝图配置、处理流水线、审核治理、组合检索、权限网关、反馈闭环和输出适配；按接口与测试逐模块交付。

当前下一步仅进入原型工作包的实施计划。平台能力需要另行形成技术方案和开发计划，不能因为原型可点击就视为已经具备真实采集、审核或检索能力。
- 关键事实缺失时明确提示缺失或转人工，不允许模型补编。
- 原型完整覆盖企业初始化、数据源、业务知识域、审核治理和 Agent 授权主流程。
