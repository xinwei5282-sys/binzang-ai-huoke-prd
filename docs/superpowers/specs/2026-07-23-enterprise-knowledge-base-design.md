# 企业级知识库设计

## 1. 背景与定位

AI 获客产品正在从内容生产工具升级为企业 AI Agent 工作平台。现有知识库以单个用户上传文件、按文件夹浏览为主，无法支撑多部门共同维护、企业权限控制、知识版本治理和多个 Agent 的受控调用。

本方案将知识库定义为企业的统一知识与规则中枢：连接企业已有资料和业务系统，经过提取、分类、确认和治理，形成可信企业知识，并按用户身份、业务场景和 Agent 权限提供知识服务。

知识库属于企业租户，不属于某个员工。员工上传资料只代表提交知识候选，不代表资料已经成为企业正式知识。

## 2. 设计目标

- 建立以企业租户为边界的统一知识空间。
- 允许不同部门共同提交、确认和维护知识，同时明确责任人。
- 客户上传资料前无需理解复杂分类，系统自动提取并推荐归属。
- 价格、规格、地址、联系方式、承诺等硬事实必须可追溯、可确认、可版本化。
- 通过业务知识域、组织归属、适用范围和安全等级管理知识，而不是只依赖文件夹。
- Agent 只能在当前用户、任务目的和授权范围内调用知识。
- 支持知识冲突、过期、纠错、归档和使用反馈的完整生命周期。

## 3. 非目标

- 不把企业知识库设计成个人笔记或个人网盘。
- 不允许普通员工随意创建企业一级知识域。
- 不把未经确认的上传文件直接作为正式价格、承诺或发布依据。
- 不将 CRM 中全部客户个人数据复制进知识库；客户数据通过授权业务接口按任务读取。
- 不在本方案中锁定具体第三方存储、OCR、ASR、向量数据库或企业系统供应商。
- 不允许 Agent 绕过权限网关直接检索整个企业知识空间。

## 4. 总体架构

企业知识库由六个相互独立的能力组成：

1. **数据源中心**：连接文件、链接、企业云盘、协作平台和业务系统。
2. **知识加工中心**：完成解析、提取、去重、冲突检测、分类和质量判断。
3. **业务知识域**：按企业业务领域组织正式知识。
4. **知识治理中心**：负责确认、版本、有效期、纠错、归档和质量检查。
5. **权限与安全中心**：控制成员、部门和 Agent 的查看及调用范围。
6. **Agent 知识服务**：根据用户、Agent、任务目的生成最小必要知识包。

数据主链路为：

```text
企业资料或业务系统
  → 企业暂存收件箱
  → 解析与知识提取
  → 自动分类、去重和冲突检测
  → 业务负责人确认
  → 正式知识发布
  → 按权限提供给 Agent
  → 使用反馈进入治理中心
```

原始资料与提取知识分离保存。一份原始文件只保留一份，但可以提取出多条分属不同知识域的正式知识。

## 5. 企业角色与责任

| 角色 | 主要责任 |
|---|---|
| 企业知识管理员 | 建立企业知识空间、维护一级知识域、配置数据源和安全策略 |
| 业务知识负责人 | 对本业务域知识的准确性、有效性和发布结果负责 |
| 知识维护人员 | 上传资料、编辑知识、处理待确认、冲突和过期事项 |
| 普通员工 | 查询授权知识、提交资料、提出纠错，不直接发布企业正式知识 |
| Agent | 按任务授权读取知识，不拥有管理权和越权浏览权 |

上传者、知识维护人员和业务负责人可以是不同的人。关键知识发布必须记录确认人和确认时间。

## 6. 企业首次初始化

企业知识初始化只对首位企业管理员触发。后续新增成员直接进入其有权限的企业工作空间，不重复建立知识库。

首次初始化流程：

1. 创建企业租户，确认企业名称、行业和组织基本信息。
2. 设置部门、企业知识管理员和首批业务知识负责人。
3. 连接已有数据源或上传第一批企业资料。
4. AI 自动盘点资料，提取企业、产品、客户、品牌、销售、流程和规则知识。
5. 管理员与业务负责人确认关键事实、冲突和安全等级。
6. 系统生成企业知识地图和缺口报告。
7. 配置首批 Agent 的知识访问范围。
8. 激活首个可验证业务工作流。

初始化允许中途保存和恢复。未完成关键事实确认时，可以浏览处理进度，但依赖这些事实的内容发布、销售承诺和自动执行能力保持受限。

## 7. 上传与数据接入

### 7.1 接入方式

- 首次初始化批量上传。
- 知识库日常自由上传。
- 对话中提交文件或链接，并明确要求加入企业知识库。
- 企业云盘、协作平台、官网、公众号或店铺的授权同步。
- CRM、ERP、客服等业务系统通过授权接口提供任务所需数据。
- Agent 产物经过人工确认后提交为知识候选。

### 7.2 上传交互

上传时不要求员工选择最终知识域。仅允许填写两个可选信息：资料来源部门或负责人、是否包含敏感内容。

所有资料先进入企业暂存收件箱。系统展示上传、解析、提取、待确认、处理失败等真实状态。解析失败的资料保留原文件和失败原因，允许授权用户重试或更换文件。

### 7.3 提取与确认

系统从资料中提取知识候选，并为每条候选保存：原始文件、页码或位置、提取时间、置信度、推荐知识域和安全等级。

以下内容必须单独确认后才能生效：

- 价格、规格、地址、联系方式和有效时间。
- 对外服务承诺、优惠政策和合同规则。
- 禁用词、审批条件和自动执行权限。
- 客户隐私、员工信息及其他敏感数据。

普通介绍性内容允许业务负责人批量确认，但仍需保留来源。

## 8. 知识分组模型

企业知识采用“固定业务域 + 多维属性”，而不是无限层级文件夹。

### 8.1 一级业务知识域

一级知识域由企业知识管理员维护，默认提供：

1. 企业与组织。
2. 产品与服务。
3. 市场与客户。
4. 品牌与内容。
5. 销售与客户服务。
6. 经营流程与制度。
7. 合规、权限与管理规则。
8. 素材、案例与历史成果。

企业可以在一级域下创建有限的二级主题，但不得用层层文件夹代替标签和适用范围。

### 8.2 知识类型

系统自动识别知识类型：结构化事实、文档知识、规则、SOP、问答话术、案例、图片素材、视频素材和历史产物。

### 8.3 多维属性

每条知识同时具有：

- 业务归属：属于哪个知识域。
- 组织归属：哪个部门和负责人维护。
- 适用范围：产品、地区、客户、渠道、业务阶段和有效期。
- 标签：支持跨知识域检索的多值标签。
- 安全等级：可对外公开、全员内部、部门内部、管理层可见、机密、严格受限。
- Agent 范围：允许哪些 Agent 在什么任务中调用。

### 8.4 文件与知识解耦示例

《2026 产品报价与服务方案.pptx》只作为一份原始资料保存，但可以提取：

- 企业介绍 → 企业与组织。
- 产品名称和卖点 → 产品与服务。
- 产品价格 → 产品与服务中的硬事实。
- 适用客户 → 市场与客户。
- 成交案例 → 素材、案例与历史成果。
- 服务承诺 → 合规、权限与管理规则。

所有知识均可追溯到原文件具体页码。

## 9. 知识对象与生命周期

正式知识对象至少包含：企业、知识域、知识类型、标题、正文或结构化字段、来源、负责人、确认人、版本、生效时间、失效时间、适用范围、安全等级、Agent 范围、状态和更新时间。

知识状态为：

```text
待处理 → 待确认 → 已发布 → 待复核 → 已失效或已归档
                 ↘ 存在冲突
```

- 新资料与已发布知识冲突时，不自动覆盖，进入“存在冲突”。
- 负责人可以选择采用新版本、保留旧版本并设置失效时间、拆分适用范围或暂不发布。
- 删除正式知识默认采用归档或失效处理，保留历史版本和使用记录。
- Agent 生成内容不能自动升级为企业事实，只能进入知识候选。

## 10. 持续维护与治理

知识库首页以治理待办为中心，展示：

- 待确认知识。
- 新旧资料冲突。
- 即将过期或长期未复核的知识。
- 解析失败的数据源。
- 缺少负责人或权限配置的知识。
- 被 Agent 高频使用但频繁人工修改的知识。

维护同时采用事件触发和周期复核：价格、联系方式、活动政策等高变更知识设置短复核周期；产品规格、流程和制度在变更时复核；企业历史和品牌故事采用低频复核。

每次修改需要记录修改人、修改原因、前后版本和影响范围。如果修改会影响已配置的 Agent 或自动化工作流，系统在发布前明确提示受影响对象。

## 11. 权限与安全

权限同时考虑用户角色、所属部门、知识安全等级、任务目的和 Agent 类型。普通文件夹权限不能替代企业知识权限。

管理层规则、老板偏好、价格底线、合同和财务数据默认受限。客户个人数据原则上保留在 CRM 等业务系统，Agent 通过任务授权查询最小必要信息，不进行无边界复制。

所有查看、导出、修改、发布和 Agent 调用都进入审计记录。高风险知识的导出和跨部门调用需要额外审批。

## 12. Agent 知识服务

每次 Agent 调用携带：企业、当前用户、所属部门、Agent、任务目的和目标输出范围。知识服务根据这些条件生成最小必要知识包，并记录使用了哪些知识及其版本。

典型知识包：

- 内容 Agent：产品、客户、品牌、素材和合规规则。
- 销售 Agent：产品、价格、客户问题、话术和销售 SOP。
- PPT Agent：企业介绍、产品、案例、品牌规则和授权经营数据。
- 企业 Agent：经营流程、组织权限和管理层规则。
- 自动发布 Agent：内容、平台规则、合规状态和审批权限。

关键事实未命中时，Agent 必须返回“知识库未提供”或转人工确认，不得自行生成价格、规格、案例和承诺。

## 13. 原型信息架构

企业知识库原型包含六个一级页面：

1. **知识概览**：知识健康度、业务域覆盖、治理待办和 Agent 使用情况。
2. **数据源中心**：上传、连接器、同步状态和原始资料。
3. **业务知识域**：按固定业务域浏览正式知识及适用范围。
4. **待审核**：待确认、冲突、过期和失败处理。
5. **治理中心**：负责人、复核周期、版本和质量规则。
6. **Agent 授权**：配置不同 Agent 可调用的知识域、安全等级和任务范围。

员工草稿与提交区只用于准备知识候选，不构成个人知识库，也不被企业 Agent 默认调用。它必须与企业正式知识区明显区分。普通员工可以提交候选、查看授权知识和提出纠错，但看不到没有权限的业务域和管理层规则。

## 14. 异常与恢复

- 上传中断：保留上传任务和已完成部分，允许重试。
- 解析失败：显示失败原因，不生成虚假摘要。
- 提取置信度低：进入人工确认，不自动发布。
- 资料冲突：并列展示来源、版本和适用范围，由负责人裁决。
- 负责人离职或权限撤销：知识不丢失，治理中心提示重新指定负责人。
- 数据源断开：保留最后同步版本并标记可能过期，不继续声称实时同步。
- Agent 越权请求：拒绝调用并记录审计事件，不返回知识存在性细节。

## 15. 验收标准

- 企业知识空间与个人用户身份分离，新增成员不重复初始化企业知识库。
- 员工可以不选知识域直接上传，资料先进入待整理收件箱。
- 一份文件可以提取到多个业务知识域，并能追溯到原文件位置。
- 硬事实、企业规则和敏感知识未经授权确认不能发布或供 Agent 调用。
- 每条正式知识都有负责人、来源、版本、有效期、安全等级和 Agent 范围。
- 冲突知识不会自动覆盖，必须由业务负责人处理。
- Agent 只能获得当前任务所需且有权访问的知识包，调用过程可审计。
- 关键事实缺失时明确提示缺失或转人工，不允许模型补编。
- 原型完整覆盖企业初始化、数据源、业务知识域、审核治理和 Agent 授权主流程。
