# PPT 异步生成与直接下载设计

## 目标

PPT 创建页只承载需要用户即时参与的操作。完整 PPT 属于长时间后台任务，不放入步骤条，也不要求二次成品审核。

## 用户流程

1. 用户用一句话描述 PPT 需求，系统读取企业大脑正式知识和已启用企业 VI。
2. 系统生成可编辑大纲，用户人工确认。
3. 确认大纲后，系统创建后台 PPT 生成任务，当前页不展示长时间步骤进度。
4. 用户返回 PPT 列表，可以离开页面处理其他工作。
5. 任务状态从“生成中”变为“可下载”。生成完成后用户可直接下载 PPTX 或 PDF，无需再提交成品审核。
6. 用户也可进入 PPT 详情页，选中任意一页后通过自然语言追问，只重新生成当前页。

## 页面结构

- 创建区只表达两个即时阶段：“填写需求”和“审核大纲”。
- 大纲主按钮改为“确认大纲并开始生成”。
- 提交成功后显示轻量反馈：“已创建后台生成任务”，随后回到 PPT 列表。
- PPT 列表行展示状态、提交时间和操作。“生成中”时不提供下载；“可下载”时提供 PPTX 和 PDF 入口。
- 删除“生成 PPT”和“成品审核与导出”两个步骤条节点，删除“提交成品审核”操作。

## 单页追问修改

- PPT 详情页使用三区布局：左侧页面缩略图，中间当前页大图，右侧追问修改区。
- 用户先明确选中一页，右侧标题持续显示“正在修改第 N 页”，避免误改其他页面。
- 追问支持自然语言，例如“标题更有冲击力”“换成数据图表”“减少文字”“改成面向经销商的表达”。
- AI 只读取当前页、当前追问、已审核大纲、企业大脑正式知识和已启用 VI，不改动其他页面。
- 每次重新生成产生一个当前页候选版本。用户可对比“上一版 / 新版”，并选择“采用新版”或“撤回”。
- 候选版本未采用前不覆盖当前页。采用后只更新该页，整套 PPT 版本号递增并保留修改记录。
- 追问失败时保留原页，显示失败原因和“重试本次修改”，不阻塞整套 PPT 下载。
- 修改过程不设置审核流程；用户采用新版后即可下载最新整套 PPT。

## 状态与边界

- 业务状态：`brief` → `outline_review` → `generating` → `ready`。
- 只有大纲人工确认是生成门禁。
- 生成失败时列表显示“生成失败”和“重试”，不伪装为可下载。
- 静态原型用定时器演示异步状态；“下载”仅表达产品交互，不宣称已接入真实 PPT 生成服务。

## 验收标准

- 创建页不再出现四步生成步骤条。
- 未确认大纲时不能创建完整 PPT 任务。
- 大纲确认后返回列表，新任务显示“生成中”。
- 任务完成后状态为“可下载”，PPTX / PDF 按钮可用。
- 页面不再出现成品审核入口。
- 详情页可明确选择任意一页并输入追问。
- 单页重新生成后先展示候选版本，未采用时不改动原页。
- 采用新版只更新当前页，其他页内容与版本保持不变。
- 撤回或生成失败后原页仍可查看和下载。
- 桌面端和移动端无空白页、无横向溢出、无控制台错误。
