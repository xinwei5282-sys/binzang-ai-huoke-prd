# 企业 VI 图片生成 Skill 设计

## 1. 目标

在 AI 获客产品内建立一个企业 VI 设计 Skill。Skill 读取企业已填写和已确认的信息，先生成三套 Logo 与基础视觉方向，在企业确认其中一套后，再根据该企业的实际经营情况生成最相关的 VI 应用场景图。

产物以 PNG/JPG 图片展示为主，不生成 SVG、AI、EPS 等矢量文件。本阶段不把原型演示表述为已上线的生产生成能力。

## 2. 外部方法参考

设计方法参考 GitHub 上 `brandkit` Skill 的品牌策略、Logo 概念、色彩、字体和应用场景统一编排思路，但不直接嵌入原 Skill。产品内的实现需要补齐企业档案读取、三方向确认、动态场景推荐、异步任务、逐张审核和正式启用边界。

## 3. 核心流程

### 3.1 品牌理解

Skill 仅读取已确认的企业信息，包括：

- 企业名称、行业与发展阶段；
- 主营业务、核心产品和主要客户；
- 交易与经营模式；
- 核心优势、客户感受与品牌语气；
- 已有 Logo、品牌资料与历史内容；
- 禁用表达、未经确认的价格、效果承诺和客户信息。

系统生成品牌策略摘要，包含品牌定位、核心隐喻、视觉关键词、应避免的表达和信息缺口。AI 推断必须显式标记，不自动成为企业正式事实。

### 3.2 三套方向生成

每套方向生成一张完整 VI 方向图，至少包含：

- Logo 主视觉图片；
- 品牌名称；
- 主色、辅助色与中性色；
- 中英文字体气质建议；
- 品牌关键词、图形语言与图片风格；
- 2–3 个代表性应用场景缩略图；
- `基于原 Logo 优化` 或 `全新 Logo 设计` 的来源说明。

有原 Logo 时，默认保留品牌识别核心，三套方向只改变比例、细节、色彩和应用系统；不在未经确认时完全重设。

### 3.3 方向与 Logo 确认

企业点击“确认此方向与 Logo”后，同时锁定方向和 Logo。未选方向保留为历史候选，不进入正式企业知识，也不供内容生成模块调用。

### 3.4 品牌种子

方向确认后，系统生成唯一的品牌种子，作为后续所有图片的一致性真源：

- 已确认 Logo 图片与 Logo 使用模式；
- 企业名称和标准文字；
- 主色、辅助色、中性色和禁用色；
- 字体气质与排版层级；
- 辅助图形、图片风格和视觉纹理；
- 品牌关键词、语气与禁用表达。

品牌种子在当前 VI 版本内不可被单张场景图自动覆盖。

### 3.5 动态场景推荐

系统不使用固定企业套餐，而是根据企业情况生成一份“推荐应用清单”。推荐依据包括：

- 经营模式；
- 核心产品或服务类型；
- 主要交易和成交场景；
- 客户类型；
- 当前获客渠道；
- 企业目标；
- 已有品牌资产。

每个候选场景包含场景名称、相关性评分、推荐原因和所需证据。默认推荐 4–6 个高相关场景，不相关的场景不生成。企业可删除、替换或追加场景，确认后再进入异步生成。

### 3.6 完整 VI 生成

生成分为两类：

1. 基础规范图：Logo 标准组合、图标版、反白版、色彩规范、字体规范和辅助图形。
2. 场景应用图：仅生成企业已确认的高相关场景。

每张图片独立异步生成，支持查看大图、单张重新生成、确认采用、标记不采用和下载 PNG/JPG。

### 3.7 正式启用

企业确认整套 VI 后，已采用图片、品牌种子和使用规则进入企业大脑的正式品牌知识。PPT、海报、朋友圈、公众号和其他内容模块仅读取已启用版本。

## 4. 页面与状态

### 4.1 VI 方向选择

每套方向卡以 VI 方向图为主视觉，展示 Logo、色板、字体气质和代表性场景，并提供“查看整套方向”与“确认此方向与 Logo”。

### 4.2 VI 详情

按以下分组展示：

- 品牌核心；
- 基础规范；
- 推荐场景清单；
- 已生成的线上和线下应用；
- VI 版本和启用状态。

图片任务状态统一为：`queued`、`generating`、`review`、`adopted`、`rejected`、`failed`。

## 5. 一致性与质量门禁

每张图片生成后检查：

- Logo 是否与已确认版本一致；
- 企业名称和可见文字是否正确；
- 主色是否超出允许偏差；
- 场景是否与企业业务相关；
- 是否出现竞品 Logo、水印或无关文字；
- 同批图片是否保持统一的品牌语言；
- 是否引入未确认的价格、效果承诺或客户信息。

未通过门禁的图片进入 `failed` 或 `review`，不自动采用。图片模型对中英文文字的产出不可完全信任，品牌名称和关键文字必须在采用前通过人工确认。

## 6. 错误恢复与版本

- 单张图片失败只重试该图片；
- 已确认图片不因其他任务重试而重新生成；
- 场景图失败不影响 Logo 和基础规范；
- 重新设计 Logo 会创建新 VI 版本，不覆盖旧版；
- 新版未正式启用前，内容模块继续使用上一个已启用版本；
- 删除采用图片时保留审计和引用影响提示。

## 7. 数据边界

最小核心对象：

- `brand_strategy`：品牌策略摘要和证据来源；
- `vi_direction`：方向图、Logo 提案、色彩、字体和预览场景；
- `brand_seed`：已确认方向的一致性真源；
- `scene_recommendation`：场景、评分、推荐原因、证据和确认状态；
- `vi_image_task`：单张图片生成任务、产物、质量状态和重试记录；
- `vi_version`：草案、正式启用、历史与审计信息。

## 8. 验收标准

1. 方向选择页展示三套真实图片方向，不再仅使用 CSS 字符 Logo。
2. 确认方向时同时确认 Logo，并生成唯一品牌种子。
3. 系统根据企业情况推荐 4–6 个高相关场景，每个场景有可解释的推荐原因。
4. 企业可修改场景清单，确认后才开始生成。
5. 每张图片有独立任务状态，支持单张重试、采用、不采用和下载。
6. 未通过质量门禁或未经人工确认的图片不进入正式 VI。
7. 内容模块仅读取已启用的 VI 版本，新版失败不影响旧版。
8. 桌面端和移动端真实渲染无横向溢出，生成、失败、待确认和已启用状态都可验收。
