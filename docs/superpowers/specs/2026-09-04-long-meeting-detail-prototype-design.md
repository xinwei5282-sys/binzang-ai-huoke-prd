# 长会议纪要详情原型设计

## 1. 目标

在现有“企业大脑 / 会议纪要”原型中，明确用户上传长音频或视频后在哪里查看 AI 总结和逐字稿。继续保持纯前端模拟，不接入 VibeVoice-ASR、FunASR、对象存储、任务队列或大模型接口。

## 2. 已确认范围

- 会议列表保留“上传音频 / 视频”入口。
- 增加一条长会议样例，展示总时长、分段处理进度和预计产物。
- 已完成会议进入统一“会议纪要详情”。
- 详情默认打开“AI 总结”，集中展示摘要、关键决策、客户意向和待确认行动项。
- 详情提供独立“逐字稿”标签，按时间戳和发言人展示全文；点击时间戳只模拟定位播放器。
- 行动项仍需人工勾选确认，确认后进入“工作中枢 / 我的待办”。
- 页面明确标注“原型演示”，不暗示真实上传或真实模型能力。

## 3. 交互结构

```text
会议纪要列表
  ├─ 处理中会议：查看分段进度，不开放虚假结果
  └─ 已完成会议：查看会议纪要
         ├─ AI 总结（默认）
         │    ├─ 会议摘要
         │    ├─ 关键决策
         │    ├─ 客户意向与证据
         │    └─ 待确认行动项
         └─ 逐字稿
              ├─ 音视频播放器占位
              ├─ 发言人筛选提示
              └─ 时间戳转写列表
```

## 4. 长会议演示

原型使用一条约 2 小时 36 分钟的会议作为处理中样例，显示“4 个分段、已完成 3 个、正在生成最后一段总结”等状态。演示数据只用于说明未来长会议会分段处理、可展示进度和局部重试，不实现真实分片。

已完成长会议仍以一个会议对象进入详情；分段只是处理状态，不把用户结果拆成多个纪要。

## 5. 视觉与响应式

- 延续当前企业后台的克制、清晰、可操作风格，不重做品牌视觉。
- 详情标签放在来源信息下方，两个入口名称固定为“AI 总结”和“逐字稿”。
- 桌面端优先展示摘要和行动项，移动端标签保持可点击、内容单列，无横向滚动。
- 逐字稿时间戳使用按钮形态，明确可回听；发言人和正文保持可扫读。

## 6. 验收标准

- 会议列表和已完成结果卡均能进入同一详情。
- 打开详情默认只显示 AI 总结面板。
- 点击“逐字稿”后显示播放器、发言人和时间戳文本。
- 点击“AI 总结”可返回摘要、决策、意向和行动项。
- 处理中长会议显示分段进度且不伪造可用结果。
- 行动项确认继续幂等进入待办。
- 桌面 1440×900、手机 390×844 无横向溢出、控制台异常或关键操作裁切。

## 7. 非本轮范围

- 真实音视频上传、转写、分片和断点续传；
- 真实播放器 seek；
- VibeVoice-ASR 或 FunASR 接口；
- 真实逐字稿编辑、发言人合并和搜索；
- 真实耗时、额度、计费或模型名称展示。
