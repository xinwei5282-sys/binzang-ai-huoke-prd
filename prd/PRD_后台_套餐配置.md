## 1. 文档概述

### 1.1 产品背景

这套 SaaS 的能力是**采购来的**：数字人成片（蝉镜，~2.36 元/分钟起）、爆款数据（蝉妈妈，按调用）、转写（ASR 算力）、内容生成（LLM token）、生成形象（蝉镜，~¥199/个）——每一次客户使用都在花我方真金白银。**定价铁律：套餐价必须覆盖满额成本，否则客户越用我方越亏**（见 [[产品规划-殡葬V1]] §四）。

本模块要解决的核心问题：**让运营定义套餐与其配额项，并在保存时强制校验「套餐月费 ≥ 满额成本」**，把"会不会亏"在配置阶段就拦下来，而不是月底对账才发现。套餐配置出来的配额，是开通模块写快照、商家端用量模块扣减的基准。

> V1 不做：客户自助选购、阶梯/团购定价、优惠券、自动续费扣款。先把"套餐结构 + 防亏校验"立住。

### 1.2 产品目标

- 运营可**定义/编辑套餐**：月费 + 5 类配额（爆款/转写/生成/成片分钟/形象）
- 保存时**强制「月费 ≥ 满额成本」校验**，不达标拦截并提示亏损
- 配置**增购项**（形象 ¥199/个、成片分钟包、爆款调用包）
- 套餐供开通模块写配额快照、供商家端用量模块扣减

### 1.3 核心指标

| 指标 | 目标值 |
|--|--|
| 上架套餐满足「月费≥满额成本」 | 100%（不达标无法上架） |
| 配额项与第三方成本单价绑定覆盖 | 100% |
| 套餐改动不影响已开通租户（快照隔离） | 100% |

### 1.4 范围

**In-Scope（本期）**
- 套餐列表（月费 / 5 类配额 / 满额成本 / 上下架）
- 新建/编辑套餐 + 防亏校验
- 增购项配置
- 配额项↔第三方成本单价绑定（满额成本自动派生）

**Out-of-Scope（不做 / 后续）**
- 客户自助购买/续费、优惠券、阶梯价
- 实际扣款/发票（V1 用量先计数，见配对 PRD）

## 2. 用户与场景

### 2.1 目标用户
- **超级管理员 / 财务**：定价决策、配置套餐与增购、维护成本单价。
- **运营**：只读查看（不可改价）。

### 2.2 典型场景
1. 报价谈定后，财务新建「旗舰版」→ 填月费、配额 → 系统按成本单价算出满额成本 ¥1,180 → 月费需 ≥ 此值，否则拦截 → 达标上架。
2. 蝉镜成片涨价 → 财务改成片单价 → 各含成片套餐的满额成本自动重算 → 提示哪些套餐已变亏损，需调价。
3. 配置增购：形象 ¥199/个，供超额客户增购。

### 2.3 用户故事
- 作为财务，我配套餐时系统能直接告诉我"这个价会亏"，这样我不会拍脑袋定价。
- 作为财务，第三方涨价时我能一眼看到哪些套餐变亏了。
- 作为超管，套餐改价不能把已经开通的老客户配额也改了。

## 3. 整体方案

### 3.1 方案原则
- **防亏前置**：亏损在配置阶段拦，不到对账才发现。
- **成本驱动**：满额成本 = Σ(配额量 × 第三方单价)，自动派生、不手填。
- **快照隔离**：套餐改动只影响"之后新开通/续期"，已开通租户用开通时快照。

### 3.2 模块结构
```
套餐配置
├─ 套餐列表（月费 / 配额 / 满额成本 / 状态）
├─ 新建·编辑套餐（配额项 + 防亏校验）
└─ 增购项配置（形象 / 成片分钟包 / 爆款调用包）
```

### 3.3 设计约束（功能限制）
1. **月费 ≥ 满额成本** 才能「上架」，否则拦截并标红差额。
2. **满额成本自动派生**，不可手填；依赖成本单价（引供应商/手维护）。
3. **配额项固定 5 类**：爆款抓取 / 参考转写 / 内容生成 / 数字人成片(分钟) / 生成形象(个)；额度 -1=不限。
4. **快照隔离**：套餐编辑不回溯已开通租户的配额快照。
5. **下架套餐**不可被新开通选用，存量不受影响。

## 4. 功能需求

### 4.1 套餐列表
字段：套餐名 · 月费 · 爆款 · 转写 · 生成 · 成片(分) · 形象 · 满额成本 · 状态(上架/下架) · 操作(编辑)
- 满额成本以徽标显示，亏损（月费<满额成本）标红。

### 4.2 新建 / 编辑套餐

| 字段 | 类型 | 必填 | 校验 / 说明 |
|--|--|:--:|--|
| 套餐名 | str | ✓ | 非空、唯一 |
| 月费 | money | ✓ | ≥ 满额成本（核心校验） |
| 爆款配额 | int | ✓ | ≥0 或 -1(不限) |
| 转写配额 | int | ✓ | 同上 |
| 生成配额 | int | ✓ | 同上 |
| 成片分钟 | int | ✓ | 同上 |
| 形象个数 | int | ✓ | 默认 1~2 |
| 满额成本 | money | — | **派生只读** = Σ(配额×单价)；不限项按封顶估算口径 |
| 状态 | enum | ✓ | 上架 / 下架（上架需过防亏校验） |

**保存校验**：月费 < 满额成本 → 拦截，提示「月费需 ≥ ¥X，当前差 ¥Y，将亏损」。「不限」配额按约定封顶量参与成本估算。

### 4.3 增购项配置
| 字段 | 类型 | 说明 |
|--|--|--|
| 名称 | str | 生成形象 / 成片分钟包 / 爆款调用包 |
| 计量 | enum | 个 / 分钟 / 次 |
| 单价 | money | 形象 ¥199(示例) |
| 适用套餐 | ref多选 | 哪些套餐可增购 |

### 4.4 成本单价（满额成本的输入）
维护各配额类型的第三方成本单价（爆款/次、转写/分、生成/条或token、成片/分、形象/个），来源引供应商或手维护。单价变更触发相关套餐满额成本重算 + 亏损套餐提示。

## 5. 状态流转（package.status）
```
(草稿) ──保存且月费≥满额成本──▶ (上架) ──下架──▶ (下架)
   │                                ▲           │
   └──保存但月费<满额成本→拦截        └───上架─────┘（需仍满足防亏）
```

## 6. 数据对象

### 6.1 `package`（套餐，**与商家端配对共用**）
| 字段 | 类型 | 说明 |
|--|--|--|
| package_id | str(PK) | 套餐ID |
| name | str | 套餐名 |
| monthly_fee | money | 月费 |
| status | enum | 上架/下架 |
| quota_items | json | 5 类配额 {type: limit} |
| full_cost | money | 满额成本(派生) |

### 6.2 `quota`（配额 · 行级表）→ **单一真相见 [[PRD索引]] §四.1，本 PRD 不另定义**
- 字段以索引 §四.1 为准:`quota_id · company_id · type · limit(-1=不限) · used · period · source · enforce · cap_estimate`。
- 本模块关系:`package.quota_items`(§6.1) 是**套餐模板**;开通时按它实例化成 `quota` 行(归账号开通);满额成本用 `cap_estimate` 估算"不限"项。

### 6.3 `addon`（增购项）
name · unit(个/分钟/次) · price(money) · apply_packages(ref list)

### 6.4 `cost_unit`（成本单价）
quota_type(enum) · supplier(ref) · unit_price(money) · updated_at

> `usage_record`（用量明细）由配对计费 PRD 定义并写入，本模块只定义"额度/快照/成本单价"。

## 7. 接口草案
| 接口 | 方法 | 入参 | 出参 |
|--|--|--|--|
| 套餐列表 | GET /admin/packages | — | list‹package›(含 full_cost) |
| 新建/编辑套餐 | POST/PUT /admin/packages | name, fee, quota_items, status | package_id / 校验结果 |
| 上下架 | PATCH /admin/packages/{id}/status | status | ok / 防亏拦截 |
| 增购项配置 | PUT /admin/addons | list‹addon› | ok |
| 成本单价 | PUT /admin/cost-units | list‹cost_unit› | ok + 受影响套餐 |

## 8. 技术考虑
- 满额成本计算服务化，套餐保存与成本单价更新都调用，保证口径一致。
- 「不限(-1)」配额的成本估算需约定封顶量（如成片按 P95 月用量），写进配置避免歧义。
- 防亏校验后端兜底（前端可绕过）。
- 套餐 `quota_items` 改动只写 package；已开通租户的 `quota` 快照不联动。

## 9. 风险与依赖

### 9.1 依赖
- 配对计费 PRD（A7）消费配额、产生用量。
- 供应商成本单价（蝉镜/蝉妈妈/ASR/LLM）——**签前商务确认后填实数**（[[产品规划-殡葬V1]] §六）。

### 9.2 风险
| 风险 | 应对 |
|--|--|
| 成本单价未定导致满额成本算不准 | V1 用估算口径占位，报价回来即替换；亏损提示仍生效 |
| 「不限」配额成本难估 | 约定封顶量参与估算并显式标注 |
| 套餐改价误伤老客户 | 快照隔离，仅影响新开通/续期 |

## 10. 验收标准
1. 新建套餐时满额成本自动算出，月费<满额成本时无法上架并标红差额。
2. 修改某配额成本单价后，相关套餐满额成本重算、亏损套餐被提示。
3. 增购项可配置并被商家端用量模块引用（形象 ¥199）。
4. 编辑套餐不改变已开通租户的配额快照。
5. 下架套餐不可被新开通选用，存量租户不受影响。

## 11. 当前通用产品开发基线（v3.0 · 2026-08-12）

### 11.1 套餐能力项

套餐按 capability 配置，不按页面硬编码。能力项至少覆盖企业大脑存储/解析、外部情报采集、LLM 生成、图片、视频、数字人、平台账号数量、公众号 API 发布、RPA 执行和成员数。

### 11.2 版本与快照

套餐发布生成不可变版本；租户开通或续期引用版本快照。修改套餐不追溯存量租户，除非创建显式迁移任务并取得授权。下架只阻止新购。

### 11.3 成本与边界

供应商成本、平台服务费、增购单价分别配置；成本未知项不得用 0 冒充。RPA、图片、视频等高波动能力必须有成本预警和最大并发/额度护栏。

### 11.4 验收

1. 新套餐能够组合不同能力和账号数量。
2. 亏损或成本未知时给出明确风险，不静默上架。
3. 存量租户套餐快照在后台改价后不变。
4. 增购产生独立订单与额度变更审计。
5. 前后端读取同一 capability code 和单位定义。
