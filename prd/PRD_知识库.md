## 1. 文档概述

### 1.1 产品背景

内容要"事实准确、像这家公司自己说的话"，前提是系统知道这家殡葬商家的**产品、价格、习俗讲究、话术**。这些事实散在老板脑子里、Excel 价目表里、口述录音里、习俗文档里。知识库就是把这些多格式资料**收上来、转写、结构化成可被内容生成精确调用的事实条目**。它是内容创作的上游：知识库空，生成就只能说套话——所以新客户的强引导是"先传资料"（替代被砍掉的 onboarding）。

本模块要解决的核心问题：**让商家把 word/txt/excel/音频/视频 等多格式资料传进来，自动转写、区分结构化/非结构化、分组管理，沉淀成可被 RAG 检索、被生成精确填充的事实库**。

> V1 不做：GraphRAG（留 V2 借沉香经验）、知识图谱可视化、自动事实校对、跨公司知识共享。

### 1.2 产品目标

- 支持**多格式上传**：word/txt/excel/音频/视频（音视频自动转写）
- **结构化（Excel 表格→字段化条目）/ 非结构化（文档→分段入库）区分**
- **分组管理**（产品/价格/习俗/讲究/话术/其他）
- 沉淀为**事实条目**，被内容创作经 RAG 调用、精确填充
- **空态强引导**："先传资料才能正常生成"

### 1.3 核心指标

| 指标 | 目标值 |
|--|--|
| 多格式上传成功率 | ≥ 99% |
| 音视频转写可用率 | ≥ 90%（清晰录音） |
| Excel 结构化解析准确率 | 高（字段对齐） |
| 新客户首传完成率（空态引导） | ≥ 90% |

### 1.4 范围

**In-Scope（本期）**
- 多格式上传 + 处理状态（上传/转写/结构化/完成/失败）
- 结构化（Excel→字段表）/ 非结构化（文档→分段）区分
- 分组管理（增组、归类、筛选）
- 事实条目（分类/时效）+ RAG 检索供生成
- 空态引导

**Out-of-Scope（不做 / 后续）**
- GraphRAG、知识图谱
- 自动事实校对/纠错、过期自动下线
- 知识共享/模板库导入

## 2. 用户与场景

### 2.1 目标用户
- **老板**：提供口述、价目表等一手事实。
- **运营**：上传整理、分组、维护时效。

### 2.2 典型场景
1. 新客户首登 → 知识库空态"先传资料才能生成" → 上传价目表.xlsx（自动结构化 120 条）+ 老板口述.mp3（转写中）+ 习俗.docx（分段 45 条）。
2. 创作时生成"七件套真丝寿衣 ¥2,880" → 来自结构化价目表的精确填充。
3. 价格调整 → 运营更新价目表、旧条目标"过期"。

### 2.3 用户故事
- 作为运营，我把价目表 Excel 传上去就能被自动拆成一条条带价格的事实，不用手敲。
- 作为运营，老板的录音能自动转成文字进知识库，省得我听写。
- 作为运营，我能按"价格/习俗/话术"分组管理，乱不了。
- 作为新客户，系统明确告诉我"先传资料"，我知道第一步干嘛。

## 3. 整体方案

### 3.1 方案原则
- **只存事实，不存观点/风格**（风格归提示词）。
- **结构化优先精确**：Excel 转字段化条目，生成可精确填充；文档转分段供语义检索。
- **空库即引导**：用强空态替代向导式 onboarding。

### 3.2 模块结构
```
知识库
├─ 分组侧栏（产品/价格/习俗/讲究/话术/其他 + 新建分组 + 计数）
├─ 资料列表（文件 · 结构化/非结构化标记 · 分组 · 处理状态 · 查看）
├─ 上传（拖拽/选择，多格式，自动判类型）
└─ 结构化预览（字段表）/ 非结构化分段查看
```

### 3.3 设计约束（功能限制）
1. **多格式**：word/txt/excel/csv/音频(mp3/wav/m4a)/视频(mp4/mov)；音视频走 ASR 转写。
2. **结构化判定**：xls/xlsx/csv→结构化（字段表）；其余→非结构化（分段）。
3. **只存事实**：不承载风格/口吻。
4. **分组枚举**：产品/价格/习俗/讲究/话术/其他（可自定义增组）。
5. **空库限制生成**：知识库空时创作 Step3 强提示先建库（非硬阻断，给降级提示）。
6. **处理异步**：转写/结构化后台进行，状态实时回显，失败可重试。
7. **价格类硬事实强制结构化**：价格/规格/材质等数字事实必须以结构化字段入库，**不进向量库**；避免向量语义检索"猜数字"。（见 [[技术方案-知识库精确召回与事实校验-殡葬V1]] §4）
8. **精确查询优先于向量召回**：生成取数时，硬事实槽（价格/规格）走结构化精确查询命中准确值；软叙述槽（习俗/话术）才走向量召回。两路分治、不混用。
9. **未命中留空不编造**：硬事实在知识库查不到时，**返回空 + 提示补充，绝不交给 LLM 生成**；生成后对文案中的数字/价格做回检，与知识库不一致即标红提醒（复用合规提醒交互）。

## 4. 功能需求

### 4.1 上传
- 拖拽/点击选择，多选；按扩展名自动判结构化/非结构化、选图标。
- 落入当前选中分组（未选用首个分组）。
- 即时建条目，状态=处理中（结构化→"解析表格中"；非结构化→"转写/分段中"）。

### 4.2 处理状态机
| 状态 | 含义 |
|--|--|
| 上传 | 文件已上传 |
| 转写 | 音视频 ASR 中 |
| 结构化 | Excel 解析字段 / 文档分段 |
| 完成 | 已入库（结构化:已结构化N条 / 非结构化:已入库） |
| 失败 | 格式不支持/转写失败 → 可重试或改手动 |

### 4.3 结构化内容
- Excel→字段表（如 价目表：产品/材质/规格/价格）。
- 可预览字段表；条目按字段入库，供生成精确填充。
- 支持手动录入结构化表（名称+分组+字段）。

### 4.4 非结构化内容
- 文档/转写文本→分段入库，供 RAG 语义检索。
- 可查看分段。

### 4.5 分组管理
- 侧栏分组 + 计数；新建分组；按分组 + 结构化/非结构化类型筛选。

### 4.6 事实条目 + RAG（供内容创作）
- 事实条目：分类 · 标题键 · 内容值 · 来源文件 · 时效(有效/待复核/过期) · 标签。
- 内容创作 Step3「知识库范围」默认全部，生成经 RAG 检索 + 结构化精确填充（见 [[PRD_内容创作]]）。

## 5. 状态流转（kb_file.status）
```
(上传) ──音视频──▶ (转写) ──▶ (结构化/分段) ──▶ (完成)
   └──文档/表格───────────────▶ (结构化/分段) ──▶ (完成)
任一步失败 ──▶ (失败) ──重试──▶ 回到对应步
```

## 6. 数据对象

### 6.1 `kb_file`（资料文件）
file_id · company_id · name · type(enum word/txt/excel/csv/音频/视频) · struct_type(结构化/非结构化) · group · uploader · status(上传/转写/结构化/完成/失败) · transcript(text) · fact_count(int) · created_at

### 6.2 `kb_fact`（事实条目）
fact_id · company_id · category(产品/价格/习俗/讲究/话术/其他) · key(str) · value(text) · source_file(ref) · validity(有效/待复核/过期) · tags(list) · struct_fields(json 结构化时)

### 6.3 `kb_group`（分组）
group_id · company_id · name · count(派生)

## 7. 接口草案
| 接口 | 方法 | 入参 | 出参 |
|--|--|--|--|
| 上传 | POST /kb/files | file, group | file_id + status |
| 文件列表 | GET /kb/files | group?, struct_type? | list‹file› |
| 处理状态轮询 | GET /kb/files/{id} | — | status + fact_count |
| 结构化预览 | GET /kb/files/{id}/struct | — | 字段表 |
| 新建分组 | POST /kb/groups | name | group_id |
| 手动录结构化 | POST /kb/struct | name, group, fields | ok |
| RAG 检索（内部） | POST /kb/retrieve | query, scope | facts |

## 8. 技术考虑
- 转写：Whisper / 讯飞 ASR（长音视频切分，有算力成本，见 [[产品规划-殡葬V1]] §四）。
- 结构化解析：Excel 表头映射字段；脏表给字段确认步骤。
- RAG：RAGFlow（GraphRAG 留 V2）；按 company_id 隔离索引。
- 处理异步化 + 状态轮询；失败可重试，长任务走后台。
- 每笔转写计入用量（参考转写类型，见 [[PRD_用量与计费]]）。

## 9. 风险与依赖

### 9.1 依赖
- ASR（转写）/ RAG（检索）能力。
- 用量模块（转写计数）。
- 内容创作（消费事实）。

### 9.2 风险
| 风险 | 应对 |
|--|--|
| 录音不清转写差 | 给质量提示 + 可改手动录入/上传文档 |
| Excel 格式杂解析错 | 字段确认步骤 + 手动校正 |
| 事实过期误用 | 时效字段 + 待复核标记（V1 人工维护） |
| 空库仍强生成出套话 | Step3 空库强引导先建库 |

## 10. 验收标准
1. 可上传多格式资料，音视频自动转写，状态实时回显，失败可重试。
2. Excel 被结构化为字段表并可预览，条目可被生成精确填充。
3. 文档被分段入库，可被 RAG 检索。
4. 分组可新建、归类、筛选，计数正确。
5. 知识库空时创作 Step3 强引导"先传资料"。
6. 每笔转写计入用量。
7. 数据按公司隔离，互不可见。
8. **硬事实零幻觉**：生成文案中的价格/规格等数字，100% 来自结构化知识库或留空；构造殡葬测试集实测硬事实准确率 ≥ 99%、未命中正确留空率 100%（评测方法见 [[技术方案-知识库精确召回与事实校验-殡葬V1]] §10）。

## 11. 当前通用产品开发基线（v3.0 · 2026-08-12）

### 11.1 模块位置

一级菜单为“企业大脑”，二级菜单为：诊断总览、企业 VI、企业知识、外部情报、进化与治理。“知识库”不再作为独立一级菜单名称。

### 11.2 企业知识总览

首屏回答“系统已经了解这家企业什么”，固定四张卡：企业身份；业务、产品与客户；获客与经营；目标、资源与品牌。每卡展示已确认摘要、来源、待确认、冲突和待补充；下方展示资料证据与治理入口。

### 11.3 候选与正式事实

- 手填并确认的内容优先级最高。
- 上传、OCR、文档理解、官网、公众号和外部情报提取统一写 `knowledge_candidate`。
- 初始状态为 `pending_confirmation`；人工采用后才写正式知识并允许生成调用。
- 硬事实未命中必须留空；生成内容不得反向覆盖价格、规格、地址、资质、案例和承诺。
- 正式知识按七域分组：企业基础事实、产品与服务、客户与市场、品牌与内容规范、销售与经营规则、案例与证明材料、外部环境与行业情报。

### 11.4 页面操作边界

- “上传资料”仅在诊断总览和企业知识需要时显示。
- 企业 VI、外部情报、进化与治理隐藏“Agent 授权”和“上传资料”。
- 外部情报使用“添加公开链接”“采集公开网站”，采用前必须人工确认。

### 11.5 验收

1. 四卡状态遵循“人工确认 > 已采用 > 待确认 > 待补充”。
2. 未确认候选不计入诊断完整度、不进入生成上下文。
3. 候选采用、驳回、冲突处理和软删除均有审计。
4. 每次生成保存实际使用的知识版本和引用位置。
