## 1. 文档概述

### 1.1 产品背景

§三 知识库内核原以**文本事实**为主（双层 RAG：内层私有 / 外层公开）。会议定调升级为**多模态营销底座**——参考卡巴斯基知识库结构，把企业的**文本 / 图片 / 视频**统一收上来，AI 解析分类整理索引，沉淀成**营销知识库**，不仅喂生成"说什么"，还供给视频生成"用什么素材"。原则：**先搭底座，再生成内容**。

本模块要解决的核心问题：**让客户傻瓜式把多模态素材/资料传进来，AI 自动解析、分类、索引，叠加人工分组兜底，沉淀成可被内容/视频生成检索调用的多模态营销底座；其中素材子类型支持 AI 按分镜需求匹配召回片段。**

> 📌 **2026-06-28 定调：一个知识库、统一上传、AI 自动判类**。客户把资料/素材一股脑拖进**同一个知识库**，AI 自动判为三类——**① 结构化事实**（价格/规格等，走精确召回）、**② 非结构化**（文档/文案/品牌口径，进 RAG）、**③ 素材（图/视）**（供混剪/i2v）。**素材是这个库的一个子类型/视图，不是独立的第二个库**（数据层就是一个库）；同一产品的「文案在事实、画面在素材」靠 `product_id` 锁定（见 §3.3）。本次把"统一上传 + AI 自动判类"明确为入口形态——素材即便在商家端单独呈现为一个视图，底座层仍是同一库内的子类型。

> 本期不做：知识图谱可视化、跨企业素材共享市场、自动版权检测、素材自动剪辑（剪辑在 [[PRD_视频模板化生成与换人换产品]]）。

### 1.2 产品目标

- **统一上传 + AI 自动判类**：一个知识库统一上传，AI 自动判为「结构化事实 / 非结构化 / 素材(图视)」三类（2026-06-28）
- **多模态入库**：文本 / 图片 / 视频 / 音频统一上传与处理（图片打标、视频抽帧+转写、文本结构化）
- **AI 自动分类 + 人工分组**：双轨——AI 自动归类索引，人工定义分组兜底纠偏
- **营销知识库**：企业背景/产品/品牌自动整理索引，喂生成不跑偏
- **素材子类型**：傻瓜式上传，AI 处理（打标/去重/归类）+ 按需匹配召回，供视频模板化生成（是同一知识库的子类型/视图，非独立库）
- **知识库↔素材 `product_id` 关联**：同一产品文案在事实、画面在素材，靠 `product_id` 锁定，生成时文案出事实、画面出素材（2026-06-28）
- **正交叠加双层结构**：多模态是"存什么"，内层私有 RAG / 外层公开发布是"给谁用"，互不冲突

### 1.3 核心指标

| 指标 | 目标值 |
|--|--|
| 多模态上传成功率 | ≥ 99% |
| 图片/视频 AI 打标可用率 | ≥ 90% |
| AI 自动分类准确率（人工抽检）| 高（可人工纠正）|
| 素材按分镜需求匹配召回相关性 | 高（供模板化生成可用）|
| 数据按企业隔离 | 100% |

### 1.4 范围

**In-Scope（本期）**
- **统一上传 + AI 自动判类**（结构化事实 / 非结构化 / 素材图视）

- AI 解析：图片打标、视频抽帧+转写、文本结构化/分段

- 企业级数据隔离

## 2. 用户与场景

### 2.1 目标用户
- **运营**：批量上传素材/资料、维护分组的主力。
- **老板**：提供品牌/产品一手信息。
- **下游小 B（分销场景）**：在大 B 统一供给的素材库内取用（核心素材库留大 B 层，对齐 Index §十七）。

### 2.2 典型场景
1. 客户把产品图、宣传视频、品牌手册、历史素材一股脑拖进来 → AI 自动打标分类（产品/场景/品牌/人物…）→ 人工微调分组。
2. 视频模板化生成需要"产品特写镜头" → 素材库按分镜槽位 AI 匹配召回可用片段（[[PRD_视频模板化生成与换人换产品]] §4.2）。
3. 生成营销文案 → 从营销知识库检索品牌口径/卖点，生成不跑偏。
4. 消保委「放心消费多模态知识库」→ 历史方案复用本底座、底层接小冰、中间层自建；当前仓库未收录该实例的独立 PRD。

### 2.3 用户故事
- 作为运营，我把素材随便传进去，系统自动给我归好类、打好标，要用时找得到。
- 作为运营，做视频时系统能自动从素材库挑出合适的片段，不用我翻文件夹。
- 作为老板，企业的资料和素材沉淀成一个底座，越用越厚，换个用途也能调。

## 3. 整体方案

### 3.1 方案原则
- **傻瓜式上传**：客户只管传，解析/分类/索引由 AI 兜。
- **AI 分类 + 人工兜底**：自动归类提效，人工分组纠偏，不全信 AI。
- **底座先行**：先搭多模态底座沉淀素材/知识，再喂生成（会议工程次序）。
- **正交不重写**：多模态维度叠加在既有双层结构之上，不动 [[PRD_知识库]] 文本事实精确召回逻辑。

### 3.2 模块结构（参考卡巴斯基：原材料层 + 解析层 + 索引层）
```
多模态知识库底座（一个库，统一上传，AI 自动判类）
├─ 统一上传（拖拽多选，文本/图片/视频/音频/Excel，傻瓜式）
├─ AI 自动判类（→ 结构化事实 / 非结构化 / 素材(图视) 三类）
├─ AI 解析层（图片打标 / 视频抽帧+转写 / 文本结构化分段 / Excel 双路拆解*）
├─ 分类与分组（AI 自动分类 + 人工定义分组，双轨）
├─ 营销知识库索引（RAG-ready / 生成检索）
├─ 素材子类型/视图（打标 → 去重 → 归类 → 按需匹配召回 → 供模板化生成）
├─ product_id 关联（事实↔素材：文案在事实、画面在素材，靠产品 ID 锁定）*
└─ 双层视角（内层私有 RAG / 外层公开发布，正交叠加）

* = 2026-06-28 待开发缺口（见 §9.3）；素材为本库子类型/视图，非独立第二个库。
```

### 3.3 设计约束（功能限制）
1. **统一上传一个库 + AI 自动判类（2026-06-28）**：一个知识库统一上传，AI 自动判为「结构化事实 / 非结构化 / 素材(图视)」三类；**素材是本库子类型/视图，不是独立的第二个库**。
2. **多模态统一入口**：文本/图片/视频/音频/Excel 一个上传口，按类型走对应解析。
3. **AI 解析分工**：图片→视觉打标；视频→抽帧+ASR 转写+打标；音频→ASR；文本→结构化/分段（沿用 [[PRD_知识库]]）；Excel→双路拆解（见 §4.6）。
4. **分类双轨**：AI 自动分类给建议，人工可改/可定义分组；最终分组以人工为准。
5. **素材可被检索匹配**：素材带结构化标签（产品/场景/人物/情绪/时长…），供视频模板化生成按段位需求召回。
6. **两类检索分治（不变）**：**硬事实精确召回**（价格/规格走结构化精确查询、不进向量库、未命中留空）/ **画面相似匹配**（素材按分镜召回供混剪），互不混用。
7. **知识库↔素材 `product_id` 关联（2026-06-28）**：同一产品「文案在事实、画面在素材」靠 `product_id` 锁定（嘴↔眼的螺栓）；生成时文案出事实、画面按 `product_id` + 分镜需求出素材。
8. **正交叠加**：每条内容同时带 `模态维度` 与 `双层维度（内层/外层）`，不互相覆盖。
9. **企业隔离**：按 company_id 隔离索引与素材；分销场景核心素材留大 B 层。
10. **底层可替换**：RAG/解析模型/底层栈（小冰等）TBD，经中间层抽象，不写死。

## 4. 功能需求

### 4.1 上传
- 拖拽/多选，自动识别模态（文本/图片/视频/音频），落入当前分组（未选用默认组），即时建条目=处理中。

### 4.2 AI 解析层
| 模态 | 解析动作 | 产物 |
|--|--|--|
| 图片 | 视觉打标（物体/场景/人物/情绪）| 标签 + 缩略 |
| 视频 | 关键帧抽取 + ASR 转写 + 打标 | 片段标签 + 转写文本 + 关键帧 |
| 音频 | ASR 转写 | 文本 |
| 文本/表格 | 结构化/分段（复用 [[PRD_知识库]]）| 事实条目 / 分段 |

### 4.3 分类与分组（双轨）
- AI 自动分类：按标签给分组建议 + 自动归类。
- 人工分组：新建/重命名分组、拖拽归类、纠正 AI；最终以人工为准。

### 4.4 营销知识库索引
- 多模态内容统一建索引，供 RAG / 生成检索；带模态维度 + 双层维度筛选。

### 4.5 素材子类型（同一知识库的子类型/视图）
| 能力 | 说明 |
|--|--|
| 傻瓜上传 | 同上传口，AI 自动判为素材类（图/视）|
| AI 处理 | 打标 / 去重 / 归类 / 提取可用片段元数据（时长/画面/适用场景）+ 打 `product_id` 标签 |
| 匹配召回 | 按分镜槽位需求（如"产品特写 3s"）AI 检索召回候选片段 → 供 [[PRD_视频模板化生成与换人换产品]] |

### 4.6 Excel 双路拆解 + product_id 关联（概览 · **可编码规则见 §13**）
> 解决"上传 Excel 时图片被丢弃"的关键缺口，打通知识库↔素材的数据贯通（Index §二十.4）。
> 🆕 **2026-06-30**：本节为概览;**自动识别表格/唯一键判定/product_id 生成/嵌入图行挂载/跨源对齐/边界 case 的可开发规则,见 [§13](#13-product_id-生成与对齐--excel-双路拆解可编码规则--2026-06-30)**。

| 能力 | 说明 |
|--|--|
| **Excel 双路拆解** | 上传 Excel 时双路处理：**文字字段 → 知识库（按行成事实）**；**嵌入的产品图自动抽取 → 存入素材**，并按产品名/行打 `product_id` 标签与对应事实挂钩。现状：Excel 只进文字，**图片被丢弃**（既不进事实也不进素材）——本期需补齐。 |
| **product_id 关联** | 同一产品「文案在事实、画面在素材」靠 `product_id` 锁定；生成时文案出事实、画面按 `product_id` + 分镜需求出素材。 |
| **混剪召回供给** | 素材按 `product_id` 精确 + 标签 + 画面相似多路召回，供 [[PRD_视频模板化生成与换人换产品]] 模板②混剪段打分决策（够格用素材/产品段转 i2v/无候选转文生视频）。 |

## 5. 状态流转（asset.status / kb_item.status）
```
(上传) ──图片──▶ (打标中) ──▶ (完成)
        ──视频──▶ (抽帧+转写中) ──▶ (打标中) ──▶ (完成)
        ──音频──▶ (转写中) ──▶ (完成)
        ──文本──▶ (结构化/分段中) ──▶ (完成)
任一步失败 ──▶ (失败) ──重试──▶ 回到对应步
```

## 6. 数据对象

### 6.1 `kb_item`（多模态知识条目）
item_id · company_id · **kind(结构化事实/非结构化/素材)** · modality(文本/图片/视频/音频) · source_file · **product_id?** · ai_tags(list) · group(人工分组) · auto_group(AI建议) · layer(内层/外层) · index_ref · status · created_at

### 6.2 `asset`（素材，知识库素材子类型）
asset_id · company_id · modality · file_ref · **product_id?** · tags(产品/场景/人物/情绪…) · duration · usable_segments(json) · dedup_hash · group · status · created_at

> `product_id` 是事实↔素材的关联键（2026-06-28）：同一产品的 `kb_fact`（文案）与 `asset`（画面）共享同一 `product_id`，生成时按 ID 配对。

### 6.3 `kb_group`（分组，复用并扩展 [[PRD_知识库]] §6.3）
group_id · company_id · name · is_manual(bool) · count(派生)

> 文本硬事实条目沿用 [[PRD_知识库]] §6.2 `kb_fact`（结构化精确召回），本底座不改。

- **解析模型（据调研）**：ASR 用 faster-whisper/WhisperX(MIT/BSD，词级)；视觉打标/视频抽帧用开源多模态模型经中间层抽象；TTS（如需）CosyVoice(Apache，中文强)。避雷 ChatTTS/Edge-TTS(非商用/违 ToS)。

#### 12.A.1 RAG 检索（非结构化语义召回 · RAG/检索类）

**① 能力定义与边界**：从企业营销知识库（文档/文案/品牌口径）检索相关片段喂生成，让内容"说什么"不跑偏；服务 [[PRD_内容创作]] 仿写。成功标准 = 召回相关、生成不跑偏。约束 = 与硬事实精确召回**分治、不混用**（§3.3-6）。能做 = 语义相似召回非结构化知识。**不能做（不确定性）**：返回精确价格/规格（那走 12.A.2，硬事实不进向量库）。
**② 输入/输出规范**：入 = query + modality? + layer?(内层/外层)；出 = 命中片段(items) + 来源。边界 = 空库返回空，提示补库；错误 = 召回为空不臆造。
**③ AI 技术需求**：模型选型见 **§12 表第 1 行**（RAGFlow 工业级，别自造内核；按 company_id 隔离索引）。数据需求 = 企业上传的非结构化文档/文案/品牌手册，规模随客户，AI 自动判类+人工分组（§4.3），更新随上传。Prompt/参数 = 检索 prompt 与重排参数后台维护、客户端不可编辑。性能 = 检索时延、召回相关性（**目标待压测**）。
- **RAG 变体**：分块策略 = chunk/overlap（**参数待压测定档**）；检索策略 = 多路召回（向量+标签）+ 重排；生成策略 = 引用命中片段供 LLM 生成，命中弱则提示补库（不强答）。
**④ 评估标准**：系统层 = 检索成功率/时延；模块层 = 召回相关性/命中率（**目标待压测**）；业务层 = 生成不跑偏（人工抽检）。Golden Dataset = query→应召回片段标注集（**待建**）。Pass/Fail = 相关片段被召回且生成不跑偏 = Pass；召回无关致跑偏 = Fail。BadCase 闭环 = 漏召/错召 → 归因（分块/向量/重排）→ 调分块或重排。
**⑤ 灰度上线**：灰度 = 随知识库底座上线，先小库验证。监控 = 召回相关性/时延/空召回率。回滚 = 调分块/重排参数；底层经中间层抽象可替换。
**⑥ 风险与缓解**：幻觉 = 召回弱不强答、提示补库。版权 = 仅检索企业自有数据。成本 = 异步索引 + 按需检索。

#### 12.A.2 硬事实精确召回（结构化字段查询 · 不进向量库 · RAG/检索类）

**① 能力定义与边界**：价格/规格等硬事实走**结构化精确查询**，是"事实不编造"的底层保障；仿写取数靠它（[[PRD_内容创作]] §11.2）。成功标准 = 硬事实零编造、命中即准、未命中留空。约束 = 🔴 **硬事实不进向量库**（不让向量"猜数字"，§3.3-6）。能做 = 结构化字段精确匹配返回事实。**不能做（不确定性）**：模糊/语义猜测价格——未命中必须留空，不编造。
**② 输入/输出规范**：入 = 结构化查询（产品/字段，可带 `product_id`）；出 = 精确事实值或空。边界 = 未命中 → 留空 + 提示（不返回近似值）。错误 = 绝不用向量近邻兜底硬事实。
**③ AI 技术需求**：模型选型见 **§12 表第 2 行**（结构化字段查询，沿用 [[PRD_知识库]] `kb_fact`，自建，不进向量库）。数据需求 = 结构化事实条目（价格/规格，客户维护、人工保鲜，更新频率随客户改价）；Excel 双路拆解按行成事实（§4.6，待开发）。Prompt/参数 = 无生成 prompt，纯查询；字段映射后台维护。性能 = 查询时延低、命中准确率应 100%（**正式目标待压测**）。
- **RAG 变体**：分块 = 不分块（结构化按字段）；检索策略 = 精确匹配（`product_id`/字段键）；生成策略 = 直接返回事实值，未命中转留空/人工补。
**④ 评估标准**：系统层 = 查询成功率/时延；模块层 = 命中事实准确率（**目标 100%，待压测核**）+ 未命中正确留空率；业务层 = 下游仿写硬事实零编造。Golden Dataset = 已知价格/规格的产品事实集（**待建**）。Pass/Fail = 命中即准、未命中留空 = Pass；返回近似/错误价格 = **直接 Fail**。BadCase 闭环 = 取错值/该空不空 → 归因（字段映射/product_id 关联）→ 修映射。
**⑤ 灰度上线**：灰度 = 与 RAG 同上线。监控 = 命中准确率/未命中留空率/`product_id` 关联正确率。回滚 = 收紧为"必须命中才给事实，否则留空"。
**⑥ 风险与缓解**：幻觉 = 🔴 硬事实精确召回铁律不改（不进向量库、未命中留空），技术保障见 [[技术方案-知识库精确召回与事实校验-殡葬V1]]。合规 = 价格/承诺事实准确是合规命脉。

#### 12.A.3 文本向量检索（非结构化语义召回 · RAG/检索类）

**① 能力定义与边界**：对非结构化文本（文案/品牌口径/分段）做向量语义召回，是 12.A.1 RAG 的检索底座之一；与硬事实精确召回分治（§3.3-6）。能做 = 语义近邻召回。**不能做（不确定性）**：精确数字事实（走 12.A.2）。
**② 输入/输出规范**：入 = query 向量 + modality?/layer? 过滤；出 = top-k 语义近邻片段 + 分数。边界/错误 = 低分阈值下不强返，交 RAG 生成策略决定（引用/转人工）。
**③ AI 技术需求**：模型选型见 **§12 表第 1/2 行**（多模态向量 + 标签混合检索，RAGFlow 体系内）。数据需求 = 非结构化文本分段 + 向量；嵌入模型须核可商用许可。Prompt/参数 = 后台维护。性能 = 向量检索时延/召回率（**目标待压测**）。
- **RAG 变体**：分块策略 = chunk/overlap（**待定档**）；检索策略 = 向量召回 + 标签过滤 + 重排；生成策略 = 供 12.A.1 RAG 引用，弱命中转人工/提示补库。
**④ 评估标准**：系统层 = 检索时延；模块层 = 语义召回率/精确率（**目标待压测**）；业务层 = 支撑 RAG 不跑偏。Golden Dataset = 与 12.A.1 共用。Pass/Fail = 相关片段进 top-k = Pass。BadCase 闭环 = 漏召 → 归因（嵌入/分块）→ 调参。
**⑤ 灰度上线**：随 RAG 统一灰度/监控/回滚（分块与重排参数可调）。
**⑥ 风险与缓解**：幻觉 = 与精确召回分治、互不混用。成本 = 异步建索引、按需检索。

#### 12.A.4 图片视觉打标（多模态模型 · 多模态类）

**① 能力定义与边界**：对上传图片/视频关键帧做视觉打标（物体/场景/人物/情绪），供素材按分镜召回（[[PRD_视频模板化生成与换人换产品]] 模板②混剪）。成功标准 = 打标可用率 ≥ 90%（§1.3）。约束 = AI 给标签建议，人工分组兜底纠偏（§3.3-4）。能做 = 自动打标+归类建议。**不能做（不确定性）**：100% 准确（人工可改）、视频抽帧后的 ASR（走 [[PRD_爆款抓取]] §11）。
**② 输入/输出规范**：入 = 图片/视频关键帧；出 = 标签(list) + 缩略 + 可用片段元数据（时长/画面/适用场景）+ `product_id` 标签。边界 = 模糊/低质图标签置信低 → 转人工。错误 = 打标失败 → 失败态可重试（§5）。
**③ AI 技术需求**：模型选型见 **§12 表第 3 行**（开源多模态模型 TBD，经中间层抽象）。数据需求 = 客户上传图/视，规模随客户；标注方式 = AI 自动打标 + 人工分组纠偏（双轨，§4.3）；更新随上传。Prompt/参数 = 打标提示/标签体系后台维护、客户端不可编辑。性能 = 打标可用率 ≥ 90%、处理时延（异步，**目标待压测**）。
- **多模态（视觉）精度变体**：输入格式 = 常见图片/视频容器；分辨率自适配（低质图标签置信下降）；打标维度 = 物体/场景/人物/情绪/时长。
**④ 评估标准**：系统层 = 打标任务成功率/时延；模块层 = 打标可用率 ≥ 90%（人工抽检）+ 召回相关性；业务层 = 素材按分镜召回供混剪可用（§1.3）。Golden Dataset = 人工标注的素材样本集（**待建**）。Pass/Fail = 标签可用且召回相关 = Pass；大面积错标致召回不可用 = Fail。BadCase 闭环 = 错标/漏标 → 收集 → 归因（模型/图质）→ 人工纠偏 + 反哺标签体系。
**⑤ 灰度上线**：灰度 = 随底座上线，先人工抽检高比例。监控 = 打标可用率/召回相关性/失败率。回滚 = 人工分组兜底；底层模型经中间层可替换。
**⑥ 风险与缓解**：偏见/质量 = AI 仅给建议、人工分组为准（§3.3-4）。版权 = 仅处理企业自有素材、不自爬。成本 = 异步 + 按需解析（非全量重解析）。

## 13. product_id 生成与对齐 + Excel 双路拆解（可编码规则 · 2026-06-30）

> 把 §4.6 / §9.3 的🔴从"描述"落成"可开发规则"。核心:**不要求固定上传模板,系统自动识别表格 + 实测唯一性定键 + 生成 product_id + 图按行挂载 + 跨源对齐**,真歧义才人工兜底。

### 13.1 总则
- **product_id** = 系统生成的内部主键(UUID),是同一商品「文案(事实)↔画面(素材)」的关联锚。
- **对齐键 external_key** = 从客户数据**自动识别**的商品唯一标识:**货号/SKU 优先 → 商品名归一次之**。
- 客户**无需用固定模板**;表格结构任意,靠 AI 识别 + 数据校验对齐。

### 13.2 Excel 上传自动识别流程（可编码）
```
Step1 列语义识别：读表头 + 抽样 N 行值 → LLM/规则给每列打标签
        {商品名 · 货号/SKU · 价格 · 规格 · 材质 · 图 · 其他}
Step2 唯一键判定（看实测数据,不只看列名）：
   候选 = 语义∈{货号/SKU/编号} 的列
     → 实测：该列 distinct_count == 非空行数 且无空 ? → 是 → 采纳为 external_key ✅
   多候选 → 取唯一且语义最强者
   无 ID 列 → 退用「商品名」列：唯一→用；重复→组合键(商品名+规格)再测；仍不唯一→标 ambiguous→人工确认
Step3 生成 product_id：对每个 external_key 值，查 product 表(company_id+external_key)
        → 命中复用 product_id；未命中新建
Step4 文字双路：每行非图字段 → kb_fact(结构化事实,打 product_id)
Step5 图抽取与挂载（见 13.3）
```

### 13.3 嵌入图抽取与行挂载（技术契约）
- **抽取**：解析 xlsx 的绘图关系(`xl/drawings/*.xml` 锚点 + `xl/media/*` 图源),拿到每张图的**锚定单元格(row,col)**。
- **挂载**：图 → 锚点所在**行** → 该行 external_key → product_id → 存 `asset`(打 product_id)。
- 退化:若工作簿用浮动图/无规范锚点 → OCR/人工对齐兜底。

### 13.4 跨源对齐（Excel / 口述转写 / 手动录入 → 同一 product_id）
- 后续来源按对齐键匹配已有 product:**有货号→精确匹配;无→商品名+别名表(aliases)模糊匹配**→命中复用,未命中新建或提示"是否同款"。

### 13.5 边界 case 处理
| case | 处理 |
|--|--|
| 商品名重复、无货号 | 组合键(名+规格)→仍重复→**人工确认** |
| 一行多图 | 全部挂该行同一 product_id(多张产品图) |
| 图锚定错位 / 浮动图 | 取锚点行;定位不了→人工对齐 |
| 合并单元格 | 取左上角所在行 |
| 同款跨表 / 别名 | 别名表归一到同一 product_id |
| 列语义/唯一键 置信度低 | 给客户**一眼轻量确认**(默认自动跑,非必经) |

### 13.6 可靠性保证（别让"自动识别"变"自动识别错"）
1. **唯一性靠实测 distinct**,不信列名(防"型号"看着像 ID 实则重复)。
2. **识别结果给轻量确认**:"已把『货号』当唯一标识、图对到对应商品,对吗?"——默认自动跑,确认是兜底。
3. **真歧义(无唯一列/名重复/图行错位)才人工**;常规表格全自动。

### 13.7 数据对象增补
- `product`(商品主表)：product_id(PK·UUID) · company_id · external_key(货号/SKU 或归一商品名) · name · aliases(list) · source(excel/手动/口述) · created_at
- `kb_fact` / `asset` 的 `product_id` 字段：识别成功时**必填关联**。
- `excel_ingest_log`：列语义映射 + 选定唯一键 + 置信度 + 人工确认状态(供追溯与复跑)。

### 13.8 验收标准
1. 上传**任意结构**的商品 Excel，系统自动识别商品标识列(实测唯一性)、生成 product_id，**无需固定模板**。
2. 文字成事实、嵌入图抽取成素材，**同行图文挂同一 product_id**。
3. 无货号时用商品名归一;重复时组合键或人工确认。
4. 一行多图全挂该 product_id;图锚定不了触发人工对齐。
5. 口述/手动录入的同款按对齐键归并到已有 product_id。
6. 生成时按 product_id 取**价格(事实)+ 产品图(素材)配对，不串商品**。

## 14. 混剪素材召回打分（可编码规则 · 2026-06-30 · 落最后一个🔴）

> **归属定清(解审查指出的"两不管")**：**召回+打分引擎归本底座**(`/assets/match`);**决策树(用素材/转 i2v/转文生)归 [[PRD_视频模板化生成与换人换产品]] §4.7.2**;两者契约 = `match_result`。
> 性质:这是 §13"混剪打分"——**素材片段对分镜需求的匹配度打分(选料用),不是成片效果打分**。

### 14.1 输入：分镜槽位需求 `shot_spec`
由视频模板的分镜产出,逐段一个:
`{ seg_id · product_id?(该段绑定的商品) · visual_query(画面需求文本,如"真丝寿衣产品特写") · need_duration(秒) · platform · style }`

### 14.2 多路召回（并行）
1. **product_id 精确路**：shot_spec 带 product_id → 精确捞该商品 asset(最高优先)。
2. **标签路**：visual_query 关键词 ↔ asset.ai_tags(产品/场景/人物/情绪)。
3. **画面向量路**：visual_query embed ↔ asset 画面向量余弦相似。
三路结果合并去重为候选集。

### 14.3 打分公式（每个候选一个综合分 score∈[0,1]）
```
score = 0.40·产品匹配 + 0.35·画面贴合 + 0.15·时长适配 + 0.10·授权可用
```
| 维度 | 取值 |
|--|--|
| 产品匹配 | product_id 精确命中=1.0 ; 同类标签=0.6 ; 无关=0 |
| 画面贴合 | visual_query 与素材画面向量**余弦相似** [0,1] |
| 时长适配 | 可用片段 ≥ need_duration → 1.0 ; 不足按可拼接/比例折算 |
| 授权可用 | 已授权可商用=1 ; **未授权=0 → 该候选直接淘汰(硬门槛)** |

> 权重为**初值,待压测校准**(POC 跑真实素材后调);写进配置不写死代码。

### 14.4 决策阈值（视频模板 §4.7.2 据 score 决策）
```
score ≥ T_use(初值 0.75)            → 用素材库片段(最省最真)
T_i2v(0.5) ≤ score < T_use 且产品段  → 转 i2v(产品图当首帧生成动态展示)
score < T_i2v 或 无候选              → 转文生视频(控量) + 提示"补素材提质"
授权=0 的候选                        → 直接淘汰,不参与
```
- **防乱拼铁律**:score < T_i2v **不硬塞**——降级而非凑不相干画面。
- 阈值 T_use / T_i2v **可配置**,支持按行业/压测调。

### 14.5 边界处理
| case | 处理 |
|--|--|
| 多候选同分 | 取时长最贴 / 最新 / 本条未用过的 |
| 同一成片多分镜 | 去重,同素材不在一条片里重复用 |
| product_id 命中但画面不符(如只有 logo) | 画面贴合仍须过线,否则降级 |
| 素材库空/全未授权 | 全段转 i2v/文生,提示补素材 |

### 14.6 数据对象 / 接口
- `shot_spec`(见 14.1) ; `match_result`：`candidate[]{asset_id · score · breakdown{产品/画面/时长/授权} · decision(use_asset/to_i2v/to_t2v)}`
- 接口 `POST /assets/match`(§7 已列)明确:入 `shot_spec`,出 `match_result`(含打分 + decision 建议)。

### 14.7 验收标准
1. 带 product_id 的分镜,精确命中该商品素材且排序优先。
2. 综合打分含产品/画面/时长/授权四维;**授权未过直接淘汰**。
3. score≥T_use 用素材、中间档产品段转 i2v、低于 T_i2v 或无候选转文生视频;**低分不硬塞**。
4. 同一成片同素材不重复用;权重与阈值**可配置**(支持压测校准)。
5. 输出 `match_result` 含每候选的分项 breakdown,供溯源与调参。

## 15. 企业级知识治理借鉴与产品转化记录（2026-08-05）

> 本节记录本产品参考的企业级知识管理做法，以及转化到 AI 获客通用底座的具体要求。参考方案用于形成设计依据，不表示直接复制第三方产品或已完成对应后端集成。

### 15.1 借鉴来源与核心做法

| 参考方案 | 借鉴的企业级做法 | 转化为本产品的要求 |
|---|---|---|
| Microsoft SharePoint 文档治理 | 元数据、草稿/正式版本、内容审批、版本历史、回滚和权限控制 | 原始资料与正式知识分离；知识发布必须经过确认；保留版本和变更原因 |
| Guru 知识验证 | 每条知识有验证状态、验证人、验证时间和复核/过期机制 | 正式知识必须带负责人、确认人、生效期和下次复核时间；到期自动进入维护任务 |
| 企业 AI 知识检索实践 | 沿用源系统权限、按权限检索、回答返回来源引用 | Agent 按企业、成员、知识域、任务目的计算权限交集；生成结果展示知识依据和版本 |

参考链接：

- [SharePoint 版本、审批与签入/签出](https://support.microsoft.com/en-US/SharePoint/libraries/plan-document-versioning-content-approval-and-check-out-controls-in-sharepoint)
- [Guru 知识验证与复核](https://www.getguru.com/features/verification)
- [OpenAI Company Knowledge 的权限与来源引用](https://help.openai.com/en/articles/12628342-company-knowledge-in-chatgpt-business-enterprise-and-edu)

### 15.2 由借鉴方案确定的产品原则

1. **资料不是知识**：上传文件、链接、录音和图片先进入资料收件箱；AI 提取的是知识候选，负责人确认后才进入正式知识。
2. **正式知识必须可追溯**：每条知识必须关联来源、来源位置、提取方式、确认人、版本、生效时间、失效时间和变更原因。
3. **草稿不影响正式调用**：待确认、低置信度和冲突内容默认不可被 Agent 用作企业硬事实。
4. **修改不能静默覆盖**：更新价格、规格、联系方式、承诺或品牌规则时创建新版本，旧版本保留归档并记录影响范围。
5. **权限和知识绑定**：人员权限、知识域权限、Agent 服务身份和任务目的共同决定可检索范围。
6. **维护由系统驱动**：到期复核、版本冲突、知识缺口、低置信度调用和授权到期都自动生成维护任务。
7. **调用结果反哺知识**：记录引用知识、用户修改、人工退回、未命中和冲突，形成知识补充线索。

### 15.3 V1 知识生命周期

```text
上传 → 处理中 → AI 候选 → 待补充/待确认 → 已发布
                              ↓
             冲突处理 / 到期复核 / 授权复核
                              ↓
                    新版本发布 / 失效 / 归档
```

状态约束：

- `处理中`：文件仍在解析、转写、抽帧或结构化。
- `AI 候选`：已提取但未被企业负责人确认，不进入正式事实检索。
- `待补充`：识别到企业信息缺口，需要用户回答或补资料。
- `待确认`：候选内容有明确来源，等待负责人确认。
- `已发布`：可按权限被诊断、内容和 Agent 调用。
- `待复核`：超过复核日期、来源发生变化或被低置信度调用触发。
- `已失效/已归档`：不再参与默认检索，但保留历史和审计记录。

### 15.4 V1 后台知识治理工作区

企业知识后台统一提供以下工作区：

1. **知识总览**：知识完整度、待确认、待补充、冲突、即将过期、低置信度调用。
2. **资料收件箱**：原始文件、解析进度、失败原因、AI 提取候选和缺口清单。
3. **正式知识**：按企业与行业知识域查看可调用的事实、规则、口径和案例。
4. **素材视图**：图片、视频、音频和历史物料，沿用本底座的素材子类型，不创建第二套库。
5. **数据源**：官网、公众号、云盘、CRM 等授权来源和同步状态。
6. **维护中心**：过期复核、冲突解决、负责人补齐、授权检查、知识缺口和使用反馈。

### 15.5 正式知识对象必备字段（V1 增补）

在现有 `kb_fact` / `asset` 字段基础上，V1 必须补齐：

`source_locator` · `extraction_method` · `confidence` · `owner_id` · `verifier_id` · `verified_at` · `effective_at` · `expires_at` · `review_cycle` · `security_level` · `agent_scope` · `external_output_rule` · `version` · `change_reason` · `last_used_at`

其中：

- 价格、规格、地址、联系方式、服务承诺等硬事实必须有 `source_locator` 和 `verifier_id`。
- 没有 `owner_id` 或超过 `expires_at` 的知识不能保持“已发布”状态，应进入维护中心。
- 没有对外授权的素材只能内部检索，不能自动进入公众号、短视频或数字人输出。

### 15.6 V1 验收补充

1. 用户上传资料后能看到原始资料、AI 提取候选、缺口和来源，不直接进入正式知识。
2. 负责人确认后生成正式知识版本，且能查看来源、确认人、有效期和历史版本。
3. 同一事实出现两个有效来源时，系统进入冲突状态，不自动覆盖旧值。
4. 知识到期、负责人缺失、授权到期或低置信度调用时，维护中心产生待办。
5. Agent 每次调用记录企业、用户、任务目的、知识版本和输出范围；关键事实未命中时返回“知识库未提供”，不允许模型补写。
6. 资料收件箱、正式知识、素材视图和维护中心共用同一企业知识底座，不形成个人知识库或第二套素材库。

## 16. AI 知识质量引擎与自动验证（2026-08-05）

> 目标：让知识质量判断由 AI 自动完成日常筛选，用户只处理高风险例外；不能用模型自评代替证据、权限和回归验证。

### 16.1 自动质检流水线

```text
上传/同步 → 解析与事实抽取 → 来源与权限识别 → 跨源一致性校验
                         ↓
              新鲜度/完整度/重复/敏感信息检查
                         ↓
                 自动决策 → 回归集测试 → 发布或隔离
                         ↓
            调用反馈、纠错和未命中 → 自动生成补充任务
```

每次新资料、版本更新或外部来源变化都触发一次评估，并记录 `evaluation_version`，保证结果可复现。

### 16.2 质量评估维度与数据字段

在 `kb_fact` / `asset` 上增补：

`source_authority` · `evidence_count` · `cross_source_consistency` · `freshness_state` · `completeness_state` · `permission_state` · `usage_quality` · `quality_decision` · `quality_reasons` · `last_evaluated_at` · `evaluation_version`

AI 至少检查：

1. 来源可信度：营业执照、企业授权系统、负责人确认高于普通网页或未署名内容。
2. 跨源一致性：同一事实出现不同值时标记 `conflict`，保留旧版本，不自动覆盖。
3. 新鲜度：提取生效/失效日期；过期或超过知识域复核周期标记 `stale`。
4. 完整度：判断诊断、内容、报价、客服等任务所需字段是否齐全，缺字段标记 `missing`。
5. 权限与授权：敏感信息、员工/客户信息和素材版权未确认时标记 `unauthorized`，不得对外调用。
6. 重复与污染：近似重复合并候选；提示词注入、无关文本和无法定位来源的内容隔离。
7. 实际使用质量：记录引用命中、用户纠错、人工退回、未命中和冲突反馈，作为下一轮评分输入。

### 16.3 自动决策状态

| 决策 | 条件 | Agent 行为 |
|---|---|---|
| `auto_usable` | 来源、权限、时效和一致性通过；任务回归集达标 | 可按权限检索并引用 |
| `draft_only` | 低风险但置信度不足、字段不完整或待负责人确认 | 仅作为候选/内部草稿，不作硬事实 |
| `quarantined` | 冲突、过期、未授权、疑似注入或来源不可追溯 | 禁止默认检索，生成维护任务 |

价格、规格、地址、联系方式、服务承诺、合同和合规规则属于高风险域：即使评分较高，也必须具备负责人确认和可定位证据，不能只凭模型判断自动发布。

### 16.4 黄金任务回归集

每个企业和知识蓝图维护 10–20 条“黄金任务”（如报价问答、产品介绍、客户画像、公众号发布前检查）。知识发布/更新后自动运行，至少输出：引用准确率、关键事实完整率、权限越界率、过期知识命中率、用户纠错率。未达阈值时自动回滚为 `draft_only` 或 `quarantined`，并在维护中心生成任务。

### 16.5 用户侧可见反馈

知识详情和治理中心必须展示：`AI 已验证`、验证时间、证据链接/来源位置、可用于哪些 Agent、不能用于哪些输出、下次自动复核时间，以及“为什么不可用”的可解释原因。日常不要求用户逐条评分；用户纠错、退回或未命中会自动反哺质量引擎。

### 16.6 V1 验收补充

1. 上传资料后自动生成质量状态、评分维度、证据位置和下一步动作。
2. 同一事实冲突、过期、无授权或无来源时自动隔离，不进入正式硬事实检索。
3. 低风险且通过回归集的知识可自动发布；高风险知识保留负责人例外确认。
4. 每次发布/更新自动运行黄金任务回归集，失败会阻止升级并给出失败原因。
5. Agent 调用记录知识版本、引用位置、质量决策和用户纠错，维护中心自动聚合为补充任务。

## 17. 当前企业大脑统一底座（v3.0 · 2026-08-12）

### 17.1 单库多类型

企业资料、结构化事实、非结构化段落、图片/视频素材和外部情报使用统一底座，但以类型、权限、确认状态和检索策略隔离。素材不是第二套知识库；硬事实不进入仅相似度召回的向量路径。

### 17.2 写入门禁

- 上传、OCR、文档理解、网页采集和外部情报全部先写候选层。
- 候选状态：`pending_confirmation | confirmed | rejected | conflict | stale`。
- 人工采用后才生成正式事实版本；任何旧“低风险自动发布事实”规则被本节覆盖。
- 系统生成内容可成为可复用内容资产，但其中硬事实不得反向覆盖事实表。

### 17.3 检索输出

检索服务必须返回 item_id、version、type、confirmation_status、source_location、validity、permission、score 和不可用原因。生成只消费 `confirmed/formal/usable_for_generation`；冲突、过期、无权限和待确认项只能进入缺口或候选上下文。

### 17.4 外部情报与 Skill

`collect-external-intelligence` 负责公开来源发现、核验、去重和标准化；`defuddle`/`summarize` 作为正文提取与长文摘要能力。输出遵循外部情报 Schema，默认 `pending_confirmation`，保留 canonical URL、时间、地区、证据级别和冲突。

### 17.5 质量与验收

1. 手填确认事实不会被模型候选覆盖。
2. 同一硬事实冲突时两者隔离并进入人工处理。
3. 价格/规格未命中正确留空率为 100%。
4. 每个生成产物可追溯知识版本与具体引用位置。
5. 删除、过期、权限撤销后，新任务不可召回，历史任务仍可解释当时输入快照。
6. 多租户、多 Agent、素材与事实检索均有权限回归测试。
