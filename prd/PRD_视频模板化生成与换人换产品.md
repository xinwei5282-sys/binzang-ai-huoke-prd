## 1. 文档概述

### 1.1 产品背景

营销短视频若用**纯 AI 从头生成整条**（如全程文生视频），成本高、不可控、效果不稳。老板定调的成本解法是：**先做几个模板，每个模板规定"分几段、每段用哪种相应的 AI 去生成"，系统按模板自动逐段生成并拼成片**——把最贵的生成方式（文生视频）只用在刀刃上，能用便宜方式（数字人口播 / 图生视频 / 字幕套壳）或零成本（套模板）的地方就不用贵的。

模板分两类（**两种都要，模板自己区分**）：
- **纯 AI 模板**：客户没素材时，整条由 AI 分段生成。
- **挂素材模板**：客户有产品图/实拍时，用 i2v 让素材动起来 + AI 补口播/过场，更省更真实。

> 🔧 **换产品的现实（据调研，定功能优先级）**：真正"保场景只换那个产品、其余画面不动"的成熟 API **国内基本空白**（可灵 O1 刚起步需打样、阿里 VACE 限 ≤5 秒）。因此「换产品」**以 i2v 为成熟主线**（产品图当首帧生成动态展示，各厂全开放、~0.6–1 元/秒），"保场景真换物"作为**前沿/后续能力**，待可灵 O1 等成熟再上。换人则相反——数字人口播/换主角国内已成熟，直接可用。

本模块要解决的核心问题：**把"视频结构 + 每段的 AI 生成方式 + 素材依赖"固化成可选模板，系统按模板自动调用相应 AI（含客户素材 i2v）逐段生成并拼装成片，且支持换人/换产品的批量再生产，成本由模板配方控制。**

> 本期不做：精剪时间线编辑器、逐帧特效/调色、BGM 版权库自管、纯 AI 全程文生视频整片（明确排除——太贵）。

### 1.2 产品目标

- **模板库**：几套可选模板，每套 = 分段结构 + 每段生成方式 + 素材依赖类型（纯AI/挂素材/混合）
- **按模板自动生成**：系统按模板逐段调用相应 AI（数字人口播 / i2v 图生视频 / 文生视频 / 字幕套壳 / 客户素材槽）→ 拼成片
- **成本由模板控**：贵的生成方式（文生视频）占比由模板固定且默认最小化
- **换人换产品**：替换模板的形象槽 / 产品素材槽 → 批量再生产系列视频
- **两类模板并存**：纯 AI 模板（无素材）+ 挂素材模板（有素材 i2v），按客户素材情况自动/手动选

### 1.3 核心指标

| 指标 | 目标值 |
|--|--|
| 按模板自动成片成功率 | ≥ 95% |
| 文生视频（最贵段）占比 | 模板可配，默认 ≤ 1 段 / 趋零 |
| 单条短视频成本 vs 纯 AI 全程生成 | 下降 ≥ 50% |
| 换人/换产品批量成片成功率 | ≥ 90% |
| 成片用量/成本计入准确 | 100% |

### 1.4 范围

**In-Scope（本期，2026-06-28 收敛为单条主流程）**
- 模板库（三类定稿模板，见 §4.1；每模板定义分段+每段生成方式+素材依赖+**约束提示词**）
- 模板化生成引擎：按模板逐段调用相应 AI（数字人/ i2v / 文生视频 / 字幕套壳 / 客户素材）→ 拼装
- **出片确认门**：出视频默认关；开启则贵且不可逆步骤前置人工确认（见 §4.5）
- 成片用量/成本计量（按段生成方式分别计）

**Out-of-Scope（不做 / 后续）**
- **换人换产品「批量再生产」（2026-06-28 暂缓）**：本期先把单条主流程跑通，批量/自动化后置（见 §4.4）
- 纯 AI 全程文生视频整片（明确排除）
- 客户端编辑系统工作流或合规基线（租户只能编辑品牌微调层并在护栏内调参）
- 精剪时间线、逐帧特效
- BGM 版权库自管（先免费/客户自备）
- 实时预览渲染（先异步出片）

## 2. 用户与场景

### 2.1 目标用户
- **运营**：选模板、填素材/文案、批量出片主力。
- **老板/大 B**：定调风格、提供数字人形象；分销场景把模板下放给小 B。
- **下游小 B（分销场景）**：换自己产品复用大 B 模板。

### 2.2 典型场景（2026-06-28 更新：模板名对齐三类定稿）

3. 客户没素材 → 选「**③ Seedance 生成视频（纯 AI）**」→ 数字人开场（可选）+ Seedance 文生视频 + 字幕 → 自动成片。
4. 大 B 把模板授权小 B → 小 B 换自己形象/产品出片（合规预审强制内置，见 Index §十七）。

### 2.3 用户故事
- 作为运营，我选个模板、传张产品图，系统就自动出一条像样的短视频，不用懂剪辑也不用懂 AI。
- 作为老板，每个模板用哪种 AI、贵不贵，是定死的，我成本心里有数。
- 作为运营，换个产品就批量复制一组视频。

## 3. 整体方案

### 3.1 方案原则
- **模板即成本配方**：模板规定每段用哪种 AI，贵的（文生视频）默认最小化，能套壳/零成本优先。
- **两类模板**：纯 AI（无素材）+ 挂素材（i2v 让客户素材动），按素材情况选。
- **自动逐段生成再拼装**：不是人工剪，是系统按模板调相应 AI 自动生成各段再拼。
- **Provider 隔离**：各类生成能力（数字人/ i2v / 文生视频，候选见 v0.3 选型表）走适配层，便于切换比价降本。

### 3.2 模块结构

### 3.3 设计约束（功能限制）
1. **禁纯 AI 全程整片**：不提供"整条文生视频"入口；文生视频只作模板内某一段，且默认 ≤ 1 段。
2. **模板定义每段生成方式**：模板的每个段位绑定一种生成器（数字人/ i2v / 文生视频 / 字幕套壳 / 客户素材槽），成本可预估。
3. **素材依赖分类**：模板标 `纯AI / 挂素材 / 混合`；挂素材模板生成前需绑定对应素材槽。
4. **客户素材走 i2v**：挂素材模板用图生视频让产品图/实拍动起来，不自爬第三方素材（合规红线 Index §十二）。
5. **数字人口播限段**：口播作为模板内的开场/穿插短段，复用 [[PRD_数字人]]，不全程口播。
6. **Provider 适配**：生成能力统一经 Provider 接口、落库缓存任务、可切换比价；候选见头部 v0.3 选型表（演示=商业 API，1.0=自部署开源）。
7. ~~**换人换产品 = 槽位替换**：模板定义形象槽/产品素材槽/文案槽，批量任务=对槽位做列表替换。~~【2026-06-28 暂缓·后置，见 §4.4】
8. **合规预审不可关**（分销下放小 B 时）：输出过合规预审（Index §十七 铁律 1）。
9. **成本计量**：按段的生成方式分别计入 usage_record（文生视频段 vs i2v 段 vs 数字人段单价不同）。
10. **模板自带「约束提示词」（2026-06-28 新增）**：每模板内置一套锁定约束——**镜头/质感/口型、人物形象、场景服装、动作、台词、语气**。换数字人/换产品时**只替换"人物形象"与"产品+台词"两项，其余全部锁定不变**，保证同模板出片风格一致。② 数字人+混剪模板的约束 = **硅基大司马同款五段结构**（震撼数字钩子 → 痛点 → 黑科技/卖点 → 价值升华 → 自报家门转化）+ **质量红线**（禁文案整段重复、加 AI 标识、不自爬素材）。
11. **提示词分层**：模板结构、生成工作流和合规基线由平台维护；租户可编辑品牌语气、卖点和额外禁忌，生成参数在护栏内调整。
12. **出片确认门（2026-06-28 新增）**：出视频默认关闭；开启后，贵且不可逆的烧钱步骤前置人工确认门（见 §4.5）。

## 4. 功能需求

### 4.1 模板库（2026-06-28 三类模板定稿）

替换旧的"产品种草 / 场景叙事 / 对比测评"，定稿三类模板：

| # | 模板 | 素材依赖 | 分段结构 | 备注 |
|--|--|:--:|--|--|
| ① | **产品讲解（换数字人+产品）** | 挂素材 | 数字人讲解 + 产品图 i2v + 字幕 | 换人/换产品主路径 |
| ② | **数字人+混剪** | 挂素材 | 数字人口播 + 素材切片混剪 + 字幕 | 【硅基大司马同款五段结构】 |
| ③ | **AI 生成视频** | 纯 AI | 数字人开场（可选）+ **文生图(阿里云)→确认→i2v** + 字幕 | 🆕 v0.7 主路径改图→i2v（画面可控、试错在图片层）；Seedance 直出文生视频降为后台兜底 |

- 模板结构：`段序列`，每段含 → 段类型(口播/产品展示/混剪片段/场景/字幕/CTA) · **生成方式**(数字人 / i2v / 文生视频(Seedance) / 套壳 / 客户素材切片) · 时长 · 是否需素材槽。
- **每模板自带「约束提示词」**：锁定镜头/质感/口型、人物形象、场景服装、动作、台词、语气；换数字人/换产品时只替换"人物形象"和"产品+台词"，其余锁定不变（见 §3.3-10）。② 模板约束 = 硅基同款五段结构 + 质量红线。
- 操作：客户端只**浏览/预览（含案例视频）/选用**；模板新增/编辑、约束与生成提示词维护**全部在后台运营侧**，**不设客户端模板管理/提示词编辑页**（对齐 Index §二十.2「模板=平台内置、商家选用」）。

### 4.2 模板化生成引擎
- 输入：选定模板 + 文案/脚本（取 [[PRD_内容创作]]）+（挂素材模板时）客户素材槽绑定。
- 处理：按模板段序列，**逐段调用相应 AI 生成器**——口播段→数字人；产品展示段→i2v(客户素材) ；场景段→文生视频(默认≤1段)；字幕/CTA→套壳(零成本) → 各段产物拼装成片。
- 输出：成片（异步）→ 预览 → 存作品库 → 按段计费。

### 4.5 出片确认门（2026-06-28 新增 ｜ 🆕 2026-07-05 升级为两级：脚本确认 → 分镜图确认）

> 把贵且不可逆的烧钱步骤前置人工确认门，避免自动直跑烧钱出废片（Index §二十.5）。
> 🆕 **两级的道理（成本结构）**：视频段才是成本大头（i2v 0.6–1 元/秒、文生视频约 1 元/秒），而**图片便宜一个量级**（素材库召回零成本、阿里云文生图约几毛/张）。换产品主线本来就是 i2v（产品图当首帧）——首帧图本来就存在，只是原设计没暴露给用户确认。把首帧图先生成出来给人看一眼，废片风险在图片层就拦掉。

- **默认关闭**：内容创作里「出视频」开关默认关；只跑到脚本/拆解层，不烧视频生成成本。
- **开启后的链路（两级门）**：`拆解 → 仿写（填知识库事实） → 脚本 + 合规预审 →【确认门1·确认脚本】→ 按分镜生成首帧图（便宜）→【确认门2·确认分镜图】→ 人工确认后才烧钱逐段生成视频 → 拼装`。
- **确认门1（文字层）可见**：脚本、合规预审结果、预估成本（按段生成方式 est_cost 汇总 + 分镜图生成成本），人工核对后确认。
- **🆕 确认门2（画面层）可见**：每个分镜一张卡 = `序号 · 口播文字 · 首帧图 · 图来源标记`，可**换图**（素材库召回 / 本地上传，上传默认入素材库）、**重生成**（阿里云文生图）；全部认可后点「确认分镜图，开始出片」。
- **🆕 各段首帧图来源**：

| 段类型 | 首帧图来源 | 成本 | 确认门2 行为 |

### 4.6 视频时长设置与分配（2026-06-30 新增）

> 出片必须设**目标时长**——时长直接决定成本（文生视频段按秒、数字人按分钟、i2v 按秒），不设会失控。

**4.6.1 商家端设置（内容创作·出视频配置）**
- 选模板后出现「视频时长」选择：**15 秒 / 30 秒 / 60 秒 / 跟模板（长混剪）**（必选）。
- 每个选择实时提示：口播字数估算（语速≈5 字/秒）+ 文生段控量说明 + 预估成本档（低/中/偏高/最高）。

**4.6.2 模板定义时长范围（后台维护）**
- 每模板带 `default_duration` + `duration_range(min,max)`：产品讲解短（~10–30s）/ 数字人混剪可长（~15s–3min，硅基同款）/ AI 生成视频短（~15–30s）。
- 超模板 range 的时长**拦截或提示**（文生视频段尤其有硬上限，模板控量）。

**4.6.3 时长分配到段（引擎）**
- 目标总时长按模板**各段时长权重/上限**分配：
  - 口播段时长 ← 口播稿字数（语速换算）；**反向约束**：仿写时按可用口播时长控字数，避免稿子塞不进时长。
  - 文生视频段（最贵）= 模板硬上限封顶，不随总时长线性放大（防成本炸）。
  - i2v 产品段 = 按分配秒数；字幕/CTA 段 = 固定短时。
- 分配结果写入 `gen_job.duration_plan`，**出片确认门展示「时长×各段成本」预估**，人工确认后才烧钱。

**4.6.4 时长↔成本联动**：总时长变化 → `est_cost` 重算（按段单价×秒/分钟）→ 确认门同步更新。超配额/超预算给提示。

### 4.7 混剪「按模板生成」的保证机制（2026-06-30 新增）

> 核心认知：**模板不是给 AI 的"建议"，是引擎执行的"确定性骨架"。结构由引擎保证，不靠 AI 自觉。**

**4.7.1 结构 vs 内容 分层保证**
| 层 | 谁决定 | 怎么保证遵守 |
|--|--|--|
| **结构**（几段·顺序·各段时长） | 模板**写死** | 引擎按段序列逐段生成 + **确定性拼装**（Revideo/FFmpeg 固定顺序）→ 100% 遵守，AI 无权改 |
| **内容**（每段说什么·用哪个画面） | AI 在**该段约束内**填 | 约束提示词 + 分镜需求（软约束） |
- 数字人混剪模板的结构 = **硅基同款五段**（震撼数字钩子 → 痛点 → 黑科技/卖点 → 价值升华 → 自报家门转化），是固定骨架；AI 只在每段格子里填内容、碰不到"几段、什么顺序"。

**4.7.2 混剪段素材召回（"切到对的素材"的保证 · 对齐 §9.3 🔴）**
```
仿写脚本(按五段结构) → 每段产出 口播文案 + 分镜需求(这段要什么画面)
  → 素材库多路召回(product_id 精确 + 标签 + 画面向量)
  → 打分(产品匹配/画面贴合/时长/授权) + 阈值
  → 够格用素材库片段(按段时长上限裁切) / 勉强转 i2v / 都没有转文生视频并提示补素材
```
- **阈值是关键**：召回分低于线**不硬塞**——留空/降级，保证"贴该段需求"而非乱拼相干画面。
- 🆕 **2026-06-30 归属定清 + 规则已落**：**召回 + 打分引擎归 [[PRD_多模态知识库底座]] §14**（多路召回 + 四维打分公式 + 阈值），本模块**只持有决策树**——据 `match_result.score` 决策:`≥T_use 用素材片段 / 中间档产品段转 i2v / <T_i2v 或无候选转文生视频`,低分不硬塞。两份 PRD 契约 = `shot_spec`(本模块出)↔ `match_result`(底座出)。原"两不管"已解。

**4.7.3 段结构后校验（兜底闸，类比硬事实后校验）**
拼装前/成片后校验，不合规则标红/重生成对应段、不直接出片（接 §4.5 出片确认门）：
- 段数 = 模板规定？各段时长在分配范围内？
- 口播稿是否覆盖五段要点（钩子/痛点/卖点/升华/转化）？
- 质量红线：文案有无整段重复？AI 生成标识是否加？仅授权形象？素材是否自爬（红线）？

**4.7.4 约束提示词锁风格**：模板自带约束锁定镜头/质感/口型/人物/场景/动作/语气；换数字人/换产品**只替换"人物形象"与"产品+台词"，其余锁定不变**，保证同模板出片风格一致。

> 一句话：**结构靠"模板=确定性编排 + 段结构后校验"保证（稳、可建）；素材贴合靠"分镜召回 + 打分阈值"保证（§9.3 🔴 待建待验）。**

## 8. 技术考虑
- **段生成器编排**：模板段序列 → 调度器逐段调相应 Provider 生成 → 拼装（转场/字幕/BGM 由模板套壳）。演示版用 Revideo(MIT)/FFmpeg 拼装。
- **Provider 适配层**：数字人 / i2v / 文生视频统一抽象、落库缓存、可切换比价（Index §十三 Provider 隔离原则）。候选见头部 v0.3 选型表，签约前核对。
- **成本两段路线**：**演示版全用商业 API 求稳**（阿里百炼一套 Key 打通 s2v+i2v，无白名单、可开票）；**1.0 自部署开源降本**（视频 Wan2.2-Apache、数字人 MuseTalk-MIT/EchoMimicV3-Apache、拼装 Revideo-MIT），高频低要求量产走自部署、少量旗舰走商业 API。
- **开源 License 护栏**：自部署选型须避雷——视频模型选 Apache 无地域/MAU 限制的（Wan2.2），避开 HunyuanVideo(EU禁)/LTX(ARR红线)；数字人避开 Wav2Lip/Sonic(非商用)、HeyGem(月活>1000需授权)；TTS 避开 ChatTTS/Edge-TTS。详见 [[AI 获客产品方案 Index]] §十八及调研笔记。
- **挂素材模板**：客户素材取自 [[PRD_多模态知识库底座]] 素材库（按素材槽匹配）。
- **成本核算**：各段生成方式单价不同，按段写 usage_record + mapped_cost，支撑 SaaS 定价（会议待办：成本核算）。
- **异步与批量**：走后台任务 + 通知；批量任务做并发与成本闸（超阈值二次确认）。
- **合规**：成片文案过合规预审 + **加 AI 生成合成内容标识**；只用授权形象、不任意换脸；素材不自爬；供应商须算法备案。

## 10. 验收标准（2026-06-28 更新）
1. 模板库含**三类定稿模板**（①产品讲解 ②数字人+混剪 ③Seedance 生成），每模板可见分段结构+每段生成方式+素材依赖+**约束提示词**+预估成本，并含案例视频预览。
2. 选模板（挂素材时绑定素材）后，系统按模板逐段调相应 AI 自动生成并拼装成片；**纯 AI 全程整片入口不存在**。
3. 文生视频(Seedance)段占比受模板约束，默认 ≤1 段，能用 i2v/数字人/混剪/套壳替代处不用文生视频。
4. 挂素材模板能用客户产品图经 i2v 生成动态产品展示段；模板②能按分镜从素材库召回片段做混剪段。
5. **提示词分层治理**：客户端不能编辑系统工作流和合规基线，但可维护租户品牌微调层并在护栏内调参。
6. **出片确认门（🆕 两级）**：出视频默认关；开启则跑到「脚本+合规预审」后停在「待确认脚本」（门1），确认后按分镜生成首帧图并停在「待确认分镜图」（门2）——**门2 确认前不产生任何视频生成成本**；门2 每个分镜可换图（素材库/本地上传）/重生成（阿里云文生图）；两道门均可见预估成本。
7. **换人/换产品「批量再生产」本期不交付（暂缓·后置）**，单条主流程跑通即达标。
8. 各段按生成方式分别计入用量与成本，准确率 100%；单条成本较纯 AI 全程生成下降 ≥ 50%。
9. 分销下放场景，输出强制过合规预审，无关闭开关。
10. 换人仅可选授权数字人/本人形象，无任意换脸入口；成片自动带 AI 生成合成内容标识。
11. 换产品默认 i2v 路径可用；"保场景真换物"未打样通过前不开放、不对客户承诺。
12. **出片必须设目标时长**（15/30/60/跟模板），系统按模板把时长分配到各段；时长变化时预估成本同步重算并在确认门展示；文生视频段不随总时长线性放大（控量封顶）。
13. **混剪按模板生成可验证**：段数/顺序/各段时长 100% 遵循模板（引擎确定性拼装）；段结构后校验能拦"段数不符/缺要点/质量红线"并触发重生成；素材召回低于阈值时降级而非乱拼（§9.3 🔴 项随召回判定落地一并验收）。

#### 11.A.1 换主角（保场景换出镜人 · 多模态视觉类）

**① 能力定义与边界**：在保留原场景的前提下替换出镜人；位于模板段生成器（§4.3 "保场景换主角"行）。成功标准 = 换人/换产品批量成片成功率 ≥ 90%（§1.3）。约束 = 🔴 只换**已授权数字人/本人**形象。能做 = 授权形象的场景内换人；**不能做（不确定性）**：任意换脸（红线）、效果不稳时硬上（降级数字人口播段）。
**② 输入/输出规范**：入 = 基准视频 + 目标授权形象；出 = `video_provider_task`(result_url+cost)。边界 = 仅授权形象列表可选；错误 = 失败降级为数字人口播段（§11 表第 2 行）。
**③ AI 技术需求**：模型选型见 **§11 表第 2 行**（阿里 `wan2.2-animate-mix`）。数据需求 = 基准视频 + 授权形象资产（来自 [[PRD_数字人]]）+ 留存肖像声音授权；无需自训练。Prompt/参数 = 模板约束提示词（镜头/质感/动作锁定，只换"人物形象"），**后台维护、客户端不可编辑**（§3.3-10/11）。性能 = 按成功秒数，时延**目标待压测**。多模态精度变体 = 输出分辨率/帧率随模板，口型与肢体连贯性为质量重点（**目标待压测**）。
**④ 评估标准**：系统层 = Provider 任务成功率/时延；模块层 = 换人后画面连贯/无明显瑕疵可用率（**目标待压测**）；业务层 = 批量成片成功率 ≥ 90%、按段成本计入 100%。Golden Dataset = 基准视频+目标形象配对样本集（**待建**）。Pass/Fail = 场景保留且换人自然 = Pass；穿帮/换非授权形象 = Fail。BadCase 闭环 = 穿帮/形变 → 收集 → 归因（基准视频质量/形象匹配）→ 调参或降级。
**⑤ 灰度上线**：灰度 = 先单条、批量后置（§4.4 暂缓）。监控 = 成功率/时延/按段成本。回滚 = 降级数字人口播段；Provider 隔离可切换比价。
**⑥ 风险与缓解**：合规 = 🔴 禁任意换脸、仅授权形象、留存授权、成片加 AI 标识、供应商须算法备案（§11 红线）。成本 = 按段计量 + Provider 比价。质量 = 效果差不入库。

#### 11.A.2 产品 i2v（换产品主线 · 多模态视觉类）

**① 能力定义与边界**：把客户产品图当首帧生成动态产品展示段（"换产品"现实主路径）；位于模板段生成器（§4.3 产品展示行）。成功标准 = 自动成片成功率 ≥ 95%。约束 = 客户素材走 i2v，不自爬第三方素材（§3.3-4）。能做 = 产品图→动态展示。**不能做（不确定性）**：保场景"真换物"（见 11.A.4，前沿/后续）。
**② 输入/输出规范**：入 = 客户产品素材槽（来自 [[PRD_多模态知识库底座]] 按 `product_id` 召回）+ 模板约束；出 = `video_provider_task`(result_url+cost) → 拼装段。边界 = 挂素材模板生成前需绑定素材槽。错误 = 失败重试 / 经 Provider 层切换厂商。
**③ AI 技术需求**：模型选型见 **§11 表第 3 行**（演示 阿里 `wan2.6-i2v`/可灵；1.0 自部署 Wan2.2-Apache）。数据需求 = 客户授权产品图/实拍（素材库供给），无需自训练。Prompt/参数 = 运镜/动效约束提示词后台维护、客户端不可编辑。性能 = i2v 720P 0.6 / 1080P 1 元/秒（§11 表，**签前核实**），时延**目标待压测**。多模态精度变体 = 输入产品图分辨率/构图建议、输出分辨率（720P/1080P）随档。
**④ 评估标准**：系统层 = 成功率/时延；模块层 = 产品展示动态自然度/不变形可用率（**目标待压测**）；业务层 = 单条成本较纯 AI 全程生成降 ≥ 50%（§1.3）。Golden Dataset = 各品类产品图样本集（**待建**）。Pass/Fail = 产品形态保真且动效自然 = Pass；产品变形/logo 错乱 = Fail。BadCase 闭环 = 变形/抖动 → 收集 → 归因（首帧质量/参数）→ 调参或换厂。
**⑤ 灰度上线**：灰度 = 主线优先放量。监控 = 成功率/时延/按段成本。回滚 = 阿里↔可灵↔自部署 Wan2.2 经 Provider 层切换。
**⑥ 风险与缓解**：版权 = 仅用素材库/客户自备，不自爬（§3.3-4）。成本 = 按秒计量 + 比价。合规 = 成片加 AI 标识、供应商算法备案。

#### 11.A.3 Seedance 文生视频段（纯 AI 场景段 · 多模态视觉类）

**① 能力定义与边界**：模板③纯 AI 场景/氛围段的文生视频（最贵段）；位于段生成器（§4.3 场景/氛围行）。成功标准 = 文生视频段默认 ≤1 段（§1.3/§3.3-1）。约束 = 🚫 禁纯 AI 全程整片，文生只作模板内某段。能做 = 无素材时的场景段生成。**不能做（不确定性）**：整条文生视频（明确排除，太贵）。
**② 输入/输出规范**：入 = 场景文案/提示 + 模板约束；出 = `video_provider_task`(result_url+cost)。边界 = 模板默认 ≤1 段；错误 = 能用 i2v/混剪/套壳替代处不用文生（降级）。
**③ AI 技术需求**：模型选型见 **§11 表第 4 行**（火山方舟 `doubao-seedance-*`/阿里 i2v；1.0 自部署 Wan2.2）。数据需求 = 仅提示词，无素材、无自训练。Prompt/参数 = 场景生成提示词后台维护、客户端不可编辑。性能 = Seedance 1080P 约 1 元/秒、fast 档更低（§11 表，**签前核实**），时延**目标待压测**。多模态精度变体 = 输出分辨率/时长按模板控量。
**④ 评估标准**：系统层 = 成功率/时延；模块层 = 场景段画面可用率（**目标待压测**）；业务层 = 文生段占比 ≤1 段、成本可控。Golden Dataset = 典型场景提示样本集（**待建**）。Pass/Fail = 场景段可用且占比受控 = Pass；超量使用文生段 = Fail。BadCase 闭环 = 画面不可用 → 归因 → 改提示/降级 i2v。
**⑤ 灰度上线**：灰度 = 模板③专用、严格控量。监控 = 文生段调用量/占比/成本。回滚 = 能用 i2v/混剪/套壳替代处不用文生。
**⑥ 风险与缓解**：成本失控 = 模板默认 ≤1 段 + est_cost 预估 + 出片确认门（§4.5）。合规 = 成片加 AI 标识、供应商算法备案。

#### 11.A.4 保场景真换物（前沿 · 多模态视觉类 · 打样验证后才开放）

**① 能力定义与边界**：保留场景只替换画面中的产品（"真换物"）；**国内基本空白、效果不稳**（§4.3/§9.2）。成功标准 = 打样通过前**不开放、不对客户承诺**。约束 = 前沿能力，列后续。能做 = 打样阶段验证。**不能做（不确定性）**：包装文字/logo 还原、边缘稳定性未达标 → 不上生产。
**② 输入/输出规范**：入 = 基准视频 + 目标产品；出 = `video_provider_task`。边界 = 未打样通过不可在客户端选用；错误 = 降级走 i2v（11.A.2）。
**③ AI 技术需求**：模型选型见 **§11 表第 5 行**（可灵 Kling O1 / 阿里 VACE≤5s）。数据需求 = 打样素材集，无自训练。Prompt/参数 = 后台维护、客户端不可编辑。性能 = O1 约 $0.11–0.17/秒、VACE ≤5 秒（§11 表，**核实**），时延**目标待压测**。多模态精度变体 = 边缘稳定/文字还原为质量红线（**待打样验证**）。
**④ 评估标准**：以**打样验收**为准——Golden Dataset = 真换物打样样本集（**待建**）；Pass/Fail = 边缘稳定+文字/logo 还原达标才 Pass，否则 Fail（不开放）。BadCase 闭环 = 打样问题归档，成熟前持续观望。
**⑤ 灰度上线**：未打样通过 = 全程关闭、不灰度；打样通过后再小流量灰度。回滚 = 降级 i2v。
**⑥ 风险与缓解**：质量 = 国内空白效果不稳 → **不承诺**；合规 = 仅授权素材、加 AI 标识、供应商算法备案。

#### 11.A.5 模板拼装（Revideo/FFmpeg · 非生成模型 · 轻量）

> 非 AI 生成模型，仅做渲染拼装；按要求只写 I/O 契约 + 失败兜底。
- **I/O 契约**：入 = 各段产物（口播/i2v/文生/混剪/套壳片段）+ 模板转场/字幕/BGM 规范；出 = 拼装成片（→ `content_film` / 作品库 `work`）。
- **模型选型**：见 **§11 表第 9 行**（Revideo MIT / FFmpeg，自部署，0 成本）。
- **失败与兜底**：拼装失败 → 重试；段间生硬 → 模板定义转场规范 + 套壳统一风格，效果差模板不入库（§9.2）。备选 FFCreator/MoviePy。
- **合规**：成片统一**加 AI 生成合成内容标识**（拼装环节注入，§8）。

## 12. 通用企业视频生成专项需求（v3.1 · 2026-08-13）

### 12.1 模块位置与流程

当前分别通过“短视频创作”和“AI 视频”进入。标准链路为：目标与参考 → 企业事实召回 → 脚本 → 分镜 → 首帧/场景图 → 人工确认 → 分段生成/混剪 → 拼装 → 质检 → 内容资产。

### 12.2 两级成本确认门

1. 人工确认脚本，避免错误事实进入画面生产。
2. 人工确认分镜首帧/场景图后，才启动高成本视频生成。

任何脚本、产品、Logo、价格或场景修改均使下游确认失效；重新生成只影响依赖该版本的片段。

### 12.3 Skill 与任务契约

图片任务使用 `imagegen` 等价服务；视频生成、数字人、素材召回和 FFmpeg/Revideo 分别作为可替换 adapter。每段保存输入快照、模型/供应商版本、成本、授权素材、状态、失败原因和重试次数。

### 12.4 发布边界

本模块只生成和审核视频资产。发布时进入统一发布任务，选择抖音或小红书具体账号及 RPA/手动方式；不得在视频生成阶段默认发布。

### 12.5 验收

1. 未确认脚本不得生成分镜图；未确认分镜图不得生成视频。
2. 单段失败可重试且不重做已通过片段。
3. 未确认事实、未授权人脸/声音/产品素材不得进入成片。
4. 成片包含 AI 标识、素材授权链、内容版本和质检结果。

### 12.6 开发执行契约

- 核心对象：`video_project`、`script_version`、`storyboard_version`、`frame_asset`、`video_segment_task`、`render_task`。
- 所有生成接口携带 tenant_id、input_version、provider、budget_limit、idempotency_key；版本不匹配返回 `VERSION_STALE`。
- Skills 按脚本、分镜、首帧、素材召回、分段生成、拼装、质检拆开，单段失败不得重跑已成功段。
- Prompt 输出逐镜 `duration/voiceover/visual_prompt/product_refs/source_refs/risk_flags`；图片/视频 Prompt 禁止生成文字、水印和未确认业务数据。
- 埋点覆盖两级确认、预算预估、供应商失败、重试、降级和人工取消。
