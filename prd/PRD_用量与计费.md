## 1. 文档概述

### 1.1 产品背景

客户每一次"爆款抓取 / 参考转写 / 内容生成 / 数字人成片 / 生成形象"，背后都是我方的采购成本。商家端需要让客户**看得见自己用了多少、还剩多少**，同时**形象额度（每企业 2 个）是单独计费项**，超额要拦截并引导增购。但 V1 决策是**先计数、不扣费**——额度结构先建好、用量先累计，真正的扣减/账单留 V2，避免一上来计费逻辑过重拖慢上线。

本模块要解决的核心问题：**在商家端透明展示按月、按类型的用量与配额水位，对"形象"这类硬限额做拦截 + 增购引导**，并把每一笔用量记录下来（含映射成本，供后台对账），为 V2 转扣费打好地基。

> V1 不做：真实扣费/账单/发票、自动续费、用量预警短信、跨月结转。

### 1.2 产品目标

- 工作台顶部 + 用量页**展示本月各类型用量与配额水位**
- **形象额度硬限**：满额上传/生成形象时拦截 + 引导增购（¥199/个 示例）
- 每笔消耗写**用量记录**（类型/数量/关联对象/映射成本）
- 其余类型 V1 **只计数不扣减**，超额不阻断（预留扣费开关）

### 1.3 核心指标

| 指标 | 目标值 |
|--|--|
| 用量展示与实际消耗一致 | 100% |
| 形象超额拦截准确率 | 100%（不漏放、不误拦） |
| 用量记录可追溯到关联对象 | 100% |
| 增购引导转化（点增购→确认） | 可统计 |

### 1.4 范围

**In-Scope（本期）**
- 用量页（按月 × 类型累计、配额水位、增购记录）
- 工作台用量概览入口
- 形象额度展示 + 满额拦截 + 增购引导
- 用量记录写入（含映射成本，回流后台对账）

**Out-of-Scope（不做 / 后续）**
- 真实扣费 / 账单 / 发票 / 自动续费
- 其他类型超额阻断（V1 仅计数）
- 用量预警推送

## 2. 用户与场景

### 2.1 目标用户
- **老板（管理员）**：关注花了多少、要不要增购、值不值。
- **运营**：关注还能不能继续生成（额度够不够）。

### 2.2 典型场景
1. 运营连做内容 → 工作台顶部「本月用量」实时涨 → 用量页看到生成 168/300。
2. 老板想再克隆一个形象，已用 2/2 → 上传被拦 → 弹「形象额度已满，增购 ¥199/个」→ 老板确认增购 → 额度 +1 可继续。
3. 月底老板看用量页，了解各类型消耗结构。

### 2.3 用户故事
- 作为老板，我要清楚看到这个月用了多少、形象还剩几个，心里有数。
- 作为运营，额度不够时我要被明确拦住并知道怎么解决，而不是默默失败。
- 作为我方，我要每笔用量都留痕且能算出成本，月底对账不抓瞎。

## 3. 整体方案

### 3.1 方案原则
- **透明优先**：用量水位一眼可见，别让客户黑箱消耗。
- **硬限只设形象**：形象是单独计费的高成本项，必须拦；其余 V1 先放（计数）。
- **记录即资产**：每笔用量带映射成本，回流后台支撑对账与定价校验。

### 3.2 模块结构
```
用量与计费
├─ 工作台·本月用量概览（入口 + 顶部计数）
├─ 用量页（按月×类型水位条 + 增购记录）
└─ 形象额度（展示 + 满额拦截 + 增购弹窗）   ← 与数字人模块联动
```

### 3.3 设计约束（功能限制）
1. **V1 只计数不扣费**：除形象外，超额不阻断；保留 `enforce` 开关供 V2 开启。
2. **形象硬限**：每企业默认 2 个生成形象（克隆/定制占额，公模不占）；满额拦截。
3. **增购即时生效**：确认增购后额度立即 +1（V1 记录增购、不走真实支付）。
4. **用量按 公司×月×类型 聚合**；记录保留映射成本字段。
5. **配额来源**：读开通时套餐快照 `quota`（见 [[PRD_后台_套餐配置]]）。

## 4. 功能需求

### 4.1 用量页
**水位区**：5 类各一条进度条
| 类型 | 展示 |
|--|--|
| 爆款抓取 | 已用/配额（不限则显示"不限·已用 N"） |
| 参考转写 | 已用/配额 |
| 内容生成 | 已用/配额 |
| 数字人成片(分钟) | 已用/配额，近满标黄 |
| 生成形象(个) | 已用/配额，满标红 |

**增购记录表**：项目 · 数量 · 金额 · 状态 · 时间

### 4.2 工作台用量概览
顶部 chip「本月用量 N 次」；卡片展示本月各类型小计；点击进用量页。

### 4.3 形象额度拦截 + 增购（与数字人联动）
- 数字人页上传/生成形象前校验 `形象.used < limit`。
- 未满 → 放行（占额）。
- 已满 → 拦截，弹增购：「形象额度已满（2/2），增购 ¥199/个」→ 确认 → `limit+1`、写增购记录、放行。
- 公模选用不校验、不占额。

### 4.4 用量记录写入（贯穿各功能模块）
任一消耗动作（抓取/转写/生成/成片/形象）完成 → 写一条 `usage_record`：类型、数量、关联对象、操作人、映射成本（按后台成本单价×量）、月份键。

## 5. 状态流转（形象额度）
```
used < limit ──消耗──▶ used+1 ──...──▶ used = limit (满)
   ▲                                      │
   └────── 增购 limit+1（满→未满）──────────┘
其他类型：used 累加，V1 不设满态（enforce=false）
```

## 6. 数据对象

> 复用 [[PRD_后台_套餐配置]] 的 `quota` / `addon` / `cost_unit`。本模块定义 `usage_record`。

### 6.1 `quota`（行级表）→ **单一真相见 [[PRD索引]] §四.1**
- 字段:`quota_id · company_id · type(5类) · limit(-1=不限) · used · period · source · enforce(V1 仅形象=true) · cap_estimate`。
- 本模块为 `quota` 的**读写消费方**:used 累加、limit 校验、增购改 limit;开通时由账号开通模块实例化 quota 行。

### 6.2 `usage_record`（用量明细，**回流后台对账**）
| 字段 | 类型 | 说明 |
|--|--|--|
| id | str(PK) | |
| company_id | ref | 租户 |
| type | enum | 爆款/转写/生成/成片/形象 |
| qty | number | 数量（次/分钟/条/个） |
| ref_object | ref | 关联草稿/作品/工单/形象 |
| operator | ref | 操作人 |
| mapped_cost | money | 映射成本=后台单价×qty |
| supplier | ref | 供应商 |
| period | str | 月份键 |
| created_at | dt | |

### 6.3 `addon_purchase`（增购记录）
company_id · addon(ref) · qty · amount · status(已确认) · created_at

## 7. 接口草案
| 接口 | 方法 | 入参 | 出参 |
|--|--|--|--|
| 用量汇总 | GET /usage/summary | period | 按类型 {used, limit} + 增购记录 |
| 校验额度 | GET /usage/check | type | {ok, used, limit} |
| 写用量 | POST /usage（内部） | type, qty, ref_object | ok（含 mapped_cost） |
| 增购 | POST /usage/addon | addon, qty | 新 limit + 记录 |

## 8. 技术考虑
- 用量写入与业务动作在同一事务/可靠队列，避免漏计或重复计。
- 映射成本在写入时按当时成本单价快照，便于对账与历史还原。
- 形象额度校验需并发安全（防同时上传两个绕过限额）。
- `enforce` 开关集中配置，V2 开启其他类型扣减时无需改业务代码。

## 9. 风险与依赖

### 9.1 依赖
- 套餐配置（B2）提供配额快照与成本单价。
- 数字人模块（A4）调用形象额度校验。
- 各功能模块（爆款/转写/生成/成片）在动作完成处调用写用量。

### 9.2 风险
| 风险 | 应对 |
|--|--|
| 用量漏计/重复计致对账失真 | 事务/幂等键保证一次一记 |
| 形象并发绕过限额 | 校验加锁/原子扣减 |
| V1 不扣费客户超用拉高成本 | 形象硬限兜住最贵项；其余监控 + V2 转扣费 |

## 10. 验收标准
1. 用量页按月展示 5 类用量与配额水位，与实际消耗一致。
2. 形象用满 2/2 后再生成被拦截并弹增购；确认增购后额度 +1 可继续；公模不占额。
3. 每笔消耗产生一条 usage_record，含关联对象与映射成本，可在后台读到。
4. 除形象外类型 V1 超额不阻断（enforce=false）。
5. 增购记录正确展示且额度即时生效。

## 11. 当前通用产品开发基线（v3.0 · 2026-08-12）

### 11.1 计量维度

按租户、能力、任务和供应商记录：LLM token/调用、网页采集页数、文档解析页数、图片生成张数、视频生成秒数、数字人成片分钟数、存储、官方发布调用、RPA 执行时长与重试。前端可聚合显示，但原始 `usage_record` 不可丢失。

### 11.2 计费规则

- 套餐额度、增购和第三方费用分开显示。
- 只有 `succeeded` 或供应商已实际计费的任务计入可计费用量；失败重试根据供应商真实账单处理。
- 每条记录带幂等键、业务对象、供应商账单引用和成本快照。
- 超额策略按能力配置为提醒、阻断或允许后付费，不能全局写死。

### 11.3 数据与验收

`usage_record` 至少包含 tenant_id、capability、quantity、unit、business_object_id、skill_run_id、provider、provider_cost、billable、idempotency_key、occurred_at。

1. 相同幂等键不重复计量。
2. RPA 一次失败一次重试可区分执行成本与最终发布结果。
3. 页面汇总可追溯到原始记录。
4. 第三方费用和平台服务费不混为一项。
5. 租户不能查看其他租户的用量和成本。
