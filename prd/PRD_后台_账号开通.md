## 1. 文档概述

### 1.1 产品背景

商家端是客户自助 SaaS，但产品形态明确**「我方后台开通，无自助注册」**。这意味着每一个殡葬商家要用上系统，都必须先由我方运营在后台**开一个公司账号 + 一个管理员账号**，并把登录凭证下发给客户。没有这一步，商家端就是一道进不去的门。

本模块要解决的核心问题：**让运营在一个表单内，可靠地把一家成交客户变成一个可登录、带正确套餐与配额、有管理员账号的租户**，并能对租户做停用/启用/续期等生命周期管理。这是整个 SaaS 的开闸阀门，也是后台最高频的操作。

> V1 不做：客户自助注册、自助计费下单、多行业切换、租户内成员的逐个开通（成员由客户管理员自助加，见配对 PRD）。

### 1.2 产品目标

- 运营**一个弹窗内完成开通**：公司 + 套餐 + 管理员账号 + 凭证下发
- 开通即**初始化该租户的套餐配额快照**（供计费模块消费）
- 租户**生命周期可管**：待开通 / 已开通 / 已停用 / 已到期
- 开通、停用等敏感操作**全部留审计**
- 行业**固定殡葬**，不给运营选错的机会

### 1.3 核心指标

| 指标 | 目标值 |
|--|--|
| 单次开通操作时长 | < 2 分钟 |
| 开通后客户首次登录成功率 | 100%（凭证有效） |
| 误开通/重复开通率 | 0（账号唯一性校验拦截） |
| 敏感操作审计覆盖 | 100% |

### 1.4 范围

**In-Scope（本期）**
- 租户列表（筛选/搜索/状态总览）
- 开通新公司（建公司 + 选套餐 + 建管理员 + 生成初始密码 + 下发）
- 租户停用 / 启用 / 续期
- 行业固定殡葬
- 开通时初始化配额快照（写入计费模块）

**Out-of-Scope（不做 / 后续）**
- 租户详情全景页（精简版砍掉，留 V2）
- 跨租户成员管理页（精简版砍掉）
- 自助注册 / 自助计费
- 子账号 / 分销开通

## 2. 用户与场景

### 2.1 目标用户
- **运营**（阿May 等）：成交后开通客户，日常处理停用/续期。主操作人。
- **超级管理员**（蔚然）：全权，含改套餐、审计查看。

### 2.2 典型场景
1. 销售成交一家「松鹤堂礼仪」→ 运营在后台点「开通新公司」→ 填公司名、选标准版、填管理员手机 → 生成初始密码 → 系统建账号、下发凭证 → 客户当天登录。
2. 客户「归园殡仪」到期未续 → 列表显示「已到期」、商家端登录被拦 → 客户续费后运营点「续期」→ 恢复。
3. 客户违约/退订 → 运营「停用」→ 商家端登录被拦、数据保留。

### 2.3 用户故事
- 作为运营，我要在一个表单里把客户开通好并拿到可下发的账号密码，这样我不用在多个系统间来回切。
- 作为运营，我要在开通时只能选殡葬行业、且账号不能和已有的重复，这样我不会开错。
- 作为超管，我要每一次开通/停用都有人、有时间、有对象的留痕，这样出问题能追溯。

## 3. 整体方案

### 3.1 方案原则
- **开闸即闭环**：开通一步到位产出「可登录账号 + 配额快照 + 审计记录」，不留半成品。
- **行业写死**：殡葬固定，表单中只读展示，杜绝选错。
- **单一真相**：租户状态由后台驱动，商家端登录鉴权读此状态（见 [[产品设计-殡葬V1-平台后台]] §八）。

### 3.2 模块结构
```
账号开通
├─ 租户列表（筛选 状态/套餐 + 搜索 + 总览计数）
├─ 开通新公司（弹窗：公司 → 套餐 → 管理员 → 初始密码 → 下发）
└─ 行操作（停用 / 启用 / 续期）
```

### 3.3 设计约束（功能限制）
1. **无自助注册**：租户只能由后台开通；商家端无注册入口。
2. **行业固定殡葬**：开通表单行业字段只读，值=殡葬。
3. **账号唯一**：管理员账号（手机/邮箱）全局唯一，重复则拦截。
4. **套餐必选**：开通时必须绑定一个上架套餐，并据此初始化配额快照。
5. **状态机受控**：状态流转只能走「待开通→已开通→已停用/已到期」，不可跳变。
6. **敏感操作留痕**：开通 / 停用 / 启用 / 续期 / 改套餐 均写审计。

## 4. 功能需求

### 4.1 租户列表

**展示字段**：公司名 · 地区(备注) · 套餐 · 状态 · 成员数 · 管理员账号(脱敏) · 到期时间 · 操作

**筛选/搜索**
| 控件 | 值 |
|--|--|
| 状态筛选 | 全部 / 已开通 / 待开通 / 已停用 / 已到期 |
| 套餐筛选 | 全部 / 标准版 / 旗舰版 |
| 搜索 | 公司名 / 管理员账号 模糊匹配 |
| 总览计数 | 共 N 家 · 已开通 X · 待开通 Y |

**行操作（按状态条件显示）**
| 状态 | 可见操作 |
|--|--|
| 已开通 | 停用 |
| 已停用 | 启用 |
| 待开通 | 继续开通 |
| 已到期 | 续期 |

### 4.2 开通新公司（弹窗）

| 字段 | 类型 | 必填 | 校验 / 说明 |
|--|--|:--:|--|
| 公司名 | str | ✓ | 非空；同名给软提示（不强拦） |
| 行业 | enum | — | 只读 = 殡葬 |
| 套餐 | enum(ref) | ✓ | 选上架套餐；决定配额快照 |
| 到期时间 | date | ✓ | 默认开通日 +1 年 |
| 管理员姓名 | str | ✓ | 非空 |
| 管理员账号 | str | ✓ | 手机/邮箱；**全局唯一**校验，重复拦截并提示 |
| 初始密码 | str | ✓ | 系统生成（可「重新生成」）；规则：前缀+6 位随机 |

**主操作**：`生成账号并下发`
- 校验通过 → 创建 `tenant_company`（状态=已开通）+ `account`（角色=管理员）→ 写 `quota`（按套餐配额快照）→ 下发凭证（短信/邮件，演示为 toast）→ 列表顶部插入新行 → 写审计。
- 校验失败（账号重复/必填缺失）→ 行内报错，不提交。

### 4.3 停用 / 启用 / 续期

| 操作 | 行为 | 二次确认 | 审计 |
|--|--|:--:|--|
| 停用 | 状态→已停用；商家端登录被拒；数据保留 | 是 | 是 |
| 启用 | 状态→已开通；恢复登录 | 否 | 是 |
| 续期 | 到期时间顺延；状态由已到期→已开通 | 是（确认时长） | 是 |
| 改套餐(超管) | 换绑套餐；降档若<当前用量给风险提示 | 是 | 是 |

## 5. 状态流转（租户 tenant_company.status）

```
            开通新公司(校验通过)
(草拟/待开通) ───────────────────▶ (已开通) ──停用──▶ (已停用)
     ▲                               │  ▲              │
     │                               │  └────启用───────┘
  继续开通                        到期到达
                                     ▼
                                 (已到期) ──续期──▶ (已开通)
```
- 合法值：`待开通 | 已开通 | 已停用 | 已到期`
- 商家端登录鉴权：仅 `已开通` 放行；其余返回对应拦截提示。

| 接口 | 方法 | 入参 | 出参 |

## 8. 技术考虑
- 初始密码：服务端生成强随机，**仅在下发那一刻可见**，不回显明文于列表。
- 配额快照：开通即把套餐配额冻结成 `quota_snapshot`，避免后续套餐改动追溯影响已开通租户。
- 商家端鉴权读 `tenant_company.status` + `account.status` 双判，任一非启用即拦。
- 唯一性校验前端即时 + 后端兜底（防并发重复）。

## 9. 风险与依赖

### 9.1 依赖
- 计费模块（批次2）提供套餐与配额快照结构。
- 短信/邮件下发通道（凭证下发）。

### 9.2 风险
| 风险 | 应对 |
|--|--|
| 凭证下发失败客户进不去 | 下发结果可见 + 可重发；列表「继续开通」补救 |
| 运营误停用在用客户 | 停用二次确认 + 审计可追溯 + 可一键启用 |
| 套餐改动影响已开通租户 | 用配额快照冻结，套餐变更不回溯 |

## 10. 验收标准
1. 能在弹窗内完成开通，列表即时出现新租户，状态=已开通。
2. 管理员账号重复时被拦截、给出明确提示，不产生脏数据。
3. 开通即生成配额快照（可在计费模块读到）。
4. 停用后商家端该账号登录被拒；启用后恢复。
5. 到期租户显示「已到期」且登录被拒；续期后恢复。
6. 开通/停用/启用/续期均产生一条审计记录（操作人/时间/对象齐全）。
7. 行业字段在表单中只读且恒为殡葬。

## 11. 当前通用产品开发基线（v3.0 · 2026-08-12）

### 11.1 开通对象

平台后台创建通用企业租户，字段包括企业名称、行业/业态、管理员、套餐、服务周期、数据区域、功能开关、默认审核策略和客户成功负责人。行业可选择或自定义，不再固定为殡葬。

### 11.2 开通事务

一次事务创建 `tenant_company`、首位管理员、套餐快照、默认角色、Prompt/合规默认版本和首次引导状态。凭证下发失败不得回滚已创建租户，但状态进入 `credential_delivery_failed` 并允许安全重发。

### 11.3 状态

`draft → provisioning → active | provisioning_failed → suspended | expired → active`。停用/到期阻止新登录和新任务，但保留数据、审计和合法导出能力。

### 11.4 验收

1. 可开通不同行业租户，行业配置进入企业画像候选而非硬编码 Prompt。
2. 管理员登录标识全局唯一；并发开通不产生重复账号。
3. 默认 Prompt、合规、套餐和权限版本可追溯。
4. 开通不会自动生成企业事实或启用企业 VI。
5. 开通、停用、续期、套餐变更和凭证重发均有审计。
