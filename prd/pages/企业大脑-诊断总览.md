# 页面 PRD：企业大脑 / 诊断总览

> 页面 ID：`diagnosis`｜版本：v1.0｜优先级：P0｜上位：[[../PRD_企业大脑]]

## 问题

企业资料分散且成熟度不一，用户既不知道当前信息能支持什么诊断，也容易把上传、OCR 或网站提取内容误当成已确认事实。

## 目标

展示企业信息完整度、六维诊断、缺口和下一步；支持四步初步信息采集自由切换；区分初步诊断与深度诊断准入条件。

## 目标用户

企业负责人查看经营全貌；企业管理员补充和确认资料；顾问发起诊断；普通成员查看授权结论。

## 用户流程

进入诊断总览 → 查看完整度和六维状态 → 点击四步任一步补充资料 → 保存为候选或确认事实 → 系统重算完整度 → 满足阈值后发起初步/深度诊断 → 进入品牌报告查看产物。

## 功能规则

- 顶部标题显示“企业大脑”，内容标题显示“诊断总览”。
- 初步诊断默认要求总体完整度≥40%；深度诊断默认要求总体≥80%且每一维≥60%，实际阈值读取租户配置。
- 仅 confirmed 事实计入诊断完整度；候选、处理中和失败资料不计入。
- 四步为企业基础、产品服务、目标客户、经营目标，可点击任意切换并保留草稿。
- 诊断结果只产生报告和建议，不自动改写企业知识或经营计划。

## 异常与边界

阈值未满足时禁止创建任务并展示逐维缺口；知识版本变化时提示重新计算；并发保存返回冲突；计算失败保留上次成功结果并标记时间；无权限字段脱敏。

## 字段交互 / 取值

### 信息完整度
只读进度条。字段键：`overall_completeness`。取值0–100；由confirmed字段按配置权重计算，显示计算时间。

### 六维诊断
六张可点击卡片。字段键：`dimensions[]`。取值品牌/产品/客户/渠道/组织/经营；每项含score、status、gap_count、evidence_count；点击展开证据与缺口。

### 资料状态统计
只读统计。字段键：`candidate_summary`。显示待处理、待确认、已采用、失败数量；点击进入企业知识统一待办。

### 四步导航
步骤条。字段键：`intake_step`。取值company/product/customer/objective；点击自由切换，不要求顺序完成。

### 企业基础信息
表单组。字段键：`company_profile`。含企业名称2–80字、行业、地区、规模、官网；未确认内容保存为draft。

### 产品与服务
可重复表单。字段键：`offerings[]`。每项含名称2–80字、客户问题、核心价值、价格口径、证据；价格和承诺需人工确认。

### 目标客户
多行与标签。字段键：`target_customers[]`。每项含类型、场景、痛点、决策角色、地区；AI建议仅为候选。

### 经营目标
目标列表。字段键：`business_objectives[]`。每项含目标、指标、目标值、期限、负责人；至少目标和期限才能确认。

### 保存草稿
次按钮。字段键：`save_intake_draft`。保存当前步骤，允许字段不完整；离开页面前自动保存一次。

### 确认信息
主按钮。字段键：`confirm_intake`。有确认权限且通过字段校验时可用；写入正式知识版本并触发重算。

### 发起初步诊断
按钮。字段键：`start_initial_diagnosis`。达到配置阈值且无运行中同类任务时可用；进入品牌报告创建流程。

### 发起深度诊断
按钮。字段键：`start_deep_diagnosis`。总体和逐维阈值均满足才可用；不足时列出具体缺口。

## 状态与权限

采集状态：`empty → draft → pending_confirmation → confirmed`；诊断任务：`queued → running → ready | failed`。管理员/知识负责人可确认，顾问可发起诊断，普通成员只读。

## 数据与接口

对象：`enterprise_profile`、`knowledge_fact`、`completeness_snapshot`、`diagnosis_run`。接口：`GET /enterprise-brain/diagnosis`、`GET/PATCH /enterprise-intake`、`POST /enterprise-intake/confirm`、`POST /diagnosis-runs`。错误码：`THRESHOLD_NOT_MET`、`DIMENSION_THRESHOLD_NOT_MET`、`FACT_UNCONFIRMED`、`VERSION_CONFLICT`。

## Skill / Prompt

```text
你是企业信息完整度与诊断路由器。仅使用 confirmed_facts 计算六维状态；candidate_items 只能生成缺口提示。输出 dimension_scores、evidence_refs、missing_fields、eligible_initial、eligible_deep。不得补造事实，不得自动采用候选。
```

## 埋点事件

`diagnosis_overview_viewed`、`intake_step_switched`、`intake_draft_saved`、`intake_confirmed`、`diagnosis_started`、`diagnosis_threshold_blocked`；属性含step、dimension、completeness、diagnosis_type。

## 验收标准

1. 四步均可点击切换且草稿不丢失。
2. 候选资料不计入完整度。
3. 阈值不足时不能发起并展示具体缺口。
4. 初步与深度诊断使用不同准入规则和任务类型。

## 核心指标

四步草稿保存成功率≥99%；完整度计算可解释率100%；未确认事实进入诊断数0；阈值绕过数0。
