# 页面 PRD：品牌与经营 / 品牌报告

> 页面 ID：`brand-report`｜版本：v1.0｜优先级：P0｜上位：[[../PRD_品牌与经营]]

## 问题

企业需要区分初步诊断和深度诊断的交付深度，查看完整报告并处理生成失败。当前若只展示摘要卡、失败原因打不开或示例未标识，会让用户误判为真实报告已生成。

## 目标

- 完整展示初步诊断和深度诊断报告。
- 支持生成、预览、下载、失败原因和重试。
- 每份报告可追溯到企业知识、Prompt 和 Skill 版本。
- 示例报告与真实报告严格区分。

## 目标用户

- 企业负责人：查看结论、证据和行动建议。
- 品牌/经营负责人：补充信息并推动后续行动。
- 顾问：生成、讲解和交付报告。
- 只读成员：查看被授权报告，不可生成或重试。

## 用户流程

1. 进入“品牌与经营 / 品牌报告”。
2. 查看报告列表或按类型、状态、时间筛选。
3. 点击“生成报告”，选择初步/深度诊断并确认依据版本。
4. 系统校验信息完整度，创建异步任务并返回列表。
5. 生成成功后预览完整正文或下载；失败时查看原因并重试。
6. 从报告结论进入经营计划或企业大脑补充信息。

## 功能规则

- 顶部标题显示“品牌与经营”，内容标题显示“品牌报告”，卡片内不重复标题。
- 初步诊断达到基础完整度阈值才可生成；深度诊断达到深度阈值且六维均满足最低值才可生成。阈值来自配置。
- 未确认候选不计入完整度，不进入报告证据。
- 初步报告至少包含六维概览、优势、问题、证据、缺口和初步建议。
- 深度报告至少包含方法、管理摘要、逐维证据、问题树、根因、机会地图、优先级、90天行动、指标、风险和证据附录。
- 报告可以是在线文档，不强制使用 PPT。
- 示例数据必须显示“案例/示例数据”，不能进入当前企业历史版本。

## 异常与边界

- 信息不足：不创建任务，展示缺口和“去补充信息”。
- 生成超时：状态保持 generating，展示最后更新时间；超过服务阈值进入 failed。
- Schema 校验失败：不展示残缺报告，记录失败阶段和错误码。
- 文件渲染失败：在线正文仍可查看，文件区显示失败并允许单独重试。
- 依据版本已删除/无权限：阻止预览和重试，管理员可查看审计原因。
- 重复点击：相同幂等键返回同一任务。

## 字段交互 / 取值

### 报告类型筛选

多选下拉；切换后立即刷新列表并回到第1页。
字段键：`report_type`
取值：`initial_diagnosis / deep_diagnosis`；可为空表示全部。
默认：全部。
权限：所有可访问页面的成员可用。

### 生成状态筛选

多选下拉；可同时选择多个状态。
字段键：`status`
取值：`generating / ready / failed`；可为空。
默认：全部。

### 时间范围

日期范围选择器；选择完成后刷新列表。
字段键：`created_range`
取值：开始日期≤结束日期，最长2年。
默认：近90天。
校验：超出范围提示“最多查询2年内的报告”。

### 关键词

搜索框；输入停止300ms后按报告名称查询。
字段键：`keyword`
取值：2–50个字符；可为空。
校验：不足2字时不请求并显示输入提示。

### 报告名称

列表主字段；点击进入预览。
字段键：`name`
取值：2–60个字符。
显示：过长省略，悬停显示全名；示例加“案例”标签。

### 报告类型

只读标签。
字段键：`report_type`
取值：初步诊断 / 深度诊断。

### 依据版本

只读链接；点击打开生成时使用的企业知识快照。
字段键：`knowledge_version_id`
取值：同租户 formal 版本 ID。
权限：无知识查看权限时只显示版本号，不显示内容。

### 生成时间

只读日期时间。
字段键：`generated_at`
取值：ISO-8601；未生成完成显示“—”。

### 报告状态

状态标签并控制可用操作。
字段键：`status`
取值：生成中 / 可查看 / 生成失败。
显示：failed 必须同时显示“查看原因”。

### 新建报告名称

单行文本，失焦保存到创建草稿。
字段键：`name`
取值：2–60个字符；必填。
默认：`企业简称 + 报告类型 + 日期`。
校验：为空提示“请输入报告名称”。

### 新建诊断类型

单选卡片。
字段键：`report_type`
取值：初步诊断 / 深度诊断；必填。
默认：初步诊断。
联动：深度阈值未满足时禁用并展示缺口。

### 企业知识版本

只读选择器，可从历史正式版本中切换。
字段键：`knowledge_version_id`
取值：同租户 formal 版本；必填。
默认：最新正式版本。

### 诊断截止日

日期选择器。
字段键：`as_of_date`
取值：不得晚于今天；必填。
默认：今天。

### 补充说明

多行文本，提交时保存。
字段键：`instructions`
取值：0–1000字符；可为空。
校验：超长提示剩余字数；内容作为任务要求，不可覆盖系统事实规则。

### 生成报告

主按钮；字段校验和完整度通过后创建异步任务。
字段键：`create_report`
显示：有生成权限时显示。
交互：点击后 loading，成功返回列表；重复点击返回同一任务。

### 预览

列表按钮；仅 ready 可用。
字段键：`preview_report`
交互：打开完整在线文档，保留列表筛选状态。

### 下载

列表按钮；ready 且文件存在时显示格式菜单。
字段键：`download_report`
取值：DOCX / PDF 或已生成格式。
交互：签发短时链接并记录下载审计。

### 查看原因

failed 时显示；打开错误弹层。
字段键：`view_failure_reason`
显示：失败阶段、错误码、可重试性、发生时间和脱敏详情。

### 重试

failed 且 retryable 时显示。
字段键：`retry_report`
交互：复用原依据快照创建新运行，原失败记录不覆盖。

## 状态与权限

状态：`draft → generating → ready | failed`；文件可独立为 `rendering → ready | failed`。

- 企业负责人/顾问：生成、预览、下载、重试。
- 品牌经营人员：按授权生成和查看。
- 只读成员：仅预览/下载授权范围。
- 所有生成、重试、下载和删除动作写审计；删除使用软删除。

## 数据与接口

`diagnosis_report`：report_id、tenant_id、name、report_type、knowledge_version_id、as_of_date、instructions、status、prompt_version、skill_version、error_code、error_detail、retry_of、created_by、created_at、updated_at、generated_at、version、deleted_at。

接口：

- `GET /diagnosis-reports`：筛选、排序、分页。
- `POST /diagnosis-reports`：创建；要求 `Idempotency-Key`。
- `GET /diagnosis-reports/{id}`：报告正文、证据和状态。
- `POST /diagnosis-reports/{id}/retry`：重试可失败阶段。
- `GET /diagnosis-reports/{id}/files`：文件和渲染状态。

错误码：`KNOWLEDGE_THRESHOLD_NOT_MET`、`KNOWLEDGE_VERSION_INVALID`、`REPORT_SCHEMA_INVALID`、`REPORT_RENDER_FAILED`、`REPORT_FILE_MISSING`、`VERSION_CONFLICT`、`PERMISSION_DENIED`。

## Skill / Prompt

Skills：`enterprise-initial-diagnosis`、`enterprise-deep-diagnosis`、`document-render`。

```text
你是企业经营诊断顾问。只使用 confirmed_facts 与 evidence_refs。
任务类型为 <initial|deep>。每项结论必须输出 conclusion、fact_or_inference、evidence_ids、confidence、recommended_action。
初步诊断输出六维概览、优势、问题、证据、信息缺口和初步建议；深度诊断额外输出方法、问题树、根因、机会地图、优先级、90天行动、指标、风险和证据附录。
证据不足时输出“待补充”，禁止编造价格、案例、资质、承诺和经营结果。严格按 output_schema 返回。
```

## 埋点事件

- `brand_report_page_viewed`：进入页面；属性：role。
- `brand_report_generation_started`：创建任务；属性：report_type、knowledge_version。
- `brand_report_generation_failed`：任务失败；属性：stage、error_code。
- `brand_report_previewed`：打开预览；属性：report_id、report_type。
- `brand_report_downloaded`：下载；属性：report_id、format。
- `brand_report_retried`：重试；属性：report_id、failed_stage。

## 验收标准

1. 初步和深度报告均能打开完整正文，章节结构明显不同。
2. 深度阈值不足时按钮禁用并显示具体缺口。
3. 未确认候选不会出现在报告引用中。
4. failed 行能打开原因；可重试错误重试后保留原记录。
5. 示例报告始终显示案例标识，不计入真实历史。
6. 下载文件与当前报告版本、知识版本一致。

## 核心指标

- 报告生成成功率：ready任务数/有效创建任务数；目标≥95%。
- 预览成功率：成功打开完整正文次数/预览点击次数；目标≥99%。
- 失败原因可查看率：有结构化原因的failed任务/failed任务；目标100%。
- 深度报告完整章节率：必需章节全部存在的报告/ready深度报告；目标100%。
