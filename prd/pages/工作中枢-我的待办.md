# 我的待办（work-tasks）

## 1. 页面概述
统一管理我的待办，服务老板与员工账号；当前为可点击原型。

## 2. 页面级业务规则
按 tenantId 隔离；private、project、enterprise 三层范围；高风险动作必须人工确认。

## 3. 页面字段
id、tenantId、ownerAccountId、visibility、customerId、projectId、status、sourceMeetingId、evidenceTimestamp。

## 4. 操作与结果
列表、筛选、详情、确认、重试和深链均记录审计；生成结果回挂任务。

## 5. 产品边界
原型演示 · 模拟生成；不接真实服务器、会议、自动发送、签署或付款。

## 6. 状态与跳转
uploaded → parsing → ready|failed；candidate → confirmed|dismissed；pending → running → ready|failed。

## 7. 通知与日志
记录账号、来源 ID、动作、时间、前后状态。

## 8. 异常与空状态
无权限、无数据、解析失败、低置信度显示原因与可恢复重试。

## 9. 页面验收标准
切换老板与员工账号，确认可见范围差异；完成核心操作后回到任务中心查看状态。

## 10. 技术评估项
静态对象保持幂等；唯一键 tenantId + id；Agent 生成均为任务子项。

## 问题与目标用户
任务聚合痛点是执行分散。目标用户为老板、员工和 Agent 观察者。用户流程：筛选→确认候选→运行子任务→审核交付物。功能规则：父任务不可代替子任务；权限按负责人。异常边界：逾期、失败可重试。字段交互：status 枚举 pending/running/ready/failed，filter 可选 mine/team/customer/project。状态与权限：负责人可编辑，老板可查看企业范围。数据与接口：Task(id,tenantId,parentTaskId,sourceMeetingId,evidenceTimestamp)，GET/POST /work/tasks。Skill / Prompt：输入任务上下文，输出结构化步骤，人工门为对外动作，失败降级为人工。埋点事件：task_filtered/task_confirmed/agent_retried。验收标准：确认一次只建一个子任务。核心指标：完成率上线后建立基线。
