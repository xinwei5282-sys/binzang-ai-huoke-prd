# 页面 PRD：工作台 / 待办工作区

> 页面 ID：`work-tasks`｜稳定路由：`home`｜版本：v2.2｜状态：原型已联通｜更新日期：2026-11-25
> 关联：[[工作中枢-项目]]、[[工作中枢-客户]]、[[企业大脑-会议纪要]]

## 问题

任务来自会议纪要、客户跟进、项目冲突和 Agent 生成，需要在统一平铺列表中保留项目与来源，并通过日历方便地调整排期。待办如果藏在独立页面，用户还需要在总览与执行之间来回切换。

## 目标用户

老板、员工和任务负责人。用户进入工作台即可快速发起工作、处理完整待办，并了解当前账号权限范围内的执行进度。

## 用户流程

进入工作台 → 查看待办事项及本周日程 → 选择任务范围和状态 → 处理任务或调整时间。项目入口携带项目过滤并定位本页待办。项目区的「查看排期」进入项目详情。

## 功能规则

1. 原“首页”改名为“工作台”，稳定路由仍为 `home`；原“工作台”改为“客户管理”，稳定路由仍为 `workhub`。
2. 工作台直接承载完整任务操作区；客户管理不再提供独立“我的待办”入口，不复制任务记录。
3. 工作台先显示待办和日程，下方显示项目整体状态与汇总。详细待办保持平铺。
4. 执行区桌面左任务列表、右周历同时可见，窄屏上下排列。周历按当前日期计算七天，支持前后周、回本周和议程切换。触屏或键盘用户可点击「调整时间」。
5. 两种排期方式都更新 `scheduledDate`、`scheduledTime` 与展示字段 `dueAt`，并立即刷新工作台。
6. Agent 生成动作必须形成可追溯子待办；PPT 继续进入营销物料 / PPT，不在任务页伪造文件。
7. 决策与审批复用 Task，入口放在待办区，仅统计当前账号负责且有权限的待处理决策和审批。
8. 决策、审批、客户跟进和 Agent 执行统一使用 `Task.kind`；是否需要判断由标签提示，仍由任务负责人自主处理。
9. 工作台移除经营数据和企业资料折叠区；经营分析、企业资料、客户管理等原有业务入口继续存在。任务卡保留负责人、项目、来源，客户跟进标注高意向；任务进度由六个状态统计呈现（包含 Agent 执行中）。
10. 列表不重复显示“X项待办”副标题或状态下拉框，状态筛选只通过六个统计入口完成。
11. 项目状态区每项目一行，显示名称、阶段、整体状态及「查看排期」。详细阶段与任务日期在项目详情查看和维护。
12. 下一节点取未完成且有日期的最早里程碑，无日期节点排在有日期节点之后。延期按最早的未完成节点或项目交付日期计算：只考虑 `project.targetDate` 及未完成 `milestones[].dueDate`，早于当前日期才延期，取最早延期日期并高亮延期天数；已完成/已归档项目不计算延期。日期无效不参与计算，同日不延期。
13. 任务列表和日程同屏展示，项目深链仅带入项目过滤并定位任务。待办筛选不扩大项目可见范围。
14. 项目总览按需关注、其他未结束、已结束、待排期排序，组内按目标日期升序且无日期置后；需关注条件为逾期、健康度风险、阻塞或存在待处理事项。

## 异常与边界

- 无项目任务不报错，归入“日常待办”。
- 项目深链上下文被清除后回到当前任务范围，不扩大为独立项目范围筛选。
- 触屏浏览器不支持原生拖拽时，使用“调整时间”表单完成相同操作。
- 当前原型以本地样例和浏览器存储模拟排期；不接真实日历、通知、自动外发或服务器持久化。

## 字段交互/取值

- `Task`：`id`、`tenantId`、`ownerAccountId`、`customerId`、`projectId`、`parentTaskId`、`status`。
- 类型：`kind = decision | approval | followup | agent | null`；审批目标使用 `approvalTarget`。
- 来源：`sourceMeetingId`、`sourceConflictId`、`evidenceTimestamp`。
- 排期：`scheduledDate`（YYYY-MM-DD）、`scheduledTime`（HH:mm）、`dueAt`（中文展示值）。
- 状态：`pending | confirmed | running | ready | failed`；未完成数为状态不等于 `ready` 的任务数量。
- 任务列表：保持平铺，不提供列表/日历互斥切换器；周历与任务列表同处执行区。

## 状态与权限

先按 `tenantId` 隔离，再按系统角色 grant、`all | team_self | self` 数据范围以及项目成员关系过滤。工作台使用 `canCurrentAccountSeeWorkItem` 判断。员工的私人任务仅本人可见，项目任务只对有项目访问权的成员可见。

## 数据与接口

原型以 `WORK_HUB_TASKS` 为任务真源。生产建议使用 `GET /tasks?scope=&projectId=&status=` 与 `PATCH /tasks/:id/schedule`；排期写入需要服务端重新鉴权、乐观锁版本和审计记录，避免多人同时拖动造成覆盖。

## Skill / Prompt

任务生成 Prompt 输入会议行动项、项目上下文和证据引用，输出结构化 `title`、`ownerAccountId`、`projectId`、`dueAtCandidate`、`sourceRefs` 和 `deliverableType`。AI 只给候选负责人和时间；员工确认或调整后才成为正式排期。

## 埋点事件

`home_task_overview_viewed`、`task_calendar_week_changed`、`task_calendar_drag_started`、`task_schedule_changed`、`task_schedule_form_opened`、`project_task_opened`、`task_source_opened`、`task_confirmed`、`agent_task_started`。记录账号、任务、项目、原时间、新时间、区域、视图和入口。

## 验收标准

1. 登录账号变化后，任务列表、统计和日程均按账号权限重新计算。
2. 工作台单页先显示待办与日程，下方显示项目整体状态。客户管理不设独立待办页。
3. 任务按状态、范围和项目上下文过滤，列表保留负责人、所属项目和来源。清除项目标签后恢复当前范围。
4. 将任务拖到所选周的 14:00 时间槽，或用表单设置同一日期和时间，列表与日程展示一致。
5. 项目整体状态与项目详情口径一致；「查看排期」进入该项目阶段排期。
6. 390×844 下六个状态入口两行显示，周历七天同时可见；空周显示紧凑提示。

## 核心指标

工作台待办操作率、项目待办完成率、排期覆盖率、拖拽/表单调整成功率、逾期率、会议行动项转待办率和任务到交付物转化率；上线后建立基线。


### 待办详情内容（2026-09-07）

详情直接展示行动内容、预期成果、负责人、截止时间及所属项目。会议来源任务展示有权限查看的对应原文、说话人和时间点，查看原文定位到逐字稿；找不到证据时明确提示，不拼接无关会议结论。任务优先通过 sourceActionId 关联行动项，创建时保留该行动项自己的时间点与截止时间。缺失预期成果时提示待补充，不假造交付要求。
