# 页面 PRD：企业大脑 / 会议纪要

上传会议可选择项目；未选择时仅展示 AI 推荐候选，人工确认后写入 `projectId`，并幂等生成唯一会议材料来源链接。项目会议页与详情双向回链，跳转重新校验权限。

> 页面 ID：`kb-memory`（兼容路由）｜版本：v1.1｜优先级：P0｜上位：[[../PRD_企业大脑]]

## 问题

会议录音和视频中的客户需求、承诺、决策与下一步容易散落，员工还要重复听录音、写总结并手工创建待办。

## 目标

让成员上传会议音频或视频后，在一个页面查看处理进度、说话人转写、会议总结、关键决策、行动项和客户意向证据；确认行动项后进入工作台待办。

## 目标用户

老板查看企业范围会议和客户机会；员工处理本人或共享项目会议；销售与项目负责人核对结论并确认行动项。

## 用户流程

进入会议纪要 → 上传音频/视频 → 系统提取音轨、转写、区分说话人并总结 → 查看原文时间戳与结论 → 人工判断客户意向 → 勾选行动项 → 确认后进入工作台待办 → 从任务回溯会议证据。

## 功能规则

- 本页只接受音频和视频；聊天记录、图片、PDF、Word、TXT 和粘贴文本进入企业知识。
- 状态固定为 `uploaded → extracting_audio → transcribing → diarizing → summarizing → ready | failed`。
- 会议总结、决策、行动项和意向都必须能回溯到说话人转写与时间戳。
- AI 输出是判断候选，不自动发送、不自动承诺、不替员工或老板做业务决策。
- 只有用户勾选并确认的行动项才创建待办；重复确认不得重复创建。

## 异常与边界

非音视频文件明确提示前往企业知识；格式不支持、音轨为空、转写失败或说话人区分失败时保留原文件、失败阶段和重试入口；低置信度标记为待人工判断；原型不上传真实服务器、不接真实 ASR 或大模型。

## 字段交互 / 取值

- 上传文件 `meeting_media`：MP3、WAV、M4A、AAC、FLAC、OGG、MP4、MOV、MKV、WEBM。
- 可见范围 `visibility`：private/project/enterprise；默认 private。
- 处理阶段 `stage`：固定状态枚举；列表显示当前阶段和失败原因。
- 转写 `transcript[]`：start、end、speaker、text、confidence。
- 总结 `summary`：只读候选，可从详情发起纠正。
- 决策 `decisions[]`：逐条展示并关联 evidence_timestamp。
- 行动项 `action_items[]`：勾选框，字段含 title、owner、due_at、evidence_timestamp。
- 客户意向 `intent`：level、confidence、evidence、evidence_timestamp；必须显示“人工判断”边界。

## 状态与权限

租户按 tenantId 隔离；private 仅上传者可见，project 仅项目成员可见，enterprise 由老板和有权限成员查看。上传者可重试和修正本人会议；项目负责人确认共享项目行动项；任务仍按负责人权限执行。

## 数据与接口

对象：`meeting`、`meeting_media`、`transcript_segment`、`meeting_summary`、`meeting_action_item`、`intent_evidence`、`task`。接口建议：`POST /meetings/upload`、`GET /meetings/:id`、`POST /meetings/:id/retry`、`POST /meetings/:id/actions/confirm`。任务来源使用 `sourceMeetingId` 和 `evidenceTimestamp`，幂等键为 tenantId + meetingId + actionItemId。

## Skill / Prompt

```text
你是会议纪要整理助手。输入带时间戳和说话人的会议转写，输出 summary、decisions、action_items、intent。每个关键结论必须携带 evidence_timestamp；无法从原文直接支持时标记 insufficient_evidence。不得代替员工确认行动项，不得自动对外发送或承诺。
```

## 埋点事件

`meeting_uploaded`、`meeting_stage_changed`、`meeting_processing_failed`、`meeting_detail_viewed`、`transcript_timestamp_clicked`、`meeting_action_confirmed`、`meeting_task_created`；记录 tenantId、meetingId、stage、mediaType、duration、result，不记录音视频正文或敏感转写全文。

## 验收标准

1. 文件选择器只允许音频和视频，错误文件能跳转企业知识。
2. 列表展示媒体类型、时长、可见范围、阶段和行动项数量。
3. 详情完整展示来源、说话人转写、总结、决策、行动项和意向证据。
4. 时间戳可触发播放器定位演示；桌面和手机不横向溢出。
5. 仅勾选行动项进入待办，重复确认不重复建任务。
6. 老板和员工看到的会议范围符合账号权限。

## 核心指标

处理成功率、转写可用率、会议总结人工采用率、行动项确认率、会议到任务转化率和平均处理时长上线后建立基线；错误入口分流成功率目标 100%。

## 长会议与阅读视图补充契约

默认打开“AI 总结”标签；“逐字稿”为独立标签，切换不改变原始来源和播放器。逐字稿每行携带 `start` 时间戳，点击后仅演示定位。超过两小时的会议按四段处理，列表显示总时长、已完成段数和当前段；结果生成后才允许查看完整总结与逐字稿。所有模型、转写和播放器能力均为原型演示，不调用真实 API。

## 结构化总结与证据回溯

AI 总结参考飞书妙记“先掌握全貌、再按章节回溯”的信息结构，但不复制其品牌视觉。页面固定按“一句话结论、客户意向、章节纪要、关键需求与异议、已确认决策、待办事项、下一步建议、未决问题与风险”八个模块展示。

- `headline`：对本次客户会议的一句话判断候选。
- `chapters[]`：title、timeRange、summary、evidenceTimestamp。
- `needs[]`、`objections[]`、`openQuestions[]`：text、evidenceTimestamp。
- `nextSteps[]`：text、destination、evidenceTimestamp；destination 只说明后续入口，不自动执行。
- `actionItems[]`：补充 owner、dueAt、evidenceTimestamp，仍需用户勾选确认后才进入待办。

客户意向、章节、需求、异议、决策、待办、下一步和风险中的时间戳均可切换到逐字稿并突出对应发言。找不到原文时提示“暂未找到”，不得伪造证据。PPT 候选进入“营销物料 / PPT”，话术进入客户档案跟进助手，报价与合同进入项目商业文件；所有结果均为可编辑候选，不自动发送或对外承诺。

## 项目同步补充契约

- 在会议纪要入口上传音视频时，可直接选择当前账号有权访问的项目；未选择项目时，AI 只写入 `recommendedProjectId` 和 `recommended` 状态，不得提前写入 `projectId`。
- 用户确认后，会议范围转为项目共享，使用 `tenantId + projectId + meetingId` 幂等回挂一条 `ProjectMaterial`；重复确认不重复建材料。
- 从项目会议页打开纪要前，同时校验会议内容权限、项目成员关系和“企业知识 / 查看”动作；纪要详情保留“返回项目”。
- 项目只保存会议来源引用和处理状态，不复制逐字稿、总结、章节或行动项正文；正文真源仍属于会议纪要。
- 纪要生成的行动项经人工勾选确认后进入待办，并携带 `projectId`、`sourceMeetingId` 和 `evidenceTimestamp`。PPT、报价、合同和话术再从任务路由到所属模块。
