## 页面概述

系统设置用于维护当前租户的企业法定与联系基础信息，为账号归属、服务通知和审计展示提供稳定主体。

- 目标用户：租户管理员、具备只读权限的观察员。
- 前置条件：已登录且已确定 `tenant_id`。
- 页面入口：左侧「系统管理 → 系统设置」。
- 权限：`system.view` 控制查看，`system.edit` 控制编辑与保存。
- 成功结果：保存新版本并在操作日志留下可追溯记录。

## 页面级业务规则

1. 页面只维护六项企业基础信息，不混放能力开通、模型、通知、审批或套餐配置。
2. 企业名称、企业简称、联系人、联系手机为必填。
3. 联系手机按大陆 11 位手机号校验；信用代码有值时按 18 位统一社会信用代码规则校验。
4. 数据严格按 `tenant_id` 隔离，服务端不得接受前端传入的其他租户标识。
5. 保存使用版本号做乐观锁；并发修改时不覆盖他人的新版本。
6. 观察员看到相同字段，但输入框只读且不显示保存按钮。
7. 日志只记录变更字段与脱敏摘要，不记录完整手机号等敏感值。

## 页面字段级定义

| 字段 | 字段键 | 类型 | 必填 | 校验 / 口径 | 权限与展示 |
|---|---|---|:---:|---|---|
| 企业名称 | `enterprise_name` | string | 是 | 2–100 字；法定或对外主体名 | 可查看；管理员可编辑 |
| 企业简称 | `enterprise_short_name` | string | 是 | 2–30 字；用于页面展示 | 可查看；管理员可编辑 |
| 统一社会信用代码 | `unified_social_credit_code` | string | 否 | 有值时 18 位；租户主体唯一 | 无权限时脱敏 |
| 注册地址 | `registered_address` | string | 否 | 0–200 字；不等同门店地址 | 可查看；管理员可编辑 |
| 联系人 | `contact_name` | string | 是 | 2–30 字 | 可查看；管理员可编辑 |
| 联系手机 | `contact_phone` | string | 是 | `^1\d{10}$` | 只读态脱敏；编辑态明文 |
| 数据版本 | `version` | integer | 是 | 服务端递增 | 页面不编辑 |
| 最近更新 | `updated_at/by` | datetime/ref | 是 | 租户时区 | 页脚只读展示 |

## 页面级操作定义

| 操作 | 展示条件 | 前置校验 | 执行结果 | 审计 |
|---|---|---|---|---|
| 查看设置 | `system.view` | 已确定租户 | 加载当前版本 | 可按策略采样 |
| 编辑字段 | `system.edit` | 页面加载成功 | 字段进入可编辑 | 不逐键记录 |
| 保存设置 | `system.edit` | 必填、格式、版本均通过 | 保存并更新最近更新时间 | `system_settings_updated` |
| 查看历史 | `audit.view` | 存在审计记录 | 跳转日志并带对象筛选 | 记录日志查询 |

保存按钮在请求期间禁用，成功后提示“企业基础信息已保存”；失败时保留用户输入。

## 产品边界

本页不负责功能开通、Agent 或 Prompt、角色权限、套餐额度、通知与审批规则，也不创建企业知识。原型只演示前端校验和状态反馈；正式存储、唯一性校验与租户隔离由后端实现。

## 页面级流程

```text
进入页面 → 校验 system.view → 加载租户当前版本
→ 管理员编辑六项字段 → 前端校验 → 提交 version
→ 服务端权限/租户/格式/并发校验 → 保存新版本 → 写审计 → 页面回显
```

只读用户流程：进入页面 → 加载脱敏信息 → 不提供保存动作。

## 通知与日志

- 保存成功写 `system_settings_updated`：操作者、时间、旧/新版本、变更字段名。
- 保存冲突写 `system_settings_conflict`，不记录完整字段值。
- 信用代码重复等安全错误只记录脱敏对象和错误码。
- 本页保存不触发外部短信或邮件。

## 异常与空状态

| 场景 | 页面表现 | 恢复动作 |
|---|---|---|
| 无查看权限 | 显示权限说明，不请求企业详情 | 联系管理员 |
| 首次无资料 | 展示空表单与字段说明 | 管理员填写并保存 |
| 必填缺失 | 字段下方错误，聚焦首个错误 | 补齐后重试 |
| 手机或信用代码格式错误 | 就地提示，不提交 | 修改格式 |
| 并发版本冲突 | 提示信息已更新，保留当前输入 | 刷新对比后重提 |
| 网络或服务失败 | 保留表单，显示可重试提示 | 再次保存 |

## 页面验收标准

1. 页面只出现批准的六个企业字段。
2. 四个必填字段为空时不能保存，并正确聚焦错误字段。
3. 非 11 位手机号不能提交。
4. 管理员保存后更新时间与审计记录一致。
5. 观察员字段只读且没有可用保存按钮。
6. 并发冲突不覆盖服务端新版本。
7. 移动端表单单列，无页面级横向滚动。
8. 页面右侧「页面 PRD」展示本文十段结构及 `system` 页面键。

## 技术实现提示

- 核心对象：`enterprise_profile(tenant_id, version, six_fields, updated_by, updated_at)`。
- 更新接口建议 `PUT /tenant/settings`，请求携带 `If-Match` 或 `version`。
- 后端执行 `system.edit`、租户隔离、格式和唯一性校验。
- 前端只作即时反馈，不把前端隐藏当权限边界。
- 敏感字段在日志与只读响应中按权限脱敏。
- 自动化测试覆盖必填、格式、只读、冲突、审计与移动端布局。
