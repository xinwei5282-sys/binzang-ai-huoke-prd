# 页面 PRD：企业大脑 / 企业知识

> 页面 ID：`content`｜版本：v1.0｜优先级：P0｜上位：[[../PRD_企业大脑]]

## 问题

资料收件箱、资料处理中和待确认分散会让用户重复处理同一内容；未经确认的提取结果又可能污染企业事实。

## 目标

用一个统一待办承接资料接收、处理和确认；展示企业知识总览与知识域；所有候选经过人工采用后才进入正式知识。

## 目标用户

企业知识管理员确认事实；业务知识负责人维护领域内容；成员提交资料和查看授权知识；Agent只按授权读取正式版本。

## 用户流程

进入企业知识 → 查看知识总览和统一待办 → 上传/录入资料 → 系统处理并生成候选 → 打开候选核对原文 → 采用/驳回/编辑后采用 → 形成新知识版本 → 查看知识条目与引用关系。

## 功能规则

- “资料收件箱、资料处理中、待确认”合并为统一待办，用状态筛选区分。
- 状态固定为`received → processing → pending_confirmation → adopted | rejected | failed`。
- 仅adopted内容写入正式知识并供诊断、计划和内容生成使用。
- 总览展示企业基础、产品服务、目标客户、经营规则四类核心卡及七个知识域覆盖度。
- 本页删除Agent授权入口；Agent权限仅在设置中维护。

## 异常与边界

重复资料按hash和来源提示合并；解析失败保留原文件并允许重试；来源无权限时禁止处理；冲突事实并列进入待确认，不自动覆盖；删除采用软删除并检查引用。

## 字段交互 / 取值

### 知识总览卡
四张只读卡。字段键：`overview_cards[]`。取值企业基础/产品服务/目标客户/经营规则；显示confirmed条数、完整度、更新时间和负责人。

### 知识域
筛选与覆盖度列表。字段键：`knowledge_domain`。取值企业基础、品牌定位、产品服务、目标客户、销售客服、经营流程、案例证据；支持多选。

### 统一待办状态
标签筛选。字段键：`inbox_status`。取值received/processing/pending_confirmation/adopted/rejected/failed；默认未完成状态。

### 待办条目
列表。字段键：`inbox_items[]`。显示标题、来源、类型、状态、提交人、处理进度、候选数、更新时间和操作。

### 上传资料
按钮+文件选择。字段键：`source_file`。支持PDF/DOCX/XLSX/PPTX/TXT/图片，单文件≤100MB；上传后仅进入received。

### 手工录入
表单。字段键：`manual_content`。标题2–100字、知识域必选、正文1–20000字、来源说明；提交为pending_confirmation。

### 原文证据
只读预览。字段键：`evidence_ref`。显示页码/段落/截图和源文件版本；候选必须至少关联1条证据。

### 候选事实
可编辑表单。字段键：`candidate_fact`。含subject、predicate、value、domain、confidence、evidence_ids；编辑后保留原提取值。

### 采用
主按钮。字段键：`adopt_candidate`。知识负责人可用；冲突时必须选择替换、并列或取消并填写说明。

### 驳回
次按钮。字段键：`reject_candidate`。必须选择原因：错误/过期/重复/无关/证据不足/其他；其他需备注。

### 批量处理
批量操作。字段键：`bulk_action`。仅同知识域、无冲突候选可批量采用；驳回仍记录逐条结果。

### 搜索知识
搜索框。字段键：`keyword`。2–100字，300ms防抖；结果展示命中段、版本和引用范围。

## 状态与权限

管理员全域维护；业务负责人维护指定知识域；成员可提交并查看授权域；只读成员不可采用；受限知识需专项授权和审计。

## 数据与接口

对象：`knowledge_inbox_item`、`source_document`、`candidate_fact`、`knowledge_fact`、`knowledge_version`、`evidence_ref`。接口：`GET/POST /knowledge/inbox`、`POST /{id}/process|retry`、`POST /candidates/{id}/adopt|reject`、`GET /knowledge/facts`。错误码：`UNSUPPORTED_FILE`、`DUPLICATE_SOURCE`、`EVIDENCE_REQUIRED`、`FACT_CONFLICT`、`REFERENCE_EXISTS`。

## Skill / Prompt

```text
你是企业知识抽取器。对输入资料只生成 candidate_facts；每项必须包含原文证据、知识域、置信度、时间有效性和冲突提示。无法从原文直接支持时标记 insufficient_evidence。禁止自动采用、补造或覆盖已有正式事实。
```

## 埋点事件

`knowledge_inbox_viewed`、`knowledge_source_uploaded`、`knowledge_processing_completed/failed`、`candidate_adopted/rejected`、`knowledge_searched`；属性含source_type、domain、status、conflict_type。

## 验收标准

1. 三类待处理内容在同一列表按状态区分。
2. 未采用候选不会被下游引用。
3. 每条正式事实可回溯原文证据和采用人。
4. 冲突内容不会自动覆盖。
5. 页面无Agent授权入口。

## 核心指标

候选证据完整率100%；误自动采用数0；待办处理时长和采用率上线后建立基线；正式事实可追溯率100%。
