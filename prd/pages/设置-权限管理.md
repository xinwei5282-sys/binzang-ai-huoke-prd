# 页面 PRD：系统管理 / 权限管理

> 页面 ID：`permissions`｜版本：v1.0｜优先级：P0｜状态：需求已确认
> 原型入口：`prototype/index.html?review=permissions`｜更新日期：2026-09-01
> 上位：[[../PRD_企业AI经营大脑_当前开发基线]]｜成员关系：[[设置-成员管理]]

## 页面概述

权限管理使用 SaaS RBAC，把模块、数据范围与按钮动作统一配置在角色上，再由成员分配一个或多个角色取得权限并集。

- 目标用户：租户管理员、权限管理员、审计员。
- 页面入口：系统管理 → 权限管理。
- 页面结构：左侧角色列表，右侧当前角色权限矩阵。
- 权限：`role.view`、`role.manage`。

## 页面级业务规则

1. 权限配置对象是角色，不是单个成员。
2. 成员最终权限为其全部角色权限并集，不支持成员级覆盖。
3. 模块父级复选框与按钮子项支持全选、取消和半选。
4. 按钮权限必须与模块查看权限共同满足，不能只授予隐藏模块的动作。
5. 数据范围支持全部数据、所属团队与本人、仅本人。
6. 提示词管理固定拆分查看、编辑、测试、发布四个按钮权限。
7. 平台预置管理员和观察员不可删除；最后一个权限管理员不可自锁。
8. 仍被成员引用的自定义角色不能删除。

## 页面字段级定义

| 字段 | 字段键 | 类型 | 必填 | 规则 | 展示 |
|---|---|---|:---:|---|---|
| 角色名称 | `role_name` | string | 是 | 2–30 字；租户内唯一 | 列表标题 |
| 角色 ID | `role_id` | uuid | 是 | 稳定不可变 | 内部引用 |
| 权限摘要 | `summary` | computed | 是 | 模块 + 数据范围摘要 | 列表只读 |
| 数据范围 | `data_scope` | enum | 是 | all/team_self/self | 矩阵顶部 |
| 模块权限 | `module_grants` | array | 否 | 允许为空 | 父级复选框 |
| 按钮权限 | `action_grants` | map | 否 | 从已注册动作中选择 | 子复选框 |
| 创建人 | `created_by` | ref | 是 | 系统或租户成员 | 列表只读 |
| 创建时间 | `created_at` | datetime | 是 | 服务端时间 | 列表只读 |
| 版本 | `version` | integer | 是 | 乐观锁递增 | 不直接展示 |

模块注册表必须包含：企业大脑、营销物料、AI 获客、提示词管理、系统管理。

## 页面级操作定义

| 操作 | 权限 | 前置条件 | 结果 | 审计 |
|---|---|---|---|---|
| 选择角色 | `role.view` | 角色有效 | 加载权限矩阵 | 无敏感正文 |
| 新建角色 | `role.manage` | 名称唯一 | 基于模板创建草稿 | `role_created` |
| 编辑角色 | `role.manage` | 角色可编辑 | 修改权限矩阵 | 保存时记录差异 |
| 复制角色 | `role.manage` | 源角色有效 | 创建独立副本 | 不复制成员关系 |
| 删除角色 | `role.manage` | 非预置且无成员引用 | 软删除 | `role_deleted` |
| 保存角色 | `role.manage` | 防自锁与版本校验通过 | 新版本生效 | `role_grants_updated` |

## 产品边界

前端矩阵只是权限配置入口，不是安全边界。所有业务接口、数据查询和导出任务必须在服务端重新校验角色权限与数据范围。本期不做逐成员覆盖、条件表达式或跨租户角色模板市场。

## 页面级流程

```text
选择角色 → 加载模块与按钮授权 → 调整父级/子级 → 选择数据范围
→ 校验模块依赖与管理员保护 → 保存新版本 → 授权缓存失效 → 成员并集生效
```

复制流程：选择角色 → 复制 → 生成“角色名 副本” → 修改 → 保存；成员关系为空。

## 通知与日志

- 新建、复制、删除角色写操作日志。
- 保存记录变更前后 `module/action/data_scope` 差异。
- 发布、导出日志、成员管理等高风险权限变化标记风险等级。
- 角色变化可通知受影响管理员，不在通知中展开敏感数据范围。
- 权限拒绝事件写安全日志，便于追踪越权尝试。

## 异常与空状态

| 场景 | 页面表现 | 恢复动作 |
|---|---|---|
| 首次无自定义角色 | 展示平台预置模板 | 复制或新建角色 |
| 角色名称重复 | 阻止创建并提示 | 修改名称 |
| 角色被成员引用 | 禁止删除并显示引用数量 | 先调整成员角色 |
| 管理员自锁 | 阻止保存 | 保留至少一个权限管理员 |
| 并发版本冲突 | 保留当前选择并提示刷新 | 对比后重新提交 |
| 模块注册变化 | 标记未知权限并只读 | 管理员重新确认 |

## 页面验收标准

1. 角色列表展示名称、摘要、创建人、创建时间和操作。
2. 角色可新建、编辑、复制；满足条件时可删除。
3. 父级勾选可全选子项，部分子项使父级半选。
4. 提示词管理包含查看、编辑、测试、发布四个独立权限。
5. 数据范围与按钮权限同时影响最终授权。
6. 被成员引用角色和平台预置角色不可删除。
7. 保存权限后成员权限缓存失效并产生审计。
8. 页面 PRD 抽屉展示本文并标识 `permissions`。

## 技术实现提示

- 对象：`role`、`permission_module`、`role_grants`、`member_roles`。
- `role_grants` 建议记录 `module_key/action_key/data_scope/effect`，本期只支持 allow。
- 保存接口采用角色 `version` 做乐观锁，并返回受影响成员数。
- 授权服务在后端计算并集；前端矩阵不可用于直接放行请求。
- 权限模块与动作使用稳定键，显示名可变但键不可复用。
- 自动化测试覆盖父子联动、提示词四权限、引用保护、自锁与并发冲突。
