## 1. 文档概述

### 1.1 产品背景

殡葬内容高度敏感，绝对化用语（"最便宜""全网最低"）、虚假承诺（"包治""一定"）、不当用词（"灵堂""死"）轻则限流、重则下架甚至触法。合规预审的准确率不可能 100%，**违禁词库与改写建议必须由人工持续维护**——这是产品的命门，也是只有我方能集中做、不能甩给每个客户各自维护的事。

本模块要解决的核心问题：**让我方（合规审核角色）在后台集中维护殡葬违禁词库与改写建议，版本化管理并一键下发到所有租户**，使商家端在生成/保存/导出时命中提醒（非阻断）。词库是"系统预置只读"内容的源头，客户不可改、只能用。

> V1 不做：按租户定制词库、AI 自动扩词、阻断式拦截（V1 为提醒）、合规复核队列（精简版砍掉，留 V2）。

### 1.2 产品目标

- 合规角色可**增删改违禁词条**（词/正则 + 类别 + 命中范围 + 改写建议 + 风险级）
- 词库**版本化**：草稿编辑 → 发布 → 可回滚
- 发布即**下发全部殡葬租户**，立即生效于商家端预审
- 维护操作**留痕**，下发范围与生效版本可追溯

### 1.3 核心指标

| 指标 | 目标值 |
|--|--|
| 词库发布到全租户生效时延 | < 1 分钟 |
| 高风险违禁词覆盖（人工维护） | 持续扩充、可统计 |
| 误改导致线上异常可回滚 | 100%（版本可回退） |
| 维护操作留痕 | 100% |

### 1.4 范围

**In-Scope（本期）**
- 词条增删改（含 v13 草稿态新增标记）
- 版本管理（生效版本 / 草稿 / 对比 / 发布 / 回滚）
- 一键下发全租户
- 维护审计

**Out-of-Scope（不做 / 后续）**
- 按租户/分群定制词库
- AI 自动扩词 / 智能改写训练
- 合规复核队列（人工兜底，留 V2）
- 阻断式拦截

## 2. 用户与场景

### 2.1 目标用户
- **合规审核（小林）**：维护词库、发布版本。主操作人，唯一有"发布"权。
- **超级管理员**：全权。
- **运营**：可提案（不可发布）。

### 2.2 典型场景
1. 平台收到一批新限流案例 → 合规整理出 3 个新违禁词 → 在 v13 草稿里新增 → 对比 v12 → 发布 → 1 分钟内 38 家租户生效。
2. 某次发布误把"告别厅"也设成违禁致大量误提醒 → 合规一键回滚到 v12 → 线上恢复。
3. 客户反馈某词不该拦 → 合规在草稿里调整命中范围 → 下个版本下发。

### 2.3 用户故事
- 作为合规，我要集中维护一份殡葬违禁词库并一键发给所有客户，不用挨个客户配。
- 作为合规，发布前我能对比改了什么、发布后能回滚，避免一次手抖搞砸全线。
- 作为超管，每次发布有谁、何时、发了哪个版本到多少租户的记录。

## 3. 整体方案

### 3.1 方案原则
- **集中维护、统一下发**：一处维护、全租户受益，杜绝各自为政。
- **版本即安全网**：所有变更走草稿→发布，可对比、可回滚。
- **提醒非阻断**：词库驱动商家端"提醒+改写建议"，不硬拦（兜不确定性）。

### 3.2 模块结构
```
合规词库
├─ 版本条（当前生效版本 / 草稿 / 对比 / 发布 / 回滚）
├─ 词条表（违禁词·类别·命中范围·改写建议·风险级）
└─ 新增/编辑/删除词条（落入当前草稿）
```

### 3.3 设计约束（功能限制）
1. **改动落草稿、不直接改生效版本**：编辑产生/累积到下一版草稿。
2. **仅"合规审核/超管"可发布**；运营只读/提案。
3. **下发范围 = 全部殡葬租户**（V1 不分群）。
4. **可回滚**到任一历史已发布版本。
5. **风险级 + 命中范围**决定商家端提醒强度与位置（标题/口播/全文）。
6. V1 **提醒非阻断**：`is_block` 字段保留，默认 false。

## 4. 功能需求

### 4.1 版本条
展示：当前生效版本（号/发布时间/词条数/生效租户数）｜ 编辑中草稿（号/+新增 改N）｜ 操作：对比、发布、回滚。

### 4.2 词条表
字段：违禁词/正则 · 类别 · 命中范围 · 改写建议 · 风险级 · 操作(编辑/删除)
- 草稿态新增词条带「vN 新增」标记。

### 4.3 新增 / 编辑词条（弹窗）
| 字段 | 类型 | 必填 | 说明 |
|--|--|:--:|--|
| 违禁词/正则 | str | ✓ | 支持纯词与正则 |
| 类别 | enum | ✓ | 绝对化/虚假承诺/敏感用词/其他 |
| 命中范围 | enum多选 | ✓ | 全文/标题/口播/标签 |
| 改写建议 | str | — | 给客户的替换/弱化建议 |
| 风险级 | enum | ✓ | 高/中/低 |
| 是否阻断 | bool | — | V1 默认 false（提醒） |
- 提交 → 落入当前草稿版本（不立即生效）。删除同理（草稿移除）。

### 4.4 发布 / 回滚
- **发布**：草稿 vN → 二次确认（提示下发租户数）→ 生成下发任务 → 全租户生效 → 写审计；生效版本切到 vN。
- **回滚**：选历史已发布版本 → 确认 → 设为生效 + 下发 → 写审计。
- **对比**：草稿 vs 生效，列出新增/修改/删除词条。

## 5. 状态流转（lexicon_version.status）
```
(草稿 draft) ──发布──▶ (已发布·生效 active) ──被新版本取代──▶ (历史 archived)
     ▲                       │                                  │
     └──继续编辑累积──────────┘            回滚(设为生效)◀─────────┘
```
约束：同一时刻仅一个 `active` 版本；下发以 active 版本为准。

## 6. 数据对象

### 6.1 `lexicon_version`（词库版本，**驱动商家端预审**）
| 字段 | 类型 | 说明 |
|--|--|--|
| version_id | str(PK) | |
| industry | enum | 固定=殡葬 |
| version_no | str | v12 / v13 |

### 6.2 `lexicon_word`（词条）
| 字段 | 类型 | 说明 |
|--|--|--|
| word_id | str(PK) | |
| version_id | ref | 所属版本 |
| pattern | str | 违禁词/正则 |

## 7. 接口草案
| 接口 | 方法 | 入参 | 出参 |
|--|--|--|--|
| 当前版本+草稿 | GET /admin/lexicon | — | {active, draft} |

| 拉取生效词库(商家端) | GET /lexicon/active | industry | active version + words |

## 8. 技术考虑
- 下发用版本号 + 缓存失效广播；商家端预审拉 active 版本（可本地缓存，版本变更即刷新）。
- 正则词条需做安全校验（防灾难性回溯 ReDoS）与性能预算。
- 发布与下发解耦：发布即切 active，下发任务异步推送/失效缓存，失败可重试。
- 回滚本质=把历史版本设为 active 并重新下发，不删历史。

## 9. 风险与依赖

### 9.1 依赖
- 商家端提示词/内容创作模块消费 active 词库做预审。
- 殡葬合规知识——**人工持续投入是前提**，非一次性。

### 9.2 风险
| 风险 | 应对 |
|--|--|
| 误发布致全线误提醒 | 发布前对比 + 一键回滚 |
| 词库覆盖不全漏判违禁 | 提醒非阻断 + 持续维护 + （V2 复核队列兜底） |
| 正则写错拖垮性能 | 提交即校验 + 复杂度预算 |
| 维护断更词库过时 | 排期固定维护节奏、案例驱动更新 |

## 10. 验收标准
1. 可在草稿中新增/编辑/删除词条，带"新增"标记，不影响当前生效版本。
2. 发布草稿后，新版本成为唯一 active，并在 1 分钟内下发全租户、商家端预审生效。
3. 可对比草稿与生效版本，列出新增/修改/删除。
4. 可回滚到历史版本并重新下发，线上立即恢复。
5. 发布/回滚产生审计记录（发布人/时间/版本/下发范围）。
6. 仅"合规审核/超管"能发布，运营无发布权。
7. 命中词条在商家端表现为提醒+改写建议（非阻断，is_block=false）。

## 11. 当前通用产品开发基线（v3.0 · 2026-08-12）

### 11.1 策略层级

合规策略按“平台全局基线 → 行业包 → 租户加严 → 渠道规则”合并。低层只能加严，不能删除全局禁用规则。殡葬仅是一种行业包。

### 11.2 规则类型

支持禁用词、风险表达、必备免责声明、平台敏感规则、事实/价格/承诺人工确认、AI 合成标识、素材授权要求。规则可配置 `warn | require_review | block`，不再默认全部非阻断。

### 11.3 发布与回滚

草稿 → 测试 → 审批 → active；发布前运行 Golden Dataset 和关键渠道回归。失败不得激活；回滚生成新版本并保留原审计，不直接修改历史版本。

### 11.4 验收

1. 不同行业和租户得到正确合并后的策略。
2. 租户不能放松平台全局基线。
3. 高风险价格、承诺、资质和 RPA 发布可配置为强制人工确认。
4. 合规执行记录规则版本、命中位置、处置和操作者。
5. 新版本失败可回滚且不影响历史任务复现。
