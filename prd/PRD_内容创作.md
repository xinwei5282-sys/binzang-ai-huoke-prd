## 1. 文档概述

### 1.1 产品背景

殡葬商家做 2C 获客，内容生产是第一道卡口：靠人写、产能低、偏行业内话术、C 端进不来；且殡葬内容高度敏感，稍不注意就被限流/下架。商家通常**看得懂别人家的爆款、却不会把它变成自己的内容**，也没有把"产品/价格/习俗讲究"这些事实稳定喂进内容的能力。

本模块要解决的核心问题：**让商家从一条参考（或爆款）出发，借助企业自己的知识库与风格提示词，一键产出"形似不抄、合规、按平台适配"的多平台内容，并可继续生成数字人口播成片**——把内容生产从"靠人靠灵感"变成"有流程、可复用、可放量"。

> V1 不做承接转化、不做内容效果归因看板、不做自动定时批量生产；先把"单次创作主流程"打通。

### 1.2 产品目标

- 让运营**从参考/爆款到多平台成稿**在一个向导内完成
- 生成内容**按平台分别适配**（抖音/小红书/视频号/快手）
- 内容**事实由知识库填充、风格由提示词控制**，借模式不洗稿
- 发布前**合规预审**降低限流/下架（提醒式，不阻断）
- 可选**一路出到数字人口播成片**（接蝉镜）
- 创作过程沉淀**爆款模板库 / 行业知识**（资产复利）

### 1.3 核心指标

| 指标 | 目标值 |
|--|--|
| 单条内容（脚本/图文）产出时长 | < 5 分钟 |
| 一次生成覆盖平台数 | ≥ 2 个 |
| 合规提醒采纳率（被提醒后修改） | 可统计、可追溯 |
| 运营独立完成一次创作（无需我方介入） | 100% |
| 拆解结果可编辑落定率 | 100% |

### 1.4 范围

**In-Scope（本期）**
- 参考输入：粘贴文案 / 上传文件 / 来自爆款库 / 粘贴链接（仅抖音 best-effort）
- 行业逻辑拆解（钩子/结构/口播脚本/分镜），逐项可编辑
- 平台与配置：多平台选择 + 知识库范围 + 提示词 + 合规规避
- 按平台分别生成（标题/正文-口播/标签），结果可编辑
- 合规预审提醒（高亮 + 改写建议，非阻断）
- 数字人口播成片（异步，接蝉镜）
- 草稿保存与恢复

**Out-of-Scope（后期）**
- 承接转化 / 私域跟进
- 内容效果回流与归因看板
- 自动定时 / 批量队列生产
- 模板变量渲染体系、A/B 测试
- 自动发布（属"作品库与发布"模块）

## 2. 用户与场景

### 2.1 目标用户

| 角色 | 使用场景 | 核心诉求 |
|--|--|--|
| 运营 | 日常产内容、一稿多平台 | 快、稳、合规、不用自己想 |
| 老板（管理员） | 偶尔自己产、把控调性 | 内容像自家、不踩敏感线 |

### 2.2 典型场景

1. 运营看到同行一条爆款 → 想做一条同款给自家账号

3. 要同时发抖音+小红书 → 一次生成两版适配内容
4. 老板要求出口播视频 → 用老板克隆形象出成片

| US-03 | 运营 | 我可以选目标平台并指定知识库范围与风格提示词 | P0 |

## 3. 整体方案

### 3.1 方案原则

向导式单流程："参考 → 拆解 → 配置 → 生成 → （可选）成片"，五步线性、可回退、可断点。不做过度平台化。

链路：
`选参考 → 行业拆解(可编辑) → 配平台+知识库+提示词 → 按平台分别生成 → 合规提醒 → 存作品库 / 出数字人成片`

### 3.2 模块结构（5 步）

1. 参考输入
2. 拆解编辑
3. 平台与配置
4. 生成结果
5. 数字人成片（可选）

### 3.3 设计约束（功能限制）

- **行业配置化**：拆解和合规加载租户行业/业态策略；殡葬仅作为行业包示例
- **职责分离**：知识库只供事实，提示词只供风格，二者不交叉；合规规避为独立系统层
- **借模式不洗稿**：生成必须用客户自有知识库填充，不照搬参考原文
- **参考链接降级**：链接抓取仅抖音 best-effort，失败必须可回退到"粘文案/上传"；不承诺全平台链接抓取
- **合规非阻断**：合规预审为提醒式，可采纳/忽略，不阻断保存与导出（殡葬命脉，靠"提示词生成前规避 + 提醒 + 人工"三层兜底）
- **成片异步**：数字人成片为长任务，异步提交、完成通知，不阻塞向导
- **按量成本**：生成（LLM token）、成片（蝉镜分钟）均产生采购成本，须计入用量（见用量模块）
- **空库依赖**：知识库为空时仍可生成（仅靠参考+行业），但应提示"补知识库可显著提升质量"

## 4. 功能需求

### 4.1 Step1 · 参考输入

**4.1.1 页面目标**
让运营快速给出一条参考来源，并触发按殡葬逻辑的拆解。

**4.1.2 页面字段**

| 字段 | 控件 | 必填 | 说明 |
|--|--|--|--|
| 参考来源 | 单选切换 | 是 | 粘贴链接 / 粘贴文案 / 来自爆款库 |
| 参考链接 | 输入框 | 条件 | 来源=链接时；支持抖音/小红书链接 |
| 参考文案 | 多行输入 | 条件 | 来源=文案时；直接粘贴 |
| 来源爆款 | 只读带入 | 条件 | 来源=爆款库时，由爆款页带入 |
| 行业/业态 | 只读上下文 | 否 | 来自企业设置；创作任务不重复选择，允许管理员在设置中维护 |
| 解析状态 | 状态标签 | 否 | 解析中/转写中/完成/失败 |

**4.1.3 页面交互**
- 切换来源时显示对应输入区，隐藏其它
- "来自爆款库"跳爆款页，选定后带回参考与标题
- 点"拆解"触发解析；解析期间按钮 loading、显示分段进度

**4.1.4 页面按钮**：`拆解 →`

**4.1.5 校验**
- 链接来源：链接非空且格式合法
- 文案来源：文案非空

**4.1.6 异常场景**

| 场景 | 行为 |
|--|--|
| 链接抓取失败 / 无字幕 | 提示"该链接抓取失败，请改用粘贴文案或上传文件" |
| 小红书链接 | 抓取不稳定，提示优先用文案/上传 |
| 解析超时 | 提示重试或改输入 |

### 4.2 Step2 · 拆解编辑

**4.2.1 页面目标**
把参考按殡葬逻辑拆成可编辑的创作骨架。

**4.2.2 拆解结构 = 通用骨架 + 形态产物双路（2026-06-30 补：图文双路拆解）**

> 缘由：生成要同时覆盖**视频**(抖音/视频号/快手)与**图文**(小红书/图文笔记),两者拆解产物不同。拆解一次产出**通用骨架**(两路共用)+ 按形态产出**视频路 / 图文路**两套产物,Step4 按所选平台各取其路。

**① 通用骨架（两路共用，均可编辑）**
| 字段 | 说明 |
|--|--|
| 钩子 | 前 3 秒/首屏抓人点（禁忌型/信息差型…） |
| 结构 | 叙事骨架（痛点→科普→方案→引导） |
| 情绪 / 卖点 | 情绪走向 + 要突出的卖点 |
| CTA | 引导动作（评论扣1/私信/收藏） |
| 可迁移公式 | 系统提炼，**沉淀进作品库（形态=公式）**，只读展示、可「用它新建」复用 |

**② 视频路产物**（目标平台含视频时产出）
| 字段 | 说明 |
|--|--|
| 口播脚本 | 可直接配音的完整脚本 |
| 分镜 | 镜头序列（序号·画面·口播·时长），喂数字人/视频模板 |

**③ 图文路产物**（目标平台含小红书/图文时产出）
| 字段 | 说明 |
|--|--|
| 正文结构 | 种草段落骨架（开头钩子段·痛点段·干货/对比段·收尾引导段） |
| 配图脚本 | 每张图说什么（图序·画面内容·图注文案），喂图文生成/配图召回 |
| 话题标签 | 平台话题/关键词标签 |

**分流规则**：拆解时按「参考类型 + Step3 目标平台形态」决定产出哪路——只选视频平台→产①+②；只选图文平台→产①+③；两者都选→①+②+③全产，生成时各平台取对应路。参考本身是图文还是视频不限制产出路（两路都可由通用骨架派生）。

**4.2.3 页面交互**
- 通用骨架 + 已产出的形态产物，每项右侧"编辑"→ 就地可编辑（高亮）→ "保存"落定
- 展示"可迁移公式"并提示**将沉淀进作品库（形态=公式），可在作品库「用它新建」复用**

**4.2.4 页面按钮**：`← 重新拆`、`下一步：平台与配置 →`

**4.2.5 异常场景**

| 场景 | 行为 |
|--|--|
| 拆解为空/失败 | 提示重试；允许手动补写各项 |

### 4.3 Step3 · 平台与配置

**4.3.1 页面目标**
确定生成哪些平台、用什么风格提示词。知识库无需选择，系统自动调用整个公司知识库。

**4.3.2 页面字段**

| 字段 | 控件 | 必填 | 默认 | 说明 |
|--|--|--|--|--|
| 目标平台 | 多选 | 是 | 抖音+小红书 | 抖音/小红书/视频号/快手，至少 1 个 |
| 风格 | 下拉 | 否 | 温情风 | **选风格(微调层 tone)**，非选单条提示词；基线/合规/生成参数自动应用，详见下 |
| 合规规避 | 开关 | 是 | 开（锁定） | 系统殡葬规则，不可关 |

> **提示词三层（对齐 [[PRD_提示词]] v2.0，2026-06-30）**：本步只暴露**风格选择**(商家微调层的 tone)。系统基线(拆解/仿写/合规/画面)、商家微调层(品牌词/卖点/禁忌)、生成参数(温度等·按商户)均由后台/「提示词微调」页维护并**自动应用**——本页**不再是"选单条 promptId"**，只读展示"已应用：基线 + 你的微调 + 合规"。
> **硬事实精确召回（约定消费侧，2026-06-30）**：仿写时对拆解出的每个**产品实体**(如"真丝寿衣")，按 **`product_id` 关联**到知识库结构化事实(价格/规格)做**精确填充**，未命中留空不编造、生成后回检(见 §11.2)。`product_id` 的生成/跨源对齐机制归 [[PRD_多模态知识库底座]]，本模块为**消费方**：拆解产物对识别出的产品实体打 `product_id` 引用,生成时据此精确取数。
> **设计约束**：知识库默认调用整个公司知识库，V1 不开放按分类筛选。页面只读提示"知识库：全公司 XX 条事实（自动）"，不提供下拉选择。

**4.3.3 页面交互**
- 平台至少选 1 个，否则不可生成
- 合规规避显示"已启用·锁定"，不可操作
- 知识库范围显示只读文字说明，不可交互

**4.3.4 页面按钮**：`← 返回`、`生成各平台内容 →`

**4.3.5 校验**：目标平台 ≥ 1

### 4.4 Step4 · 生成结果

**4.4.1 页面目标**
按所选平台分别生成内容，供编辑与合规处理。

**4.4.2 页面结构**
- 平台 Tab（按所选平台）
- 每平台：标题、正文/口播、标签（均可编辑）
- 合规提醒条（如有）

**4.4.3 字段**

| 字段 | 说明 |
|--|--|
| 平台 Tab | 切换查看各平台版本 |
| 标题 | 可编辑 |
| 正文/口播 | 可编辑；抖音偏口播、小红书偏图文笔记 |
| 标签/话题 | 可编辑 |
| 合规提醒 | 违禁词 + 改写建议 + 处理状态 |

**4.4.4 页面交互**
- 切 Tab 内容随平台变化（各平台适配文案）
- 合规提醒：`采纳改写`（替换文本，提醒转绿/已处理）/ `忽略`（隐藏）
- 单平台生成失败可"重试该平台"

**4.4.5 页面按钮**：`← 配置`、`就到脚本/图文`（存作品库结束）、`→ 数字人成片`

**4.4.6 状态**

| 状态 | 说明 |
|--|--|
| 生成中 | 多平台并行，逐个就绪 |
| 部分失败 | 成功的正常展示，失败平台单独重试 |
| 全部失败 | 提示重试/返回配置 |

**4.4.7 合规提醒规则**
- 检测违禁/敏感表达（殡葬词库），给"国标俗称↔合规说法"改写建议
- **提醒非阻断**：可采纳/忽略；忽略也能存/导出
- 处理状态：待处理/已采纳/已忽略（作品库可筛）

**4.4.8 图文形态展示 ——「图文预览」（🆕 v1.4）**

> 缘由：v1.3 图文路拆出了「配图脚本」（每张图说什么），但 Step4 只展示标题/正文/标签三个纯文本字段——配图没变成图、也没地方展示图，"图文"实际只交付了"文"。本节补齐展示与配图生成。

- **展示结构**：图文平台（小红书等）的查看结果新增「**图文预览**」tab，**左右分栏**（与成片视图"左视频/右口播"同构）：
  - **左：配图预览**——按「配图脚本」逐张对应（P1 封面 + 内页图），小红书 3:4 比例，图上可叠**图注文字**（套壳渲染，零成本）；每张图可「**换图**（素材库召回/本地上传，上传默认入素材库）/ **重生成**（阿里云文生图）」。
  - **右：文案区**——标题、正文（可编辑）、话题标签、合规提醒，独立滚动。
- **配图来源三级降级**（不硬凑）：① 素材库按 `product_id`/标签召回**产品实拍**（最真·零成本）→ ② **阿里云文生图**（`qwen-image`/`wanx-v1`，约几毛/张）→ ③ 无合格候选则**留空 + 提示补素材**。
- **多平台规则（🆕 2026-07-05 定）**：**图片本体一套共用、文字层按平台适配**——配图脚本平台无关，图片（实拍召回/文生图）只生成一次、所选图文平台复用同一组（文生图按张计费，重复生成纯浪费；小红书/抖音图文同为 3:4 不需重出）；**图注/封面大字为零成本套壳**，跟随各平台文案分别叠加。**文案/标题/标签按平台分别生成**（既有设计，§4.4.2 平台 Tab）。某平台单独换图/重生成时只作用于该平台——`images(json)` 按平台存引用，默认指向同一组图，换过才分叉。
- **无确认门**：图片便宜，图文**直接生成**（不设人工确认门），生成后可随时换图/重生成；这是与视频路（两级确认门，见 [[PRD_视频模板化生成与换人换产品]] §4.5）的关键区别。
- **出口**：小红书无开放接口 → **导出 zip（N 张图 + 文案 txt）手动发布**；或存作品库（形态=图文）后从作品库导出。
- **统一能力**：「配图脚本/分镜 → 图（召回 or 文生图）→ 确认/替换」与视频路分镜首帧图为**同一套能力**——图文走到图片层即交付，视频在图片确认后再 i2v。

## 8. 技术考虑

- **生成**：调 LLM；prompt = 拆解骨架 + 知识库检索(事实) + 风格提示词 + 平台适配 + 合规规避规则
- **合规**：生成时 prompt 规避 + 生成后 LLM/词库二次检测；用 LLM 结构化抽取判违禁，不用纯字符串匹配
- **成片**：蝉镜异步任务（提交→轮询/回调→落库 video_url），失败不扣额度
- **参考链接**：抖音 best-effort（可复用现有抓取/转写能力），不稳定即回退
- **异步与通知**：生成（秒级）、成片（分钟级）走任务化 + 通知中心
- **成本计量**：生成按 token、成片按分钟，写入用量

## 11. AI 能力规格

> 模板 = AI PM Playbook 6 段 + **内容生成类变体**（质量要求/不适内容过滤/幻觉处理/编辑修改率）。
> 共性约定：**模型 = 国产 LLM（DeepSeek / 通义 / Kimi 官方 API，合规直连、中文强，多家可切换）**，按 token 计费、量级低；**RAG/检索与硬事实精确召回归属 [[PRD_多模态知识库底座]] §12**（本模块只发起检索、消费事实，不重复规格）；**口播转写 ASR 归属 [[PRD_爆款抓取]] §11**；**所有提示词由后台运营维护、客户端不可编辑**（客户端只「选风格 / 套爆款公式」，对齐 v1.1 变更 2）。数字人成片 → [[PRD_数字人]] §11.2。

### 11.1 爆款拆解（LLM，八维度 → 公式 · 内容生成类）

**① 能力定义与边界**
- 背景/必要性：商家看得懂爆款却不会变成自己的内容；拆解把爆款转成可复用创作骨架。
- 成功标准：拆出钩子/结构/口播脚本/分镜，逐项可编辑落定率 100%（§1.3）。
- 约束：拆解规则由平台按行业/业态适配；租户可调整品牌微调层，但不能修改系统结构与合规底线。
- 能做：结构化拆解 + 提炼可迁移公式。**不能做（不确定性）**：保证拆解 100% 准确（可人工补写）、跨行业拆解（V1 不支持）。

**② 输入/输出规范**
- I/O 契约：入 = 参考文本（文案/转写稿/burst_item）+ 行业=殡葬；出 = `content_dissection`(hook·structure·script·storyboard(json)·transferable_formula)，逐项可编辑。
- 边界条件：参考来自链接转写时依赖 [[PRD_爆款抓取]] §11 ASR，失败回退粘贴/上传（§4.1.6）。
- 错误处理：拆解为空/失败 → 提示重试 + 允许手动补写各项（§4.2.5）。

**③ AI 技术需求**
- 模型选型：国产 LLM 官方 API（DeepSeek/通义/Kimi，合规直连、中文强）；多家可切换。
- 数据需求：八维度拆解规则模板（平台按行业维护的后台资产）；沉淀 transferable_formula **归入作品库（形态=公式）**，客户只读/「用它新建」复用、**不可手动新建或编辑公式规则**（规则=提示词，归后台）；无需自训练，规则随行业版本更新。
- Prompt/参数策略：低 temperature 求稳定结构化抽取；拆解规则 prompt **后台维护、客户端不可编辑**。
- 性能要求：拆解时延秒级（**目标值待压测**）。
- 内容生成类变体：质量 = 结构字段完整率（**目标待压测**）；编辑修改率 = 拆解结果被人工编辑的比例（监控项，越低越好）。

**④ 评估标准**
- 分层：系统层 = 拆解成功率/时延；模块层 = 字段完整率 + 公式可用性（**目标待压测**）；业务层 = 进 Step2 后落定率 100%、拆解→生成转化。
- Golden Dataset：标注好"标准拆解"的殡葬爆款样本集，规模**待建**。
- 验收 Pass/Fail：八字段齐全且可编辑落定 = Pass；结构错乱/字段缺失致无法编辑 = Fail。
- BadCase 闭环：拆错钩子/结构 → 收集 → 归因（规则/输入质量）→ 优化拆解规则模板。

**⑤ 灰度上线**
- 灰度策略：随内容创作向导上线。
- 监控指标：拆解成功率 / 字段完整率 / 编辑修改率 / 时延。
- 回滚方案：失败率超阈值 → 切换备用 LLM；极端 → 纯手动补写。

**⑥ 风险与缓解**
- 幻觉：拆解为结构提炼、不输出对外发布文案，合规在生成阶段把关。
- 版权：不照搬参考原文（借模式不洗稿，§3.3）。
- 成本：单次 token 量级低，**待核实**。

### 11.2 仿写生成（LLM + 知识库 RAG · 内容生成类）

**① 能力定义与边界**
- 背景/必要性：以拆解骨架为模板、用企业自有知识库事实填充，按平台分别生成"形似不抄、合规"的成稿。
- 成功标准：一次生成覆盖平台 ≥ 2、**硬事实零编造**（价格/规格与知识库一致）。
- 约束：知识库只供事实、提示词只供风格，二者不交叉（§3.3 职责分离）；合规为独立系统层。
- 能做：多平台适配文案生成 + 知识库事实填充。**不能做（不确定性）**：🔴 **杜撰价格/规格**（召回为空必须留空/提示）；保证 100% 不被限流（合规为提醒式三层兜底）。

**② 输入/输出规范**
- I/O 契约：入 = 拆解骨架 + 目标平台(多选) + 风格提示词 + 知识库检索结果（全公司事实，自动）；出 = `content_generation`（按平台一条：title·body·tags·compliance_flags·token_usage）。
- 边界条件：空知识库 → 仍可生成（仅靠参考+行业）并提示"补库提质"（§3.3）。
- 错误处理：单平台失败 → "重试该平台"不影响其它（§4.4.6）；硬事实召回为空 → 留空+提示补库，不编造。

**③ AI 技术需求**
- 模型选型：国产 LLM 官方 API（同 §11.1）；**RAG 检索与硬事实精确召回归属 [[PRD_多模态知识库底座]] §12**（结构化精确召回不进向量库、未命中留空），本模块只发起检索并把事实喂入 prompt。
- 数据需求：企业自有知识库（结构化事实 + 非结构化文案/品牌口径）+ 风格提示词库 + 殡葬合规词库；事实更新依赖客户维护知识库；无需自训练模型。
- Prompt/参数策略：prompt = 拆解骨架 + 知识库事实 + 风格提示词 + 平台适配 + 合规规避规则（§8）；🔴 **硬事实只用知识库精确召回值，禁止 LLM 杜撰**；提示词**后台维护、客户端不可编辑**。
- 性能要求：多平台并行生成时延、单平台成功率（**目标值待压测**）。
- 内容生成类变体：质量 = 硬事实一致率 100%（**目标待压测**）；不适内容过滤 = 殡葬词库违禁检测（LLM 结构化抽取判违禁，非纯字符串，§8）；幻觉处理 = 事实走精确召回、召回空则留空；编辑修改率 = 监控项。

**④ 评估标准**
- 分层：系统层 = 各平台生成成功率/时延；模块层 = 硬事实编造率(抽检) + 合规命中率（**目标待压测**）；业务层 = 覆盖平台数 ≥ 2、合规提醒采纳率可追溯。
- Golden Dataset：含已知价格/规格的殡葬样本 + 违禁词样本集，用于核"事实一致 + 违禁拦截"，规模**待建**。
- 验收 Pass/Fail：硬事实与知识库一致且违禁词被提醒 = Pass；**编造价格/规格 = 直接 Fail**。
- BadCase 闭环：编造事实/漏判违禁 → 收集 → 归因（召回缺失/prompt/词库）→ 补库或调词库。

**⑤ 灰度上线**
- 灰度策略：随向导上线，先小流量核事实一致率。
- 监控指标：硬事实编造率 / 平台生成成功率 / 合规命中率 / 编辑修改率。
- 回滚方案：编造/越线超阈值告警；多家 LLM 可切换；极端 → 收紧为"必须命中知识库才生成事实句"。

**⑥ 风险与缓解**
- 幻觉：🔴 **事实不编造**——价格/承诺靠知识库精确召回，技术保障见 [[PRD_多模态知识库底座]] §12 第 2 行 / [[技术方案-知识库精确召回与事实校验-殡葬V1]]。
- 版权：借模式不洗稿，用自有知识库填充、不照搬原文。
- 合规：生成即过合规规避规则（殡葬词库）+ 生成后二次检测；提醒式三层兜底（prompt 规避+提醒+人工）。
- 成本：按 token 计入用量，量级低。

### 11.3 脚本 / 口播文案生成（LLM · 内容生成类）

**① 能力定义与边界**
- 背景/必要性：把拆解脚本/成稿变成可直接配音的口播稿，喂数字人成片（Step4→Step5）。
- 成功标准：口播稿可配音可用、时长可控。
- 约束：含价格/承诺的口播稿须过人工"已核对价格无误"门（[[PRD_数字人]] §11.2 / §3.3-6）。
- 能做：口语化、断句、时长适配的口播稿。**不能做（不确定性）**：编造价格/承诺（同 §11.2）。

**② 输入/输出规范**
- I/O 契约：入 = 拆解脚本/成稿 + 风格 + 时长约束；出 = 口播稿(text)，默认带入 Step5 可改（§4.5.2）。
- 边界条件：时长超限 → 按预计时长提示精简。
- 错误处理：生成失败 → 重试或直接复用拆解 `script` 字段。

**③ AI 技术需求**
- 模型选型：国产 LLM 官方 API（同 §11.1）；多家可切换。
- 数据需求：复用拆解脚本/成稿 + 口播风格提示词；无需自训练。
- Prompt/参数策略：口播提示词（口语化/断句/时长控制）**后台维护、客户端不可编辑**。
- 性能要求：生成时延秒级（**目标值待压测**）。
- 内容生成类变体：质量 = 可配音可用率（**目标待压测**）；幻觉处理 = 事实同 §11.2（不编造价格/承诺）。

**④ 评估标准**
- 分层：系统层 = 生成成功率/时延；模块层 = 口播可用率 + 时长达标率（**目标待压测**）；业务层 = 进成片的稿件通过率。
- Golden Dataset：与 §11.2 共用 + 口播专项样本，规模**待建**。
- 验收 Pass/Fail：口播稿可直接配音且时长达标 = Pass；含未核价格直接进成片 = Fail。
- BadCase 闭环：拗口/超时/事实错 → 收集 → 归因 → 调口播 prompt。

**⑤ 灰度上线**
- 灰度策略 / 监控指标 / 回滚方案：随仿写生成统一管理（token 成本、成功率、合规命中、编辑修改率）。

**⑥ 风险与缓解**
- 幻觉/事实：同 §11.2，含价格/承诺走人工确认门。
- 合规：口播稿过合规规避 + 预审（殡葬词库）。
- 成本：按 token，量级低。

## 12. 通用企业产品专项需求（v3.1 · 2026-08-13）

### 12.1 统一内容工厂

当前营销物料统一使用 `content-factory-v1`，共享已确认企业知识、已启用企业 VI、已授权素材和合规策略。渠道 Agent 只负责结构与平台适配，不得突破事实和审核边界。

| 渠道 | 核心产物 | 审核后终点 |
|---|---|---|
| PPT | 可编辑页面、引用、PPTX/PDF | 大纲确认后异步生成，成品直接下载 |
| 朋友圈图文 | 封面、正文、配图、CTA | 图文包导出 |
| 海报 | 主标题、主视觉、CTA | 图片下载 |
| 公众号文章 | 标题、摘要、正文、封面、配图、CTA | 选择账号与方式后发布 |

朋友圈和海报没有发布、账号选择和结果回收。PPT 只做文件交付，不进入发布和结果回收。公众号创建时必须选择具体公众号和 `api/rpa/manual` 中该账号实际支持的方式。

### 12.2 PPT 创建、异步生成与编辑

#### 12.2.1 问题与目标

PPT 的完整生成耗时较长，不适合将“生成中”和“成品审核”放入需要用户持续停留的步骤条。用户只需参与需求输入和大纲审核；完整 PPT 在后台生成，生成后可直接下载或进入独立编辑页修改。

#### 12.2.2 用户流程

1. 用户用一句话说明 PPT 用途、对象和目标；参考文件可选。
2. 系统读取企业大脑正式知识、已确认案例和已启用企业 VI，生成逐页大纲。
3. 用户可修改每页标题和目的，确认大纲后才创建完整 PPT 任务。
4. 系统返回 PPT 列表，任务显示“生成中”；用户可离开页面处理其他工作。
5. 完成后状态变为“可下载”，可直接下载 PPTX/PDF，不设成品审核门。
6. 点击“预览 / 编辑”时新开独立页面，原 PPT 列表保留。

#### 12.2.3 创建页与任务状态

- 创建页只展示两个即时阶段：`01 填写需求` 和 `02 审核大纲`。
- 大纲未人工确认时，不得创建完整 PPT 任务。
- 任务状态为 `brief → outline_review → generating → ready`；异常进入 `failed`，支持重试。
- `generating` 不提供下载；`ready` 同时提供“预览 / 编辑”、“下载 PPTX”和“下载 PDF”。
- 列表保留历史 PPT、版本、生成时间和状态。

#### 12.2.4 独立预览 / 编辑页

- 页面为三区布局：左侧页面缩略图，中间当前页画布，右侧 AI 追问、替换图片和页面操作；三列占满标题栏以下一屏且高度一致。
- 左侧栏头和添加页面固定，缩略图列表独立纵向滚动；移动端缩略图改为横向滚动。
- 中间画布的标题和正文可直接点击编辑；悬停或聚焦时显示轻量边界。
- 停止输入或离开文字区后自动保存，展示“保存中 / 已保存 / 保存失败”。
- 修改只影响当前选中页；切换页面后，其他页内容不变。
- 保留上一页、下一页、全屏播放和 PPTX/PDF 下载。
- 标题、正文、页码/栏目、指标组、要点组和来源文字可在画布安全边界内任意拖拽，坐标按页、按元素自动保存。
- 右侧不显示模式切换、设计工具、版式候选、“编辑图表”或标题/正文结构化表单。

#### 12.2.5 AI 追问修改

- AI 每次只修改当前页，输入包括当前页、用户追问、已审核大纲、企业大脑正式知识和已启用 VI。
- 追问先生成当前页候选版，未点击“采用新版”前不覆盖原页。
- 用户可选择“采用新版”或“撤回”；采用后只更新当前页，整套 PPT 版本号递增。
- 追问失败时保留原页，显示原因和重试入口，不阻断下载已有版本。

#### 12.2.6 数据与边界

- PPT 任务必须保存需求、大纲版本、企业知识快照、VI 版本、页面版本和生成错误。
- 未确认候选知识不得注入 PPT；价格、案例、效果承诺无正式来源时必须留空或标记缺口。
- 本期支持文字类元素自由拖拽；图片/图形自由拖拽、图层编辑、对齐参考线、群组和矢量节点编辑不在本期。
- PPT 不设发布、账号选择和结果回收。
- 静态原型中的定时器、下载提示和演示数据只表达交互，不代表真实 PPT 生成、存储或下载服务已接入。

### 12.3 通用生成状态

```text
draft → generating → pending_review → approved → exported | publishing → published
              ↘ failed → retrying
编辑或重新生成：approved/pending_review → pending_review（新版本）
```

PPT 使用上述独立状态机，不强制套用图文内容的 `pending_review → approved` 成品审核门。

### 12.4 Prompt 与 Skill

- 全局安全基线、意图路由、内容工厂和公众号 Prompt 使用 [[PRD_企业AI经营大脑_当前开发基线]] P-000、P-001、P-040、P-041。
- 每次执行记录 `skill_id`、`skill_version`、`prompt_id`、`prompt_version`、知识快照和 VI 版本。
- 图片由 `imagegen` 等价服务生成；生产服务、版权检查和素材授权仍需接入。

### 12.5 验收

1. 朋友圈页面只有新建、预览、编辑、审核、导出。
2. 海报页面只有新建、预览、编辑、审核、下载。
3. 公众号无账号或发布方式时不得创建发布任务。
4. 未启用 VI 不进入生成；价格、地址、案例、承诺无来源时进入 `gaps`。
5. 输出必须通过 JSON Schema、事实引用和合规检查后才生成业务草稿。
6. PPT 创建页只有“填写需求 / 审核大纲”两个即时阶段；未确认大纲时不能开始完整生成。
7. 大纲确认后返回列表并显示“生成中”；完成后可直接下载 PPTX/PDF，不出现成品审核入口。
8. 点击“预览 / 编辑”新开独立页面，原列表页保留，新页直接进入对应 PPT。
9. 画布标题和正文可直接编辑并显示保存状态；修改当前页不得影响其他页。
10. 右侧只显示 AI 追问、候选版采用和撤回，不显示结构化编辑表单或模式切换。
11. AI 候选版未采用时不覆盖原页；采用后只更新当前页并递增版本号。
12. 桌面 1440×900 和移动 390×844 下无空白页、无横向溢出、无控制台错误。
