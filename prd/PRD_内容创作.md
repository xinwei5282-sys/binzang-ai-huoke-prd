## 1. 文档概述

### 1.1 产品背景

殡葬商家做 2C 获客，内容生产是第一道卡口：靠人写、产能低、偏行业内话术、C 端进不来；且殡葬内容高度敏感，稍不注意就被限流/下架。商家通常**看得懂别人家的爆款、却不会把它变成自己的内容**，也没有把"产品/价格/习俗讲究"这些事实稳定喂进内容的能力。

本模块要解决的核心问题：**让商家从一条参考（或爆款）出发，借助企业自己的知识库与风格提示词，一键产出"形似不抄、合规、按平台适配"的多平台内容，并可继续生成数字人口播成片**——把内容生产从"靠人靠灵感"变成"有流程、可复用、可放量"。

> V1 不做承接转化、不做内容效果归因看板、不做自动定时批量生产；先把"单次创作主流程"打通。

### 1.2 产品目标

- 让运营**从参考/爆款到多平台成稿**在一个向导内完成
- 生成内容**按平台分别适配**（抖音/小红书/视频号/快手）
- 内容**事实由知识库填充、风格由提示词控制**，借模式不洗稿
- 发布前**合规预审**降低限流/下架（提醒式，不阻断）
- 可选**一路出到数字人口播成片**（接蝉镜）
- 创作过程沉淀**爆款模板库 / 行业知识**（资产复利）

### 1.3 核心指标

| 指标 | 目标值 |
|--|--|
| 单条内容（脚本/图文）产出时长 | < 5 分钟 |
| 一次生成覆盖平台数 | ≥ 2 个 |
| 合规提醒采纳率（被提醒后修改） | 可统计、可追溯 |
| 运营独立完成一次创作（无需我方介入） | 100% |
| 拆解结果可编辑落定率 | 100% |

### 1.4 范围

**In-Scope（本期）**
- 参考输入：粘贴文案 / 上传文件 / 来自爆款库 / 粘贴链接（仅抖音 best-effort）
- 行业逻辑拆解（钩子/结构/口播脚本/分镜），逐项可编辑
- 平台与配置：多平台选择 + 知识库范围 + 提示词 + 合规规避
- 按平台分别生成（标题/正文-口播/标签），结果可编辑
- 合规预审提醒（高亮 + 改写建议，非阻断）
- 数字人口播成片（异步，接蝉镜）
- 草稿保存与恢复

**Out-of-Scope（后期）**
- 承接转化 / 私域跟进
- 内容效果回流与归因看板
- 自动定时 / 批量队列生产
- 模板变量渲染体系、A/B 测试
- 自动发布（属"作品库与发布"模块）

### 2.2 典型场景

## 3. 整体方案

### 3.1 方案原则

向导式单流程："参考 → 拆解 → 配置 → 生成 → （可选）成片"，五步线性、可回退、可断点。不做过度平台化。

链路：
`选参考 → 行业拆解(可编辑) → 配平台+知识库+提示词 → 按平台分别生成 → 合规提醒 → 存作品库 / 出数字人成片`

### 3.2 模块结构（5 步）

1. 参考输入
2. 拆解编辑
3. 平台与配置
4. 生成结果
5. 数字人成片（可选）

### 3.3 设计约束（功能限制）

- **行业固定殡葬**：拆解逻辑、合规规则均按殡葬，V1 不支持切行业
- **职责分离**：知识库只供事实，提示词只供风格，二者不交叉；合规规避为独立系统层
- **借模式不洗稿**：生成必须用客户自有知识库填充，不照搬参考原文
- **参考链接降级**：链接抓取仅抖音 best-effort，失败必须可回退到"粘文案/上传"；不承诺全平台链接抓取
- **合规非阻断**：合规预审为提醒式，可采纳/忽略，不阻断保存与导出（殡葬命脉，靠"提示词生成前规避 + 提醒 + 人工"三层兜底）
- **成片异步**：数字人成片为长任务，异步提交、完成通知，不阻塞向导
- **按量成本**：生成（LLM token）、成片（蝉镜分钟）均产生采购成本，须计入用量（见用量模块）
- **空库依赖**：知识库为空时仍可生成（仅靠参考+行业），但应提示"补知识库可显著提升质量"

## 4. 功能需求

### 4.1 Step1 · 参考输入

**4.1.1 页面目标**
让运营快速给出一条参考来源，并触发按殡葬逻辑的拆解。

**4.1.2 页面字段**

| 字段 | 控件 | 必填 | 说明 |
|--|--|--|--|
| 参考来源 | 单选切换 | 是 | 粘贴链接 / 粘贴文案 / 来自爆款库 |
| 参考链接 | 输入框 | 条件 | 来源=链接时；支持抖音/小红书链接 |
| 参考文案 | 多行输入 | 条件 | 来源=文案时；直接粘贴 |
| 来源爆款 | 只读带入 | 条件 | 来源=爆款库时，由爆款页带入 |
| ~~所属行业~~ | — | — | **v1.2 删除**：行业写死殡葬，配置页不再展示该字段 |
| 解析状态 | 状态标签 | 否 | 解析中/转写中/完成/失败 |

**4.1.3 页面交互**
- 切换来源时显示对应输入区，隐藏其它
- "来自爆款库"跳爆款页，选定后带回参考与标题
- 点"拆解"触发解析；解析期间按钮 loading、显示分段进度

**4.1.4 页面按钮**：`拆解 →`

**4.1.5 校验**
- 链接来源：链接非空且格式合法
- 文案来源：文案非空

**4.1.6 异常场景**

| 场景 | 行为 |
|--|--|
| 链接抓取失败 / 无字幕 | 提示"该链接抓取失败，请改用粘贴文案或上传文件" |
| 小红书链接 | 抓取不稳定，提示优先用文案/上传 |
| 解析超时 | 提示重试或改输入 |

### 4.2 Step2 · 拆解编辑

**4.2.1 页面目标**
把参考按殡葬逻辑拆成可编辑的创作骨架。

**4.2.2 页面字段（拆解结果，均可编辑）**

| 字段 | 说明 |
|--|--|
| 钩子 | 前 3 秒抓人点（如禁忌型/信息差型） |
| 结构 | 叙事骨架（如 痛点→科普→方案→引导） |
| 口播脚本 | 可直接配音的完整脚本 |
| 分镜 | 镜头序列（画面+口播） |
| 可迁移公式 | 系统提炼，沉淀进爆款模板库（只读展示，可一键存模板库） |

**4.2.3 页面交互**
- 每项右侧"编辑"→ 就地可编辑（高亮）→ "保存"落定
- 展示"可迁移公式"并提示将沉淀进「殡葬爆款模板库」

**4.2.4 页面按钮**：`← 重新拆`、`下一步：平台与配置 →`

**4.2.5 异常场景**

| 场景 | 行为 |
|--|--|
| 拆解为空/失败 | 提示重试；允许手动补写各项 |

### 4.3 Step3 · 平台与配置

**4.3.1 页面目标**
确定生成哪些平台、用什么风格提示词。知识库无需选择，系统自动调用整个公司知识库。

**4.3.2 页面字段**

| 字段 | 控件 | 必填 | 默认 | 说明 |
|--|--|--|--|--|
| 目标平台 | 多选 | 是 | 抖音+小红书 | 抖音/小红书/视频号/快手，至少 1 个 |
| 选用提示词 | 下拉 | 否 | 我的·温情风 | 客户风格提示词之一 |
| 合规规避 | 开关 | 是 | 开（锁定） | 系统殡葬规则，不可关 |

> **设计约束**：知识库默认调用整个公司知识库，V1 不开放按分类筛选。页面只需展示"知识库：全公司 XX 条事实（自动）"作为只读提示，不提供下拉选择。

**4.3.3 页面交互**
- 平台至少选 1 个，否则不可生成
- 合规规避显示"已启用·锁定"，不可操作
- 知识库范围显示只读文字说明，不可交互

**4.3.4 页面按钮**：`← 返回`、`生成各平台内容 →`

**4.3.5 校验**：目标平台 ≥ 1

### 4.4 Step4 · 生成结果

**4.4.1 页面目标**
按所选平台分别生成内容，供编辑与合规处理。

**4.4.2 页面结构**
- 平台 Tab（按所选平台）
- 每平台：标题、正文/口播、标签（均可编辑）
- 合规提醒条（如有）

**4.4.3 字段**

| 字段 | 说明 |
|--|--|
| 平台 Tab | 切换查看各平台版本 |
| 标题 | 可编辑 |
| 正文/口播 | 可编辑；抖音偏口播、小红书偏图文笔记 |
| 标签/话题 | 可编辑 |
| 合规提醒 | 违禁词 + 改写建议 + 处理状态 |

**4.4.4 页面交互**
- 切 Tab 内容随平台变化（各平台适配文案）
- 合规提醒：`采纳改写`（替换文本，提醒转绿/已处理）/ `忽略`（隐藏）
- 单平台生成失败可"重试该平台"

**4.4.5 页面按钮**：`← 配置`、`就到脚本/图文`（存作品库结束）、`→ 数字人成片`

**4.4.6 状态**

| 状态 | 说明 |
|--|--|
| 生成中 | 多平台并行，逐个就绪 |
| 部分失败 | 成功的正常展示，失败平台单独重试 |
| 全部失败 | 提示重试/返回配置 |

**4.4.7 合规提醒规则**
- 检测违禁/敏感表达（殡葬词库），给"国标俗称↔合规说法"改写建议
- **提醒非阻断**：可采纳/忽略；忽略也能存/导出
- 处理状态：待处理/已采纳/已忽略（作品库可筛）

### 4.5 Step5 · 数字人成片（可选）

**4.5.1 页面目标**
把脚本变成数字人口播成片。

**4.5.2 字段**

| 字段 | 控件 | 必填 | 说明 |
|--|--|--|--|
| 选用形象 | 下拉(分组) | 是 | 我的生成形象 / 默认公模形象 |
| 选用声音 | 下拉 | 是 | 音色库 / 复刻声音 |
| 口播稿 | 多行输入 | 是 | 默认取 Step4 脚本，可改 |
| 字幕/背景模板 | 下拉 | 否 | 素雅模板等 |
| 预计时长 | 只读 | 否 | 系统估算 |

**4.5.3 页面交互**
- 点"生成成片"→ 提交蝉镜异步任务 → 提示"完成后通知" → 成片回作品库
- 形象/声音来源与配额限制见「数字人」模块（克隆形象限 2 个、单独计费；公模不占额度）

**4.5.4 状态**：成片中（异步）/ 成功 / 失败（可重试）

**4.5.5 异常**

| 场景 | 行为 |
|--|--|
| 未选可用形象/声音 | 不允许提交，提示去数字人页准备 |
| 蝉镜任务失败 | 通知失败，可重试，不扣形象额度 |

## 5. 状态流转（创作草稿）

```text
新建草稿
  -> 参考已输入 -> 拆解完成 -> 配置完成 -> 已生成
已生成
  -> 已存稿（就到脚本/图文，进作品库）
  -> 成片中 -> 已成片（进作品库）
任一步可保存为草稿；草稿可在工作台恢复。
```

- 草稿状态：`参考/拆解/配置/生成/成片/完成`
- 成片为异步终态分支，不阻塞主流程

## 8. 技术考虑

- **生成**：调 LLM；prompt = 拆解骨架 + 知识库检索(事实) + 风格提示词 + 平台适配 + 合规规避规则
- **合规**：生成时 prompt 规避 + 生成后 LLM/词库二次检测；用 LLM 结构化抽取判违禁，不用纯字符串匹配
- **成片**：蝉镜异步任务（提交→轮询/回调→落库 video_url），失败不扣额度
- **参考链接**：抖音 best-effort（可复用现有抓取/转写能力），不稳定即回退
- **异步与通知**：生成（秒级）、成片（分钟级）走任务化 + 通知中心
- **成本计量**：生成按 token、成片按分钟，写入用量

## 9. 风险与依赖

### 9.1 依赖
- 知识库可检索（RAG 就绪）、提示词可用
- 蝉镜成片 API（形象/声音/合成任务）
- LLM 服务、ASR（链接/上传音视频转写）

### 9.2 风险

| 风险 | 可能性 | 影响 | 应对 |
|--|--|--|--|
| 合规漏判致限流/下架 | 中 | 高 | 三层兜底（prompt 规避+提醒+人工）+ 词库持续维护 |
| 空知识库生成质量差 | 中 | 中 | 空态提示补库；允许生成但标注 |
| 参考链接抓取不稳 | 高 | 中 | 主路径粘文案/上传，链接仅 best-effort |
| 多平台生成部分失败 | 中 | 低 | 单平台重试，不影响其它 |
| 成片成本失控 | 中 | 中 | 用量计量 + 形象额度 + 公模优先 |

## 10. 验收标准

1. 可用 粘文案/上传/爆款 三种来源触发拆解；链接抓取失败有回退
2. 拆解出钩子/结构/脚本/分镜且逐项可编辑保存
3. 可选多平台 + 知识库范围 + 提示词，合规规避锁定开
4. 一次生成多个平台适配内容，可编辑；部分失败可单独重试
5. 合规提醒可采纳改写/忽略，不阻断保存；处理状态可追溯
6. 可"就到脚本"结束或继续生成数字人成片（异步+通知）
7. 创作草稿可保存并在工作台恢复

## 11. AI 能力规格

> 模板 = AI PM Playbook 6 段 + **内容生成类变体**（质量要求/不适内容过滤/幻觉处理/编辑修改率）。
> 共性约定：**模型 = 国产 LLM（DeepSeek / 通义 / Kimi 官方 API，合规直连、中文强，多家可切换）**，按 token 计费、量级低；**RAG/检索与硬事实精确召回归属 [[PRD_多模态知识库底座]] §12**（本模块只发起检索、消费事实，不重复规格）；**口播转写 ASR 归属 [[PRD_爆款抓取]] §11**；**所有提示词由后台运营维护、客户端不可编辑**（客户端只「选风格 / 套爆款公式」，对齐 v1.1 变更 2）。数字人成片 → [[PRD_数字人]] §11.2。

### 11.1 爆款拆解（LLM，八维度 → 公式 · 内容生成类）

**① 能力定义与边界**
- 背景/必要性：商家看得懂爆款却不会变成自己的内容；拆解把爆款转成可复用创作骨架。
- 成功标准：拆出钩子/结构/口播脚本/分镜，逐项可编辑落定率 100%（§1.3）。
- 约束：行业固定殡葬，拆解规则（八维度）由平台按行业适配、**客户不写**（[[PRD_多模态知识库底座]] §11）。
- 能做：结构化拆解 + 提炼可迁移公式。**不能做（不确定性）**：保证拆解 100% 准确（可人工补写）、跨行业拆解（V1 不支持）。

**② 输入/输出规范**
- I/O 契约：入 = 参考文本（文案/转写稿/burst_item）+ 行业=殡葬；出 = `content_dissection`(hook·structure·script·storyboard(json)·transferable_formula)，逐项可编辑。
- 边界条件：参考来自链接转写时依赖 [[PRD_爆款抓取]] §11 ASR，失败回退粘贴/上传（§4.1.6）。
- 错误处理：拆解为空/失败 → 提示重试 + 允许手动补写各项（§4.2.5）。

**③ AI 技术需求**
- 模型选型：国产 LLM 官方 API（DeepSeek/通义/Kimi，合规直连、中文强）；多家可切换。
- 数据需求：八维度拆解规则模板（平台按行业维护的后台资产）；沉淀 transferable_formula **归入作品库（形态=公式）**，客户只读/「用它新建」复用、**不可手动新建或编辑公式规则**（规则=提示词，归后台）；无需自训练，规则随行业版本更新。
- Prompt/参数策略：低 temperature 求稳定结构化抽取；拆解规则 prompt **后台维护、客户端不可编辑**。
- 性能要求：拆解时延秒级（**目标值待压测**）。
- 内容生成类变体：质量 = 结构字段完整率（**目标待压测**）；编辑修改率 = 拆解结果被人工编辑的比例（监控项，越低越好）。

**④ 评估标准**
- 分层：系统层 = 拆解成功率/时延；模块层 = 字段完整率 + 公式可用性（**目标待压测**）；业务层 = 进 Step2 后落定率 100%、拆解→生成转化。
- Golden Dataset：标注好"标准拆解"的殡葬爆款样本集，规模**待建**。
- 验收 Pass/Fail：八字段齐全且可编辑落定 = Pass；结构错乱/字段缺失致无法编辑 = Fail。
- BadCase 闭环：拆错钩子/结构 → 收集 → 归因（规则/输入质量）→ 优化拆解规则模板。

**⑤ 灰度上线**
- 灰度策略：随内容创作向导上线。
- 监控指标：拆解成功率 / 字段完整率 / 编辑修改率 / 时延。
- 回滚方案：失败率超阈值 → 切换备用 LLM；极端 → 纯手动补写。

**⑥ 风险与缓解**
- 幻觉：拆解为结构提炼、不输出对外发布文案，合规在生成阶段把关。
- 版权：不照搬参考原文（借模式不洗稿，§3.3）。
- 成本：单次 token 量级低，**待核实**。

### 11.2 仿写生成（LLM + 知识库 RAG · 内容生成类）

**① 能力定义与边界**
- 背景/必要性：以拆解骨架为模板、用企业自有知识库事实填充，按平台分别生成"形似不抄、合规"的成稿。
- 成功标准：一次生成覆盖平台 ≥ 2、**硬事实零编造**（价格/规格与知识库一致）。
- 约束：知识库只供事实、提示词只供风格，二者不交叉（§3.3 职责分离）；合规为独立系统层。
- 能做：多平台适配文案生成 + 知识库事实填充。**不能做（不确定性）**：🔴 **杜撰价格/规格**（召回为空必须留空/提示）；保证 100% 不被限流（合规为提醒式三层兜底）。

**② 输入/输出规范**
- I/O 契约：入 = 拆解骨架 + 目标平台(多选) + 风格提示词 + 知识库检索结果（全公司事实，自动）；出 = `content_generation`（按平台一条：title·body·tags·compliance_flags·token_usage）。
- 边界条件：空知识库 → 仍可生成（仅靠参考+行业）并提示"补库提质"（§3.3）。
- 错误处理：单平台失败 → "重试该平台"不影响其它（§4.4.6）；硬事实召回为空 → 留空+提示补库，不编造。

**③ AI 技术需求**
- 模型选型：国产 LLM 官方 API（同 §11.1）；**RAG 检索与硬事实精确召回归属 [[PRD_多模态知识库底座]] §12**（结构化精确召回不进向量库、未命中留空），本模块只发起检索并把事实喂入 prompt。
- 数据需求：企业自有知识库（结构化事实 + 非结构化文案/品牌口径）+ 风格提示词库 + 殡葬合规词库；事实更新依赖客户维护知识库；无需自训练模型。
- Prompt/参数策略：prompt = 拆解骨架 + 知识库事实 + 风格提示词 + 平台适配 + 合规规避规则（§8）；🔴 **硬事实只用知识库精确召回值，禁止 LLM 杜撰**；提示词**后台维护、客户端不可编辑**。
- 性能要求：多平台并行生成时延、单平台成功率（**目标值待压测**）。
- 内容生成类变体：质量 = 硬事实一致率 100%（**目标待压测**）；不适内容过滤 = 殡葬词库违禁检测（LLM 结构化抽取判违禁，非纯字符串，§8）；幻觉处理 = 事实走精确召回、召回空则留空；编辑修改率 = 监控项。

**④ 评估标准**
- 分层：系统层 = 各平台生成成功率/时延；模块层 = 硬事实编造率(抽检) + 合规命中率（**目标待压测**）；业务层 = 覆盖平台数 ≥ 2、合规提醒采纳率可追溯。
- Golden Dataset：含已知价格/规格的殡葬样本 + 违禁词样本集，用于核"事实一致 + 违禁拦截"，规模**待建**。
- 验收 Pass/Fail：硬事实与知识库一致且违禁词被提醒 = Pass；**编造价格/规格 = 直接 Fail**。
- BadCase 闭环：编造事实/漏判违禁 → 收集 → 归因（召回缺失/prompt/词库）→ 补库或调词库。

**⑤ 灰度上线**
- 灰度策略：随向导上线，先小流量核事实一致率。
- 监控指标：硬事实编造率 / 平台生成成功率 / 合规命中率 / 编辑修改率。
- 回滚方案：编造/越线超阈值告警；多家 LLM 可切换；极端 → 收紧为"必须命中知识库才生成事实句"。

**⑥ 风险与缓解**
- 幻觉：🔴 **事实不编造**——价格/承诺靠知识库精确召回，技术保障见 [[PRD_多模态知识库底座]] §12 第 2 行 / [[技术方案-知识库精确召回与事实校验-殡葬V1]]。
- 版权：借模式不洗稿，用自有知识库填充、不照搬原文。
- 合规：生成即过合规规避规则（殡葬词库）+ 生成后二次检测；提醒式三层兜底（prompt 规避+提醒+人工）。
- 成本：按 token 计入用量，量级低。

### 11.3 脚本 / 口播文案生成（LLM · 内容生成类）

**① 能力定义与边界**
- 背景/必要性：把拆解脚本/成稿变成可直接配音的口播稿，喂数字人成片（Step4→Step5）。
- 成功标准：口播稿可配音可用、时长可控。
- 约束：含价格/承诺的口播稿须过人工"已核对价格无误"门（[[PRD_数字人]] §11.2 / §3.3-6）。
- 能做：口语化、断句、时长适配的口播稿。**不能做（不确定性）**：编造价格/承诺（同 §11.2）。

**② 输入/输出规范**
- I/O 契约：入 = 拆解脚本/成稿 + 风格 + 时长约束；出 = 口播稿(text)，默认带入 Step5 可改（§4.5.2）。
- 边界条件：时长超限 → 按预计时长提示精简。
- 错误处理：生成失败 → 重试或直接复用拆解 `script` 字段。

**③ AI 技术需求**
- 模型选型：国产 LLM 官方 API（同 §11.1）；多家可切换。
- 数据需求：复用拆解脚本/成稿 + 口播风格提示词；无需自训练。
- Prompt/参数策略：口播提示词（口语化/断句/时长控制）**后台维护、客户端不可编辑**。
- 性能要求：生成时延秒级（**目标值待压测**）。
- 内容生成类变体：质量 = 可配音可用率（**目标待压测**）；幻觉处理 = 事实同 §11.2（不编造价格/承诺）。

**④ 评估标准**
- 分层：系统层 = 生成成功率/时延；模块层 = 口播可用率 + 时长达标率（**目标待压测**）；业务层 = 进成片的稿件通过率。
- Golden Dataset：与 §11.2 共用 + 口播专项样本，规模**待建**。
- 验收 Pass/Fail：口播稿可直接配音且时长达标 = Pass；含未核价格直接进成片 = Fail。
- BadCase 闭环：拗口/超时/事实错 → 收集 → 归因 → 调口播 prompt。

**⑤ 灰度上线**
- 灰度策略 / 监控指标 / 回滚方案：随仿写生成统一管理（token 成本、成功率、合规命中、编辑修改率）。

**⑥ 风险与缓解**
- 幻觉/事实：同 §11.2，含价格/承诺走人工确认门。
- 合规：口播稿过合规规避 + 预审（殡葬词库）。
- 成本：按 token，量级低。
