## 二、优先级排期（前后端配对写，共享数据对象）

> 原则：**配对模块同批写**——后台与商家端共用同一批数据对象（租户/套餐/词库版本），一起写两边字段才对得齐。批次内按地基→上层推进。

| 批次 | 主题 | 含 PRD | 共享数据对象 | 依赖 |
|--|--|--|--|--|
| **1** | 账号体系（地基） | B1 后台·账号开通 + A8 商家端·账号与成员 | `tenant_company` / `account` / `role` | 无（最先写） |
| **2** | 计费 | B2 后台·套餐配置 + A7 商家端·用量与计费 | `package` / `quota` / `usage_record` / `addon` | 批次1（租户） |
| **3** | 合规 | B3 后台·合规词库 + A5 商家端·提示词 | `lexicon_version` / `lexicon_word` / `prompt` | 批次1 |
| | | ⚠️ 注（2026-06-28）：提示词已收后台，客户端不再有独立提示词模块；本配对的提示词部分以后台能力实现 | | |
| **4** | 内容资产 | A3 知识库 + A4 数字人 | `kb_file` / `kb_fact` / `avatar` / `voice` | 批次1、2（配额） |

## 三、全局约定（各模块 PRD 共用）

- 形态：客户自助 SaaS · Web 端 · 我方后台开通账号（无自助注册）· 行业固定殡葬 · 公司账号多成员
- 架构：引擎/资产分离；数据带 `租户ID × 行业ID` 双维度
- 关键状态由**后台单一驱动**、商家端只读：形象训练态 / 授权态 / 合规词库版本 / 长任务态 / 配额额度（见 [[产品设计-殡葬V1-平台后台]] §八）
- 外部依赖：蝉镜（数字人）/ 蝉妈妈（爆款数据）/ ASR（转写）/ LLM（拆解·生成·合规）/ 抖音发布 API
- 合规红线：禁自爬、私域企微官方、合规预审为提醒非阻断 + 人工复核兜底
- PRD 模板：1 概述 / 2 用户场景 / 3 整体方案(含设计约束) / 4 功能需求(逐字段) / 5 状态流转 / 6 数据对象 / 7 接口草案 / 8 技术考虑 / 9 风险依赖 / 10 验收标准
