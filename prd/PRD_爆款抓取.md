## 1. 文档概述

### 1.1 产品背景

殡葬商家做内容获客，核心难题之一是**不知道拍什么**：行业封闭、商家之间信息隔离、很难系统性地发现同行/同类爆款并从中提炼规律。现状是运营偶尔刷到爆款，截图收藏，没有形成可持续的对标体系。

本模块要解决的核心问题：**让商家系统性地发现同行爆款，按关键词/账号/榜单三条路径持续取数，计算相对基线的爆款倍数，并能一键带入内容创作向导**——把"偶尔刷到"变成"可配置、可持续的对标机制"。

> 数据来源必须走第三方数据服务（合规取数），禁止自建爬虫。V1 接蝉妈妈 API（厦门蝉语网络科技）；价格/权限/字段以商务对接签约为准。

### 1.2 产品目标

- 支持**三种取数模式**（关键词搜索 / 对标账号 / 热门榜单），覆盖不同发现路径
- 展示**爆款倍数**（播放/点赞相对账号基线自算），让商家一眼判断内容潜力
- 对标源**配置一次、持续复用**，不用每次重填
- **一键带入拆解**，爆款直接流转到内容创作向导 Step2
- 收藏夹沉淀高价值参考，复用不丢失

### 1.3 核心指标

| 指标 | 目标值 |
|--|--|
| 单次搜索/抓取到列表展示时长 | < 10 秒 |
| 点击「拆解」进入内容创作 Step2 转化率 | 可统计，初期不设阈值 |
| 对标源配置完成率（首次使用当天） | > 80% |
| 爆款倍数计算覆盖率（有基线账号时） | 100% |

### 1.4 范围

**In-Scope（本期）**

- 对标源配置（关键词 + 对标账号 + 平台）
- 三模式取数：按关键词搜索、按对标账号拉取、热门榜单
- 通用筛选条：平台 / 时间范围 / 排序维度
- 爆款列表（封面 + 标题 + 互动数 + 爆款倍数 + 平台）
- 单条操作：拆解（带入内容创作）/ 收藏
- 收藏夹（标记已收藏）

**Out-of-Scope（后期）**

- 内容趋势预测与告警
- 竞品账号涨粉/发布频次追踪看板
- 批量收藏 / 收藏夹管理
- 爆款模板自动归档（内容创作 Step2 已有"可迁移公式"沉淀）
- 小红书/视频号/快手完整数据覆盖（V1 抖音最全，其他平台数据有限）

## 3. 整体方案

### 3.1 方案原则

- **配置与取数分离**：对标源（关键词 + 账号 + 平台）配置一次存档，三种模式共用，不重复填写
- **三模式 Tab**：切换模式不刷新已配置的筛选参数，切回时保留上次状态
- **爆款倍数自算**：蝉妈妈给原始指标（播放/点赞/评论/转发），我方按账号近期平均基线计算倍数；无基线时显示「—」
- **数据局限诚实展示**：抖音数据最全，小红书覆盖有限；界面明确标注，不过度承诺

### 3.2 页面结构

```
[爆款抓取 Header]                [配置对标源]
┌ 模式 Tab ──────────────────────────────────────┐
│  [按关键词搜索] [按对标账号] [热门榜单]           │
├ 模式专属操作行 ─────────────────────────────────┤
│  关键词模式：[关键词输入框]  [搜索抓取]           │
│  账号模式：  账号 tag 列表   [+添加账号] [抓取]   │
│  榜单模式：  [行业分类下拉]              [出热门榜]│
├ 通用筛选行（所有模式共用）────────────────────────┤
│  平台[抖音▾] 时间[近7天▾] 排序[按点赞▾] [配置对标源]│
└───────────────────────────────────────────────┘
[爆款卡片列表，3列 Grid]
  ┌ 封面区（含爆款倍数徽标）──────┐
  │ 🔥 8.5×                      │
  └───────────────────────────────┘
    老人寿衣有什么讲究？作为子女一定要懂
    ▶ 12.4w  ♥ 3.2w  [抖]
  [拆解]  [收藏]
[数据来源说明条]
```

### 3.3 设计约束（功能限制）

- **禁自爬**：爆款数据必须来自蝉妈妈 API（第三方合规取数），禁止自建爬虫，合同须含"数据来源合法"保证条款
- **小红书数据有限**：蝉妈妈小红书覆盖不如抖音，界面需标注"覆盖有限"，不承诺与抖音同等完整度
- **爆款倍数非厂商直供**：蝉妈妈给原始热度数据，不直接给"X 倍爆款"标签；倍数由我方按账号近期基线自算。账号模式有基线可算；关键词/榜单模式若无基线则以平台整体均值为参考
- **接口 / QPS / 字段 = 签约后确认**：企业版 API 约 5000 次/天，精确字段和权限以商务对接为准；本 PRD 字段按蝉妈妈公开文档预估
- **封面版权**：展示封面仅供内部选题参考，不可直接使用原创封面作为自有内容素材
- **按次计用量**：每次搜索/抓取计入「爆款抓取」用量，与月度配额绑定（见用量模块）

## 4. 功能需求

### 4.1 对标源配置（弹窗）

**4.1.1 触发方式**

- 首次进入爆款页（空态）→ 自动弹出引导
- 点击 Header「配置对标源」按钮
- 点击账号模式「+ 添加账号」
- 点击通用筛选行「配置对标源」按钮

**4.1.2 字段**

| 字段 | 控件 | 必填 | 说明 |
|--|--|--|--|
| 关键词 | 输入框（逗号分隔） | 否 | 关键词搜索模式使用；如"寿衣, 骨灰盒, 殡葬讲究" |
| 对标账号 | 输入框（逗号分隔账号名称/链接） | 否 | 账号模式使用；最多 10 个 |
| 平台 | 多选（抖音/小红书/视频号/快手） | 是 | 默认抖音+小红书 |

**4.1.3 交互**

- 保存后 toast 提示"对标源已更新"，关闭弹窗
- 修改后已有列表不自动刷新，需手动点"搜索抓取/抓取/出热门榜"触发

**4.1.4 校验**

- 平台至少选 1 个
- 关键词和对标账号可同时为空（未配置时对应模式提示"先配置"）

### 4.2 通用筛选条（三模式共用）

位于模式专属操作行下方，所有模式均展示。

**4.2.1 字段**

| 字段 | 控件 | 默认值 | 说明 |
|--|--|--|--|
| 平台 | 下拉单选 | 抖音（数据最全） | 抖音 / 小红书（覆盖有限）|
| 时间范围 | 下拉单选 | 近 7 天 | 近 7 天 / 近 30 天 / 近 90 天 |
| 排序维度 | 下拉单选 | 按点赞 | 按点赞 / 按播放 / 按评论 / 按涨粉 |

**4.2.2 交互**

- 修改筛选条件不自动重新拉取，需再次点对应取数按钮才生效
- 切换模式 Tab 时筛选条保留已选值

### 4.3 模式一：按关键词搜索

**4.3.1 页面目标**

按指定关键词从蝉妈妈搜索相关视频，按爆款倍数排序展示。

**4.3.2 操作行字段**

| 字段 | 控件 | 必填 | 默认 | 说明 |
|--|--|--|--|--|
| 关键词输入 | 输入框 | 是 | 上次输入值 / 配置中的关键词 | 支持单次临时输入，优先级高于配置中关键词 |
| 搜索抓取 | 按钮 | — | — | 触发取数 |

**4.3.3 交互**

- 关键词回车 = 点「搜索抓取」
- 取数期间按钮 loading（"抓取中…"），不可重复触发
- 返回列表后：计入爆款抓取用量 +1

**4.3.4 空态**：提示"输入关键词开始抓取，如：寿衣 / 骨灰盒 / 殡葬讲究"

**4.3.5 异常**

| 场景 | 行为 |
|--|--|
| 关键词为空 | 不可触发，按钮置灰 |
| API 返回 0 条 | "没找到相关爆款，换个关键词试试" |
| API 调用失败 | "抓取失败，请稍后重试" |
| QPS 超限 | "今日抓取次数已达上限（XXX 次）" |

### 4.4 模式二：按对标账号

**4.4.1 页面目标**

拉取已配置的对标账号近期视频，找出该账号自己的爆款。

**4.4.2 操作行字段**

| 字段 | 控件 | 说明 |
|--|--|--|
| 账号 Tag 列表 | 只读 Tag | 展示已配置的对标账号；点击 Tag 可单独抓该账号 |
| + 添加账号 | 按钮 | 打开配置对标源弹窗，跳转至账号输入字段 |
| 抓取该账号爆款 | 按钮 | 抓取所有已配置账号的爆款合并展示 |

**4.4.3 交互**

- 未配置账号时操作行显示"未配置对标账号 → 去配置"入口，抓取按钮置灰
- 抓取结果按爆款倍数排序；倍数 = 该账号视频互动数 / 该账号近 30 条均值
- 多账号结果合并展示，每条带来源账号标签

**4.4.4 空态**：提示"未配置对标账号，点「配置对标源」添加"

**4.4.5 异常**

| 场景 | 行为 |
|--|--|
| 账号不存在 / 无数据 | 该账号跳过，提示"以下账号未找到数据：XXX" |
| 账号近期无发布 | 提示"该账号近期无发布内容" |

### 4.5 模式三：热门榜单

**4.5.1 页面目标**

调取蝉妈妈热门视频榜，按行业分类筛选殡葬方向的当前趋势内容。

**4.5.2 操作行字段**

| 字段 | 控件 | 默认 | 说明 |
|--|--|--|--|
| 行业分类 | 下拉单选 | 殡葬 · 寿衣 | 殡葬·寿衣 / 殡葬·骨灰盒 / 殡葬·一条龙服务 / 殡葬·习俗科普 |
| 出热门榜 | 按钮 | — | 触发取数 |

**4.5.3 交互**

- 切换行业分类不自动刷新，点"出热门榜"才取数
- 榜单结果以蝉妈妈热度排序为准；有账号基线的条目展示爆款倍数，无基线的以平台整体均值估算并标注「参考值」

**4.5.4 空态**：提示"选择行业分类后点「出热门榜」"

**4.5.5 异常**

| 场景 | 行为 |
|--|--|
| 该分类榜单为空 | "当前分类暂无上榜内容，试试其他分类或时间范围" |
| API 不支持该分类 | 提示并引导切换关键词模式搜索 |

### 4.6 爆款卡片（列表展示）

**4.6.1 卡片字段**

| 字段 | 来源 | 说明 |
|--|--|--|
| 封面 | 蝉妈妈 | 视频封面缩略图；加载失败显示占位图 |
| 爆款倍数徽标 | 自算 | `🔥 X.X×`，浮层显示于封面右下角；无法计算时不显示 |
| 标题 | 蝉妈妈 | 2 行截断，展示视频标题 |
| 播放量 | 蝉妈妈 | `▶ 12.4w`；小红书无播放量时仅显示点赞 |
| 点赞数 | 蝉妈妈 | `♥ 3.2w` |
| 评论数 | 蝉妈妈 | `💬 860`（可选展示，榜单模式优先） |
| 平台徽标 | 本地 | 抖/书/视/手 |
| 收藏状态 | 本地 | 已收藏时图标实心；点击切换 |

**4.6.2 单条操作**

| 操作 | 行为 |
|--|--|
| 拆解 | overlay"正在拆解…" → 跳转内容创作页 Step2，并带入该视频标题/文案作为参考 |
| 收藏 | 切换收藏状态（本地标记 + 落库），toast"已收藏" |

**4.6.3 列表状态**

| 状态 | 表现 |
|--|--|
| 加载中 | 骨架屏（3列 × N行） |
| 空结果 | 空态文案 + 换词/换模式引导 |
| 部分失败 | 已有结果正常展示，失败平台提示"该平台数据获取失败" |
| 加载更多 | 若 API 支持分页，底部"加载更多"按钮 |

## 5. 状态流转

```text
进入爆款页
  -> 未配置对标源 -> 弹出配置引导 -> 保存对标源 -> 就绪态
  -> 已配置对标源 -> 直接就绪态

就绪态
  -> 触发取数（任一模式）-> 加载中 -> 展示爆款列表
  -> 修改筛选条件（不触发取数，仅标记"筛选已改"）
  -> 再次触发取数 -> 刷新列表

单条爆款
  -> 点「拆解」-> overlay 动画 -> 跳转内容创作 Step2（带入参考）
  -> 点「收藏」-> 收藏标记切换（乐观更新，异步落库）
```

## 6. 数据对象

### 6.1 `burst_source_config`（对标源配置，每公司一条）

`id · tenant_id · keywords(list) · accounts(list‹名称,平台,uid›) · platforms(list‹enum›) · updated_at · updated_by`

`id · tenant_id · user_id · burst_item_id · created_at`

### 6.4 `burst_usage`（用量记录，关联用量模块）

`id · tenant_id · user_id · source_type(enum) · count(int=1) · created_at`

## 7. 接口草案

| 接口 | 方法 | 说明 |
|--|--|--|
| `/burst/source-config` | GET/PUT | 读取/保存对标源配置 |
| `/burst/fetch/keyword` | POST | 入参：keyword + platform + time_range + sort → 返回 burst_item 列表 |
| `/burst/fetch/account` | POST | 入参：account_uids[] + platform + time_range + sort → 返回 burst_item 列表（含自算爆款倍数） |
| `/burst/fetch/rank` | POST | 入参：category + platform + time_range + sort → 返回热门榜 burst_item 列表 |
| `/burst/favorite` | POST/DELETE | 收藏 / 取消收藏 |
| `/burst/favorite/list` | GET | 收藏列表 |
| `/burst/dissect` | POST | 入参：burst_item_id → 创建内容创作草稿（status=拆解中），返回 draft_id，前端跳转 Step2 |

> `/burst/fetch/*` 均为后端调蝉妈妈 API + 自算爆款倍数 + 落库缓存后返回。前端不直连蝉妈妈。

## 8. 技术考虑

- **蝉妈妈调用层**：后端统一封装，前端不直连；接口限速/重试由后端处理；企业版 API ~5000 次/天，需监控用量
- **爆款倍数计算**：账号模式 = 单条互动指标 / 该账号近 30 条均值（播放+点赞加权）；关键词/榜单模式 = 无基线时显示「—」或以平台整体均值参考（标注"参考值"）
- **数据缓存**：同 tenant_id + 相同取数参数 + 1小时内 → 命中缓存直接返回，不重复调蝉妈妈；超时或强制刷新时重拉
- **封面跨域**：封面 URL 由后端转存 CDN，前端统一走自有 CDN 展示，避免跨域问题和封面版权争议
- **拆解跳转**：点拆解后端即创建草稿，前端跳转到内容创作向导 Step2 并注入 burst_item_id；Step2 展示"来自爆款库"标签，内容由内容创作模块的拆解逻辑负责处理

## 9. 风险与依赖

### 9.1 依赖

- 蝉妈妈 API（签约·年费采购）— 字段/QPS/价格以商务对接为准
- 内容创作模块的草稿创建与拆解接口

## 11. AI 能力规格（视频转写 ASR · 全局真源）

> 模板 = AI PM Playbook 6 段（能力定义与边界 / 输入输出规范 / AI 技术需求 / 评估标准 / 灰度上线 / 风险与缓解）+ **多模态类变体**（语音语种/口音/格式精度）。
> 📌 本节集中定义**全局 ASR（视频/音频口播转写）能力**作为**真源**。爆款抓取本身取蝉妈妈结构化数据；链路中对爆款视频口播转写、[[PRD_内容创作]] 链接转写（Step1）、[[PRD_多模态知识库底座]] 视频抽帧后/音频转写，**统一复用本能力，不在各自 PRD 重复整段**。

### 11.1 视频转写 ASR（语音转文本 · 多模态类）

**① 能力定义与边界**
- 背景/必要性：拆解、仿写、字幕卡点都需要口播文本；行业封闭、参考多为视频，ASR 是把视频变可处理文本的入口。
- 成功标准：中文口播稳定转写 + 句/词级时间戳，供拆解与卡点取用。
- 约束：抖音视频流防盗链，带画面抓取受阻（见 [[PRD_视频模板化生成与换人换产品]] §9.2），以音频转写为主。
- 能做：中文口播转文本 + 时间戳 + 置信度；长视频自动切段并行。**不能做（不确定性）**：带画面流稳定抓取（受阻）、说话人分离（不做）、强噪声/重口音方言高精度（未验，目标值待压测）。

**② 输入/输出规范**
- I/O 契约：入 = 音视频文件或 URL（抖音 best-effort）+ 可选语言提示；出 = 转写全文 + 分段时间戳（句/词级）+ 置信度（JSON）。
- 边界条件：无字幕/空声轨 → 返回空文本 + 原因；超长 → 自动切段。
- 错误处理：抓取失败 / 被拒（防盗链）/ 超时分别返回明确状态；**必须轮询到 `done`/`error`/真超时才判成败，不凭中间态（pending/claimed 不算结论）**。

**③ AI 技术需求**
- 模型选型：`faster-whisper`(MIT) / `WhisperX`(BSD-2，词级对齐)，**本地自部署 whisper-server**（`localhost:8765` + Chrome 扩展投递抖音 tab 抓取 → 本地 Whisper → 轮询取结果）；降级 `whisper.cpp`(CPU/Apple Silicon)。计费 = 自部署算力（无 per-call 采购，**单条边际成本待核实**）。
- 数据需求：预训练模型直接用，**无需自有训练数据**；殡葬专有名词/品牌热词表可选（后台维护，随业务更新）；评估集见 ④。
- Prompt/参数策略：非生成类无业务 prompt；语言锁 zh、VAD 切分、长视频切段；模型档/beam/VAD 阈值/热词由**后台运营维护、客户端不可编辑**。
- 性能要求：短视频 30–90s、长视频 2–5 分钟、极限 ≤10 分钟（本地链路经验区间；正式**成功率/时延目标待压测**）。
- 多模态（语音）精度变体：语种 = 中文为主（方言/口音准确率**待验**）；输入 = 常见音视频容器、单声道口播声轨；采样率自适配。

**④ 评估标准**
- 分层：系统层 = 转写服务成功率/时延（**目标待压测**）；模块层 = 字准确率 CER + 时间戳对齐误差（**目标待压测**）；业务层 = 下游拆解可用率。
- Golden Dataset：人工校对的殡葬口播样本集（覆盖正常/噪声/口音/长视频），规模与基线**待建**。
- 验收 Pass/Fail：CER ≤ 阈值（**阈值待定**）且 `done` 态返回 = Pass；持续中间态判完成 / 空音段脑补内容 = Fail。
- BadCase 闭环：漏字/串词/脑补 → 收集 → 归因（口音/噪声/切段边界）→ 优化（热词、VAD 调参、换档）。

**⑤ 灰度上线**
- 灰度策略：先音频转写灰度放量，带画面抓取暂不依赖。
- 监控指标：转写成功率 / 时延 / 队列积压 / 空结果率。
- 回滚方案：whisper-server 健康检查（`/health`）+ 自启自愈；异常 → 降级 whisper.cpp 或回退人工"粘贴文案/上传"（[[PRD_内容创作]] §4.1.6）。

**⑥ 风险与缓解**
- 幻觉：Whisper 静音/噪声段易"脑补"→ VAD 过滤 + 置信度阈值 + 空则留空不补全。
- 成本失控：自部署算力，长视频切段并行（边际成本待核实）。
- 版权/合规：仅做转写、**不二次发布原视频**；封面/原视频仅供内部选题参考（§3.3）；转写结果**如实呈现，抓不到/为空如实标注，绝不编造口播内容**。
