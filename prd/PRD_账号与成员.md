## 1. 文档概述

### 1.1 产品背景

商家是一个**公司**，不是一个人——老板要用、运营也要用。系统采用**公司账号 + 多成员**模型：公司由我方后台开通（带一个管理员=老板账号），公司内的运营成员由**管理员自助添加**，不必每个都来麻烦我方。同时殡葬商家普遍不懂技术，登录、找回密码这类基础体验必须傻瓜化、零客服介入。

本模块要解决的核心问题：**让一家殡葬公司的老板和运营，用我方分配的账号顺畅登录，并由老板在公司内自助管理运营成员与其权限**——把"谁能用、能用到什么程度"管清楚，同时不增加我方人工负担。

> V1 不做：自助注册、个人账号跨公司、细粒度功能级权限（只分管理员/运营两档）、SSO。

### 1.2 产品目标

- 老板/运营用**我方分配的账号**登录，支持记住登录、找回密码
- 老板（管理员）在公司内**自助增删运营成员**、停启用
- 角色**两档清晰**：管理员（全权）/ 运营（用工具、不碰成员与绑定）
- 所有人/数据严格**按公司（租户）隔离**

### 1.3 核心指标

| 指标 | 目标值 |
|--|--|
| 首次登录成功率（凭后台凭证） | 100% |
| 找回密码自助完成率（无需客服） | ≥ 95% |
| 管理员自助加成员成功率 | 100% |
| 跨公司数据越权 | 0 |

### 1.4 范围

**In-Scope（本期）**
- 登录（账号+密码、记住登录）
- 找回密码（账号→验证码→新密码）
- 成员管理（列表、添加运营、停用/启用、改角色）
- 两档角色权限（管理员 / 运营）
- 修改本人密码

**Out-of-Scope（不做 / 后续）**
- 自助注册 / 自助开通公司（属平台后台）
- 套餐/计费自助（见用量与计费 PRD）
- 个人跨公司、第三方登录、细粒度权限、操作审计看板

## 2. 用户与场景

### 2.1 目标用户
- **老板（管理员）**：公司开通时带的账号，全权；负责加运营、管权限。
- **运营**：老板添加的成员；用内容创作/爆款/作品库等工具，但不碰成员/平台绑定。

### 2.2 典型场景
1. 公司刚被我方开通，老板收到账号密码 → 首次登录 → 进工作台（知识库空态引导）。
2. 老板招了个运营 → 成员管理「添加成员」→ 填姓名手机、选运营 → 运营拿到账号登录。
3. 运营忘了密码 → 登录页「找回密码」→ 手机验证码 → 设新密码 → 登录。
4. 运营离职 → 老板「停用」该成员 → 其账号立即无法登录。

### 2.3 用户故事
- 作为老板，我要自己加运营成员、设成"运营"权限，这样不用每次找服务方。
- 作为运营，我登录后只看到能用的工具，看不到成员管理和平台绑定，避免误操作。
- 作为运营，我忘记密码能自己找回，不耽误干活。
- 作为老板，离职成员我能立刻停用，保证数据安全。

## 3. 整体方案

### 3.1 方案原则
- **公司即租户**：一切数据带 `company_id`，严格隔离。
- **两档够用**：殡葬小团队不需要复杂权限，管理员/运营两档覆盖。
- **零客服自助**：找回密码、加成员都能自己完成。

### 3.2 模块结构
```
账号与成员
├─ 登录（账号+密码 / 记住登录 / 找回密码）
├─ 成员管理（列表 + 添加运营 + 停启用 + 改角色）   ← 仅管理员可见
└─ 我的（修改本人密码 / 退出）
```

### 3.3 设计约束（功能限制）
1. **无注册入口**：登录页只登录 + 找回密码，无注册。
2. **成员管理仅管理员可见可用**：运营进入直接 403/隐藏入口。
3. **角色两档**：管理员 / 运营，不做更细。
4. **账号即后台分配**：新成员账号在公司内可由管理员加（落库走平台账号体系），登录全局唯一。
5. **数据隔离**：任何查询强制带 `company_id`，越权返回空/拒绝。
6. **管理员不可停用自己 / 公司至少保留 1 个管理员**。

## 4. 功能需求

### 4.1 登录

| 字段 | 类型 | 必填 | 校验 |
|--|--|:--:|--|
| 账号 | str | ✓ | 手机/邮箱；我方分配 |
| 密码 | str | ✓ | 错误给统一提示（不暴露账号是否存在） |
| 记住登录 | bool | — | 勾选延长会话 |

- 登录成功 → 返回 `company_id` / `account_id` / `role` → 进工作台。
- 鉴权前置：公司状态≠已开通 或 账号≠启用 → 拦截并提示（「账号已停用/公司已到期，请联系服务方」）。

### 4.2 找回密码
流程：输入账号 → 获取验证码（短信/邮件）→ 校验码 → 设新密码 → 回登录。
- 验证码有效期、错误次数限制（防爆破）。

### 4.3 成员管理（仅管理员）

**列表字段**：姓名 · 账号(脱敏) · 角色 · 状态 · 加入时间 · 操作

**添加成员（弹窗）**
| 字段 | 类型 | 必填 | 校验 |
|--|--|:--:|--|
| 姓名 | str | ✓ | 非空 |
| 手机号 | str | ✓ | 全局唯一；格式校验 |
| 角色 | enum | ✓ | 运营 / 老板·管理员（默认运营） |

- 提交 → 建 `account`（company_id=当前公司）→ 下发账号 → 列表新增。

**行操作**
| 操作 | 条件 | 行为 |
|--|--|--|
| 停用 | 非本人、非最后一个管理员 | 状态→停用，立即不可登录 |
| 启用 | 已停用 | 状态→启用 |
| 改角色 | 非最后一个管理员降级 | 运营↔管理员切换 |
| 重置密码 | — | 发重置链接 |

### 4.4 角色 × 权限

| 能力 | 管理员（老板） | 运营 |
|--|:--:|:--:|
| 工作台 / 内容创作 / 爆款 / 知识库 / 提示词 / 数字人 / 作品库 | ✓ | ✓ |
| 用量查看 | ✓ | ✓ |
| 成员管理 | ✓ | ✗（隐藏入口） |
| 平台账号绑定 / 自动发开关 | ✓ | ✗ |
| 增购 / 计费相关确认 | ✓ | ✗ |

## 5. 状态流转（account.status）
```
(启用) ──停用──▶ (停用) ──启用──▶ (启用)
  │
  └─ 公司状态≠已开通 → 登录鉴权统一拦截（账号态不变）
```
约束：公司内至少 1 个「管理员 + 启用」的账号，最后一个不可停用/降级。

## 6. 数据对象

> 与平台后台**共用** `tenant_company` / `account`（见 [[PRD_后台_账号开通]] §6），此处补充商家端关注字段与角色权限。

### 6.1 `account`（复用）
account_id · company_id · name · login(unique) · role(enum 管理员/运营) · status(启用/停用) · created_at
- 本模块新增：管理员可在公司内创建 role=运营 的 account。

### 6.2 `role_permission`（角色权限，配置型）
| role | 可见模块集 |
|--|--|
| 管理员 | 全部 |
| 运营 | 全部 − {成员管理, 平台绑定, 增购确认} |

### 6.3 `password_reset`（找回密码临时）
login · code · expire_at · used(bool)

## 7. 接口草案

| 接口 | 方法 | 入参 | 出参 |
|--|--|--|--|
| 登录 | POST /auth/login | login, password, remember | token + {company_id, account_id, role} |
| 找回-发码 | POST /auth/reset/send | login | ok |
| 找回-重置 | POST /auth/reset/confirm | login, code, new_password | ok |
| 成员列表 | GET /members | （隐含 company_id） | list‹member› |
| 添加成员 | POST /members | name, phone, role | account_id |
| 成员停启用/改角色 | PATCH /members/{id} | status? / role? | ok |
| 改本人密码 | PATCH /me/password | old, new | ok |

## 8. 技术考虑
- 所有业务接口强制注入会话中的 `company_id` 做行级隔离，禁止前端传入覆盖。
- 登录错误提示统一化，避免账号枚举。
- 找回密码验证码限频 + 失败锁定。
- 角色权限前端控制入口可见性 + 后端接口二次校验（运营调成员接口直接拒）。
- 「最后一个管理员」约束在后端事务内校验。

## 9. 风险与依赖

### 9.1 依赖
- 平台后台账号开通（批次1·B1）：公司与首个管理员账号由其创建。
- 短信/邮件通道（登录凭证、找回验证码）。

### 9.2 风险
| 风险 | 应对 |
|--|--|
| 运营越权访问成员/绑定 | 入口隐藏 + 后端鉴权双保险 |
| 误停用最后一个管理员致公司锁死 | 后端硬约束拦截 |
| 跨公司数据泄露 | 强制 company_id 行级隔离 + 测试覆盖 |
| 验证码被爆破 | 限频 + 锁定 + 有效期 |

## 10. 验收标准
1. 用后台分配账号可登录，进入工作台；公司停用/到期或账号停用时登录被拦并给对应提示。
2. 找回密码可自助走通（发码→校验→改密→登录），全程无需客服。
3. 管理员可添加运营成员，新成员可登录；手机号重复被拦。
4. 运营登录后看不到「成员管理 / 平台绑定」入口，直接调相关接口被拒。
5. 停用某成员后其账号立即不可登录；启用后恢复。
6. 无法停用/降级公司最后一个管理员。
7. 任一接口越权访问他公司数据返回空/拒绝（行级隔离生效）。

## 11. 通用企业权限专项需求（v3.1 · 2026-08-13）

### 11.1 租户与角色

通用角色为企业管理员、老板/负责人、运营、审核人、只读成员；平台运营账号与企业成员物理分域。角色只提供默认权限，最终按 `tenant_id + role + resource_scope + action` 校验。

### 11.2 关键权限

- 企业管理员：成员、平台账号、企业设置、权限配置。
- 老板/负责人：经营计划、正式事实、VI 启用、高风险承诺审批。
- 运营：内容创建编辑、候选整理、发布任务发起；不能绑定账号或放松合规。
- 审核人：内容、候选、VI 图片和 RPA 启动审批，权限可按模块分配。
- 只读成员：查看被授权数据，不可生成、采用、发布或删除。

### 11.3 审计与安全

登录、权限变更、成员停启用、事实采用、VI 启用、发布、RPA 确认均写审计。禁止停用最后一个管理员；成员离职后会话立即失效，但历史操作保留操作者快照。

### 11.4 验收

1. 企业运营不能进入平台后台或绑定平台账号。
2. 无 VI 启用权限的运营不能调用启用接口。
3. 审核人只看到授权模块的审批。
4. 所有列表和接口均验证 tenant_id，跨租户返回拒绝且记安全日志。

### 11.5 开发执行契约

- 权限接口以资源+动作校验，不只依赖前端菜单隐藏；高风险动作同时校验审批人权限和对象版本。
- 数据对象：member、role、permission、role_binding、session、approval_policy、audit_event。
- 错误码覆盖跨租户、权限不足、最后管理员、会话失效、审批范围不匹配和并发版本冲突。
- 本模块不调用生成 Skill/Prompt；任何角色推荐只形成配置建议，不自动授予权限。
