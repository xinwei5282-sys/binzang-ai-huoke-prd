## 1. 文档概述

### 1.1 产品背景

殡葬商家做口播视频，真人出镜有顾虑、成本高、产能低。数字人把"口播稿→成片"自动化：用**蝉镜 API**——上传 10 秒视频克隆老板形象、5 秒样本复刻声音、或直接用公模形象/音色，异步合成口播视频。但数字人是**采购成本大头**（成片 ~2.36 元/分钟、形象 ~¥199/个），所以**形象限额（每企业 2 个生成形象，公模不占）+ 单独计费**是产品硬约束。

本模块要解决的核心问题：**让商家管理自己的数字人形象与声音（上传克隆/公模/复刻），并在内容创作里把口播稿一键合成为成片**，同时把形象额度与成片用量算清楚，不让客户越用我方越亏。

> V1 不做：多人对话、表情/手势精调、绿幕/实景合成、形象二次编辑；i2v 图生视频作为关联能力另议。

### 1.2 产品目标

- **形象**：上传视频克隆（10s）/ 选公模（不占额度）/ 申请定制
- **声音**：5s 样本复刻 / 预置音色，可试听
- **成片**：取内容创作口播稿，选形象+声音+字幕模板，异步合成、可预览存作品库
- **额度与计费**：每企业 2 个生成形象（克隆/定制占额，公模不占），形象单独计费、成片按分钟计

### 1.3 核心指标

| 指标 | 目标值 |
|--|--|
| 形象克隆训练成功率 | ≥ 90%（合格素材） |
| 成片合成成功率 | ≥ 95% |
| 形象额度拦截准确 | 100%（公模不占、生成占） |
| 成片用量/成本计入准确 | 100% |

### 1.4 范围

**In-Scope（本期）**
- 形象：上传克隆 / 公模选用 / 申请定制（工单提交）
- 声音：复刻 / 预置 / 试听
- 成片：选形象+声音+模板+口播稿→异步合成→预览→存作品库
- 形象额度（2 个，公模不占）+ 满额拦截+增购引导
- 成片/形象用量与成本计入

**Out-of-Scope（不做 / 后续）**
- 形象精调/二次编辑、多人、实景
- i2v 图生视频（关联，另议）
- 后台定制工单履约页（精简版暂不做后台 PRD，工单仅商家端提交侧）

## 2. 用户与场景

### 2.1 目标用户
- **老板**：常作为克隆形象本人；决定是否增购形象。
- **运营**：日常选形象+声音出成片。

### 2.2 典型场景
1. 老板上传 10s 出镜视频 → 蝉镜克隆训练（进度回显）→ 可用 → 占用 1/2 形象额度。
2. 运营创作完口播稿 → Step5 选"老板克隆形象 + 温情女声 + 素雅模板" → 提交成片（异步，约 1 分钟）→ 通知完成 → 预览存作品库。
3. 老板想再克隆一个，已 2/2 → 拦截 → 增购 ¥199 → +1 可继续。
4. 运营图省事 → 选公模主播 A（不占额度）直接出片。

### 2.3 用户故事
- 作为老板，上传一小段视频就能克隆出我自己的数字人，出片像我本人。
- 作为运营，我把口播稿一键变成视频，不用真人拍。
- 作为我方，形象和成片都按量计入成本，定价覆盖得住。

## 3. 整体方案

### 3.1 方案原则
- **采购成本透明**：形象、成片都按蝉镜计费口径计入用量。
- **公模兜底**：不想占额度/不想克隆的，用公模即可出片。
- **状态后台驱动**：形象训练/审核状态由后台（蝉镜回调）驱动，商家端只读（见 [[产品设计-殡葬V1-平台后台]] §八）。

### 3.2 模块结构
```
数字人
├─ 形象（我的生成形象[占额] / 公模库[不占额] / 上传克隆 / 申请定制）
├─ 声音（复刻 / 预置 / 试听）
└─ 成片（在内容创作 Step5：形象+声音+模板+口播稿 → 合成 → 预览 → 存作品库）
```

### 3.3 设计约束（功能限制）
1. **接蝉镜 API**：克隆(10s)/公模/声音复刻(5s)/口播成片(异步轮询)。
2. **形象额度**：每企业 2 个生成形象；克隆/定制占额，**公模不占**；满额拦截+增购（见 [[PRD_用量与计费]]）。
3. **形象状态后台驱动**：训练中/审核中/可用/失败由后台回填，商家端只读。
4. **成片异步**：提交后台任务，完成通知（走通知中心）。
5. **成片计量**：按分钟计入用量与成本。
6. **含价格/承诺口播稿成片前人工确认**：成片是高代价输出（按分钟付费、改不动、"老板本人形象+声音"放大效应像郑重承诺）。口播稿若含价格/承诺类事实，**必须人工勾选"已核对价格无误"才允许提交合成**；事实准确性的技术保障见 [[技术方案-知识库精确召回与事实校验-殡葬V1]] §8。

## 4. 功能需求

### 4.1 形象
**展示**：我的生成形象（占额，状态徽标）+ 公模形象（不占额）；额度"已生成 X/2"。

| 操作 | 行为 | 占额 |
|--|--|:--:|
| 上传克隆 | 传 10s 视频→蝉镜训练（进度）→可用/失败 | 是 |
| 选公模 | 从蝉镜公模库选用 | 否 |
| 申请定制 | 提交需求工单（描述+联系人）→ 我方履约 | 是(完成后) |
- 满额时"上传克隆/申请定制"被拦 → 增购引导。

### 4.2 声音
- 复刻：传 5s 样本→蝉镜复刻→试听。
- 预置：选音色库，可试听。

### 4.3 成片（内容创作 Step5）
| 字段 | 类型 | 必填 | 说明 |
|--|--|:--:|--|
| 选用形象 | ref | ✓ | 我的生成 / 公模 |
| 选用声音 | ref | ✓ | 复刻 / 预置 |
| 口播稿 | text | ✓ | 取 Step4，可改 |
| 字幕/背景模板 | ref | — | 素雅模板等 |
| 预计时长 | int | — | 估算只读 |
- 提交 → 蝉镜异步合成（overlay/后台）→ 完成通知 → 预览 → 存作品库 → 计入成片用量(分钟)。

## 5. 状态流转

**形象 avatar.status（后台驱动）**
```
(上传/申请) ──▶ (训练中) ──▶ (审核中) ──▶ (可用) 
                   └────────────────────▶ (失败) ──重试──▶ 训练中
公模：直接 (可用)，不经训练
```
**成片 film.status**
```
(提交) ──▶ (成片中) ──▶ (完成·可预览/存库)
                └──▶ (失败) ──重试──▶ 成片中
```

## 8. 技术考虑
- 蝉镜异步任务：提交拿任务ID，轮询/回调拿结果；状态由后台统一接回调再回填商家端（单一真相）。
- 形象额度并发安全（见 [[PRD_用量与计费]]）。
- 成片完成走通知中心（长任务后台 + 通知）。
- 蝉镜自带内容安全审核，但**不替代我方殡葬专属合规预审**（口播稿仍过词库预审）。
- 计费：形象按个、成片按分钟，写 usage_record + mapped_cost。

## 9. 风险与依赖

### 9.1 依赖
- 蝉镜 API（克隆/公模/复刻/成片）——**计费与接口签前商务确认**（[[产品规划-殡葬V1]] §六）。
- 用量与计费（形象额度、成片计量）。
- 内容创作（Step5 口播稿来源）。

### 9.2 风险
| 风险 | 应对 |
|--|--|
| 克隆素材不合格训练失败 | 素材要求提示 + 失败重试 + 改用公模 |
| 成片成本高拉低毛利 | 按分钟计费 + 套餐覆盖（防亏校验）+ 公模降本 |
| 形象额度被绕过 | 原子扣减 + 公模/生成区分 |
| 蝉镜不可用 | 状态告警 + 任务暂停重试（后台监控） |

## 10. 验收标准
1. 可上传 10s 视频克隆形象，状态由后台驱动（训练→审核→可用/失败），商家端只读展示。
2. 公模可直接选用且不占额度；生成形象占额，满 2/2 后被拦并引导增购。
3. 声音可复刻/预置并试听。
4. 内容创作 Step5 可选形象+声音+模板+口播稿提交成片，异步完成后可预览、存作品库。
5. 形象按个、成片按分钟计入用量与成本。
6. 口播稿仍经我方合规预审（不被蝉镜审核替代）。
7. 口播稿含价格/承诺类事实时，成片前出现"已核对价格无误"确认勾选，未勾选不可提交合成。

## 11. AI 能力规格

> 模板 = AI PM Playbook 6 段 + **多模态类变体**（视觉/语音/口型精度）。
> **模型选型**统一引用 [[PRD_视频模板化生成与换人换产品]] §11 选型表对应行（数字人口播 = 第 1 行 `wan2.2-s2v`/腾讯 IVH，自部署 MuseTalk/EchoMimicV3），**不重复整张表**；**殡葬 V1 商家端现状实际接入蝉镜 API**（克隆/公模/复刻/成片一体，属同类数字人能力），母版级演进按 §11 候选切换。

### 11.1 数字人形象训练（克隆 / 授权形象 · 多模态类）

**① 能力定义与边界**
- 背景/必要性：真人出镜成本高、产能低、有顾虑；克隆出可复用形象是口播量产的前提。
- 成功标准：合格素材训练成功率 ≥ 90%（§1.3），出片像本人。
- 约束：形象是采购成本大头，每企业限 2 个生成形象（公模不占）、单独计费（§3.3-2）。
- 能做：上传授权素材克隆形象 + 声音复刻 + 选公模。**不能做（不确定性）**：任意换脸（红线，禁）、形象二次精调/表情手势精调（§1.1 不做）、素材不合格时强行出像（失败转公模）。

**② 输入/输出规范**
- I/O 契约：入 = 10s 出镜视频（克隆）/ 5s 语音样本（复刻）/ 公模 ID（不训练）；出 = `avatar`(vendor_id+status+preview) / `voice`(vendor_id+audition)。
- 边界条件：素材时长/分辨率/正脸/背景不达标 → 拒训并提示；额度满 2/2 → 拦截。
- 错误处理：训练失败 → 失败态 + 可重试 + 引导改公模；状态由后台回调单一真相驱动，商家端只读（§5）。

**③ AI 技术需求**
- 模型选型：现状 = 蝉镜 API（采购 ~¥199/形象，**签前商务核实**）；母版候选见 [[PRD_视频模板化生成与换人换产品]] §11 第 1/2 行（自部署 MuseTalk(MIT)/EchoMimicV3(Apache) 降本）。
- 数据需求：训练数据 = 客户自有授权出镜视频/语音样本（本人/已授权数字人），**须留存肖像+声音授权凭证**；规模 = 单形象 1 段合格素材；无需平台侧标注；更新随客户增购。
- Prompt/参数策略：非文本生成，无 prompt；素材规格与训练参数由**后台维护、客户端不可编辑**，仅按提示上传。
- 性能要求：异步训练，时延**目标值待压测**。
- 多模态（视觉+语音）精度变体：出镜视频建议正脸清晰、稳定背景；语音样本干净无底噪；具体规格阈值后台维护（**待压测定档**）。

**④ 评估标准**
- 分层：系统层 = 训练任务成功率/时延；模块层 = 克隆训练成功率 ≥ 90%（合格素材）+ 相似度主观评分（**目标待压测**）；业务层 = 形象额度扣减 100% 准确（公模不占、生成占）。
- Golden Dataset：合格/不合格素材样本集 + 验收人审清单，规模**待建**。
- 验收 Pass/Fail：合格素材训成"可用"且像本人 = Pass；额度误扣/公模误占额 = Fail。
- BadCase 闭环：出片不像/训练失败 → 收集素材特征 → 归因（光线/角度/时长）→ 反哺素材要求提示。

**⑤ 灰度上线**
- 灰度策略：先公模即用、克隆灰度放量。
- 监控指标：训练成功率 / 失败原因分布 / 形象额度扣减准确性。
- 回滚方案：蝉镜不可用 → 状态告警 + 任务暂停重试（§9.2）；克隆受阻 → 公模兜底。

**⑥ 风险与缓解**
- 偏见/质量：素材不合格致不像 → 素材要求提示 + 重试 + 公模兜底。
- 成本失控：形象限额 2 个 + 满额拦截增购（[[PRD_用量与计费]]）。
- 合规：🔴 **禁任意换脸**——只训练**已授权数字人/本人**形象，留存肖像声音授权；状态后台单一真相驱动防越权生成。

### 11.2 口播驱动生成（音频/文本驱动对口型成片 · 多模态类）

**① 能力定义与边界**
- 背景/必要性：把口播稿自动变成成片，免真人拍摄；位于内容创作 Step5「成片」（§4.3）。
- 成功标准：合成成功率 ≥ 95%、口型/音画同步可用（§1.3）。
- 约束：成片是高代价输出（按分钟付费、不可改、"本人形象+声音"放大效应近似郑重承诺，§3.3-6）。
- 能做：选形象+声音+模板+口播稿 → 异步对口型合成口播视频。**不能做（不确定性）**：多人对话、实景/绿幕合成、含价格/承诺稿未经人工核对即出片（强制确认门）。

**② 输入/输出规范**
- I/O 契约：入 = 形象 ref + 声音 ref + 口播稿(text) + 字幕/背景模板 ref；出 = `content_film`(video_url+duration+status+usage 分钟)。
- 边界条件：未选可用形象/声音 → 不可提交（§4.5.5）；含价格/承诺事实 → 必须勾选"已核对价格无误"。
- 错误处理：合成失败 → 重试，**不扣形象额度**；异步完成走通知中心。

**③ AI 技术需求**
- 模型选型：现状 = 蝉镜口播成片 API（异步轮询/回调，~2.36 元/分钟，**签前核实**）；母版候选见 [[PRD_视频模板化生成与换人换产品]] §11 第 1 行（演示 `wan2.2-s2v` / 腾讯 IVH；1.0 自部署 MuseTalk）。
- 数据需求：运行期消费已训练 `avatar`/`voice` + 口播稿，无需额外训练数据；口播文案来自 [[PRD_内容创作]] §11.3。
- Prompt/参数策略：口播稿取 Step4 可改、字幕/背景套模板；提示词归 [[PRD_内容创作]]（后台维护、客户端不可编辑），本模块只消费成稿。
- 性能要求：成功率 ≥ 95%、单条约 1 分钟（§1.3，正式**目标值待压测**）。
- 多模态（口型+语音）精度变体：口型对齐、音画同步可用率为核心质量指标（**目标待压测**）；输出分辨率/时长按模板与计费档。

**④ 评估标准**
- 分层：系统层 = 合成成功率/时延；模块层 = 口型同步可用率 + 字幕准确（**目标待压测**）；业务层 = 按分钟成本计入 100% 准确、毛利可覆盖。
- Golden Dataset：典型口播稿+形象组合样本集，规模**待建**。
- 验收 Pass/Fail：合成成功且口型/音画同步可接受 = Pass；含价格稿未过确认门即出片 = Fail。
- BadCase 闭环：口型错位/吞字/字幕错 → 收集 → 归因（稿长/停顿/音色）→ 调参或换档。

**⑤ 灰度上线**
- 灰度策略：长任务后台 + 完成通知灰度。
- 监控指标：成片成功率 / 时延 / 按分钟成本计入准确性。
- 回滚方案：蝉镜回调异常 → 暂停重试 + 告警；商业 API ↔ 自部署互为兜底（§9.2）。

**⑥ 风险与缓解**
- 幻觉/事实：口播稿含价格/承诺 → 必须人工"已核对价格无误"门（§3.3-6），事实保障见 [[PRD_多模态知识库底座]] §12 / [[技术方案-知识库精确召回与事实校验-殡葬V1]]。
- 成本失控：按分钟计费 + 套餐防亏校验 + 公模降本（§9.2）。
- 合规：成片须加 **AI 生成合成内容标识**；只换已授权形象、禁任意换脸；口播稿仍过**我方殡葬合规预审**（不被蝉镜审核替代，§8）；供应商须算法备案。
