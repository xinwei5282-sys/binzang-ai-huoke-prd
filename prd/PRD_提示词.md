## 1. 文档概述

### 1.1 产品背景

内容生成要"形似不抄、合规、对味"，靠两层提示词：**风格层**（客户自定义的口吻/视角，如"温情风""专业风"）让内容像自己；**合规层**（系统预置、只读）让内容规避殡葬违禁表达。把这两层拆开，客户能调风格、但碰不了合规底线——既灵活又安全。

本模块要解决的核心问题：**让客户在商家端自建/编辑风格提示词，并以只读方式展示由后台下发的合规规避规则**，在内容创作 Step3 被选用、作用于生成。风格层归客户，合规层归我方（来源是 [[PRD_后台_合规词库]] 下发的内容）。

> V1 不做：提示词 A/B 测、提示词市场/共享、按平台分别提示词、版本历史。

### 1.2 产品目标（已迁后台 · 历史记录）

- 客户可**新建/编辑/启用多个风格提示词**
- **合规层只读展示**（系统预置 + 后台下发），客户不可改
- 提示词在**内容创作 Step3 被选用**，风格控口吻、合规控底线
- 风格层与合规层职责清晰、互不越界

### 1.3 核心指标

| 指标 | 目标值 |
|--|--|
| 客户自建风格提示词成功率 | 100% |
| 生成时合规层必被应用 | 100%（不可关闭） |
| 风格切换对生成口吻的可感差异 | 可感知 |

### 1.4 范围

**In-Scope（本期）**
- 风格提示词：列表、新建、编辑、启用/停用
- 合规提示词：只读展示（来自后台下发的合规词库/模板）
- 被内容创作选用

**Out-of-Scope（不做 / 后续）**
- 提示词版本历史 / A/B / 市场
- 按平台分提示词
- 客户自定义合规规则（合规归我方）

## 2. 用户与场景

### 2.1 目标用户
- **运营/老板**：建几个常用风格，创作时挑一个用。

### 2.2 典型场景
1. 运营新建「温情风」提示词（口吻柔和、重情感、避免推销感）→ 启用 → 创作时选用。
2. 创作 Step3 选「专业风」→ 生成更偏知识科普口吻。
3. 客户在提示词页看到"行业合规规避（系统预置·只读🔒）"，知道生成会自动规避违禁，但改不了。

### 2.3 用户故事
- 作为运营，我要把团队常用的几种口吻存成提示词，复用不重复写。
- 作为运营，我能改自己的风格，但不该也不能动合规规则。
- 作为我方，合规规则统一由后台下发，客户端只读，保证底线一致。

## 3. 整体方案

### 3.1 方案原则
- **两层分治**：风格层（客户可编辑）+ 合规层（系统只读），物理隔离。
- **合规不可关**：生成时合规层强制应用，不给关闭入口。
- **就近选用**：提示词在创作 Step3 直接下拉选用。

### 3.2 模块结构（已迁后台 · 商家端不再呈现此模块）
```
提示词
├─ 我的风格（可编辑）：列表 + 新建 + 编辑 + 启用/停用
└─ 行业合规规避（系统预置·只读🔒）：展示当前下发的合规规则/版本
```

### 3.3 设计约束（功能限制）
1. **合规层只读**：无编辑/删除入口；内容来自后台下发（[[PRD_后台_合规词库]] 的合规模板/词库）。
2. **合规层不可在生成中关闭**：创作 Step3 合规规避"锁定开"。
3. **风格层按公司隔离**：本公司可见可编辑。
4. **至少一个启用风格**可被创作选用（无则空态引导新建）。

## 4. 功能需求

### 4.1 我的风格（可编辑）
**列表**：名称 · 备注 · 启用状态 · 创建人/时间 · 操作(编辑/启用停用/删除)

**新建/编辑（弹窗）**
| 字段 | 类型 | 必填 | 说明 |
|--|--|:--:|--|
| 名称 | str | ✓ | 如"温情风" |
| 内容 | text | ✓ | 口吻/视角/禁忌的描述 |
| 备注 | text | — | 用途说明 |
| 启用 | bool | — | 启用后可在创作选用 |

### 4.2 行业合规规避（只读）
展示：标题"系统预置·只读🔒" + 当前生效合规版本号（同步后台 [[PRD_后台_合规词库]] active 版本）+ 规则摘要（自动规避违禁、给改写建议）。无任何编辑控件。

### 4.3 被内容创作选用
内容创作 Step3：
- 提示词下拉 = 本公司启用的风格列表。
- 合规规避：显示"● 已启用（锁定开）"，不可关。
- 生成时：风格层注入 LLM 控口吻；合规层（词库/模板）参与预审与改写建议（见 [[PRD_内容创作]] §4.3/4.4）。

## 5. 状态流转（风格 prompt.enabled）
```
(草稿/新建) ──启用──▶ (启用·可选用) ──停用──▶ (停用·不可选用)
合规层：无客户态；随后台 lexicon active 版本变更而更新（只读同步）
```

## 6. 数据对象

### 6.1 `prompt`（风格提示词，公司隔离）
| 字段 | 类型 | 说明 |
|--|--|--|
| prompt_id | str(PK) | |
| company_id | ref | 所属公司 |
| name | str | 名称 |
| content | text | 提示词内容 |
| note | text | 备注 |
| enabled | bool | 是否启用 |
| created_by | ref | 创建人 |
| created_at | dt | |

### 6.2 合规层（只读引用，不在商家端建表）
引用后台 `lexicon_version`(active) + 合规提示词模板（见 [[PRD_后台_合规词库]] / 平台后台「合规模板下发」）。商家端只读拉取，不存可改副本。

## 7. 接口草案
| 接口 | 方法 | 入参 | 出参 |
|--|--|--|--|
| 风格列表 | GET /prompts | — | list‹prompt› |
| 新建/编辑 | POST/PUT /prompts | name, content, note, enabled | prompt_id |
| 启用/停用/删除 | PATCH/DELETE /prompts/{id} | enabled? | ok |
| 合规层展示 | GET /lexicon/active | industry=殡葬 | version_no + 规则摘要(只读) |

## 8. 技术考虑
- 合规层走后台 active 版本拉取并缓存，版本变更即刷新（与 [[PRD_后台_合规词库]] 下发联动）。
- 生成时提示词组装顺序：合规约束 + 风格 + 知识库事实 + 参考拆解，合规优先级最高。
- 删除被创作引用的风格需软删/提示（避免历史草稿丢引用）。

## 9. 风险与依赖

### 9.1 依赖
- 后台合规词库/模板（B3）提供合规层内容与版本。
- 内容创作（A1）消费提示词。

### 9.2 风险
| 风险 | 应对 |
|--|--|
| 客户误把合规当风格想改 | 合规层明确"只读🔒" + 文案说明 |
| 风格写得太离谱影响合规 | 合规层优先级最高，生成仍预审兜底 |
| 无启用风格导致创作无选项 | 空态引导新建 + 可用系统默认风格兜底 |

## 10. 验收标准
1. 客户可新建/编辑/启用多个风格提示词，按公司隔离。
2. 合规层只读展示且无任何编辑入口，版本号与后台 active 一致。
3. 内容创作 Step3 可选用本公司启用的风格；合规规避锁定开、不可关。
4. 切换风格生成口吻有可感差异；合规层始终被应用。
5. 后台发布新合规版本后，商家端合规层只读展示同步更新。
