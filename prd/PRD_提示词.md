## 1. 文档概述

### 1.1 产品背景

内容生成要"形似不抄、合规、对味"，靠两层提示词：**风格层**（客户自定义的口吻/视角，如"温情风""专业风"）让内容像自己；**合规层**（系统预置、只读）让内容规避殡葬违禁表达。把这两层拆开，客户能调风格、但碰不了合规底线——既灵活又安全。

本模块要解决的核心问题：**让客户在商家端自建/编辑风格提示词，并以只读方式展示由后台下发的合规规避规则**，在内容创作 Step3 被选用、作用于生成。风格层归客户，合规层归我方（来源是 [[PRD_后台_合规词库]] 下发的内容）。

> V1 不做：提示词 A/B 测、提示词市场/共享、按平台分别提示词、版本历史。

### 1.2 产品目标（已迁后台 · 历史记录）

- 客户可**新建/编辑/启用多个风格提示词**
- **合规层只读展示**（系统预置 + 后台下发），客户不可改
- 提示词在**内容创作 Step3 被选用**，风格控口吻、合规控底线
- 风格层与合规层职责清晰、互不越界

### 1.3 核心指标

| 指标 | 目标值 |
|--|--|
| 客户自建风格提示词成功率 | 100% |
| 生成时合规层必被应用 | 100%（不可关闭） |
| 风格切换对生成口吻的可感差异 | 可感知 |

### 1.4 范围

**In-Scope（本期）**
- 风格提示词：列表、新建、编辑、启用/停用
- 合规提示词：只读展示（来自后台下发的合规词库/模板）
- 被内容创作选用

**Out-of-Scope（不做 / 后续）**
- 提示词版本历史 / A/B / 市场
- 按平台分提示词
- 客户自定义合规规则（合规归我方）

## 2. 用户与场景

### 2.1 目标用户
- **运营/老板**：建几个常用风格，创作时挑一个用。

### 2.2 典型场景
1. 运营新建「温情风」提示词（口吻柔和、重情感、避免推销感）→ 启用 → 创作时选用。
2. 创作 Step3 选「专业风」→ 生成更偏知识科普口吻。
3. 客户在提示词页看到"行业合规规避（系统预置·只读🔒）"，知道生成会自动规避违禁，但改不了。

### 2.3 用户故事
- 作为运营，我要把团队常用的几种口吻存成提示词，复用不重复写。
- 作为运营，我能改自己的风格，但不该也不能动合规规则。
- 作为我方，合规规则统一由后台下发，客户端只读，保证底线一致。

## 3. 整体方案

### 3.1 方案原则
- **两层分治**：风格层（客户可编辑）+ 合规层（系统只读），物理隔离。
- **合规不可关**：生成时合规层强制应用，不给关闭入口。
- **就近选用**：提示词在创作 Step3 直接下拉选用。

### 3.2 模块结构（已迁后台 · 商家端不再呈现此模块）
```
提示词
├─ 我的风格（可编辑）：列表 + 新建 + 编辑 + 启用/停用
└─ 行业合规规避（系统预置·只读🔒）：展示当前下发的合规规则/版本
```

### 3.3 设计约束（功能限制）
1. **合规层只读**：无编辑/删除入口；内容来自后台下发（[[PRD_后台_合规词库]] 的合规模板/词库）。
2. **合规层不可在生成中关闭**：创作 Step3 合规规避"锁定开"。
3. **风格层按公司隔离**：本公司可见可编辑。
4. **至少一个启用风格**可被创作选用（无则空态引导新建）。

## 4. 功能需求

### 4.1 我的风格（可编辑）
**列表**：名称 · 备注 · 启用状态 · 创建人/时间 · 操作(编辑/启用停用/删除)

**新建/编辑（弹窗）**
| 字段 | 类型 | 必填 | 说明 |
|--|--|:--:|--|
| 名称 | str | ✓ | 如"温情风" |
| 内容 | text | ✓ | 口吻/视角/禁忌的描述 |
| 备注 | text | — | 用途说明 |
| 启用 | bool | — | 启用后可在创作选用 |

### 4.2 行业合规规避（只读）
展示：标题"系统预置·只读🔒" + 当前生效合规版本号（同步后台 [[PRD_后台_合规词库]] active 版本）+ 规则摘要（自动规避违禁、给改写建议）。无任何编辑控件。

### 4.3 被内容创作选用
内容创作 Step3：
- 提示词下拉 = 本公司启用的风格列表。
- 合规规避：显示"● 已启用（锁定开）"，不可关。
- 生成时：风格层注入 LLM 控口吻；合规层（词库/模板）参与预审与改写建议（见 [[PRD_内容创作]] §4.3/4.4）。

## 5. 状态流转（风格 prompt.enabled）
```
(草稿/新建) ──启用──▶ (启用·可选用) ──停用──▶ (停用·不可选用)
合规层：无客户态；随后台 lexicon active 版本变更而更新（只读同步）
```

## 8. 技术考虑
- 合规层走后台 active 版本拉取并缓存，版本变更即刷新（与 [[PRD_后台_合规词库]] 下发联动）。
- 生成时提示词组装顺序：合规约束 + 风格 + 知识库事实 + 参考拆解，合规优先级最高。
- 删除被创作引用的风格需软删/提示（避免历史草稿丢引用）。

## 9. 风险与依赖

### 9.1 依赖
- 后台合规词库/模板（B3）提供合规层内容与版本。
- 内容创作（A1）消费提示词。

### 9.2 风险
| 风险 | 应对 |
|--|--|
| 客户误把合规当风格想改 | 合规层明确"只读🔒" + 文案说明 |
| 风格写得太离谱影响合规 | 合规层优先级最高，生成仍预审兜底 |
| 无启用风格导致创作无选项 | 空态引导新建 + 可用系统默认风格兜底 |

## 10. 验收标准
1. 客户可新建/编辑/启用多个风格提示词，按公司隔离。
2. 合规层只读展示且无任何编辑入口，版本号与后台 active 一致。
3. 内容创作 Step3 可选用本公司启用的风格；合规规避锁定开、不可关。
4. 切换风格生成口吻有可感差异；合规层始终被应用。
5. 后台发布新合规版本后，商家端合规层只读展示同步更新。

## 11. 当前模型（v2.0 · 2026-06-30 · 权威定义，覆盖 §1–§10）

> 对齐原型：商家端 `prototype/index.html`「提示词微调」页 + 后台 `prototype-boss/index.html`「提示词管理 / 模型参数」页。

### 11.1 三层结构
| 层 | 内容 | 维护方 | 商家端 |
|--|--|--|--|
| ① **系统基线** | 爆款拆解（八维度）/ 仿写脚本 / 标题·字幕·CTA / 合规预审 / 视频画面提示词 | 后台运营 | **只读可见**（展示完整内容，不可编辑） |
| ② **商家微调** | 风格口吻 / 品牌落款话术 / 强调卖点 / 额外禁忌词 | 商家自助 | **可编辑** |
| ③ **生成参数** | 模型 / 温度 / top_p / 最大字数（按场景） | 后台按商户默认+覆盖 | **可调**（合规预审温度锁定 0.0） |

**生效顺序（组装）**：合规预审（基线，最高优先）> 系统基线（拆解/仿写/画面）> 商家微调（叠加风格/卖点/禁忌）> 生成参数（控温度/长度）。微调与参数都**不能突破基线与合规**。

### 11.2 商家端「提示词微调」页（A5 恢复）
- **系统基线（只读可见）**：列出 5 条基线提示词的**完整内容** + 「🔒 系统维护·只读」，让商家看得见系统怎么生成（透明），但不可改。
- **我的风格微调（可编辑）**：风格口吻（下拉+自定义）/ 固定品牌话术 / 强调卖点 / 额外禁忌词（叠加到合规之上）。
- **生成参数（进阶·可调）**：爆款拆解 / 仿写 / 标题三场景的**温度 + 最大字数**可调；**合规预审温度锁定 0.0、disabled**；「恢复默认」。
- 操作：保存微调（下次生成生效）。

### 11.3 后台「模型参数」页（按商户）
- 配置对象选择：**平台默认（全租户基线）** 或 **指定租户**。
- 场景 × 参数表：爆款拆解 / 仿写 / 标题字幕CTA / 合规预审 / 图片视频打标，各配 模型 / 温度 / top_p / 最大tokens。
- 选某租户 → 每行显示「继承默认 / 自定义」，可**单独覆盖**或**重置**；未覆盖继承平台默认。
- 商家端 ③ 的可调范围 = 平台为该租户设定的范围内（运营设护栏，商家在内微调）。

### 11.4 数据对象（增补）
- `prompt_baseline`（基线·后台）：scene(enum) · content(text) · version · industry · editable=false · visible_to_tenant=true
- `prompt_tune`（商家微调·公司隔离）：company_id · tone · brand_line · selling_points · extra_taboo · updated_at
- `gen_param`（生成参数·按商户）：company_id(null=平台默认) · scene(enum) · model · temperature · top_p · max_tokens · source(默认/自定义/继承) · locked(合规=true)

### 11.5 设计约束 / 红线
1. **基线不可编辑**：商家端只读可见，无任何编辑入口（know-how 透明但不外泄编辑权）。
2. **合规不可松**：合规预审基线 + 温度 0.0 锁定，商家微调的「额外禁忌词」只能**加严不能放松**。
3. **微调不破基线**：风格/卖点/参数叠加，不能覆盖拆解逻辑与合规规则。
4. **按商户隔离**：微调层与生成参数均按 company_id 隔离；后台覆盖只影响目标租户。
5. **参数边界**：温度 (0,2]，超界拦截；合规场景参数对商家只读。

### 11.6 验收标准（v2.0）
1. 商家端可看到 5 条基线提示词**完整内容**且无编辑入口。
2. 商家可编辑风格微调（口吻/品牌词/卖点/禁忌）并保存，生成时可感叠加生效。
3. 商家可调爆款拆解/仿写/标题三场景温度与字数；**合规预审温度锁定、不可改**。
4. 后台可对指定租户覆盖某场景模型参数，未覆盖租户继承平台默认；可重置。
5. 微调与参数均按 company_id 隔离，互不影响；合规底线不被任何微调放松。

### 12.2 三层与版本

继续采用系统基线、租户微调、生成参数三层模型。每次运行必须保存 Prompt ID/版本、Skill ID/版本、模型、输入快照、知识版本、VI 版本和输出产物。租户微调只能加严合规或调整语气，不得覆盖事实确认门和渠道边界。

### 12.3 结构化校验

Prompt 输出必须经过 JSON Schema 校验、事实引用校验、合规校验。校验失败进入 `failed`，不得写正式知识或创建发布任务。合规检查温度锁定为 0；密钥、Cookie、token 和密码禁止进入 Prompt 或日志。

### 12.4 验收

1. P-001 能区分朋友圈/海报导出与公众号发布。
2. P-010 不覆盖人工确认字段。
3. P-030 默认输出 `pending_confirmation`。
4. P-041 缺少公众号账号或发布方式时返回校验错误。
5. 历史任务可按 Prompt/Skill/模型版本复现。
6. P-042 优先使用企业大脑已确认事实；证据不足时输出宽泛人群并标记待确认，不得虚构具体客户属性。
7. P-043 只生成待确认方案，不创建正式成片任务；P-044 存在 blocker 或未处理 warning 时必须返回 `render_allowed=false`。
